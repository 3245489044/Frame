## §3 分型（决定能否机械替换）

### 3.1 可**等价**替换（直接 `PortGuard.Required`，1:1，同抛点 / 同 `ParamName`）
| 旧形 | 新形 |
|---|---|
| `ArgumentNullException.ThrowIfNull(x);` | `PortGuard.Required(x, nameof(x));` |
| `x ?? throw new ArgumentNullException(nameof(x))` | `PortGuard.Required(x, nameof(x))` |
| `_f = x ?? throw new ArgumentNullException(nameof(x));` | `_f = PortGuard.Required(x, nameof(x));` |

> 语义保证：`MissingDependencyException : ArgumentNullException`，既有 `catch (ArgumentNullException)` **不回归**。

### 3.2 需**注意**（可替换，但须带消息 / 保留语义）
| 旧形 | 新形 |
|---|---|
| `throw new ArgumentNullException(nameof(x), "msg");` | `PortGuard.Required(x, nameof(x), "msg");`（3 参重载） |
| `if (x is null) throw new ArgumentNullException(nameof(x));` | `x = PortGuard.Required(x, nameof(x));`（或保留 if，语义不变） |

### 3.3 **禁止**直接替换（保持原样或另行处理）
| 形态 | 原因 |
|---|---|
| `: base(...)` 内的空值护栏 | 基类构造语义，非端口 |
| 字段初始化器内 `= x ?? throw …` | 初始化器不可含复杂表达式（视 C# 版本） |
| 表达式体成员 `=> x ?? throw …` | 替换后仍需表达式体，注意返回值类型 |
| `?? throw new InvalidOperationException/ArgumentException` | **非** `ArgumentNullException` 家族，不属本门禁 |
| `ArgumentNullException.ThrowIfNull` 对 **值类型/结构** 端口 | `PortGuard.Required<T> where T : class` 不适用（需另法） |
| 三元/链式 `a ?? b ?? throw …` | 需人工判断唯一必填点 |

> **替换前必须分型**，不可"全量正则一把梭"（禁大爆炸，红线见设计 §11）。

## §6 `FailSink` 应用点（P4 · 执行期记账）

**适用**：`Check-FallbackInventory` F2 的 `catch` 吞并候选（1196 处，无 `throw`/`handle(`/`FailureBudget`）。

| 旧形 | 新形 |
|---|---|
| `try { … } catch (Exception ex) { _log.Warn(ex.Message); continue; }` | `_sink.Try(() => …, "op");`（分类 + 落账，不吞并） |
| `catch { return default; }`（静默） | `var o = _sink.Try(() => …, "op"); return o.Ok ? … : default;` |

**接线**（组合根）：`new FailSink(ErrorClassifierPortAdapter.Instance, new FailureBudget())`；未接线/测试用 `NullGuardSink.Instance`。

**分批**：优先 `Agent.Modules`/`Agent.Core`/`Operation` 的生产路径（F2 热点：`DatabaseModule`/`DaemonPool`/`ElementCalculate_Script`…）。**不追求 1196 → 0 一次**；先接"熔断不可见"的敏感路径，判据 F2 棘轮下降。

## §7 `ModuleAssembler` 应用点（P3 · 初始化编排）

**适用**：`LifecycleManager`/`RegisterModule` 顺序初始化族（顺序错即失败）。

**步骤**：
1. 将各初始化单元改实现 `IModuleNode`（或继承 `InitializableBase`），声明 `Name`/`DependsOn`/`Order`。
2. 组合根用 `ModuleAssembler` 替代手工顺序：`Add(node…)` → `await AssembleAsync(ct)`。
3. 失败分层：`result.MissingPorts`（装配缺陷）与 `result.FailedModules`（运行失败）分别处置。

**顺序**：先在**一个**组合根（如 `FrameworkInitializer` 或某 `XxxHosting`）试点（乱序注册仍正确），再推广。

## §8 风险与陷阱（应用时必读）

1. **语义等价红线**：`PortGuard.Required` 与 `ThrowIfNull` 同抛点、同 `ParamName`；`MissingDependencyException : ArgumentNullException` 保证既有 `catch` 不回归（红线 #1）。
2. **值类型端口**：`PortGuard.Required<T> where T : class` 不含 struct；结构端口沿用原判空。
3. **框架自身树**：`BasicMethod\Initialization\` 内的 `?? throw new MissingDependencyException` **不计入** G1/G2（已是新形）；统计时须剔除。
4. **传递可见**：Frame 侧经 `BasicMethod` 伞工程传递可见；**产品侧（Agent/Produce）** 经烘焙二进制 → 已登记 `Projects\BuildFramework\CsharpBakeRefs.props`（`Check-BakeFramework` 在册）。
5. **禁大爆炸**：按 area 分批；每批 `build`（含隐藏 `: base()` 兜底）+ 门禁。
6. **`InitializableBase.Require` 延后抛**：缺失端口返回 `null!`，组件须 `State==Ready` 后方可对外使用（否则 NRE 掩盖装配缺陷）。
7. **`FailSink.Try` 仅同步 `Action`**：异步/返回值场景需扩 `TryAsync`/`Try<T>`（非本框架现状；按需增量）。
8. **基线纪律**：`InitGuards.psd1` 只减不增（G1/G2）/只增不减（G3），`-UpdateBaseline` 仅收紧。
