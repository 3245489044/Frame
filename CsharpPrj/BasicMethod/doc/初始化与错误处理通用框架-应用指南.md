## §0 一句话与适用面

> 把散落的手写 `?? throw` / `?? new 默认` / `catch→log→continue` 收口为四件事：
> **一条端口声明（`PortSlot`/`Require`）＋ 一个处置门面（`PortGuard`）＋ 一次拓扑编排（`ModuleAssembler`）＋ 一个失败账本（`FailSink → IFailureBudget`）**，同时保留 **T/N/D 三出口** 的语义不变性。

| 你面对的场景 | 用哪个 |
|---|---|
| 构造/方法入口要「必填参数不能为空」 | `PortGuard.Required`（§4） |
| 类有一堆必填依赖，要在装配期一次性报全缺失 | `InitializableBase.Require` + `AssertPortsComplete`（§3、§4） |
| 可选依赖，缺省要显式空对象而非匿名兜底 | `PortSlot.Optional` / `InitializableBase.Optional`（§3） |
| 模块初始化有先后依赖，不能靠注册顺序 | `IModuleNode` + `ModuleAssembler`（§5） |
| 一次可能失败的调用，要分类且落账、不吞错 | `FailSink.Try` / `Record` + `IFailureBudget`（§6） |

## §2 三出口 T/N/D 对照（唯一受控出口）

| 出口 | 语义 | 本框架载体 | 约束 |
|---|---|---|---|
| **T** `throw`（fail-fast） | 缺前置即崩，不掩盖 | `PortGuard.Required` / `PortGuard.PortsComplete` → `MissingDependencyException` | 禁 `catch` 后静默继续；禁 `?? new 默认` 冒充装配 |
| **N** 命名空对象 | 显式声明「此处允许无操作」 | `PortSlot.Optional` / `PortGuard.Optional(value, NullXxx.Instance)` | 空对象须**命名**（`NullXxx`），禁匿名 `?? new` |
| **D** 显式降级 + 可见化 | 有界降级且必落证据 | `PortSlot.Degradable` + `FailSink.Try/Record`（落 `IFailureBudget`） | 禁静默；须带原因 + 动作 |

## §3 用法 A — 声明端口（`InitializableBase`）

组件继承 `InitializableBase`，用 `Require`（T）/`Optional`（N）解析端口；`Require` **不就地抛**，而是登记缺失，等到 `InitializeAsync` 末尾统一 fail-fast（一次性报全）。

```csharp
using BasicMethod.Initialization;
using BasicMethod.Initialization.Errors;
using BasicMethod.Initialization.Ports;

public sealed class SessionWriter : InitializableBase
{
    private readonly IStore _store;       // T：必填
    private readonly IClock _clock;       // N：可选（缺省用命名空对象）

    public SessionWriter(IStore? store, IClock? clock)
    {
        _store = Require(store, nameof(store));                 // 缺失登记，不抛
        _clock = Optional(clock, NullClock.Instance);           // 缺省空对象
    }

    public override string Name => "SessionWriter";
    public override IReadOnlyList<string> DependsOn => new[] { "Store" };  // 拓扑依赖（§5）
    public override int Order => 10;

    protected override async ValueTask OnInitializeAsync(CancellationToken ct)
    {
        await _store.OpenAsync(ct).ConfigureAwait(false);        // 建连接/预热
        // 若 _store 之前缺失，这里 _store 为 null! —— 初始化完成前不得使用
    }
}
```

> **关键约定**：`Require` 缺失时返回 `null!`，真正抛点在 `InitializeAsync` 末尾的 `AssertPortsComplete()`。**组件须在初始化完成后（`State==Ready`）方可对外使用**。

用 `PortSlot<T>` 可把"必填/可选/可降级"进一步**声明化**（一个槽位对象承载出口语义）：

```csharp
var storeSlot  = PortSlot<IStore>.Required("store");     // T
var clockSlot  = PortSlot<IClock>.Optional("clock");     // N
var cacheSlot  = PortSlot<ICache>.Degradable("cache");   // D
var bound      = storeSlot.Bind(store);                  // 装配期唯一赋值点
```

## §4 用法 B — 装配期 fail-fast（`PortGuard`）

`PortGuard` 是**参数入口 / 装配期**的唯一处置门面，用于两类场景：

1. **参数入口**（替代手写空值护栏，行为等价 `ArgumentNullException.ThrowIfNull`，**同抛点、同 `ParamName`**）：

```csharp
using BasicMethod.Initialization.Guards;

// 旧： ArgumentNullException.ThrowIfNull(input);
// 新：
PortGuard.Required(input, nameof(input));

// 旧： _client = client ?? throw new ArgumentNullException(nameof(client));
// 新：
_client = PortGuard.Required(client, nameof(client));

// 旧的带消息形态： throw new ArgumentNullException(nameof(x), "配置缺失");
_x = PortGuard.Required(x, nameof(x), "配置缺失");
```

2. **装配期集合校验**（一次性报全缺失，非首个即抛）：

```csharp
PortGuard.PortsComplete("SessionWriter", new[] { "store", "clock" });
// → throw new MissingDependencyException("SessionWriter", new[]{"store","clock"})
```

**异常语义**：`MissingDependencyException : ArgumentNullException`，故既有 `catch (ArgumentNullException)` **不回归**；`e.MissingPorts` 给出缺失端口集合（供门禁/看板统计装配期缺陷）。

## §5 用法 C — 模块拓扑序装配（`IModuleNode` + `ModuleAssembler`）

把"注册顺序即初始化顺序"升级为"依赖拓扑序"。模块实现 `IModuleNode`（或继承 `InitializableBase`），声明 `DependsOn`；用 `ModuleAssembler` 装配。

```csharp
using BasicMethod.Initialization;
using BasicMethod.Initialization.Modules;

var assembler = new ModuleAssembler();          // 或经 IModuleAssembler 注入
assembler.Add(new StoreModule());               // Name="Store"
assembler.Add(new SessionWriter(...));          // DependsOn=["Store"]

AssemblyResult result = await assembler.AssembleAsync(ct);
if (!result.Ok)
{
    // 装配缺陷（缺端口）与运行失败（模块体异常）分层可见：
    foreach (var p in result.MissingPorts)   Console.WriteLine($"缺端口: {p}");
    foreach (var m in result.FailedModules)  Console.WriteLine($"初始化失败模块: {m}");
}
```

**行为要点**：

| 情形 | 处理 |
|---|---|
| 同层多个就绪节点 | 按 `Order` 稳定排序（确定性装配序） |
| 依赖名未注册 | `throw InvalidOperationException("模块 'X' 依赖的 'Y' 未注册。")` |
| 模块名重复 | `throw InvalidOperationException("模块名重复：X …")` |
| 存在依赖环 | 环内节点进 `AssemblyResult.FailedModules`（**不就地抛**） |
| 模块抛 `MissingDependencyException` | 缺失端口进 `AssemblyResult.MissingPorts`，模块名进 `FailedModules` |
| 模块抛其它异常 | 模块名进 `FailedModules`（不吞并语义，交由上层账本/日志） |

## §6 用法 D — 执行期折叠 + 记账（`FailSink` + `IFailureBudget`）

`FailSink` 是"分类 + 记账"的单一入口；分类委托上提端口 `IErrorClassifier`，记账委托上提端口 `IFailureBudget`（实现经组合根注入，本层零对外依赖）。

```csharp
using BasicMethod.Initialization;
using BasicMethod.Initialization.Ports;

// 组合根装配：classifier 必填；budget 可选（未注入则只折叠不记账）
var sink = new FailSink(classifier, budget);

// 用 Try 折叠一次可能失败的调用（不吞错，失败即落账）
ErrorOutcome outcome = sink.Try(() => _store.Flush(), op: "store.flush");
if (!outcome.Ok)
{
    // outcome.Class（ErrorClass?）/ outcome.Error 可读；已按容忍度记账
}

// 已有的 ErrorOutcome 也可显式记账
sink.Record(ErrorOutcome.From(ex, "store.flush", classifier.Classify(ex)));
```

**容忍度判定**（`FailSink.ClassifyToTolerance`，对齐 axioms §5）：

| ErrorClass | 容忍度 | 账本动作 |
|---|---|---|
| `CompilationError` / `ExecutionFailure` | `Tolerated` | 只记账，不升 level |
| 其余（`Timeout`/`EmptyResult`/`ResourceExhausted`/`Irrecoverable`/`ParseError`/`PartialOutput`） | `Fatal` | 升级 `FailureBudget.level` |

> 未接线场景用 `NullGuardSink.Instance`（分类恒 `ExecutionFailure`、记账空操作）作确定性替身，避免调用点匿名 `?? new`。

## §7 组合根接线（端到端）

```csharp
// 组合根（唯一装配点）：显式 new 具体实现 + 声明端口 + 启动自检
IErrorClassifier classifier = Share.TaskStatusPool.Loops.ErrorClassifierPortAdapter.Instance;  // 桥接 canonical 分类器（§11 P0.5-b 已接线）
IFailureBudget   budget     = new Share.TaskStatusPool.Loops.FailureBudget();

var sink     = new FailSink(classifier, budget);
var assembler = new ModuleAssembler();
assembler.Add(new StoreModule());
assembler.Add(new SessionWriter(store, clock));

AssemblyResult r = await assembler.AssembleAsync(ct);   // 拓扑序初始化 + 失败分类
if (!r.Ok) throw new MissingDependencyException("Composition", r.MissingPorts);
```

## §8 依赖与工程规则

- **零对外依赖**：`BasicMethod.Initialization` 的 csproj **不含任何 `<ProjectReference>`**（仅 BCL）。所需原语以**端口倒置**上提至本层（`ErrorClass`/`ErrorTolerance`/`IErrorClassifier`/`IFailureBudget`），实现留在下游经组合根注入。
- **禁止**：`BasicMethod` 侧反向引用其它 root（`Share`/`Modules`/`DataCenter`/…）。历史欠账（`BasicMethod → Share.ConfigurationModels`、`Share.LayoutAnalysis`）不在本框架范围。
- **下游引用方式**：
  - **Frame 侧**：引用 `BasicMethod` 伞工程（或经其传递）即**编译期可见** `BasicMethod.Initialization`（传递引用）；如需显式，加 `<ProjectReference Include="$(Proj_BasicMethod_Initialization)" />`。
  - **产品侧（Agent/Produce）**：经烘焙二进制消费——在 `Projects\BuildFramework\CsharpBakeRefs.props` 的具名清单登记 `BasicMethod.Initialization`（**P0.5-b 待办**，见 §11）。
- **命名**：本框架门面名为 `PortGuard`，**非** `Guard`——避免与既有 `Share.TaskStatusPool.Loops.Guard`、`GraphFramework.Helpers.Guard` 撞名（禁第三同名平行实现）。
- **拓扑复用**：`ModuleAssembler` 的 Khan 排序用于「模块装配序」；通用图拓扑在 `GraphFoundation.GraphTopology`（因跨工程边界，本层不引用）。

## §9 反模式（Do / Don't）

| 场景 | ✅ 推荐 | ❌ 禁止 | 违反 |
|---|---|---|---|
| 必填依赖缺省 | `PortGuard.Required` / `Require`+`AssertPortsComplete` | `?? new 默认服务()` 掩盖装配缺失 | 隐藏第二真源 |
| 可选依赖缺省 | `Optional(x, NullXxx.Instance)` 命名空对象 | 匿名 `?? new X()` | 非命名 N |
| 参数空值 | `PortGuard.Required(x, nameof(x))` | 各文件散落手写 `if (x is null) throw new ArgumentNullException(...)` | 重复载体 |
| 可能失败的调用 | `FailSink.Try`（分类 + 记账） | 裸 `catch { log; continue; }` | 吞并 |
| 模块初始化顺序 | `DependsOn` + `ModuleAssembler` | 靠 `RegisterModule` 调用顺序 | 顺序耦合 |
| 需要空值/降级门面 | 复用 `PortGuard` | 新建第三个 `Guard` | 平行实现 |
