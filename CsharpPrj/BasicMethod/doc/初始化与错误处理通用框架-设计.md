# 初始化与错误处理通用框架 — 设计文档

> 日期：2026-10-04
> 范围：`Frame\CsharpPrj` + `Projects\Plug\Agent\src`
> 触发：框架回退消除重构（`Docs\analysis\2026\10\10.5\2026-10-04-框架回退逻辑彻底消除-重构方案.md`）过程中暴露的结构性问题 —— 大量 `?? throw` / `?? new` 不是"点状欠账"，而是**缺失一个统一的初始化与错误处理框架**。
> 关联规则：`axioms.md`（T/N/D 三出口、`AX.FailureBudgetEscalation`、`SEP.JudgmentCarrierStructural`）、`logic.md`（`LO.Resolve` 末路完备）、`dsl.md`（载体映射）。

## §0 一句话结论

> 当前代码里 **1939 处 `throw new ArgumentNullException` + 1001 处 `ArgumentNullException.ThrowIfNull`（合计约 2940 处空值护栏）**、**82 处服务端口 `?? new 默认`**，本质是同一个缺失：**没有一个"声明式端口 + 统一装配 + 分类处置"的通用框架**。开发者只能对**每一个**构造点手写「校验必填 / 兜底可选 / 生命周期初始化 / 失败处置」，于是同一件事被重复了数千次，且每次都在重新发明 T/N/D 三种控制流。

## §1 症状量化（实测，2026-10-04）

| 症状 | 计数 | 位置 |
|---|---|---|
| `throw new ArgumentNullException(nameof(x))` | **1939** | 构造/方法入口 |
| `ArgumentNullException.ThrowIfNull(x)` | **1001** | 构造/方法入口 |
| 服务端口 `X ?? new 默认服务()` | 82（已消 27，余 55） | 构造函数 |
| `catch` 块 | 1476 | 全库 |
| `catch` 吞并候选（无 throw/handle/FailureBudget） | 1196 | 全库 |
| 灰发开关 / `[Obsolete]` / legacy 形参 | 30 / 53 / 50 | 全库 |

**特征**：三种控制流（T=`throw`、N=命名空对象、D=显式降级+可见）在**同一个方法里被临时决定**，无统一载体、无统一账本、无统一校验点。约 2940 处护栏中，绝大多数是**机械重复**（"这个参数不能为 null"）。

## §2 根因分析（为什么"缺框架"必然导致护栏洪水）

### 2.1 缺失「初始化契约」
- **端口必填性无声明载体**：一个类需要 `IResolver`/`IExecutor`/`IConfig`… 只能靠**构造函数签名 + 手写 `?? throw`** 表达"必填"。没有 `PortSlot`/`required` 之类的**声明式**载体，于是每个类各自 `?? throw`。
- **依赖装配无唯一入口**：`new X(a ?? new DefaultA(), b ?? NullB.Instance)` 散布在**调用点**（组合根、工厂、Builder、测试）。谁负责装配、缺了谁负责 fail-fast，**没有架构答案**，只能就地兜底 → 产生 82 处 `?? new`（隐藏第二真源）。
- **生命周期无编排**：`IModule`/`ILifecycleManager`（`BasicMethod.Framework.Abstractions`）已存在，但**不成体系**：无端口声明、无依赖拓扑序、无"初始化失败如何处置"的分类。

### 2.2 缺失「错误分类与处置」
- **"缺前置条件"（装配期）与"运行失败"（执行期）未分层**：两者都写成 `throw` 或都写成 `catch→log→continue`，于是：
  - 装配期该 fail-fast 的被 `?? new` 掩盖（C1）；
  - 执行期该记 `FailureBudget` 的被裸 `catch` 吞掉（C2，1196 处）。
- **无统一账本接入口**：`FailureBudget`（tolerated/fatal/level）已在 `axioms` 定义，但代码侧没有 `Guard`/`Outcome` 门面把它接到"每一次可能失败的调用"，于是每处 `catch` 各写各的。

### 2.3 缺失「递归式的策略作用域」
- 错误动作域（halt/retry/switch）由 `Scope` 决定（`axioms §4`），但代码侧无统一 `handle(error, Scope)` 落点，导致同一错误在不同文件里被处置成不同动作。

## §3 设计目标与原则

| # | 目标 | 原则（对齐规则） |
|---|---|---|
| G1 | **端口必填性声明化** | 必填=编译期/装配期强制（T）；可选=命名空对象（N）；有界降级=可见化（D）。对齐 `axioms` T/N/D 三出口 |
| G2 | **装配唯一入口** | `new 默认实现` 只允许出现在组合根；其余点只"声明需求"。对齐 `Strategy.SingleImplementation`、`AX.StateRootSingleSource` |
| G3 | **失败分类单一入口** | 装配期缺前置 → fail-fast；执行期失败 → `ClassifyError` → `FailureBudget`。对齐 `AX.FailureBudgetEscalation`、`LO.Resolve 末路完备` |
| G4 | **零侵入可增量** | 先做"语义等价封装"，再逐批替换 `?? throw`；不改变现有公开行为 |
| G5 | **不引入新基底算子** | 只做门面/声明层，逻辑仍是 3 高阶函数（Assess/Aggregate/Resolve） |

## §5 初始化侧设计 —— 声明式端口 + 统一装配

### 5.1 端口声明：`PortSlot<T>`（替代手写 `?? throw` / `?? new`）

**核心思想**：把"这个依赖是什么"从**命令式的 `?? throw`** 提升为**声明式绑定**，绑定表达式只写一次，T/N/D 语义由 `PortSlot` 统一裁决。

```csharp
namespace BasicMethod.Initialization;

/// <summary>端口的受控出口（对齐 axioms T/N/D 三出口）。</summary>
public enum PortExit { Required, NullObject, Degrade }

/// <summary>声明式端口槽：把「必填/可选/可降级」从命令式 ?? throw 提升为声明。</summary>
public readonly struct PortSlot<T> where T : class
{
    public T? Value { get; }
    public string Name { get; }
    public PortExit Exit { get; }

    private PortSlot(string name, T? value, PortExit exit) { Name = name; Value = value; Exit = exit; }

    /// <summary>T：必填端口。缺省即 fail-fast（装配期）。</summary>
    public static PortSlot<T> Required(string name) => new(name, null, PortExit.Required);

    /// <summary>N：可选端口，缺省用命名空对象（NullXxx.Instance）。</summary>
    public static PortSlot<T> Optional(string name) => new(name, null, PortExit.NullObject);

    /// <summary>D：有界降级，缺省即显式 Degrade + 可见化。</summary>
    public static PortSlot<T> Degradable(string name) => new(name, null, PortExit.Degrade);
}
```

### 5.2 初始化基类：`InitializableBase`（把 `?? throw` 收敛成一句 `Require`）

```csharp
/// <summary>可初始化组件基类：统一端口校验 + 生命周期，消除每类各自手写 ?? throw。</summary>
public abstract class InitializableBase : IAsyncInitializable
{
    private readonly List<string> _missing = new();
    private InitState _state = InitState.Created;

    public InitState State => _state;

    /// <summary>T：解析必填端口；null 即登记缺失（装配期统一 fail-fast，而非就地抛）。</summary>
    protected T Require<T>(T? value, string name) where T : class
    {
        if (value is null) { _missing.Add(name); return Missing<T>.Instance; }
        return value;
    }

    /// <summary>N：解析可选端口；缺省用命名空对象（调用方提供 Null 实现）。</summary>
    protected T Optional<T>(T? value, T nullObject) where T : class
        => value ?? nullObject;

    /// <summary>装配期自检：任一必填缺失 → 一次性 fail-fast（可诊断、可归因）。</summary>
    protected void AssertPortsComplete(string component)
        => Guard.PortsComplete(component, _missing);

    public async ValueTask InitializeAsync(CancellationToken ct)
    {
        if (_state != InitState.Created) return;
        _state = InitState.Initializing;
        await OnInitializeAsync(ct).ConfigureAwait(false);
        AssertPortsComplete(GetType().Name);
        _state = InitState.Ready;
    }

    protected virtual ValueTask OnInitializeAsync(CancellationToken ct) => ValueTask.CompletedTask;
}

public enum InitState { Created, Initializing, Ready, Failed, Disposed }

public interface IAsyncInitializable
{
    InitState State { get; }
    ValueTask InitializeAsync(CancellationToken ct);
}
```

### 5.3 门面：`Guard`（唯一处置入口，区分"缺前置" vs "运行失败"）

```csharp
public static class Guard
{
    /// <summary>装配期 / 参数入口：必填为空 → fail-fast（等价 ArgumentNullException，但统一载体）。</summary>
    public static T Required<T>(T? value, string name) where T : class
        => value ?? throw new MissingDependencyException(name);      // 出口 T

    /// <summary>装配期：端口集合校验，一次性报告全部缺失（非首个即抛）。</summary>
    public static void PortsComplete(string component, IReadOnlyList<string> missing)
    {
        if (missing.Count > 0) throw new MissingDependencyException(component, missing);
    }

    /// <summary>执行期：把可能失败的操作折叠为 Outcome（不吞错，落 FailureBudget）。</summary>
    public static ErrorOutcome Try(Action body, string op)
    {
        try { body(); return ErrorOutcome.Ok(op); }
        catch (Exception ex) { return ErrorOutcome.From(ex, op); }   // 分类 + 记账在 FailSink
    }
}

/// <summary>缺前置依赖（装配期错误）——与"运行失败"分层的专用异常。</summary>
public sealed class MissingDependencyException : InvalidOperationException
{
    public IReadOnlyList<string> MissingPorts { get; }
    public MissingDependencyException(string port) : base($"缺少必填端口：{port}") 
        => MissingPorts = new[] { port };
    public MissingDependencyException(string component, IReadOnlyList<string> missing)
        : base($"{component} 缺少必填端口：{string.Join(", ", missing)}") => MissingPorts = missing;
}
```

> **收益**：`?? throw new ArgumentNullException(nameof(x))`（1939 处）→ `Guard.Required(x, nameof(x))`；`ArgumentNullException.ThrowIfNull(x)`（1001 处）→ `Guard.Required(x, nameof(x))`。**语法近恒等、可脚本批量替换**，同时把"缺前置"收敛为**专用异常类型**（可被门禁/看板统计，可与运行失败分层）。

## §6 错误处理侧设计 —— 分类 + 账本 + 处置

### 6.1 分层模型（装配期 vs 执行期）

| 阶段 | 失败语义 | 载体 | 处置 | 出口 |
|---|---|---|---|---|
| **装配期**（构造/Initialize） | 缺前置依赖 | `MissingDependencyException` | fail-fast，一次性报告全部缺失 | **T** |
| **执行期**（方法调用/IO） | 运行失败 | `ErrorOutcome` + `ErrorClass` | `ClassifyError` → `FailureBudget`（tolerated 只记账 / fatal 升级） | **D**（可见） |
| **可选依赖** | 语义上允许无操作 | 命名空对象 `NullXxx.Instance` | 无操作，显式声明 | **N** |

### 6.2 `ErrorOutcome`（执行期统一折叠，替代裸 `catch→log→continue`）

```csharp
/// <summary>执行期结果（不吞错）：把 try/catch 的处置统一为可记账的 Outcome。</summary>
public readonly struct ErrorOutcome
{
    public bool Ok { get; }
    public string Op { get; }
    public ErrorClass? Class { get; }   // 复用 axioms.ErrorClass
    public Exception? Error { get; }

    public static ErrorOutcome Ok_(string op) => new(true, op, null, null);
    public static ErrorOutcome Ok(string op) => Ok_(op);
    public static ErrorOutcome From(Exception ex, string op)
        => new(false, op, FailSink.Classify(ex), ex);
}

/// <summary>错误分类与账本接线的单一入口（对齐 axioms Gate.ClassifyError + AX.FailureBudgetEscalation）。</summary>
public static class FailSink
{
    /// <summary>纯分类：异常 → ErrorClass（无动作）。</summary>
    public static ErrorClass Classify(Exception ex) => ex switch
    {
        OperationCanceledException => ErrorClass.timeout,
        TimeoutException          => ErrorClass.timeout,
        FormatException           => ErrorClass.parse_error,
        _                         => ErrorClass.execution_failure,
    };

    /// <summary>记账：分类 → FailureBudget（tolerated 只记账 / fatal 升级 level）。</summary>
    public static void Record(ErrorOutcome outcome, IFailureBudget budget)
    {
        if (outcome.Ok) { /* eval=pass → level 衰减，由调用方决定 */ return; }
        budget.Apply(ClassifyToTolerance(outcome.Class!.Value));
    }

    private static ErrorTolerance ClassifyToTolerance(ErrorClass c)
        => c is ErrorClass.compilation_error or ErrorClass.execution_failure
            ? ErrorTolerance.tolerated   // 单步增量试错：只记账、不升级
            : ErrorTolerance.fatal;      // timeout/empty_result/resource_exhausted：升级
}
```

> **接线**：`IFailureBudget` 适配既有 `Context.budget`（`axioms §2` / `formula §4.5 EvaluateDrivenUpdate`）。`FailSink` 是**唯一**分类+记账入口，替代全库 1196 处 `catch` 吞并。

## §7 生命周期编排 —— 拓扑序 + 阶段化

### 7.1 现有资产与差距

- **已有**：`Modules.Framework.Abstractions.IModule`（`Name`/`State`/`Initialize`/`Shutdown`）、`ILifecycleManager`（`RegisterModule(s)` + `Initialized`/`ShutdownCompleted` 事件）、基础实现 `LifecycleManager`。
- **差距**：
  1. 无**依赖拓扑序**（`RegisterModule` 顺序即初始化顺序 → 顺序错即失败）；
  2. 无**异步**（`void Initialize()`）；
  3. 无**端口完备性校验**（缺端口只能运行期炸）；
  4. 无**失败处置分类**（初始化失败与运行失败混淆）。

### 7.2 增强设计：`ModuleAssembler`（依赖拓扑序 + 阶段化 + 失败分类）

```csharp
/// <summary>模块初始化编排器：拓扑序 + 阶段化 + 失败分类（扩展既有 ILifecycleManager）。</summary>
public interface IModuleAssembler
{
    void Add(IModuleNode node);
    ValueTask<AssemblyResult> AssembleAsync(CancellationToken ct);
}

public interface IModuleNode : IModule
{
    /// <summary>本模块依赖的其它模块名（用于拓扑排序）。</summary>
    IReadOnlyList<string> DependsOn { get; }
    int Order { get; }                    // 同层内次序
}

public readonly struct AssemblyResult
{
    public bool Ok { get; }
    public IReadOnlyList<string> FailedModules { get; }
    public IReadOnlyList<string> MissingPorts { get; }
}
```

**阶段化**（对齐 `formula` 五步模型类比）：`Construct`（`new`/注入）→ `Configure`（读配置）→ `Initialize`（建连接/预热）→ `Ready`（对外可用）。每阶段失败 → `AssemblyResult` 归类（`MissingPorts` ⇒ 装配缺陷；其它 ⇒ 运行失败）。

> **复用**：拓扑排序复用既有 `GraphTopology.Sort`（`ExecutionFramework`，Kahn），避免第二实现（`Strategy.SingleImplementation`）。

## §11 风险与红线

1. **禁语义漂移**：`Guard.Required` 必须**行为等价**于 `ArgumentNullException.ThrowIfNull`（同抛点、同参数名），否则 P1 替换即引入回归。
2. **禁大爆炸**：P1 批量替换按**子系统分批**（证据：批 3 中隐藏 `: base()` 调用点只能靠构建兜住），每批 build+门禁。
3. **不新增基底算子**：本框架只是门面/声明层，逻辑仍归 3 高阶函数（`logic §1`）；`MissingDependencyException` 归 `LO.Resolve` 的 T 出口。
4. **不与既有框架冲突**：复用 `BasicMethod.Framework.Abstractions.IModule`、`FailureBudget`、`GraphTopology`，禁第二实现（`Strategy.SingleImplementation`）。
5. **保留既有合法面**：`FacadeDataStore`/`UniversalMiddleware` 等文档化可选默认仍为 N（登记），不强制 T。
6. **白名单/棘轮纪律**：`Check-FallbackInventory` 基线只减不增、禁降基线过关（沿用）。
