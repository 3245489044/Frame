> 版本：v1.0（2026-09-17）

> 纪律：本文档只写「怎么基于 Pipeline 重构 + 哪些不做」，**不重写**既有文档已覆盖的机制搬迁方案（分工见 §0.3）。

## §0 结论与定位

### 0.1 一句话结论

> 管线框架的能力面**已经够用**（三体系 + 8 个组合子 + StaticPipeline + StepExec + CentralPipeline + 阶段注册表，29 文件 / 约 196 KB），
> 真正的问题不在"缺能力"，而在**三个错配**：
> ① **该用没用的**——多处「逐类型分派（switch/if 链）+ 批处理」仍手写（GraphFramework 指令分发 13×2、QueryService 2 处、TreeTrace 15、LogicComposition 15/16/14、FrontEndDriven 18、UniversalMiddleware 6 …）；
> ② **不该用硬用的**——递归遍历 / JSON Schema 递归 / 热路径 per-element 求值被误当阶段编排（本轮已用「表驱动 + 零依赖遍历骨架」解掉标准层那一处，见 §0.3）；
> ③ **依赖面不清的**——`Operation\FrontEndDriven` 出现 `using Modules.Pipeline` 却**未声明** Pipeline 依赖（经 `PlaceholderFramework`/`UniversalMiddleware`/`StateManagement`/`EventBindingOrchestrator` 传递获得），属隐式依赖。
>
> 收敛方向：**以"是否存在阶段边界"为唯一判据**——有阶段边界（顺序/分支/并行/重试/超时/可见化）→ 用 Pipeline；无阶段边界（纯递归/查表/逐元素转换）→ 用**表驱动**，禁包 Pipeline。

### 1.2 选型速查（决策树）

```
是否存在"阶段边界"（阶段可命名、可单独成败、可单独插拔）？
├─ 否 → 不要用 Pipeline
│   ├─ 结构递归下钻 → BasicMethod.Declarative.StructuralWalk（零依赖遍历骨架）
│   ├─ 逐成员/逐键映射 → 契约层表（如 PortImplVocabulary.ExprSlots 范式）
│   └─ O(1) 查表路由 → 直接表/字典（包 Pipeline = 纯调度开销）
└─ 是 → 用 Pipeline
    ├─ 步骤集合编译期固定 → StaticPipeline + Step(..., IsFatal)
    ├─ 步骤集合运行期增删 → StagePipeline<TContext> / CentralPipeline（分段）
    ├─ 逐类型/逐键分派 → PipelineSwitch / PipelineBranch
    ├─ 批量逐项处理 → ForEachPipeline / ParallelPipeline
    ├─ 需要降级/重试/超时 → PipelineTryCatch / PipelineRetry / WithTimeout
    └─ 数据流换类型 → 体系 A（IPipeline<TIn,TOut>）+ Then()
```

## §2 依赖红线矩阵（决定"能不能引"的唯一依据）

### 2.1 三类依赖面（实测，2026-09-17）

| 类 | 项目 | 依据（csproj / ModuleRule） | 可直引 Pipeline |
|---|---|---|---|
| **直引** | `Modules`、`Operation\{BackEndDriven,DataStoreDriven,StateHoldDriven,WorkFlowMethod}`、`Share\Composition\{CommandFramework,PlaceholderFramework,UniversalMiddleware}`、`Share\Foundations\StateManagement`、`Share\Frameworks\{Diagnostics,GraphFramework,UniversalReference}`、`Share\Orchestration\EventBindingOrchestrator` | `<ProjectReference Include="$(Proj_Pipeline)" />` | ✅ |
| **间接** | `Operation\FrontEndDriven`（用 `using Modules.Pipeline`，无直引）、`DataCenter.Core`/`Adapters`/`Hosting`（经 `Share.StateManagement` 得 `StagePipeline`/`IStageContext`） | 传递引用 | ⚠️ 可用但**须显式声明或收敛**（见 §2.3） |
| **禁引** | `DataCenter.Protocol`（纯契约）、`DataCenter.Abstractions`（零依赖纯端口）、`DataCenter.Standards`（L0.5：**零机制依赖**）、`Strategy.Observability`（内核：**外部引用白名单** = `Modules.Threading` + `Share.TaskStatusPool` + `DataCenter.Protocol`） | ModuleRule_Rules 明文 | ❌ |

> 结论：**架构上"该管线化"的候选，多数落在可引区**；禁引区（标准层 / 内核）需要的不是 Pipeline，而是**表驱动**或**零依赖件**。

### 2.2 禁引区的两条合法通道（本轮已验证，范式可复制）

1. **表驱动（推荐首选）**：契约层放**数据表**、机制层放**唯一算法**。
   实例：`PortImplVocabulary.ExprSlots`（62 成员：下钻形态 + 算子组）+ `StandardNodeWalk`（唯一父→子规则）+ 反射对拍守卫。
   收益：新增算子从"改 6 处"降为"改 2 处（声明 + 表）"，且判据（C10 算子组恰一）自此有代码取值域。
   **适用**：逐成员枚举、词表/键/枚举派生、逐类型分派的多路选择。
2. **Plate 零依赖件 + 烘焙引用（Ledger 模式）**：新增 `Plate\X` 组件，`零 ProjectReference` + `AssemblyName` 显式 + 烘焙二进制引用（`$(CsharpBuildOutputDir)`）+ **仅顺序边** ProjectReference + CentralTest `*.dll` 通配自动可见。
   实例：`BasicMethod.Declarative.Ledger`（判据宿主）、`BasicMethod.Declarative.StructuralWalk`（遍历骨架）。
   **适用**：两侧（机制层 + 契约层）都要用的**纯算法**；不适用需要 Pipeline 编排语义的场合。

### 3.3 统一迁移配方（五步，每步都有判据）

1. **定阶段边界**：每个阶段能命名、能单独成败、能单独插拔 —— 否则退回（§4）。
2. **选体系**：步骤固定 → `StaticPipeline` + `Step(IsFatal)`；可插拔/分段 → `StagePipeline<TContext>` / `CentralPipeline`；数据流换类型 → 体系 A。
3. **抽上下文**：复用 `PipelineContext`/`IStageContext`（`Share.StateManagement`）或自定义 `TContext : IPipelineContext`；**禁止**在阶段间用静态字段传参。
4. **组合子替换控制流**：`switch` → `PipelineSwitch`/`PipelineBranch`；`foreach` → `ForEachPipeline`；`try/catch` 降级 → `PipelineTryCatch`；重试 → `PipelineRetry`/`WithRetry`；超时 → `WithTimeout`。
5. **收口判据**：① 行为对拍（同输入 → 旧分派与新管线逐字同输出，含错误文案）；② **旧机制删除**（禁止新旧并存，违 `SingleImplementation`）；③ 该项目的 Pipeline 依赖**显式声明**（防 X1 类隐式依赖）。

### 7.1 裁决登记（Q0-2 A4 / Q0-3 X2，2026-09-17）

#### Q0-2 · A4：通用遍历的单一实现口径

**裁决：不合并为单一二进制**；"通用遍历实现 = 1" 的准确口径是**同一语义的唯一实现**，而非"同名字符串只出现一处"。边界如下：

| 维度（实测） | `Framework.Tree.TreeWalker<TNode>`（BasicMethod） | `BasicMethod.Declarative.StructuralWalk`（Plate 零依赖件） |
|---|---|---|
| 遍历序 | 前序（`DepthFirst`/`PreOrder`）/ 后序 / 广度优先 | **仅前序** |
| 回调签名 | `Action<TNode,int>`（**回传深度**） | `Action<TNode>`（无深度） |
| 异步 | `WalkAsync`（逐节点 await） | 无 |
| 截断可见性 | 无（`MaxDepth` 静默丢子树） | `StructuralWalkStats.Truncated`（**强制可见化**） |
| 环/共享引用 | 无去重（共享子树重复访问；深树为递归实现） | 显式栈 + `SkipRepeatedReferences`（缺省 true） |

**否决"TreeWalker 内嵌转发 StructuralWalk"的两条硬证据**（对齐 Q0-2 判据「若执行：行为逐字不变」）：
1. `Action<TNode,int>` 的**深度回传**在 `StructuralWalk` 无对应输出 → 转发即丢信息，消费方（`ControlFinder.FindAll(...)`、`UIInspector`、`TraceTree`）行为改变；
2. 去重语义会改变**共享子树/DAG 的访问次数**（`StructuralWalk` 缺省去重 vs `TreeWalker` 不去重）→ 逐字对拍必红。

**分工（可机器校验）**：
- **禁引区**（`DataCenter.Protocol` / `Abstractions` / `Standards` / `Strategy.Observability`）：遍历唯一通道 = `StructuralWalk`（`StandardNodeWalk` 已消费；`TreeWalker` 命中 = 0，守卫 ③）；
- **可引依赖区**：需要 BFS/后序/异步/深度回传 → `TreeWalker`；**只需前序** → 一律 `StructuralWalk`（借其截断可见化，且不添第三套）。

| `Share\Foundations\TreeTraceFramework\Core\TraceQueryEngine.cs` | 15 `case` 查询算子分派 | **表驱动**（算子表 + 单派发） | 该工程 csproj 仅引 `BasicMethod`；引 Pipeline = 新增跨层依赖，收益仅"分派"，违 §1.2 决策树（无阶段边界→不用 Pipeline） |
