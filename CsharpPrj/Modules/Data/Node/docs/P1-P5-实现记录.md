## 2. 提取融入（P1）的执行口径 —— D-1 案 A

设计文档（提取分册 §6）的 11 件薄适配在**语义**上已按框架件落地；但**未把 `Operation\WorkFlowMethod` 的类型搬进本工程**，原因是层序与 K1/K6/P20：

| 事实（实测） | 影响 |
|---|---|
| `NodeOutput` / `INodeOutputStore` 在 `Operation\WorkFlowMethod\Nodes\Contracts`（层 4） | 若写进 `Modules.Node` 公共签名 ⇒ 位置层被上层绑定（违 K1/K6/P20） |
| `Chain<TKey,TNode>` / `UniversalMiddlewareEntry` 在 `Share\`（层 2） | 同上（并产生向上引用告警） |

因此本批采用：**框架持有中立契约（键 + JSON 字符串 + BCL），上层适配器持有 DTO/序列化**。

| 提取分册 §6 的件 | 本批落地形态 | 剩余（P6/P7 上层工作） |
|---|---|---|
| `PortKeySpace` | `Modules.Node.Ports.PortKeySpace`（`{node}.{port}` 恒有 + 裸键先到者胜 + 溯源一致） | `Operation` 侧 `NodeOutputReadView`/`NodeParameterHydrator` 改为委托本件 |
| `NodePortBinding` | `NodePortBinding`（声明优先 + `inferred` 诊断 + 特化注册表 + 默认端口） | `NodeResultExtractor` 改为委托（保留特化提取器注册） |
| `NodeWriteGate` | `NodeWriteGate`（fail-fast / 串行 / 有界等待 / 冲突可见化） | `NodePersistCoordinator` 改为委托；与库级单写门关系登记（治 P16 门缝） |
| `NodeFormCodec` | `NodeFormCodec`（raw/view/digest 策略单源；digest 有损可辨） | `Output\StrategyResolver` 与 `I*Strategy` 改为其策略实现 |
| `NodeCompensation` | `NodeCompensation`（快照/回滚；append-only 明确不可撤销） | `Snapshot/RollbackStage` 接入 |
| `SpecDefaults` | `SpecDefaults`（只填载荷字段；与位置解析物理隔离） | `NodeConfigFactory.CompleteConfig` 改为委托（禁 P13） |
| `NodeRunState` | `NodeRunState`（受控词转移表 + 外部阶段映射 + 展示投影） | `NodeExecutionState`/`TaskExecutionState` 语义映射 |
| `NodeChainComposer` | `NodeChainComposer`（三态去重 + 冲突改名 + 引用级联） | `ConfigDeduplicationProcessor`/`NodeChainMergeFacade` 收口 |
| `NodeSpecValidator` | `NodeSpecValidator`（无环/无悬空/入口出口/writer 一对一/模板可区分/载体已注册） | `WorkflowValidator.ValidateChainConnectivity`/`GraphValidator` 复用同一图判据 |
| `NodeReferenceIndex` | `NodeReferenceIndex`（引用字段清单 + 反向引用 + 改名级联，数组元素亦覆盖） | `NodeConfigReferenceRegistrar` 改为声明化清单 |
| `NodeDirectiveSet` | `NodeDirectiveSet`（版本单调 + 只产计划） | `GraphUpdateDirective` 集载体形态裁决（U8）后接线 |

> 结论：**框架侧不再需要新写任何节点语义**；P6/P7 只剩"把 `Operation` 侧既有实现改为委托 + 登记等价门"的迁址工作，且该工作须在 `Operation` 工程内进行（那里才可见 DTO）。
