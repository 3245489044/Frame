# 节点通用框架设计（与位置无关 · JSON 键连接版）

> **状态**：设计稿（只出文档，未落地代码；实现归属 `Frame/CsharpPrj/Modules/Node`，命名空间 `Modules.Node`）
> **范围**：把「节点是什么、节点在哪里、怎么连、谁来落、怎么读」五件事从业务代码抽出，使**节点身份 + 键连接**成为一等概念；「转换」降级为**位置物化**。
> **不重造**：仓库已有三套相关机制（`LoopFoldMethod.Node` 内存装配 / `WorkFlowMethod.NodeProcess` 执行与端口 / `HierarchyMethod`+`DataStoreDriven` 持久与图）。本框架是它们**之间的位置层**，复用而非替代（SingleImplementation）。
> **配套**：[Agent 应用篇](./节点通用框架-Agent应用篇.md) · [提取清单与复用映射](./节点通用框架-提取清单与复用映射.md)（逐项裁决 WorkFlowMethod 既有件的复用/提取/留业务侧，含 14 项缺口与反模式 P12–P16） · [表层语言与 Usharp 接入](./节点通用框架-表层语言与Usharp接入.md)（定义来源端口化：Node 不引语言、只留端口）

## 0. 一句话模型

```
节点 = ⟨Key(身份), Json(载荷), Placement*(位置), Form(形态)⟩

Key        ：节点身份（键）—— 全系统唯一、载体无关（如 session.{c}.r{r}.msg.{seq}）
Json       ：节点载荷 —— **恒为 JSON 文档**（不引入第二载体形态；形态差异由 Form 声明）
Placement  ：键在哪个容器/载体上物化（可有多个；位置不改变身份）
Form       ：该位置的载荷形态（raw / view / digest）

运行 = 键空间上的显式拼接：
  · 定义   ：工作流 = JSON 链（ChainInfo<string, NodeConfig>），节点 = NodeConfig JSON
  · 连接   ：节点间连接**只用键**（ParameterKeys ← ResultKeys；NextNodeKey / MapKeyConfig）
  · 物化   ：产出 = NodeOutput JSON（端口键空间 {node}.{port}）→ 按 Placement 落库
  · 读取   ：按 Placement + Selection 读回键空间 → 下一节点按键取参
```

**核心主张**：当前"节点 → 历史/任务"的转换逻辑之所以外置且模糊，根因是**节点被等同于数据库行**、**连接被写成隐式回调**。把节点降为「键 + JSON 文档」、把连接降为「键引用」之后，剩下的只有位置声明与物化——不再有"转换"。

## 1. 概念与术语

### 1.1 键（Key = 身份）

| 项 | 说明 |
|---|---|
| 定义 | 节点在全系统内的唯一标识；**同时是它的地址**（键连接的另一端靠它寻址） |
| 形状 | 由 `IdentitySpec` 声明的段序列拼接：`{container}.r{round}`、`{container}.r{round}.msg{seq}`、`{wf}.{node}` 等 |
| 生成 | 唯一生成器（`NodeIdentity.For`）；序数段由 `ISequenceAuthority` 单源分配 |
| 复用 | 仓库既有键权威继续使用：`SessionMessageKeys`、`HierarchyResourceKeys`、`NodeRelationFactory.NodeId`、`WorkFlowMethod.KeyManager.GenerateCallkey` —— 本框架把它们**统一到同一 `IdentitySpec` 语法**，不新增平行键族 |

### 1.2 JSON 文档（载荷）

| 项 | 说明 |
|---|---|
| 唯一性 | 载荷**恒为 JSON**：`NodeConfig`（定义）、`NodeOutput`（产出）、`ChainInfo`（链）、`ConversationMessage`（消息）都是 JSON 文档的不同 schema |
| 序列化单轨 | 统一走既有 `UniversalMiddlewareEntry.FromJson`（`WorkflowDeserializer` 已用），禁双 JSON 库 |
| 形态 | `raw`（外部原文，如 cline `messages.json`）/ `view`（规范化）/ `digest`（摘要）——**形态由 Placement 声明**，不由节点类型表达 |

### 1.3 位置（Placement）

| 项 | 说明 |
|---|---|
| 结构 | `Placement = ⟨LevelId, CarrierId, KeyTemplate, Form, Retention, WriterId⟩` |
| 定位 | `PlacementKey = KeyTemplate(Key)` —— 键是位置的函数；**位置不改变身份** |
| 状态 | `Active / Legacy（拒写可读）/ Retired` —— 灰度退役（N10） |

> **位置可由 `loc` 反解**（不手写）：`loc` = UniversalReference 的 `ResourceIdentifier.Location`（**位置轴，非身份**，实测 `Location` 不参与键）。`.ushar` 声明 loc 空间 + 反解矩阵（`[Space] Loc` / `[Ref] … loc=` / `[Matrix] … over=Loc`，零新增语言单元），Node 框架经 `IPlacementResolver` 端口取反解产物 ⇒ `Placement` 降为**派生值（Origin=Derived）**。硬约束：反解不产身份（L-1）、唯一（L-2）、表为唯一来源（L-3）、键模板含序数占位（L-4）、失败即 ∅（L-5）。见 [表层语言与 Usharp 接入](./节点通用框架-表层语言与Usharp接入.md) §13。

### 1.4 端口键空间（键连接的实际载体）

| 项 | 说明 |
|---|---|
| 端口 | 节点产出/入参的命名槽位：`ResultKeys`（产出）/ `ParameterKeys`（入参） |
| 键空间 | **`{node}.{port}` 恒有**；裸 `{port}` 仅在未被任一更早节点占用时并入（防跨节点互覆盖）——既有 `NodeOutputReadView` 语义 |
| 溯源 | 每个键对应 `(Node, Port)` 溯源（provenance），与源键集合恒一致 |
| 运行时 | 循环期键空间落在 `AxiomContext.Data`（`IDictionary<string, object>`，键名权威 `RoundKeys`） |
| 映射 | 连接处的键改名经 `KeyMappingConfig{Rules, WildcardChar, DefaultSeparator}` 声明（既有 `KeyProcessor`） |

### 1.5 连接（Connection）

| 形态 | 表达 |
|---|---|
| 链式 | `NodeConfig.Id / NextNodeId / nextNodeConfig.NextNodeKey` |
| 数据流 | 下游 `ParameterKeys` ← 上游 `ResultKeys`（经键映射规则改写） |
| 图 | 键序列 → 图 + 边：边 Id = `{src}->{tgt}`（既有 `GraphFoundationBridge.ChainToGraph`） |
| 时序 | **顺序由键内序数表达，不由边表达**（N6）——边只承载归属/数据流 |

### 1.6 运行态来源（Origin）

沿用既有运行态轴：`Live`（内存装配，如 `NodeItem`）→ `Snapshot`（已物化，如 `NodeOutput` 落库）→ `Derived`（投影/聚合）。装配按 `Live > Snapshot > Derived` 字段级叠加，**无来源命中 ⇒ ∅，不伪造**。

### 1.7 与仓库既有机制的分工（关键）

| 既有机制 | 视角 | 已有能力 | 本框架的定位 |
|---|---|---|---|
| `LoopFoldMethod.Node`（`NodeItem`/`NodeSlot`/`NodeCategory`/`NodeBuilder`/`INodeSlotPolicy`/`NodeComponent`/`INodeSource`/`NodeAssemblyEngine`/`INodeProjector`） | **内存装配**（不落库；`NodeItem.Key` 可空） | 组件声明、动态源、头/中/尾排布、消费域投影 | 作为 `Origin=Live` 层：**产出装配结果**，不负责位置 |
| `WorkFlowMethod`（`NodeConfig`/`ChainInfo`/`Chain<string,NodeConfig>`/`NodeProcessPipelineBuilder`/`NodeOutputPersistStage`/`NodePersistCoordinator`/`INodeOutputStore`/`NodeOutputReadView`/`KeyProcessor`/`KeyManager`） | **执行与端口**（JSON 定义 → 执行 → 端口物化 → 单写门 → 读视图） | JSON 链、键连接、单写门、端口键空间、读视图 | 作为**执行与物化通道**：本框架只声明"写到哪个位置"，通道复用 |
| `HierarchyMethod` + `DataStoreDriven`（`NodeRecord`/`NodeTypes`/`ReferenceGrounding`/`IHierarchyReferenceManager`/`ReferenceGraphCoordinator`/`INodeStore`） | **持久与图**（库行 + 引用边 + 端点镜像） | 多层容器（history/task/session/node）、边、端点 | 作为 `Carrier` 实现：本框架经适配器调用 |

> 本框架**只新增**：身份规范（`IdentitySpec`）、位置声明与注册表、物化器（单写者判定）、读投影、对账。其余全部复用。

> **复用清单的权威分册**：[提取清单与复用映射](./节点通用框架-提取清单与复用映射.md) —— 本表是**摘要**，该分册给出 WorkFlowMethod 六组资产（定义/执行/端口/键/形态/基础设施）的逐项裁决（`复用`/`补登记`/`提取`/`迁出`/`留业务侧`/`退役`）、14 项可测缺口（G1–G14）与提取实测勘误。**实现前先查该分册，避免重复造轮子**。

## 2. 不变式（N1–N12）

| # | 不变式 | 判定式（可测） | 违反后果 |
|---|---|---|---|
| **N1** | 身份唯一 | 任意载体上的记录都能还原出同一个 Key | 同一事实多身份 → 只能靠推导对齐（轮次/序号漂移） |
| **N2** | 位置不改变身份 | 按 Key 枚举 → N 个 Placement，载荷可交叉校验为同一事实 | 每加一个载体就多一次"转换代码" |
| **N3** | 单写者 | ∀`(Key, Placement)` 恰一个 `WriterId`；二次写 → 诊断 | 双写互覆，读到的内容取决于时序 |
| **N4** | 幂等 | 同 `(Key, Placement, Digest)` 重放无副作用 | 重试产生重复行/重复边 |
| **N5** | 只增不丢 | 不同 Digest → 版本化或**可见化冲突**，绝不静默覆盖 | 历史被覆盖 |
| **N6** | 顺序内嵌 | 顺序仅由键内序数（+声明排序器）决定；删除全部边后顺序不变 | 边即顺序 → 链断/多写者 |
| **N7** | 读侧裁剪 | 写侧无"为某消费者裁剪/另存"逻辑；过滤只在 `SelectionSpec` | 同一事实多份裁剪副本 |
| **N8** | 声明驱动 | 键模板/位置/保留/选择/映射规则全部来自 JSON 声明，代码无策略常量 | 策略散落各处演化 |
| **N9** | 来源可辨 | 投影结果携带 Origin；无来源 ⇒ ∅ | 伪造状态，故障不可归因 |
| **N10** | 位置可退役 | `Legacy` 拒写可读；读侧切换后才 `Retired` | 无法灰度替换载体 |
| **N11** | **JSON 形态单源** | 载荷 JSON 的读写走同一序列化入口；同一 schema 只有一个 DTO | 双 JSON 库/双 DTO → 字段漂移 |
| **N12** | **键连接不外溢** | 节点间数据传递**只经键**（端口键空间），不传对象引用/闭包 | 隐式耦合 → 无法声明化、无法跨进程/跨语言 |

**组合推论**

- `N1 ∧ N2 ∧ N3 ∧ N12` ⇒ **框架内不存在"节点→历史/任务转换"逻辑**：只有「位置清单 + 键空间 + 单写者」。
- `N6 ∧ N12` ⇒ 时序链边非必需；顺序由键序数保证。
- `N7 ∧ N8` ⇒ "哪部分进模型上下文"成为**读侧声明**，不再驱动写侧另存副本。

## 3. JSON 显式拼接（定义 → 执行 → 产出 → 拼接）

### 3.1 四种 JSON schema（沿用既有 DTO，不新造）

| schema | 既有类型 | 作用 |
|---|---|---|
| 链定义 | `Chain<TKey,TNode>` / `ChainInfo<TKey,TNode>`（`ChainId/StartNode/EndNode/AllNodes/Label/Metadata`） | 工作流 = 节点序列 JSON |
| 节点定义 | `NodeConfig`（`Id/NextNodeId/Symbol/Label` + `funcPipelineConfig{ParameterKeys,ResultKeys,FuncName,ParameterType,Params}` + `nextNodeConfig{NextNodeKey,MapKeyConfig,ConnectChainInfoKey,ConnectChainInfoConfig,UpdateChain,...}` + `basicConfig{Callkey,...}`） | 节点 = 声明式 JSON（键连接就在字段里） |
| 节点产出 | `NodeOutput`（`NodeKey/WorkflowId/OutputPorts{port→value}` + 信号元数据） | 产出 = 端口 JSON |
| 消息载荷 | `ConversationMessage` / cline `messages.json` | 对话域载荷 JSON |

### 3.2 显式拼接（拼接 = 组合已有 JSON，而非新写代码）

```
① 定义拼接：多个 Chain JSON → 去重合并（既有 ConfigDeduplicationProcessor：Callkey 为节点键，
   冲突改名 + 引用重写）→ 单一 ChainInfo<string, NodeConfig>
② 键映射拼接：connection(FromNode→ToNode) + KeyMappingConfig JSON
   → 上游 ResultKeys 归一化后写入下游 ParameterKeys（既有 KeyProcessor.ProcessConnectionKeyMapping）
③ 执行拼接：ChainInfo → 反序列化（WorkflowDeserializer）→ NodeProcessPipelineBuilder 装配
   （GraphDefinition → NodeChain → NodeExtractor → GraphChainUpdate → NodeExecution → NodeLoop{执行步→端口物化} → NodeMetrics）
④ 产出拼接：每步产出 NodeOutput（端口 JSON）→ 键空间并入下一节点入参（NodeOutputReadView）
⑤ 图拼接：键序列 → 图 + 边 {src}->{tgt}（GraphFoundationBridge.ChainToGraph）
```

**要点**：整条链上"谁连谁、传什么"全部写在 JSON 里（`NextNodeKey`/`MapKeyConfig`/`ParameterKeys`/`ResultKeys`），**没有一处靠 C# 回调隐式接线**——这是"显式拼接"的判据（N12）。

### 3.3 与 Agent 现有 spec 的关系（应用篇细化）

Agent 会话链现用 `RoundSpec/Steps`（`funcName/paramKeys/resultKeys/nodeId`）。它与 `NodeConfig` 字段一一对应，**目标是收敛为同一 schema**（`Steps` → `ChainInfo<string, NodeConfig>`），使"会话链"与"通用工作流链"共用同一 JSON 定义与同一执行管线。

## 4. 键连接契约

### 4.1 键空间

```
键空间 K = { {node}.{port} }  ∪  { 裸 {port}（未被更早节点占用时） }
入参解析：ParameterKeys 逐个在 K 中查找（命中即取值 + 记 provenance）
产出写入：ResultKeys 逐个写入 K（null 不写；键即地址）
```

- 该语义已由 `NodeOutputReadView.BuildInputSourceAsync/BuildProvenanceAsync` 实现 → **本框架直接复用**，不重写。
- 循环期同一键空间另有一层：`AxiomContext.Data`（`RoundKeys.*`）——**应用篇需明确两者的合并规则**（见应用篇 §3.3）。

### 4.2 键映射（连接处改名）

| 配置 | 作用 |
|---|---|
| `KeyMappingConfig.Rules` | 源键模式 → 目标键（含通配 `WildcardChar`、`DefaultSeparator`） |
| `KeyMappingConfig.EnableHierarchyNormalization` | 层次前缀归一（链内多实例同符号时避免键碰撞，配合 `KeyManager.EnsureChainSuffix`） |
| `KeyProcessor.ProcessNodeKeys(node, hierarchy)` | 单节点键加层次前后缀 |

### 4.3 连接声明

| 字段 | 语义 |
|---|---|
| `NextNodeKey` / `NextNodeId` | 链式下一跳（键） |
| `ConnectChainInfoKey` / `ConnectChainInfoConfig` | 连接点声明（跨链连接信息，键值对） |
| `MapKeyConfig` | 本次连接的键映射（JSON） |
| `UpdateChain` | 连接后是否更新工作流链（动态改图，`GraphChainUpdateStage` 消费） |

### 4.4 键连接不变量（N12 的可测形式）

| ID | 判据 |
|---|---|
| K1 | 任意两节点间**不存在**非键参数传递（DTO/闭包不入节点边界） |
| K2 | 同一 `(Key, port)` 在键空间内唯一可寻址（冲突 → 诊断，不静默覆盖） |
| K3 | 连接变更（改 `MapKeyConfig`/`ParameterKeys`）**不需要改代码**（声明即可重连） |
| K4 | 键空间可完整 dump 为 JSON（可重放/可对拍） |

## 5. 声明面（JSON schema 草案）

> 声明即 JSON（N8/N11）。装载入口：`NodeFrameworkSpecLoader`（读 `Config/node.ushar` 或 `.json`，沿用既有声明装载约定）。

```json
{
  "domain": "conversation",
  "identity": "{container}.r{round}",
  "sequence": ["round"],
  "placements": [
    { "id": "session-view",   "level": "session", "carrier": "sql-nodes",
      "key": "session.{container}.r{round}", "form": "view",
      "retention": "contextual", "selection": "marked", "writer": "writer-session" },
    { "id": "archive-raw",    "level": "archive", "carrier": "sql-nodes",
      "key": "cline.session.{container}.round.{round}", "form": "raw",
      "retention": "audit", "selection": "all", "writer": "writer-archive" },
    { "id": "task-membership","level": "task",    "carrier": "graph-edge",
      "refType": "cross_db_link", "writer": "writer-membership" }
  ],
  "selections": { "marked": "items[mark != none]", "all": "true" },
  "retentions": { "contextual": "供模型消费", "audit": "仅供审计/回灌", "presentational": "仅供展示" }
}
```

| 事项 | 声明面 | 代码面 |
|---|---|---|
| 身份粒度/键形状 | `identity` / `key` 模板 | 模板求值（唯一实现） |
| 谁写哪个位置 | `writer` | writer 只备载荷，不拼键不建边 |
| 顺序 | `sequence` | `ISequenceAuthority` |
| 读什么/过滤什么 | `selection` / `retention` | 谓词实现（纯函数） |
| 连接与改名 | `MapKeyConfig` / `ConnectChainInfoKey`（既有字段） | `KeyProcessor`（既有） |
| 载体细节 | 只给 `carrier` 标识 | `ICarrierRegistry` 适配器 |
| **位置来源** | `loc` 声明（`[Space] Loc` + `[Ref] … loc=`）+ 反解矩阵 `[Matrix] … over=Loc`（`.ushar`） | `IPlacementResolver`（反解：`loc → Placement`）；框架内**禁**硬编码映射（P22） |

**装配期校验（fail-fast）**：身份模板字段 ⊆ 序数/上下文键集；同域键模板可区分；`(domain,placementId)→writer` 一对一；`carrier` 已注册（未注册 → 该位置 `Unbound` + 诊断，不阻断其它位置）；**链无环 ∧ 无悬空引用 ∧ 入口/出口存在**（后者既有 `WorkflowValidator.ValidateChainConnectivity` / `GraphValidator` 已实现，见 [提取清单与复用映射](./节点通用框架-提取清单与复用映射.md) G10）。

### 6.3 两条路径

```
写：Live 节点（NodeItem / 本轮产出 JSON）
   → Key（IdentitySpec + ISequenceAuthority）
   → Placement（声明）
   → NodeMaterializer：单写者判定 → 编码（form）→ 键求值 → 幂等 upsert → 归属边
   → 载体适配器（sql-nodes / graph-edge / sql-kv …）

读：消费方 Scope
   → Placement 选择（retention）
   → 解码（form）
   → Selection 过滤（读侧裁剪）
   → 排序（键内序数）
   → Origin 标注（Live>Snapshot>Derived；无命中 ∅）
```
