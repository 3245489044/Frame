## 1. 判据：什么该进 `Modules.Node`

### 1.1 准入门槛（须全过）

| # | 判据 | 判定方式 | 对应不变式 |
|---|---|---|---|
| K1 | **领域无关** | 类型/成员名不含 Agent、会话、任务、UI 等领域词（`WorkflowId`/`NodeKey` 等结构词除外） | 通用篇 §5「框架程序集无载体/领域词」 |
| K2 | **≥2 使用方** | 至少两个互不相同的消费方（框架侧 + Agent 侧，或两套工作流宿主） | [CR: axioms:Strategy.RedundancyElimination@consume] 反面 |
| K3 | **可声明化** | 语义可由 JSON 声明表达（键模板/映射/选择/指令），代码只求值 | N8 |
| K4 | **单源可寻址** | 不引入第二份身份/键/DTO（复用既有 DTO 与键权威） | N1 / N11 |
| K5 | **无进程静态** | 无 `static` 可变配置、无 `AsyncLocal` 运行期全局、无进程级钩子 | N8；通用篇 P6 |
| K6 | **可测且无宿主** | 单测可直接构造（无 WinForms/DB/HTTP 依赖） | 通用篇 §9.2 合同测试 |

### 1.2 反判据（命中即不得进）

- **载体细节**（表名、库名、连接串、控件类型）→ 归 `ICarrier` 适配器，不进框架。
- **业务默认值**（Agent 的轮次语义、会话命名、任务归属）→ 归领域声明，不进框架。
- **UI/宿主管线**（控件取值、线程派发、宿主全局 Pipeline）→ 归宿主层（见 §10）。
- **一次性接线**（把 A 轨键搬成 B 轨键的赋值代码）→ 属于被框架消灭的对象，不进框架。

## 6. `Modules.Node` 组件清单增补（在通用篇 §6.1 之上）

> 通用篇 §6.1 的 9 件（`IdentitySpec`/`NodeIdentity`、`PlacementSpec`/`PlacementRegistry`、`KeyTemplateEvaluator`、`ISequenceAuthority`、`INodeCarrier`/`ICarrierRegistry`、`NodeMaterializer`、`NodeReadProjection`、`NodeFrameworkSpecLoader`、`NodeReconciler`、`NodeFrameworkDiagnostics`）**全部保留**。下表是本次提取新增的**薄适配件**——它们**不新造抽象**，而是把 WorkFlowMethod 已有实现搬到框架并契约化。

| 新增件 | 来源既有件 | 职责 | 明确不做 |
|---|---|---|---|
| `PortKeySpace` | `NodeOutputReadView` + `NodeParameterHydrator` | `{node}.{port}` 恒有 + 裸键先到者胜；源键 ↔ 溯源一致 | 不写库、不决定读哪些位置 |
| `NodePortBinding` | `NodeResultExtractor` | 声明优先的端口提取 + 反射兜底（带 `inferred` 诊断）+ 特化扩展点 | 不解析键映射、不做类型转换 |
| `NodeWriteGate` | `NodePersistCoordinator` | 单写者 fail-fast + 串行 + 有界等待（阈值声明化） | 不决定写哪些位置 |
| `NodeRunState` | `NodeExecutionState` / `NodeStatus` / `TaskExecutionState` | 节点阶段受控词 + 转移表 + 计数/时间戳 | 不持有业务状态框架实现 |
| `NodeChainComposer` | `ConfigDeduplicationProcessor` / `NodeChainMergeFacade` / `WorkflowMediator` | 多链合并 + 三态去重 + 改名 + 引用重写 | 不做位置分配 |
| `NodeSpecValidator` | `WorkflowValidator` / `GraphValidator` / `ModularValidator` | 装配期 fail-fast：模板可区分、writer 一对一、**无环**、**无悬空引用**、入口/出口存在 | 不静默修正数据 |
| `NodeReferenceIndex` | `NodeConfigReferenceRegistrar` | 引用字段清单 + 反向引用 + 改名级联 | 不定义键模板 |

## 10. 明确留在业务侧（不进 `Modules.Node`）

> 这些件**看起来像节点逻辑，但不是**：它们绑定 UI/宿主/领域，搬进框架会把 Node 变成杂物间（违反 K1/K6）。

| 件 | 位置 | 归属 | 理由 |
|---|---|---|---|
| `ParameterValueResolver`（literal/expression/**control** 三源取值） | `Parameters\` | 参数绑定层（`ParameterResolver`/WinForms 侧） | 依赖 `TConfig.Controls` + 控件路径反射 |
| `WinFormsValueAccessor` / `WinFormsThreadDispatcher` / `ParameterContextFactory` | `Adapters\`、`Parameters\` | 宿主 UI 层 | 有界面/线程亲和性 |
| `WorkFlowPipeline\CentralPipeline` / `PipelineSession` / `PipelineStages` | `WorkFlowPipeline\` | 宿主管线层 | 宿主级阶段编排，非键空间层 |
| `OutputPipelineRunner`（`IStorageEngine` + `EventContext`） | `Output\` | 宿主输出层 | 载体 = 控件/事件；**其策略语义**另行收编（G12） |
| `WorkflowMethodUseage` / `WorkflowMethodExecutionService` | 根目录 | 宿主门面 | 应用入口 |
| `Adapters\CSG\*`（`CsgIntegrationService` 与三适配器） | `Adapters\CSG\` | CSG 协议集成 | 属另一个投影体系（C/S/G），非节点身份层 |
| `WorkflowExecution\FunctionExecutionFramework\` | 子项目 | 函数执行框架 | 函数调用语义，非键连接语义 |
| `Orchestration\ModuleCreation\` / `Content\ConnectRequest` | `Orchestration\` | 编排业务 | 连接请求的业务语义（其**合并算法**归 G8） |
| `LoopFramework` | `LoopFramework\`（docs 提及） | 循环业务（LLM 驱动） | 决策语义属 Agent/领域，不属位置层 |
