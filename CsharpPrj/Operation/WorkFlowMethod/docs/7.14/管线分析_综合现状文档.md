## 二、核心数据流

### 2.1 执行流程

```
IGraph (GraphFoundation)
  │
  ├─ GraphBuilder.BuildFromConfig() → 从配置构建图
  ├─ GraphValidator.Validate() → 验证图拓扑
  │
  ▼
GraphSnapshot.CreateFrom(graph) → 不可变快照
  │
  ▼
WorkflowContext.SetGraphSnapshot(snapshot)
  │
  ▼
PipelineBuilder.ConfigureDefaultPipeline(pipeline, graph)
  │
  ▼
WorkflowCentralPipeline.Execute(context)
  │
  ├─ [GraphDefinition] GraphDefinitionSkeleton
  │   ├─ 创建 GraphSnapshot
  │   ├─ 创建 ExecutionSession
  │   └─ 设置入口节点 CurrentNodeKey
  │
  ├─ [GraphDefinition] WorkflowProcessorSkeleton
  │   └─ 顶层流程控制（循环执行节点）
  │
  ├─ [FunctionExec] NodeProcessSkeleton
  │   ├─ Step 1: GetConfig → 从 NodeConfig 获取输入配置
  │   ├─ Step 2: ExecuteFunc → 执行节点函数
  │   ├─ Step 3: RecordCallFrame → 记录调用帧
  │   └─ Step 4: ResolveNextNode → 解析下一节点
  │
  ├─ [PostProcess] MetricsCollectSkeleton
  │   └─ 收集执行指标
  │
  └─ [UpdateCheck] WorkflowChainUpdateSkeleton
      ├─ 检查是否需要更新
      └─ 应用 GraphUpdateDirective 更新图
```

### 2.2 数据传递路径

```
IGraph (原始图)
  → GraphSnapshot (不可变快照，作为执行凭证)
    → WorkflowContext (统一状态容器)
      → ExecutionSession (会话状态)
        → DataContext (数据上下文)
          → NodeExecutionState (节点执行状态)
```

### 2.3 更新流程

```
外部更新请求
  → GraphUpdateDirective (InsertNode/DeleteNode/ReplaceNode/RedirectEdge)
    → DirectiveApplier.ConvertToAction() (转换为 Action<IGraph>)
      → GraphUpdateService.ApplyUpdate() (应用更新)
        → GraphSnapshot.CreateFrom() (创建新快照)
          → WorkflowContext.SetGraphSnapshot() (更新上下文)
```

## 三、关键类型映射

| 旧类型 | 新类型 | 说明 |
|--------|--------|------|
| `WorkflowGraph` | `IGraph<string, NodeConfig, object>` | GraphFoundation 的图接口 |
| `NodeDefinition` | `string` (nodeKey) + `NodeConfig` | 节点键 + 配置数据 |
| `EdgeDefinition` | `string` (edgeId) | 边标识 |
| `ExecutionContext` | `WorkflowContext` | 统一状态容器 |
| `GraphUnit.dic` | `GraphSnapshot` | 不可变图快照 |
| `ChainInfo` | `IGraph` + `GraphSnapshot` | 链信息 |
| `UniversalNode` | `NodeConfig` | 节点配置 |
| `CurrentNode` (NodeDefinition) | `CurrentNodeKey` (string) | 当前节点键 |

## 五、管线阶段说明

### 5.1 GraphDefinition 阶段

**目的**：初始化图快照和执行会话

```
输入: IGraph<string, NodeConfig, object>
输出: WorkflowContext (包含 GraphSnapshot + ExecutionSession)

步骤:
1. GraphDefinitionSkeleton
   - 调用 GraphSnapshot.CreateFrom(graph) 创建不可变快照
   - 创建 ExecutionSession
   - 设置入口节点 CurrentNodeKey
2. WorkflowProcessorSkeleton
   - 验证 GraphSnapshot 不为空
   - 设置入口节点
   - 启动执行循环
```

### 5.2 FunctionExec 阶段

**目的**：执行单个节点的完整生命周期

```
输入: WorkflowContext (CurrentNodeKey 已设置)
输出: WorkflowContext (CurrentOutput + NextNodeKey 已设置)

步骤:
1. GetConfig: 从 NodeConfig 获取输入配置
2. ExecuteFunc: 执行节点函数
3. RecordCallFrame: 记录调用帧
4. ResolveNextNode: 从 GraphSnapshot 获取后继节点键
```

### 5.3 PostProcess 阶段

**目的**：收集执行指标

```
输入: WorkflowContext (节点执行完成)
输出: WorkflowContext (附加指标数据)
```

### 5.4 UpdateCheck 阶段

**目的**：检查并应用图更新

```
输入: WorkflowContext (可能包含 PendingDirectives)
输出: WorkflowContext (更新后的 GraphSnapshot)

步骤:
1. GraphUpdateCheckSkeleton: 检查是否需要更新
2. WorkflowChainUpdateSkeleton:
   - 从 DataContext 读取 PendingDirectives
   - 使用 DirectiveApplier 转换为 Action<IGraph>
   - 使用 GraphUpdateService 应用更新
   - 创建新的 GraphSnapshot
```

## 六、重构前后对比

### 6.1 旧架构问题

```
旧架构:
  WorkflowGraph (自定义图实现)
    ├─ NodeDefinition (自定义节点类型)
    ├─ EdgeDefinition (自定义边类型)
    ├─ OriginalConfig (旧配置耦合)
    └─ 与 GraphFoundation 重复的图操作

  ExecutionContext (分散的状态容器)
    ├─ CurrentNode (NodeDefinition)
    ├─ GraphUnit.dic (图数据)
    └─ ChainInfo (链信息)

  问题:
    1. WorkflowGraph 与 GraphFoundation 功能重复
    2. NodeDefinition/EdgeDefinition 与 NodeConfig 类型重复
    3. 状态分散在多个容器中
    4. 图操作和业务逻辑耦合
```

### 6.2 新架构优势

```
新架构:
  IGraph<string, NodeConfig, object> (GraphFoundation 标准接口)
    ├─ 统一的图操作 API
    ├─ 事务支持 (BeginTransaction/Commit)
    ├─ 命令模式 (AddNodeCommand/RemoveNodeCommand)
    └─ 与外部系统兼容

  GraphSnapshot (不可变执行凭证)
    ├─ 创建后不可变，确保执行一致性
    ├─ 基于 IGraph 的快照
    └─ 轻量级，可快速创建

  WorkflowContext (统一状态容器)
    ├─ CurrentNodeKey (string) - 轻量级节点引用
    ├─ GraphSnapshot - 不可变图数据
    ├─ ExecutionSession - 会话状态
    └─ SharedData - 共享数据

  优势:
    1. 消除重复：WorkflowGraph/NodeDefinition/EdgeDefinition 废弃
    2. 统一接口：所有操作基于 IGraph
    3. 不可变快照：执行一致性保证
    4. 状态集中：WorkflowContext 统一管理
    5. 类型简化：NodeDefinition → string + NodeConfig
```
