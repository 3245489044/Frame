# PlaceholderFramework 优化重构方案

## 基于 BasicMethod.Pipeline + BasicMethod.MetaCommand 的框架级重构

---

## 一、现状分析

### 1.1 重复代码问题

PlaceholderFramework 自实现了完整的 Pipeline 体系，与 `BasicMethod.Pipeline` 存在大量重复：

| 重复类型 | PlaceholderFramework 旧类型 | BasicMethod.Pipeline 对应类型 | 行数 |
|---------|---------------------------|------------------------------|------|
| 错误级别 | `ErrorLevel` 枚举 | `ErrorLevel` 枚举 | ~10 |
| 错误条目 | `ProcessingError` 类 | `ErrorEntry` 类 | ~90 |
| 错误收集器 | `ErrorCollector` 类 | `ErrorCollector` 类 | ~180 |
| 管线上下文 | `PipelineContext` 类 | `PipelineContext` 类 | ~80 |
| 管线状态 | `PipelineStatus` 枚举 | `PipelineResultStatus` 枚举 | ~15 |
| 管线结果 | `PipelineResult` 类 | `PipelineResult` 类 | ~110 |
| 泛型结果 | `PipelineResult<T>` 类 | `PipelineResult<T>` 类 | ~30 |
| Stage 接口 | `IPipelineStage` 接口 | `IPipelineStage` 接口 | ~15 |
| 泛型 Stage | `IPipelineStage<TIn,TOut>` 接口 | `IPipelineStage<TIn,TOut>` 接口 | ~15 |
| 管线编排器 | `Pipeline` 类 | `Pipeline` 类 | ~100 |
| 泛型管线 | `Pipeline<TIn,TOut>` 类 | `Pipeline<TIn,TOut>` 类 | ~100 |
| 工厂类 | `PipelineFactory` 类 | `PipelineBuilder` 类 | ~30 |
| 会话管理 | `SessionManager<TKey,TData>` 类 | `SessionManager<TTarget,TConfig,TContext>` 类 | ~160 |
| **合计** | **13 个类型** | **13 个对应类型** | **~940 行** |

此外，`_Compat.cs` 适配层又增加了 **861 行**包装代码，导致总重复代码超过 **1800 行**。

### 1.2 设计问题

1. **适配层过度封装**：`_Compat.cs` 对每个类型都做了包装适配，引入了双向转换开销（`ProcessingError` ↔ `ErrorEntry`、`PipelineContext` ↔ `BasicPipeline.PipelineContext` 等）
2. **命名空间不一致**：Pipeline 类型在 `Common.PlaceholderFramework.Core.Pipeline`，而其他核心类型在 `Common.PlaceholderFramework.Core`
3. **缺少异步支持**：自实现的 Pipeline 只有同步版本
4. **功能缺失**：BasicMethod.Pipeline 提供的组合子（Then/Branch/Loop/Parallel）、中间件、重试、超时、缓存等能力，PlaceholderFramework 都无法使用

### 1.3 外部依赖分析

搜索结果显示，**PlaceholderFramework 内部只有 `PipelineService.cs` 和 `_Compat.cs` 自身引用了这些 Pipeline 类型**。其他文件（`HandlersService.cs`、`MetadataStore.cs`、`QueryService.cs`、`PlaceholderResolverSkeleton.cs`、`ConfigurationService.cs`）使用的是 `Common.PlaceholderFramework.Core` 命名空间（非 `.Pipeline`），不依赖这些 Pipeline 类型。

这意味着：**删除这些 Pipeline 类型不会影响其他文件**。

---

## 二、重构目标

1. **消除重复**：删除 PlaceholderFramework 中与 BasicMethod.Pipeline 重复的 13 个类型
2. **消除适配层**：删除 `_Compat.cs`，不做任何包装适配
3. **直接引用**：所有需要 Pipeline 能力的地方，直接使用 `BasicMethod.Pipeline`
4. **保留核心价值**：保留 `IStructureHandler` / `BaseStructureHandler`（PlaceholderFramework 特有的结构处理策略）
5. **框架整合**：将 Handler 体系与 MetaCommand 对接，实现命令驱动的结构处理

## 七、风险与注意事项

1. **外部依赖**：如果有其他项目引用了 `Common.PlaceholderFramework.Core.Pipeline` 命名空间下的类型，需要改为引用 `BasicMethod.Pipeline`
2. **API 差异**：`BasicMethod.Pipeline.ErrorEntry` 的属性名与旧版 `ProcessingError` 可能不同（如 `Code` vs `ErrorCode`），需要适配
3. **`PipelineResult.Document` vs `PipelineResult.Data`**：旧版使用 `Document` 属性，BasicMethod 使用 `Data` 属性，需要修改引用处
4. **`PipelineStatus` vs `PipelineResultStatus`**：枚举值映射关系需要确认
