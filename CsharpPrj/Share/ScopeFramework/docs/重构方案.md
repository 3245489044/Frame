# ScopeFramework 通用化重构方案

> **面向执行者**：本方案按阶段（P0→P3）组织，每阶段给出具体文件、改法、验证方式与回滚边界。核心原则：**保持执行端口签名不变（`Func<string, Task<string>>`）、保持既有 JSON 产物不变**，从而对 Agent / FileDriven / Share 聚合引用方零破坏。
>
> **对应文档**：本方案是《任务中心多层作用域封装框架设计》（`Projects/Agent/doc/任务中心多层作用域封装框架设计.md`）的**演进与落地篇**，其中"策略 C → 抽 `ITemplateExpander`"在此落地为 P3。

**目标**：把 ScopeFramework 从"拼 JSON 字符串的短路步骤链"演进为"强类型动作描述 + 可注册命令路径 + 单一命名/派生源 + 结构化诊断"的通用作用域封装层，并修复 E1/命名默认漂移等已知缺陷。

**架构要点**：步骤从"产 JSON 文本"改为"产强类型 `ScopeAction`"，JSON 生成下沉到统一序列化器（保证 Preview 与执行同一条路径）；命令→步骤路径由可注册转移表决议；命名/归一化派生收敛到 `IScopeNamingRule`；执行策略随 `ScopeContext` 以快照透传。

**技术栈**：C# / .NET 10 / MSTest（CentralTest：`ScopeFramework.Tests`）/ 零 Agent 依赖（LLM-free）。

### 1.2 当前架构

* `ScopeCommandTranslator`：命令 → （`ResolvePath` switch）→ 步骤序列，逐条 `ExecuteAsync`。

* `IStep`：`CanExecute`（短路）/ `ProduceActionJson`（返归 JSON 字符串）/ `Diagnostics`。

* 步骤均为静态单例（S0\~S7），`ResolvePath` 以命令类型静态决定路径。

* 命名派生在 `IScopeNamingRule` / `DefaultScopeNamingRule`。

* 进球端口由组装层注入（Agent 侧 `RunJsonAsync`，测试侧桩）。

### 1.3 既有设计文档已定调的关键结论（需沿用，不重推）

* **策略 B（短期/P0 已采用）**：`ScopeCommandTranslator` 独立实现，借鉴 GraphKey `ChainTemplate` 模式但不引用——避免引入图模型重依赖。

* **策略 C（长期/P2 后评估）**：在 Share 层抽 `ITemplateExpander<TTemplate, TStep, TResult>`，让 `ChainTemplateExpander`（GraphKey）与 `ScopeCommandTranslator`（作用域）各实现一份，消除两套展开管线设计重复。→ **本方案 P3 即该策略的落地**。

* **数据流模型差异**：GraphPipeline 是 `Execute` 链式（上一步输出是下一步输入）；ScopeCommandTranslator 是扇出式（每步独立产 JSON 列表收集）。→ 结论：不能直接复用 Execute 循环，只能复用"步骤接口+容器+串行执行"的模式结构。

## 二、问题诊断（为什么重构）

### 2.1 已知缺陷

**D1 · E1：enqueue 默认调度模式分歧（已有注释自认）**

* 框架 [EnqueueStep S7](file:///D:/Project/Program/WorkFlowPrj/CsharpPrj/Share/ScopeFramework/Steps/EnqueueStep.cs#L21) 硬编码 `"mode":"Hybrid"`。

* Agent 权威 [HandleTaskAsync](file:///D:/Project/Program/WorkFlowPrj/Projects/Agent/src/Agent.Launcher/Modules/Libraries/AgentUiLibraryRuntime.cs#L211-L225) 对 enqueue 空 mode 默认 **Deterministic**（纯簿记不默认 LLM），且 `TaskPoolEnqueueAsync` 默认即 `Deterministic`。

* **后果**：经 task-center 高层命令入队的任务可能静默走 LLM 路径，与权威路径行为不一致。

**D2 · 命名默认双源漂移**

* 框架 [ResolveWorkflowId](file:///D:/Project/Program/WorkFlowPrj/CsharpPrj/Share/ScopeFramework/Naming/DefaultScopeNamingRule.cs#L9-L23)：`scope.WorkflowId ?? TaskKey ?? ""`。

* Agent [ResolveWorkflowId](file:///D:/Project/Program/WorkFlowPrj/Projects/Agent/src/Agent.Launcher/Modules/AgentUiLibrarySupport.cs#L76-L78)：`workflowId ?? "agent-round"`。

* **后果**：同一"空值回退"语义在两处有不同默认，是 TH-12/单一实现在命名派身上的违反。

**D3 · 表达力缺口：执行策略无法透传**

* `ScopeRequest`（[RunRequest.cs L96-L107](file:///D:/Project/Program/WorkFlowPrj/Projects/Agent/src/Agent.Launcher/Modules/Contracts/RunRequest.cs#L96-L107)）仅 7 字段，装不下调度/入队策略。

* 权威 `TaskPoolEnqueueAsync`（[L213-L255](file:///D:/Project/Program/WorkFlowPrj/Projects/Agent/src/Agent.Launcher/Modules/Libraries/AgentUiLibraryTaskPool.cs#L213-L255)）有 priority/maxRetries/input/executorId/schedulingMode/active 等全套。

* **后果**：框架只能以"硬编码子集"表达 enqueue，高层命令天然弱于直接 action。

**D4 · 手拼 JSON 易错、双路径**

* 每个 step 手工 `"action":"node","op":"write",...` 拼字符串（[ScopeJson.Str](file:///D:/Project/Program/WorkFlowPrj/CsharpPrj/Share/ScopeFramework/Internal/ScopeJson.cs#L8-L14) 手工转义）。

* 执行走 `ProduceActionJson`（字符串），预览走 `ResolvePath`（步骤 id），两条路径产物分离，易漂移。

**D5 · 转移表被 switch 硬编码**

* [ResolvePath](file:///D:/Project/Program/WorkFlowPrj/CsharpPrj/Share/ScopeFramework/ScopeCommandTranslator.cs#L64-L83) 用 switch 枚举命令类型，无法外部扩展新命令。违反项目"`TryRegister*` 反射注册防崩溃"的模块注册惯例。

**D6 · 诊断为非结构化字符串**

* `ScopeCommandResult.Diagnostics` 是 `List<string>` 裸串，无法结构化过滤/聚合/对齐。

### 2.2 边界：明确**不该**上提 / 不该动

| 逻辑                                                                              | 归属                | 理由                                                                |
| ------------------------------------------------------------------------------- | ----------------- | ----------------------------------------------------------------- |
| `OpOf` / `UnknownOpError` / `Truncate` / `JoinOrNone` / `ToStr` / `WithDbAsync` | 留在 Agent          | 全 AgentUi 面通用（runloop/graph/config…），非 task-scope 专属；上提会耦合非作用域消费方 |
| addReference 语义（`node_to_node`、cross\_db\_link、写透守卫建边）                          | 留在 Agent/LiteDB 层 | 图领域真知识，非通用                                                        |
| 装配端口（`RunJsonAsync` 分发、`HasReferenceGrounding`/`HasTaskPool` 取值）                | 留在 Agent          | 组装责任，本就是框架注入点                                                     |
| `FrontEndDriven/ControlLookup/ScopeContext` 等同名类                                | 不动                | 是另一套概念，非本框架，勿并                                                    |

## 三、设计目标（目标态）

1. **步骤产出强类型动作，JSON 生成唯一化**：`IStep.ProduceActions(scope,naming) : IReadOnlyList<ScopeAction>`；序列化器统一产出 JSON；Preview 与执行共用同一描述 → 消除 D4。
2. **命令→路径可注册**：用 `IScopeCommandRegistry` 替代 switch → 消除 D5，对齐 `TryRegister*` 惯例。
3. **命名/归一化单一源**：`IScopeNamingRule` 统一持有 nodeKey 列表归一化、workflowId 空值默认；Agent 删除本地 `ResolveWorkflowId` 兜底并改用框架 → 消除 D2。
4. **执行策略快照透传**：`ScopeContext` 增可选执行策略字段；S7 从上下文取值、默认修正为 Deterministic → 消除 D1、缓解 D3。
5. **结构化诊断**：`DiagnosticEntry(step, kind, message)` → 消除 D6。
6. **对齐** **`ITemplateExpander`（设计 § 策略 C）**：P3 把"展开 + 串行执行"的结构抽到 Share 层通用接口，作用域与 GraphKey 各实现一份 → 消除跨层设计重复。

### 迁移兼容性红线

* `ScopeCommandTranslator` 构造签名、`ExecuteAsync`/`Preview` 成员签名、执行端口类型 `Func<string, Task<string>>` **保持不变**（可新增构造函数重载/静态工厂，不删旧）。

* 步骤产出的 **JSON 文本序列与字段含义保持不变**（S1/S2/S3/S4/S5/S6/S7）。唯一行为变化是 D1 修复（enqueue 默认 mode → Deterministic），该变化即重构目标之一，需在 Agent 侧同步验证。

* CentralTest 现有断言大多校验 JSON 字段，重构后**应原样通过**；新增/变更行为补新用例。

### 4.3 命令转移表可注册化

```csharp
/// <summary>命令 → 步骤路径决议器（可注册，替代 ResolvePath 的 switch）。即时方法注册失败不抛，返回默认 S0 直通。</summary>
public interface IScopeCommandPathRegistry
{
    IReadOnlyList<IStep> Resolve(ScopeCommand command);
}

public sealed class ScopeCommandPathRegistry : IScopeCommandPathRegistry
{
    private readonly Dictionary<string, Func<ScopeCommand, IReadOnlyList<IStep>>> _paths = new(StringComparer.OrdinalIgnoreCase);

    /// <summary>TryRegister* 语义：反射/外部注册特定命令路径；命名冲突返回 false 不抛。</summary>
    public bool TryRegister(string cmd, Func<ScopeCommand, IReadOnlyList<IStep>> path)
        => _paths.TryAdd(cmd.Trim().ToLowerInvariant(), path);

    public IReadOnlyList<IStep> Resolve(ScopeCommand command) { ... } // 未命中默认 S0 直通
}
```
