# UniversalJsonMiddleware 逻辑错误分析报告

## 🔴 严重逻辑错误

### 1. LockHelper.ExecuteWithLockAsync 异步锁缺陷 (Utilities.cs:19-24) ✅ 已修复
`lock` 语句不能与 async/await 一起使用，锁未保护异步操作。
- **修复方案**：将 `lock` 替换为 `SemaphoreSlim`，使用 `WaitAsync/Release` 模式实现异步锁。

### 2. MiddlewarePipeline.Use 第二个重载忽略 next (Core.cs:282-289) ✅ 已修复
创建了 wrappedNext 但未传递给 middleware，导致管线链中断。
- **修复方案**：将 `next` 包装为 `Func<Task<JsonCommandResult>>` 闭包并传递给 middleware。

### 3. CacheManager.Contains 语义错误 (Infrastructure.cs:185) ✅ 已修复
使用 `Get<object>` 检查键是否存在，当值为 null 时返回 false。
- **修复方案**：直接检查 `ConcurrentDictionary` 中是否存在键，并处理过期逻辑。

### 4. LayoutValidator 重叠检测负值计算错误 (Infrastructure.cs:658-687) ✅ 已修复
负 Left/Top 值直接作为像素值处理，未按比例计算。
- **修复方案**：添加 `CalculateApproximateRect` 方法，负值按比例计算（从右侧/底部偏移）。

### 5. JsonMerger.DeepMerge 数组合并深拷贝问题 (Serialization.cs:488-498) ✅ 已修复
AppendArray 模式下不必要的序列化/反序列化，null 处理错误。
- **修复方案**：使用 `DeepClone()` 替代 `JsonNode.Parse(item?.ToJsonString())`，避免 null 引用异常。

## 🟡 中等严重度逻辑错误

### 6. EventBus.Unsubscribe 忽略 handler 参数 (Infrastructure.cs:137-147) ✅ 已修复
清除了所有 handler 而非指定的 handler。
- **修复方案**：将 `_cleanups` 存储结构改为 `List<(Action Cleanup, Func<object?, Task> Handler)>`，只移除匹配的 handler。

### 7. StateManager.RemoveState<T> 泛型参数未使用 (Infrastructure.cs:205-209) ✅ 已修复
- **修复方案**：添加类型检查 `existing is T`，只移除类型匹配的状态。

### 8. JsonPipelineBuilder 泛型不匹配 (Core.cs:122-156)
强制所有 stage 为相同泛型类型，无法表达类型转换链。
- **状态**：未修复（架构设计问题，需较大重构）

### 9. SmartSpacingCalculator 引用但可能缺少 using (Infrastructure.cs:1190)
- **状态**：未修复（需确认引用是否正确）

## 🟢 轻微逻辑问题

### 10. JsonCommandParser.Parse 边界情况 (Core.cs:339-346)
`=` 开头参数导致空 key。
- **状态**：未修复（边界情况，影响较小）

### 11. JsonFileSaveStage 元组强制转换 (Core.cs:263-264)
命名元组运行时类型不匹配风险。
- **状态**：未修复（需较大重构）
