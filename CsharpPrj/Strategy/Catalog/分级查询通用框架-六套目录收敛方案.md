# 分级查询通用框架 —— 六套目录收敛为一套（Strategy.Catalog）

> 结论先行：**「索引 → 目录 → 明细 → 检索 → 统计」不是六种能力，是同一种能力的六个副本。**
> 本方案把它们收敛为 `Frame/CsharpPrj/Strategy/Catalog` 一套通用框架：
> 各域只提供 `ICatalogSource`（数据），分组/检索/统计/分级呈现只有一份实现（`CatalogGrouper`），
> 多级/不定深度复用 `Modules.DeclarativeDataflow`（不重造层遍历）。
> 落地状态：框架代码已建并独立编译通过（`dotnet build Strategy\Catalog\Catalog.csproj` → 0 警告 0 错误）；
> 六套旧面按 §5 分阶段转调，旧名保留不再新增。

### 共同缺陷（收敛动因）

1. **轴写死**：前缀 / 文件夹 / module 三种口径各自硬编码，新增轴必须改代码。
2. **显示名写死**：`ToolCatalogGrouper.DisplayNames` 等映射表散落，增域必改 C#。
3. **层数固定**：一律 3 级（index/域/明细），无法表达"工作流→步骤→函数""节点→子节点"这类不定深度。
4. **一套域一套 API**：调用方（脚本 / UI / LLM 提示词）面对 `Math_Get*`、`Func_Get*`、`Ui_List*`、`ProduceUi_List*` 四套命名与返回形态。
5. **无预算 / 无环守卫**：目录若来自层次数据，展开无界；检索无上限（全量倒出）。
6. **未命中无引导**：只回"未找到"（如 `ProduceUi_ChainInfo`、`Math_Execute`），调用方无从自纠。
7. **明细与索引混用**：部分面把明细塞进列表返回（上下文膨胀的结构性来源）。

## 2. 目标形态：一本可逐级查的"新华字典"

| 字典要素 | 框架对应 | 产出类型 | 纪律 |
|---|---|---|---|
| 字典柜（有哪几本字典） | `sources` | `CatalogSourceInfo[]` | 源必须自报规模（total/axes） |
| 部首表 / 拼音表（有哪些分区、各多少字） | `index` | `CatalogIndex`（`Pinned` + `Groups`） | **不含明细** |
| 部首页字表（该部有哪些字） | `list` | `CatalogList` | 只出摘要行 |
| 字条（读音/义项/例句/用法） | `describe` | `CatalogDetail`（`Fields`） | 按需展开 |
| 按字/拼音查字 | `search` / `searchAll` | `CatalogSearchResult` | 有上限 + 截断可见 |
| 凡例（收字规模、分部统计） | `stats` | `CatalogStats` | 轴分布 + 最大分组 |

关键设计判断：

- **分级不是条目的固有属性，而是视图粒度**（`CatalogTier` 标注结果而非数据），
  故同一个 source 既能平铺（`index.Pinned`）又能分组（`Groups`）又能细看（`describe`），无需为"层级"建模。
- **轴是数据**（`CatalogAxis` 声明 + `CatalogAxisValue` 挂载），条目可同时属于多轴（前缀 / 文件夹 / module / skill / 层级），
  消除"轴口径写死"与"新增一轴改代码"。
- **层次化交给已有引擎**：层数不定的场景（节点域 / 工作流→步骤→函数 / 资源发现）不新增查询代码，
  用 `HierarchyCatalogSource` 把 `HierarchySchema` 投影成目录面；实例数经 `HierarchyCatalogExpander`
  跑 `HierarchyProcessEngine`（预算 + 环守卫免费获得）。

## 3. 框架设计（已落地）

### 3.1 分层

```
Model/      数据与视图（CatalogItem / CatalogDetail / CatalogAxis / CatalogTier / 各视图记录）
Ports/      唯一扩展点（ICatalogSource）+ 注册表端口（ICatalogSourceRegistry）
Core/       CatalogGrouper（唯一算法）+ CatalogRegistry（唯一装配）+ CatalogQueryService（唯一查询面）
Json/       CatalogJson（唯一文本出口：CatalogQuery → 稳定 JSON）
Hierarchy/  HierarchyCatalogSource / HierarchyCatalogExpander（复用 DeclarativeDataflow）
Diagnostics/ CatalogException 族（未注册源 / 未声明轴 / 重复 Id）
```

### 3.2 唯一扩展点

```csharp
public interface ICatalogSource
{
    string SourceId { get; }                       // 装配期唯一
    string Display  { get; }
    IReadOnlyList<CatalogAxis> Axes { get; }       // 声明式多轴
    IReadOnlyList<CatalogItem> Enumerate();        // 条目全集（摘要行，禁明细）
    CatalogDetail? Describe(string key);           // 明细按需；未命中返 null（不抛）
}
```

接入成本三档（详见 `README.md`）：`ListCatalogSource.ByPrefix/ByFolder`（一行）→
`DelegateCatalogSource`（两段委托）→ 自定义 `ICatalogSource`（明细另存他处）。

### 3.3 单一算法（`CatalogGrouper`，纯函数零 IO）

`Index` / `List` / `Group` / `Describe` / `HintFor` / `Search` / `SearchAll` / `Stats` / `Info`。
排序口径统一（计数降序 → 取值序 → 键序），大小写口径由 `CatalogAxis.CaseSensitive` 声明，**各域不再各写一遍**。

### 3.4 错误与引导契约

- 未注册源 → `UnknownCatalogSourceException`（带**已注册源清单**）；
- 未声明轴 → `UnknownCatalogAxisException`（带**可用轴清单**）；
- 明细未命中 → 返回 null **且** 给 `CatalogHint`（前缀命中 → 包含命中 → 样本），**不静默返空**；
- 检索超限 → `CatalogSearchResult.Truncated = true`，**不静默截断**；
- 重复 Id 注册不同实例 → `DuplicateCatalogSourceException`（替换须显式 `Replace`）。
- JSON 面把上述错误统一收敛为 `{ "status":"error", ... }` 信封（消费方不必 try/catch）。

### 3.5 有界量化（对齐 `AX-CORE.QuantificationConstraint`）

索引只出"轴值 + 计数"，明细按需；检索默认上限 `CatalogGrouper.DefaultSearchLimit = 50`；
层次展开预算 `ProcessBudget`（`MaxNodes=10000 / MaxDepth=64` 缺省，不定深度必配）。

## 4. 六套 → 一套：API 收敛映射

统一入口（JSON 面 `CatalogJson.Dispatch`，入参 = `CatalogQuery{ Op, SourceId, AxisId, Value, Key, Query, Limit }`）：

| 旧面 | 旧 API（保留转调，标 deprecated） | 新 op | 新 source 建议 Id |
|---|---|---|---|
| ① Agent 工具面 | `tool_catalog_index` | `index` | `tools`（轴：`prefix`=域；`Pinned`=原 Core 表 `ToolCatalogCore.Names`） |
| ① | `tool_catalog_describe {domain}` | `list {axisId:"prefix", value:"<域>"}` | 同上（原"按域展开"=二级目录） |
| ① | （无） | `describe {key:"Activation_ReLU"}` | 同上（明细：描述 + 执行体轨 + 参数） |
| ② 数学域 | `Math_GetDomains` / `Math_GetFunctionsInDomain` / `Math_GetFunctionDetail` / `Math_Search` / `Math_GetStats` | `index` / `list` / `describe` / `search` / `stats` | `math`（轴：`prefix`=数学域） |
| ③ 函数库 | `Func_GetLibraries` / `Func_GetFunctions` / `Func_Search` / `Func_GetStats` | `index` / `list` / `search` / `stats` | `functions`（轴：`prefix`=库；与 ② 合并为**同一 source**，用第二轴 `library` 区分） |
| ④ 注册表 | `registry_search {query?/prefix?/module?/skill?}` | `search`（单源）/ `searchAll` + `index`（**新增**：按 module/skill 轴的计数，替代三口径 if） | `registry`（轴：`module` / `skill`） |
| ⑤ 模板目录 | `Ui_ListCatalog` / `Ui_ListCatalogTree` / `Ui_LoadCatalog` / `Ui_LoadCatalogDoc` | `index` / `list {axisId:"folder"}` / `describe {key:"<folder>/<file>"}` | `templates`（轴：`folder`=分类；模板说明 = 明细字段） |
| ⑥ 产出链 | `ProduceUi_ListChains` / `ProduceUi_ChainInfo` | `index` / `describe {key:"<chainId>"}` | `produce-chains`（单层；`describe` 未命中给候选，替代"未知产出链：x"） |
| ⑦ 声明面 / 节点域 | `db_declaration_list` / `db_declaration_get`；域键表 | `index` / `describe` | `declarations`（轴 `kind`）/ `node-domains`（`HierarchyCatalogSource` 投影） |

**执行类 API 不属本框架**（`Math_Execute` / `Func_Execute` / `registry_call` / `ProduceUi_Run` /
`Ui_RunCommand` 等）：它们是"调用面"，只需把**发现入口**（list/index/describe）换成统一三件套，
调用仍按 `describe` 返回的 `key` + 契约走各自既有执行体（`RegistryToolService.CallAsync` / `Func_Execute` 形态），
不在本框架内再造执行链。

## 5. 迁移路线（分阶段，先并行后收敛）

| 阶段 | 内容 | 判据 |
|---|---|---|
| **P0 基线对拍** | 为每套旧面写"旧 API 输出 ↔ 新 source 输出"的全等对拍脚本（`Information/DrivenConfig/Scripts/...`）；此阶段**不改任何旧函数** | 对拍全绿（`Math_GetDomains` 的分组 = `index.groups`；`Func_GetLibraries` 同） |
| **P1 接入不改名** | 六套各实现一个 `ICatalogSource`（多数用 `ListCatalogSource`/`DelegateCatalogSource`）；新查询面注册进 `CatalogRegistry`；旧 API 内部改为**转调**新面 | 新旧双跑输出一致；旧脚本零改动仍通过 |
| **P2 工具面目录化** | 宿主工具面只平铺「目录三件套 + 核心控制面」，其余工具改为按需展开（替代当前把上百个 `Math_*`/`Func_*`/`Ui_*` 平铺进提示词） | 工具面工具数上限断言 + 提示词长度回归；模型经 `index→list→describe` 仍能命中同一批工具 |
| **P3 层次化收口** | "工作流→步骤→函数""节点→子节点""资源类型发现"改用 `HierarchyCatalogSource` + `HierarchyCatalogExpander`；删除各处自写的层遍历/深度判据 | 深度/节点预算截断用例 + 环守卫用例通过 |
| **P4 门禁** | 新增 `Xxx_GetDomains` / `Xxx_GetLibraries` / `Xxx_ListChains` 形态函数被门禁拒绝（"目录能力单源"断言）；`CatalogGrouper` 唯一实现断言 | CI 门禁脚本（`Frame/PowerShellScript/.../Test-ProjectReferences.ps1` 同类） |

顺序理由：P1 保证"零回归"才允许 P2 收缩提示词面；P3 依赖 P1 的 source 契约稳定；P4 是防止收敛成果再分叉。

## 6. 风险与取舍

| 风险 | 说明 | 对策 |
|---|---|---|
| 旧调用方依赖旧名 | 脚本 / UI 配置（`MainLayout.json` 的 `click:"Ui_ListCatalogTree"`）/ LLM 记忆 | P1 旧名保留**转调** + 双跑对拍；P4 门禁只拦"新增变体"，不强行删名 |
