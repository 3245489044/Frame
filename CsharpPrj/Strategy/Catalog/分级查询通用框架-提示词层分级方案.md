# 分级查询通用框架 —— 提示词层分级方案（索引浅、明细按需 · 代码维护）

> 定位：把《六套目录收敛方案》确立的「sources / index / list / describe / search / stats」分级查询面，
> **向提示词侧延伸**：让注入提示词的资源面也走「索引常驻 + 明细按需」，而不是当前的全量枚举 → 整块注入。
> 维护方式：与 `PromptSegmentCatalog` 同构——**一个代码内声明式注册表**（新增分级组 = 加一行），禁止把分组/档位写进配置或字符串。
> 前置阅读：《分级查询通用框架-六套目录收敛方案.md》《分级查询通用框架-重构施工单.md》。

---

## §0 结论速览

- 提示词里那段 `<runtime_resource ...>` 块由 **运行时资源发现链** 产出，**不是** `Strategy.Catalog` 的产物。
- 该链**既不读 Catalog 分级，也没有相关性门限**：候选全收 + 估值器给统一地板值 0.5 + 预算兜不住 ⇒ 全部 `Full` 通过。
- `Strategy.Catalog` **已被真实应用**，但只用在**查询面**（SubAgent 工具面 / 注册表 / 节点域 / 产出链 / 模板 / 资源类型元数据 + MCP `catalog_*`），**未接入注入链**。
- 目标：新增一个**代码维护**的提示词层分级注册表 `PromptTierCatalog`，把 Catalog 的 `index/list/describe` 投影为提示词的「索引档 / 分组档 / 明细档」，并把资源块从「裸拼串」升级为真段。

## §1 现状接线（两路面）

### 1.1 段目录面 —— **已经是代码维护的单一声明**

提示词由「段」拼装，段的定义集中在唯一注册表：

| 部件 | 位置 | 作用 |
|---|---|---|
| `PromptSegmentCatalog` | `Share/Frameworks/Conversation/ContextBinding/PromptSegmentCatalog.cs` | 段的**有序唯一注册表**（`Fixed` 列表）；新段只改此处一处 |
| `SegmentSpec` | 同目录 `SegmentSpec.cs` | 段声明：`Key` / `UiStage` / `Produce`(写侧) / `Text`(读侧) / `Toggle` / `Band` / `Target` |
| `PromptSnapshotBuilder` | 同目录 `PromptSnapshotBuilder.cs` | 由段目录**驱动发射** binding，`Bindings` 按 `CacheBand` 升序稳定排序 |

现有固定段：`prompt:l0` / `prompt:skill.block` / **`prompt:tools`** / `prompt:l1` / `prompt:l2` / `prompt:mode` / `prompt:subagent`；
完备性判据 `PromptSegmentCatalog.Validate()`（每段须具 UiStage/Produce/Text，且 Band 非降，可机械复算）。

> 即：**提示词层已经有一个"由代码维护的段框架"**。缺的不是框架，而是**分级**——`prompt:tools` 段只承接一个整块 `ToolBlock`，段内没有 index/group/detail 之分。

### 1.2 运行时资源面 —— **旁路裸拼串，既非段、也无分级**

`state_response` 工作流函数在单步内直接调资源发现门面，把返回块**拼到文本尾部**：

- `Agent.Modules.Response/Response/StateResponseFunction.cs`
  - L111 `AgentServiceSlots.Resolve<IResourceDiscoveryFacade>()`
  - L116-118 构造 `ResourceDiscoveryContext(mode, signal, scopeKey, null)` 并 `RunAsync`
  - **L122** `text = text + "\n\n" + outcome.Block;` ← 裸拼串（非段、不进 `PromptSnapshot`、无 Band/哈希/投影/toggle）
  - L124-129 另经 `IResourceInjectionPort.InjectAsync(scopeKey, block)` 注入目标 task

产出块 = `Agent.Modules.Response/Response/ResourceBlockComposer.Build(entries)`（块头 `# 运行时资源（自动发现 · 按需加载）`）。

## §2 为什么现在仍是"大段函数整块注入"（根因三处）

| # | 缺失 | 证据位置 | 后果 |
|---|---|---|---|
| R1 | **候选全量**，未按需收窄 | `ResourceDiscoveryService.cs` L53 传 `schema: null`；`ResourceDiscoveryPipeline.cs` L59 `schema ?? ResourceHierarchyDeclaration.Build(_registry)` | 每个登记类型的**全部**条目成为候选 |
| R2 | **相关性无门限**（选择器只按预算与零价值裁剪） | `ResourceRoiSelector.cs` L75-100：仅丢 `value<=0` 与超全局预算；`weight` 只拼进 reason，**不参与过滤** | 不相关工具也进 |
| R3 | **估值器统一地板值 0.5** | `DeclarativeRoiEstimator.cs` L34 `value=0.5`；L63 未命中 `reason="声明式基线"` | 未命中项永不为 0 ⇒ 永不 Drop |

叠加两个成本事实，使预算彻底兜不住：

- `ResourceCostModel.cs` L17-21：成本 ≤0 → 1；
- `ToolResourceTypeProvider.cs` L48-49 `ResolveAsync` 返回 `null` ⇒ 每条工具成本 ≈1（正文为空，只注入描述）；
- `ResourceBudget.cs` L12 缺省 `GlobalTokens=2000 / PerItemTokens=800` ⇒ 约 30 条工具全部 `Full` 通过。
- reason 显示为 `声明式基线·w=80·v=0.5`（`weight=80` 来自 tool descriptor，`v=0.5` 来自地板值）。

**另有两条"声明了但没接线"的死元数据**（应一并修）：

- `ToolResourceTypeProvider.cs` L20 `Descriptor{ DefaultDisclosure:"summary_only" }` —— **`ResourceRoiSelector` 只读 `ValueWeight`，从不读 `DefaultDisclosure`**（L50-51），工具"仅摘要"的声明被忽略。
- `StatePromptCatalog.cs` L60-75 `StatePromptAction.ResourceKinds` —— 声明了"本模式该发现的资源类型集"，但 `StateResponseFunction.cs` L116-117 构造 `ResourceDiscoveryContext` 时**未传入**，按模式 scope 的能力悬空。

## §4 目标：Catalog 五 op → 提示词三级映射

对照「新华字典」的口径（见 `README.md`），提示词侧分三档，**档 = 披露深度**：

| Catalog op | 提示词档 | 注入形态 | 常驻/按需 | 成本 |
|---|---|---|---|---|
| `sources` | —（可选页眉） | 有哪些目录可查（一行） | 常驻 | 极低 |
| `index` | **索引档** | 组行：轴值 + 计数（`functions：12 库 / 340 函数`） | **常驻（浅）** | 低 |
| `list` | **分组档** | 某轴值下条目摘要行（键 + 一句话） | **命中相关轴值才展开** | 中 |
| `describe` | **明细档** | 单条完整契约 / 参数 / 示例 | **仅按需（工具调用）** | 高 |
| `search`/`searchAll` | 检索档 | 关键词命中（有上限、截断可见） | 仅按需 | 中 |
| `stats` | 凡例档 | 规模 + 轴分布 | 仅按需 | 低 |

纪律对齐 `README.md` §「纪律（红线）」#4：**索引不得携带明细；检索有上限且截断可见**。

## §5 目标架构（四部件 + 数据流）

```
                 ┌──────────────────────────────────────────────┐
                 │  CatalogRegistry（真源，已有）                │
                 │  tools / functions / registry / nodes / ...   │
                 └───────────────┬──────────────────────────────┘
                                 │ 读（CatalogGrouper.Index/List/Describe）
                 ┌───────────────▼──────────────────────────────┐
                 │  CatalogPromptProjector（新增·纯函数）        │  零领域字符串
                 │  tiers → 文本行（索引档/分组档/明细档）       │
                 └───────────────┬──────────────────────────────┘
                                 │ 声明/排序/Band
                 ┌───────────────▼──────────────────────────────┐
   ★ 焦点 ★      │  PromptTierCatalog（新增·代码单一声明）       │  仿 PromptSegmentCatalog
                 │  TierSpec：Key/Source/Axis/Project/Band       │
                 └───────────────┬──────────────────────────────┘
                                 │ 发射段 binding
                 ┌───────────────▼──────────────────────────────┐
                 │  PromptSnapshot → 段 `prompt:resources`      │  纳入 Band 排序 / I3 哈希 / UI 投影 / toggle
                 └───────────────┬──────────────────────────────┘
                                 │
                 ┌───────────────▼──────────────────────────────┐
                 │  按需展开：catalog_list / catalog_describe    │  已有（P2 七件套）
                 └──────────────────────────────────────────────┘
```

现状：`全量枚举 → 整块注入`。目标：`索引常驻 + 明细按需`。

## §6 "通过代码来维护"的具体落点

**核心理念**：与 `PromptSegmentCatalog` 完全同构——**一个静态声明表 + 一个完备性判据**，新增分级组 = 加一行；分组/轴/档位是**数据**，框架内禁硬编码映射表（对齐红线 #3）。

```csharp
// PromptTierCatalog.cs（新增，示意）
public static class PromptTierCatalog
{
    /// 分级组声明单一真源：一行接入一个提示词级目录面。
    public static readonly IReadOnlyList<TierSpec> Declared = new[]
    {
        new TierSpec(AnchorKey.PromptResource("tools"), "prompt:resources:tools",
            SourceId: "tools", AxisId: "prefix",
            Project: CatalogPromptProjector.Index, Band: CacheBand.B2),

        new TierSpec(AnchorKey.PromptResource("functions"), "prompt:resources:functions",
            SourceId: "functions", AxisId: "prefix",
            Project: CatalogPromptProjector.Index, Band: CacheBand.B2),
        // 新增一个分级面 = 加一行，不碰别处
    };

    /// 完备性判据（机械可复算）：Stage/Project/Band 齐备，Band 非降。
    public static IReadOnlyList<string> Validate() { /* 仿 PromptSegmentCatalog.Validate() */ }
}

public sealed record TierSpec(
    AnchorKey Key, string UiStage, string SourceId, string AxisId,
    Func<CatalogQueryService, string> Project, CacheBand Band,
    TierDepth Depth = TierDepth.Index);   // Index 常驻；Group/Entry 需命中才展开
```

**要点**：

1. **投影是纯函数**：`CatalogPromptProjector.Index(qs, sourceId, axisId)` 直接转 `CatalogGrouper.Index`；可单测、可 CI 对拍。
2. **段目录单一驱动**：把 `PromptTierCatalog.Declared` 折叠进 `PromptSegmentCatalog.Fixed`（或由其派生），从而复用 `PromptSnapshotBuilder` 的发射/Band 排序、`ContextBindingValidator` 的校验、`prompt:*` 折叠气泡投影。
3. **零新增查询实现**：不得再造 `Xxx_GetDomains` 变体（红线 #2）；一律经 `CatalogQueryService`（`CatalogJson.Dispatch` 唯一文本出口）。
4. **可回退**：每个分级组走 `Toggle`（如 `ToggleResources`），关闭即回退到旧整块，零回归。

## §7 关键设计决策与取舍

| # | 决策点 | 建议 | 理由 / 代价 |
|---|---|---|---|
| D1 | 资源块**升级为真段** 还是保留旁路？ | **升级为段**（`prompt:resources`） | 复用 Band 排序 / I3 哈希一致性 / UI 投影 / 档案开关；消除「野段」。代价：需改 `StateResponseFunction.cs` L122 的裸拼串为段发射 |
| D2 | 相关性门限放**哪一层**？ | **三层各司其职**：估值器只出"价值"；选择器补 `minValue` 门限 + 尊重 `DefaultDisclosure`；投影层默认只出 index | 最小侵入；同时修 R2/R3 与死元数据。代价：触及 ROI 语义，需回归用例 |
| D3 | 按需展开**复用 catalog_\*** 还是新造？ | **复用**七件套（P2 已建） | 守「唯一查询面」红线，避免第二套查询代码 |
| D4 | 投影放 **Frame** 还是 **Plug**？ | **Frame**（`Share.Conversation.ContextBinding`） | 需读 Strategy.Catalog 全局 registry，且与段目录同层；Plug 只注入 context |
| D5 | 索引档**是否按 mode scope**？ | **是**：把 `StatePromptAction.ResourceKinds` 接进 `ResourceDiscoveryContext` | 兑现已声明未接线的能力，避免每轮全量索引 |
