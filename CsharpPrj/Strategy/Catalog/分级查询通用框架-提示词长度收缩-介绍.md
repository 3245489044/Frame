# 提示词长度收缩 —— 实现介绍（代码与逻辑）

> 定位：面向维护者的**实现说明**，回答「提示词长度是怎么被收缩的、由哪些代码负责、收缩量怎么核」。
> 上游：`分级查询通用框架-提示词层分级方案.md`、`分级查询通用框架-重构施工单.md`（W8）、`分级查询通用框架-提示词层分级-后续施工单.md`（A5 判据）。
> 版本：初稿 · 依据当前工作区源码实证归纳（路径/行号静态可核）。

---

## §0 一句话概括

**把「全量明细/全量资源清单」从**常驻**提示词里搬出去**，改为：

```
常驻面 = 索引档（域 + 计数）        ← 体积 = O(域数)
明细面 = 按需展开（工具调用 / ROI 选中才取）  ← 体积 = O(本次真正用到的条目)
```

即：**信息可达性不变，常驻体积从 O(条目数 × 明细体积) 降到 O(域数)**。

---

## §1 病根：上下文膨胀的结构性来源

| 旧形态 | 后果 |
|---|---|
| 工具面在基础提示词里**平铺全量工具清单** | 每加一个工具，常驻提示词线性增长 |
| `state_response` 把资源发现结果**裸拼串**成 `<runtime_resource>` 全量块追加进正文 | 正文随资源数线性增长 |
| 目录 API 一次吐「索引 + 目录 + 明细」 | 「分级展开」退化为「把全量明细塞进一次响应」 |

框架侧的**纪律条款**（判据载体，非叙述）：

- `Frame/CsharpPrj/Strategy/Catalog/Model/CatalogTier.cs` —— 四条分级视图声明（`Index`/`Group`/`Entry`/`Detail`），并明写：
  > 「`Index` 层**不得携带** `Detail` 内容，否则『分级展开』退化为『把全量明细塞进一次响应』，正是上下文膨胀的结构性来源。」

这条纪律就是「长度收缩」的**唯一判据点**：只要常驻段只取 `Index` 档，长度就与明细总量解耦。

## §2 三条收缩通道（总览）

```
                 ┌──────────────────────────────────────────────┐
  常驻提示词 ────▶│ 通道一 · 索引档投影（Strategy.Catalog/Prompt）│
                 │  CatalogPromptProjector.Index → "域：计数" 行 │
                 └──────────────────┬───────────────────────────┘
                                    │ 段化
                 ┌──────────────────▼───────────────────────────┐
                 │ prompt:resources 段（Band B2 / ToggleResources）│
                 └──────────────────┬───────────────────────────┘
                                    │ 装配相位注入
  按需面 ─────────▶ 通道二 · 按需展开（catalog_* / tool_catalog_* 工具）
  运行时资源面 ───▶ 通道三 · ROI 渐进披露（Drop / Summary / Full）
```

| 通道 | 收缩的「什么」 | 落点 |
|---|---|---|
| 一 · 索引档投影 | 常驻段的**粒度**（明细 → 计数行） | `Strategy/Catalog/Prompt/**` + `PromptTierRegistration` |
| 二 · 按需展开 | 明细的**搬运时机**（常驻 → 调用时） | `CatalogCallableTrack` 七件套 / `ToolCatalogSubAgentTools` |
| 三 · ROI 渐进披露 | 运行时资源块的**体积**（全量 → 预算内子集） | `Agent.Modules.Response/Roi/**` + `ResourceDiscoveryService` |

## §3 通道一：索引档投影（常驻面收缩）

### 3.1 三档披露深度（声明）

`Frame/CsharpPrj/Strategy/Catalog/Prompt/TierDepth.cs`

| 枚举 | 语义 | 是否常驻 |
|---|---|---|
| `Index = 0` | 索引档（轴取值 + 计数） | **是**（浅、常驻） |
| `Group = 1` | 分组档（命中轴值下的条目摘要） | 否 |
| `Entry = 2` | 明细档（单条完整信息） | 否（仅按需） |

### 3.2 投影器（纯函数 / 零领域字符串）

`Frame/CsharpPrj/Strategy/Catalog/Prompt/CatalogPromptProjector.cs`

| 方法 | 产出 | 收缩角色 |
|---|---|---|
| `Index(queryService, sourceId, axisId)` | `源（N 条）` + 逐行 `- 域：计数` | **常驻段唯一来源** |
| `Group(queryService, sourceId, axisId, value, limit)` | 该域下条目摘要行（默认上限 `DefaultGroupLimit = 50`，**截断可见**） | 按需档 |
| `Entry(queryService, sourceId, key)` | 单条完整信息（字段逐行）；未命中 → 引导文本（不静默返空） | 按需档 |

关键点：`Index` **只读 `queryService.Index(sourceId).Groups` 里该轴的 `Display`/`Count`**，不触条目、不触明细 —— 与总量无关。

### 3.3 分级组注册表与聚合

`Frame/CsharpPrj/Strategy/Catalog/Prompt/PromptTierCatalog.cs`、`TierSpec.cs`、`PromptTierRow.cs`

| 成员 | 作用 |
|---|---|
| `TierSpec(Key, UiStage, SourceId, AxisId, Project, BandOrder, Depth=Index)` | **一行接入一个分级面**；`Project` 是纯投影函数；`Depth` 缺省 `Index` |
| `PromptTierCatalog.Register(spec)` | 幂等（同 `Key` 忽略），显式装配可复现 |
| `PromptTierCatalog.Validate()` | 完备性判据（Key/UiStage/SourceId/AxisId/Project 齐备 + `BandOrder` 非降） |
| `PromptTierCatalog.ProjectAll(queryService)` | 逐组投影并**拼接为一段文本**；未注册源 / 投影异常 → **跳过该行**（不阻断、零回归） |

### 3.4 领域声明（组合根一行接入）

`Projects/Plug/Agent/src/Agent.Modules/Response/Response/PromptTierRegistration.cs`


### 3.5 收缩量（结构口径）

```
全量枚举（旧）：Σ_条目 ( |Key| + |Display| + |Summary| ) + Σ_条目 |明细字段|
索引档 （新）：|源名| + Σ_域 ( |域显示名| + |数字| )      ≈ O(域数)
```

> 典型量级：工具面数十~数百条目 / 若干域 ⇒ 常驻段由「数百行」降到「域数行」。这是 A5「索引档 ≪ 全量枚举」的结构基础。**注意**：本形态下《分级查询通用框架》的 `Strategy.Catalog` 只产**文本**，不落盘、不缓存，长度可直接量。

## §5 通道三：运行时资源块的 ROI 渐进披露（体积收缩）

链路（`Projects/Plug/Agent/src/Agent.Modules/Response/Response/ResourceDiscoveryService.cs`）：

```
发现索引（廉价） → 估值（零 LLM 或一次 LLM） → 性价比选择（预算内） → 只对选中项 Resolve 正文（昂贵） → 渲染块
```

### 5.1 廉价层：索引项结构上不含正文

`Discovery/ResourceItem.cs` —— 只含 `TypeKind / Id / Title / Tags / SummaryFingerprint / EstimatedTokens`，**结构上不含正文**；正文经 `IResourceTypeProvider.ResolveAsync` 在决策**之后**按需取。

`Discovery/ResourceCandidateIndex.cs` —— 含 `Truncated`（「展开未穷尽」结论，**不是失败**）、`Deduplicated`（去重审计）。

`Discovery/ResourceDiscoveryPipeline.cs` —— 发现编排（遍历/环守卫/深度预算全部由 `Modules.DeclarativeDataflow` 提供，本类只装配）；`FilterByKinds` 按上下文声明的类型集**收窄 Provider**（未声明 ⇒ 全量，零回归）。

`Discovery/ResourceDiscoveryContext.cs` —— `Kinds` 即「本模式该发现的资源类型集」的收窄入口。

### 5.2 估值层：未命中即零价值（可被淘汰）

`Roi/DeclarativeRoiEstimator.cs` —— 零 LLM、确定性：按「信号/目标是否命中资源 `Id`/`Title`/`Tags`」打分（命中 Id `+0.4`、标题 `+0.2`、标签 `+0.2`），**`NeutralBaseline = 0.0`**（未命中即零价值 ⇒ 可被 Drop）。
`Roi/LlmRoiEstimator.cs` / `IResourceValueJudge.cs` —— LLM 只影响「价值」输入，不改变选择口径（可解释、可复现）。

### 5.3 选择层：门限 + 预算 + 三档披露

`Roi/ResourceRoiSelector.cs`

| 机制 | 代码 | 收缩作用 |
|---|---|---|
| 相关性门限 | `MinValue`（`DefaultMinValue = 0.0`） | 价值 < 门限 → `Drop`（修「统一地板值 ⇒ 永不 Drop」） |
| 零价值淘汰 | `value <= 0` → `Drop` | 未被信号命中的条目不进块 |
| 全局预算 | `ResourceBudget.GlobalTokens`（默认 **2000**） | 累计超预算 → `Drop`（不再追加） |
| 单项预算 | `ResourceBudget.PerItemTokens`（默认 **800**） | 单项超限 → **降级为 `Summary`**（渐进披露） |
| 类型声明 | `ResourceTypeDescriptor.DefaultDisclosure == "summary_only"` | 该类型恒 `Summary`（正文永不全文进上下文） |
| 排序 | `score = 类型权重 × 价值 / 成本` | 预算优先给「性价比高」的条目 |

`Roi/ResourceDisclosure.cs` —— `Drop(0) < Summary(1) < Full(2)`，「看见多少」的三档。

### 5.4 计价层：唯一 token 口径

`Roi/ResourceCostModel.cs` → `ContextEconomy.Estimate`（`StateGovernance/Kernel/ContextEconomy.cs`）→ `SkillTokenBudget`（**全库唯一估算实现**）：
- `BodyCost` / `EffectiveCost`（除零保护 = 1）
- `SummaryCost(body) = max(1, body/4)`（摘要档按正文 1/4 计价）
- `ResourceBudget.Default = (GlobalTokens: 2000, PerItemTokens: 800)`（**绝不无界**）

### 5.5 渲染与审计

`Response/ResourceBlockComposer.cs` —— 只渲染 `Full`/`Summary`（`Drop` 直接跳过）；无有效条目 → 空串（空槽自动剔除）。

`ResourceDiscoveryService.RecordAudit` —— 产出**可核的收缩指标**：

```
CandidateCount · Deduplicated · SelectedCount · DroppedCount · FullCount · SummaryCount
IndexTokens · InjectedTokens · Truncated · Trigger
```

> `IndexTokens`（若全量搬运的成本）与 `InjectedTokens`（实际注入）的差，就是本通道的收缩量。

## §7 长度收缩怎么核（判据与复算）

| 层级 | 可观测量 | 取法 |
|---|---|---|
| 索引档本身 | 段文本长度 / 行数 | `PromptTierCatalog.ProjectAll(CatalogQueryService.Shared).Length` |
| 全量枚举基线 | 旧块长度 | `ResourceBlockComposer.Build(...)` 全量条目渲染 |
| 快照总长 | `prompt:resources` 段哈希与长度 | `PromptSnapshot.BindingFor(AnchorKey.PromptResources)` + `PromptSnapshotBuilder.Hash(text)` |
| 运行时注入 | `IndexTokens` vs `InjectedTokens` | `ResourceDiscoveryService` 的 `ResourceDiscoveryAudit` |
| 结构性判据 | `CatalogTier` 纪律（Index 不得携带 Detail） | `CatalogPromptProjector.Index` 只读 `CatalogIndex.Groups` |

**A5 判据（施工单原文）**：`提示词长度收缩（索引档 ≪ 全量枚举）`，**判定方式 = 灰度前后快照长度对比记录**。

建议的对比口径（复核用）：
1. 关开关取快照 → 记 `prompt:resources` 段（无该段）/ 旧裸拼串块长度；
2. 开开关取快照 → 记段文本长度；
3. 比值与「域数 / 条目数」比对，确认落入 `O(域数)` 量级。
