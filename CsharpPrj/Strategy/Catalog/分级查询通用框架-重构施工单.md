# 分级查询通用框架 —— 基于新框架的重构施工单

> 目标：把「索引 → 目录 → 明细 → 检索 → 统计」六套副本逐步收敛到 `Frame/CsharpPrj/Strategy/Catalog`
> 一套实现上。本单是可执行施工单（每项含：现状 → 目标 → 改动文件 → 代码骨架 → 验收判据），
> 与《分级查询通用框架-六套目录收敛方案.md》配套（后者讲"为什么/收敛到哪"，本单讲"谁改哪个文件、怎么验"）。
>
> 三条硬约束（贯穿全单）：
> 1. **只换发现入口，不换执行体**——`Math_Execute` / `Func_Execute` / `registry_call` / `ProduceUi_Run` / `Ui_RunCommand` 等调用面**一律不动**。
> 2. **旧名保留转调**——旧函数名/旧返回文本在过渡期保持不变（脚本、UI 配置、LLM 记忆零破坏）。
> 3. **先对拍后切换**——每项先落对拍断言（旧输出 ≡ 新输出），全绿才允许把旧实现切为转调。

## §1 重构总原则

1. **数据留在原域，算法上收框架**：各域的"有哪些条目"事实（工具面 / 函数注册表 / 模板扫描 / 链路表 / 域键表）
   仍是各自真源，只把它包成一个 `ICatalogSource`；分组/检索/统计/分级呈现全部走 `CatalogGrouper`。
2. **一域一 source，能合则合**：数学域（Math）与通用函数库（Func）本是一张注册表 → 合成 **一个** `functions` source
   （两轴：`prefix`=域/库、`library`=注册库名），不再两份 API。
3. **轴与显示名外置**：原 `ToolCatalogGrouper.DisplayNames` 这类硬编码映射改为声明数据（`CatalogAxis.Display` +
   `CatalogAxisValue.Display`），增域零改码。
4. **索引浅、明细按需**：索引/目录只出摘要（键 + 显示名 + 一句话 + 执行体轨）；参数/契约/示例只走 `describe`。
5. **旧面转调，不做双份真源**：旧函数体内改为调用新查询面并**适配回旧文本形态**；禁止"新面一份、旧面另一份"并行维护。

```csharp
using Strategy.Catalog.Model;   // CatalogItem / CatalogAxis / CatalogAxes
using Strategy.Catalog.Ports;    // ICatalogSource

public sealed class ToolFaceCatalogSource : ICatalogSource
{
    public const string Id = "tools";
    public string SourceId => Id;
    public string Display => "工具面";
    public IReadOnlyList<CatalogAxis> Axes { get; } = new[]
    {
        CatalogAxis.Of("prefix", "域"),
        CatalogAxis.Of("backend", "执行体轨"),
    };

    public IReadOnlyList<CatalogItem> Enumerate()
        => (AgentServiceSlots.Resolve<IToolFaceCatalog>()?.Describe() ?? Array.Empty<ToolFaceItem>())
            .Where(i => i is not null && !string.IsNullOrWhiteSpace(i.Name))
            .Select(i => new CatalogItem(
                Key: i.Name, Display: i.Name,
                Axes: new[]
                {
                    CatalogAxes.PrefixValue(i.Name, "prefix"),
                    CatalogAxisValue.Of("backend", i.Backend ?? "(未标注)"),
                },
                Summary: i.Description,
                InvokeRef: i.Backend,
                Pinned: ToolCatalogCore.IsCore(i.Name)))
            .ToList();

    public CatalogDetail? Describe(string key) { /* 字段：描述/域/执行体轨/回环调用名/参数 */ }
}
```

- 一律用 `CatalogRegistry.Register`（同 Id 同实例幂等），**不用** `Replace` 除非确有热换需求；

- 注册点必须与数据源同层（谁持有真源谁注册），避免跨层反向依赖。

| 目录能力单源 | 新增 `Xxx_GetDomains` / `Xxx_GetLibraries` / `Xxx_ListChains` 形态的**新**注册名 → 门禁红（存量白名单） |
| 分组单源 | `Strategy.Catalog` 之外不得新增"按 `_` 前缀分组"的实现（`IndexOf('_')` 分组模式扫描） |
| 工具面有界 | 宿主提示词面工具条目数 ≤ 上限（7 件套 + 核心控制面 + 声明白名单） |
| 烘焙完整性 | `Check-BakeFramework.ps1` 全绿（含 `Strategy.Catalog` 在 manifest） |

### 4.3 每项的"完成定义"（DoD）

一项工作只有同时满足以下四条才算完成：
1. 新 source 已注册且 `CatalogJson` 五件事可查（`sources/index/list/describe/stats` 均有非空结果）；
2. 旧 API 转调后，对拍脚本**全绿**；
3. 旧 API 的**对外文本/JSON 形态未变**（字段名、序、文案）；
4. 新增能力（检索/统计/未命中引导）在脚本中有正向断言（不是"能跑就行"）。
