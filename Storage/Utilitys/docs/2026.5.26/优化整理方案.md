## 2. 问题清单

### 2.1 结构性问题

| 编号 | 严重程度 | 问题描述 |
|------|---------|---------|
| S-01 | 🔴 严重 | **文件组织混乱**：根目录与 `RoslynBasic/` 子目录职责重叠，无清晰分层 |
| S-02 | 🔴 严重 | **命名空间混乱**：存在 6+ 个不同命名空间，同一命名空间分散在多个文件 |
| S-03 | 🟡 中等 | **超大文件**：3 个文件超过 2000 行（`IntegratedAlgorithmLibrary.cs` 3800行、`ProcessCode_Script.cs` 2800行、`Merge.cs` 2100行） |
| S-04 | 🟡 中等 | **命名不规范**：文件名使用混合大小写（`INsert.cs`），部分文件名含 `_Script` 后缀 |

### 2.2 代码质量问题

| 编号 | 严重程度 | 问题描述 |
|------|---------|---------|
| Q-01 | 🔴 严重 | **重复定义**：`AnalysisContext` 和 `RoslynAnalyzer` 在 `RoslynBasic/RoslynBasic.cs` 和 `RoslynRelated.cs` 中重复 |
| Q-02 | 🟡 中等 | **大量注释代码**：`CharacterCalculate_Script.cs` 末尾约 400 行被注释的旧版代码 |
| Q-03 | 🟡 中等 | **中文注释乱码**：部分 `#region` 注释显示为乱码 |
| Q-04 | 🟡 中等 | **硬编码魔法值**：阈值、权重等散落在各处，未集中管理 |
| Q-05 | 🟢 轻微 | **XML 文档缺失**：部分公共 API 缺少文档注释 |
| Q-06 | 🟢 轻微 | **未使用的 using**：部分文件包含未使用的命名空间引用 |

### 2.3 架构设计问题

| 编号 | 严重程度 | 问题描述 |
|------|---------|---------|
| A-01 | 🔴 严重 | **职责边界模糊**：单个文件混合多个关注点（如 `Merge.cs` 同时包含合并逻辑、质量度量、数据类型） |
| A-02 | 🟡 中等 | **缺少模块分层**：没有清晰的基础设施层、业务逻辑层、表现层分离 |
| A-03 | 🟡 中等 | **循环依赖风险**：`AnalysisContext` 与 `CodeRemovalService` 之间存在双向引用 |
| A-04 | 🟢 轻微 | **缺少接口抽象**：模块间直接依赖具体实现，不利于测试和扩展 |

### 2.4 可维护性问题

| 编号 | 严重程度 | 问题描述 |
|------|---------|---------|
| M-01 | 🟡 中等 | **缺少单元测试**：核心算法无测试覆盖 |
| M-02 | 🟡 中等 | **异常处理不一致**：部分方法吞异常（空 catch），部分抛出 |
| M-03 | 🟢 轻微 | **日志系统不完善**：`DiagnosticReporter` 方法体为空 |
| M-04 | 🟢 轻微 | **缓存策略不统一**：多处独立实现缓存，无统一缓存管理 |

## 3. 优化目标

### 3.1 核心目标

1. **清晰的项目结构**：建立模块化、分层清晰的项目组织
2. **消除重复代码**：合并重复定义，减少维护成本
3. **合理的文件大小**：拆分超大文件，每个文件聚焦单一职责
4. **统一的命名规范**：文件、命名空间、类名统一规范
5. **提升可维护性**：完善文档、添加测试、统一异常处理

### 3.2 非目标

- ❌ 不改变现有功能行为
- ❌ 不引入新的第三方依赖
- ❌ 不进行大规模 API 重设计（仅做结构优化）

### 4.4 阶段四：质量提升

#### 4.4.1 完善 XML 文档注释

为所有公共 API 添加标准 XML 文档注释：

```csharp
/// <summary>
/// 从代码字符串中提取增强的代码元素列表。
/// </summary>
/// <param name="code">要分析的 C# 源代码</param>
/// <returns>提取的代码元素列表</returns>
/// <exception cref="ArgumentNullException">当 code 为 null 时抛出</exception>
public static List<EnhancedCodeElement> Extract(string code)
```

#### 4.4.2 统一异常处理

- 移除空的 `catch { }` 块，至少记录日志
- 为公共 API 添加参数验证（使用 `Guard` 类）
- 定义自定义异常类型

#### 4.4.3 添加单元测试

优先为以下核心模块添加测试：

1. **语法分析**：`SyntaxElementExtractor.Extract()`
2. **聚类算法**：各聚类算法的正确性
3. **合并引擎**：各合并策略的正确性
4. **相似度计算**：各距离/相似度算法
