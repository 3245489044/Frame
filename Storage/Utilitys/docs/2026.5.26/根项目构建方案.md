## 二、方案设计

### 方案一：创建根 Solution 文件（推荐）

在根目录创建一个 `Utilitys.sln`，引用所有项目。这是最标准、最推荐的方式。

**优点：**
- 标准做法，VS/Rider 原生支持
- 可以按文件夹组织项目
- 不影响现有项目结构
- 支持 `dotnet build` 一键构建所有项目

**缺点：**
- 需要手动维护 .sln 文件
- CodeAnalyzer 已有自己的 .sln，需要决定是否合并

### 方案二：创建根 csproj 聚合项目

在根目录创建一个 `Utilitys.csproj`，通过 ProjectReference 引用所有项目。

**优点：**
- 纯 csproj 方式，无需 .sln
- 可以用 `dotnet build` 直接构建
- 可以添加全局的 Target/Task

**缺点：**
- 聚合项目本身不包含代码，概念上有点奇怪
- 如果某个项目是 Exe 类型，聚合项目也需要指定 OutputType
- 引用关系需要手动维护

### 方案三：创建根 Directory.Build.props

在根目录创建 `Directory.Build.props`，统一所有项目的构建配置。

**优点：**
- 不影响现有项目结构
- 可以统一版本号、包引用等
- 配合 .sln 或 csproj 使用效果更好

## 三、推荐方案：根 Solution + Directory.Build.props

### 3.1 创建 `Utilitys.sln`

```bash
dotnet new sln -n Utilitys
```

然后添加所有项目：

```bash
# 主要项目
dotnet sln Utilitys.sln add RoslynMethod/RoslynMethod.csproj
dotnet sln Utilitys.sln add Mathematics/RoslynMethod.Mathematics.csproj
dotnet sln Utilitys.sln add Agent/Agent.csproj
dotnet sln Utilitys.sln add CodePathExplorer/CodePathExplorer.csproj
dotnet sln Utilitys.sln add CodeRLFramework/CodeRLFramework.csproj

# CodeAnalyzer 项目（如果决定合并）
dotnet sln Utilitys.sln add CodeAnalyzer/src/CodeAnalyzer.Core/CodeAnalyzer.Core.csproj
dotnet sln Utilitys.sln add CodeAnalyzer/src/CodeAnalyzer.Analysis/CodeAnalyzer.Analysis.csproj
dotnet sln Utilitys.sln add CodeAnalyzer/src/CodeAnalyzer.Prompt/CodeAnalyzer.Prompt.csproj
dotnet sln Utilitys.sln add CodeAnalyzer/src/CodeAnalyzer.Optimization/CodeAnalyzer.Optimization.csproj
dotnet sln Utilitys.sln add CodeAnalyzer/src/CodeAnalyzer.Demo/CodeAnalyzer.Demo.csproj

# 测试项目
dotnet sln Utilitys.sln add TestMent/RoslynMethod.Tests/RoslynMethod.Tests.csproj
dotnet sln Utilitys.sln add TestMent/Agent.Tests/Agent.Tests.csproj
dotnet sln Utilitys.sln add TestMent/CodePathExplorer.Tests/CodePathExplorer.Tests.csproj
dotnet sln Utilitys.sln add CodeRLFramework/Tests/CodeRLFramework.Tests.csproj
```

### 3.2 创建 `Directory.Build.props`

```xml
<Project>
  <PropertyGroup>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
    <LangVersion>latest</LangVersion>
  </PropertyGroup>
</Project>
```

### 3.3 创建 `Directory.Build.targets`（可选）

用于添加全局的构建后任务，比如复制输出文件等。

## 四、替代方案：根 csproj 聚合项目

如果不想用 .sln，也可以创建 `Utilitys.csproj`：

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>

  <!-- 主要项目 -->
  <ItemGroup>
    <ProjectReference Include="RoslynMethod\RoslynMethod.csproj" />
    <ProjectReference Include="Mathematics\RoslynMethod.Mathematics.csproj" />
    <ProjectReference Include="Agent\Agent.csproj" />
    <ProjectReference Include="CodePathExplorer\CodePathExplorer.csproj" />
    <ProjectReference Include="CodeRLFramework\CodeRLFramework.csproj" />
  </ItemGroup>

  <!-- CodeAnalyzer 项目 -->
  <ItemGroup>
    <ProjectReference Include="CodeAnalyzer\src\CodeAnalyzer.Core\CodeAnalyzer.Core.csproj" />
    <ProjectReference Include="CodeAnalyzer\src\CodeAnalyzer.Analysis\CodeAnalyzer.Analysis.csproj" />
    <ProjectReference Include="CodeAnalyzer\src\CodeAnalyzer.Prompt\CodeAnalyzer.Prompt.csproj" />
    <ProjectReference Include="CodeAnalyzer\src\CodeAnalyzer.Optimization\CodeAnalyzer.Optimization.csproj" />
    <ProjectReference Include="CodeAnalyzer\src\CodeAnalyzer.Demo\CodeAnalyzer.Demo.csproj" />
  </ItemGroup>

  <!-- 测试项目 -->
  <ItemGroup>
    <ProjectReference Include="TestMent\RoslynMethod.Tests\RoslynMethod.Tests.csproj" />
    <ProjectReference Include="TestMent\Agent.Tests\Agent.Tests.csproj" />
    <ProjectReference Include="TestMent\CodePathExplorer.Tests\CodePathExplorer.Tests.csproj" />
    <ProjectReference Include="CodeRLFramework\Tests\CodeRLFramework.Tests.csproj" />
  </ItemGroup>

</Project>
```

## 五、注意事项

### 5.1 TargetFramework 不一致问题

当前项目使用了不同的 TargetFramework：
- `net10.0`：Mathematics, Agent, Agent.Tests
- `net10.0-windows`：RoslynMethod, CodePathExplorer, CodeRLFramework, CodeAnalyzer 系列, 其他测试项目

如果创建根 csproj，需要选择一个兼容的 TargetFramework。建议使用 `net10.0`，因为 `net10.0-windows` 是 `net10.0` 的超集。

### 5.2 CodeAnalyzer 已有独立 .sln

CodeAnalyzer 有自己的 `CodeAnalyzer.sln`。有两种处理方式：
1. **合并到根 .sln**：将所有 CodeAnalyzer 项目添加到根 .sln，保留原有 .sln 作为子集
2. **保持独立**：根 .sln 不包含 CodeAnalyzer，需要单独构建

### 5.3 测试项目的处理

测试项目（.Tests.csproj）通常不需要被其他项目引用，但可以添加到 .sln 中方便统一运行测试。

## 六、推荐执行步骤

1. **创建 `Directory.Build.props`** - 统一构建配置
2. **创建 `Utilitys.sln`** - 使用 `dotnet new sln` + `dotnet sln add`
3. **验证构建** - `dotnet build Utilitys.sln`
4. **可选：创建 `Utilitys.csproj`** - 如果需要聚合项目的方式

## 七、总结

| 方案 | 复杂度 | 推荐度 | 说明 |
|-----|-------|-------|------|
| 根 .sln | 低 | ⭐⭐⭐⭐⭐ | 标准做法，推荐 |
| 根 csproj | 中 | ⭐⭐⭐⭐ | 适合不需要 IDE 的场景 |
| Directory.Build.props | 低 | ⭐⭐⭐⭐ | 配合 .sln 使用 |
| 根 .sln + Directory.Build.props | 中 | ⭐⭐⭐⭐⭐ | 最佳实践组合 |
