# FrameManage 框架与架构

## 1. 框架概述

FrameManage 是一个基于**工作流(W)-代码(C)-数据(D)-Prompt(P)**四维数学映射系统的模块化工作流管理和执行框架。它支持跨框架的工作流编排、数据处理和模块化扩展，提供了灵活的元工作流管理机制，能够统一管理来自不同框架的工作流，实现工作流的链式连接和数据处理。

### 1.1 核心特性
- 基于四维数学映射模型的智能工作流管理
- 跨框架工作流编排和执行
- 灵活的元工作流管理机制
- 模块化扩展和集成能力
- 强大的数据处理和转换能力
- 支持工作流的链式连接和数据传递

## 2. 核心概念

### 2.1 四维映射模型

FrameManage 采用四维数学映射模型，构建了一个统一的工作流补全系统：

| 维度 | 数学符号 | 数学表示 | 实际含义 |
|------------|-------------------|--------------------------|---------------|
| 工作流  | W | 有向图  G = (V, E) | 业务流程的执行逻辑和节点关系 |
| 代码    | C | 函数集合  C = \{ f_1, f_2, ..., f_n \} | 工作流节点的具体功能实现 |
| 数据    | D | 模式集合  D = \{ (s_i, t_i, c_i) \}    | 工作流和代码操作的数据结构 |
| Prompt | P | 自然语言集合  P = \{ p_1, p_2, ..., p_k \} | 工作流的自然语言描述 |

### 2.2 补全映射函数

框架支持从任意维度到其他维度的补全，通过以下映射函数实现：

| 补全方向 | 数学表达式 | 含义 |
|----------|------------|------|
| 工作流→其他 |  f(W) → (C, D, P)  | 从工作流补全代码、数据和Prompt |
| 代码→其他 |  g(C) → (W, D, P)  | 从代码补全工作流、数据和Prompt |
| 数据→其他 |  h(D) → (W, C, P)  | 从数据补全工作流、代码和Prompt |
| Prompt→其他 |  k(P) → (W, C, D)  | 从Prompt补全工作流、代码和数据 |

## 3. 技术架构

### 3.1 分层架构

FrameManage 采用分层架构设计，清晰分离不同职责的组件：

```
┌─────────────────────────────────────────┐
│         Application Layer           │
│         (应用层)                  │
└─────────────────────────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│      Orchestration Layer            │
│      (编排层)                     │
└─────────────────────────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│      Framework Adapter Layer        │
│      (框架适配层)                 │
└─────────────────────────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│      External Frameworks           │
│      (外部框架)                   │
└─────────────────────────────────────────┘
```

- **应用层**：提供用户接口和应用程序入口，处理用户请求和配置
- **编排层**：负责工作流的编排和执行，管理工作流的生命周期
- **框架适配层**：适配不同的外部框架，提供统一的接口
- **外部框架**：集成各种第三方工作流框架和工具

## 4. 通用框架组件

### 4.1 事件驱动框架

#### 4.1.1 概述

事件驱动框架提供了一个基于事件的引用管理系统，支持资源和关系的变更通知，以及灵活的订阅机制。

#### 4.1.2 核心组件

- `IEventDrivenReferenceManager`：事件驱动引用管理器接口
- `ObservableReferenceManager`：事件驱动引用管理器实现
- `EventSubscription`：事件订阅类
- `EventDrivenReferenceManagerFactory`：事件驱动引用管理器工厂

#### 4.1.3 使用示例

```csharp
// 创建事件驱动引用管理器
var referenceManager = EventDrivenReferenceManagerFactory.Create();

// 订阅资源变更事件
var subscription = referenceManager.SubscribeToResource("user", args =>
{
    Console.WriteLine($"资源变更: {args.Resource.Id}, 类型: {args.ChangeType}");
});

// 添加资源
var resource = new ResourceIdentifier { ResourceType = "user", Id = "123" };
await referenceManager.AddResourceAsync(resource, new Dictionary<string, object> { { "name", "John" } });

// 释放订阅
subscription.Dispose();
```

### 4.2 存储框架

#### 4.2.1 概述

存储框架提供了一个通用的工作流存储接口，支持不同类型的存储实现，包括文件系统存储和图数据库存储。

#### 4.2.2 核心组件

- `IWorkflowStorage<T>`：工作流存储接口
- `GenericWorkflowStorage<T>`：通用工作流存储实现
- `GraphDatabaseStorage<T>`：基于图数据库的工作流存储实现
- `StorageKeyBuilder`：存储键构建器

#### 4.2.3 使用示例

```csharp
// 创建文件系统存储
var storage = new GenericWorkflowStorage<MyWorkflow>("C:\\Workflows");

// 存储工作流
await storage.StoreAsync("workflow1", new MyWorkflow { Id = "workflow1", Name = "Test Workflow" });

// 检索工作流
var workflow = await storage.RetrieveAsync("workflow1");

// 删除工作流
await storage.DeleteAsync("workflow1");

// 检查工作流是否存在
var exists = await storage.ExistsAsync("workflow1");

// 获取所有工作流ID
var workflowIds = await storage.GetAllWorkflowIdsAsync();
```

### 4.3 工作流管理框架

#### 4.3.1 概述

工作流管理框架提供了一个通用的工作流管理系统，支持工作流的注册、更新、删除和查询，以及工作流执行验证。

#### 4.3.2 核心组件

- `WorkflowManager<T>`：工作流管理器
- `WorkflowExecutionValidator`：工作流执行验证器
- `UniversalFrameworkIntegration`：通用框架集成

#### 4.3.3 使用示例

```csharp
// 创建工作流存储
var storage = new GenericWorkflowStorage<MyWorkflow>("C:\\Workflows");

// 创建工作流管理器
var workflowManager = new WorkflowManager<MyWorkflow>(storage);

// 注册或更新工作流
await workflowManager.RegisterOrUpdateWorkflowAsync("workflow1", new MyWorkflow { Id = "workflow1", Name = "Test Workflow" });

// 获取工作流
var workflow = await workflowManager.GetWorkflowAsync("workflow1");

// 删除工作流
await workflowManager.RemoveWorkflowAsync("workflow1");

// 检查工作流是否存在
var exists = await workflowManager.WorkflowExistsAsync("workflow1");

// 获取所有工作流ID
var workflowIds = await workflowManager.GetAllWorkflowIdsAsync();
```

### 4.4 UI-AI映射框架

#### 4.4.1 概述

UI-AI映射框架提供了UI操作和AI操作之间的映射功能，支持基于图数据库的逻辑执行，以及分支管理和验证。

#### 4.4.2 核心组件

- `UIAIMappingFramework`：UI-AI映射框架核心类
- `UIBranchGraph`：UI分支图
- `UIBranchNode`：UI分支节点
- `UIBranchEdge`：UI分支边
- `UIAction`：UI操作
- `AIAction`：AI操作
- `UIBranchManager`：UI分支管理器

#### 4.4.3 使用示例

```csharp
// 创建分支存储
var branchStorage = new GenericWorkflowStorage<UIBranchGraph>("C:\\Branches");

// 创建UI-AI映射框架
var mappingFramework = new UIAIMappingFramework(branchStorage);

// 初始化框架
await mappingFramework.InitializeAsync();

// 创建分支图
var branchGraph = new UIBranchGraph
{
    BranchId = "branch1",
    Name = "Test Branch",
    Description = "Test UI branch",
    Nodes = new List<UIBranchNode>
    {
        new UIBranchNode { NodeId = "node1", Type = NodeType.Start, Name = "Start" },
        new UIBranchNode { NodeId = "node2", Type = NodeType.Action, Name = "Action" },
        new UIBranchNode { NodeId = "node3", Type = NodeType.End, Name = "End" }
    },
    Edges = new List<UIBranchEdge>
    {
        new UIBranchEdge { EdgeId = "edge1", SourceNodeId = "node1", TargetNodeId = "node2", Type = EdgeType.Normal },
        new UIBranchEdge { EdgeId = "edge2", SourceNodeId = "node2", TargetNodeId = "node3", Type = EdgeType.Normal }
    }
};

// 注册分支
await mappingFramework.RegisterUIBranchAsync("branch1", branchGraph);

// 映射UI操作到AI操作
var uiAction = new UIAction { ActionId = "ui1", ActionType = "click", Parameters = new Dictionary<string, object> { { "element", "button" } } };
var aiAction = await mappingFramework.MapUIActionToAIActionAsync(uiAction);

// 执行基于图数据库逻辑的操作
var executionResult = await mappingFramework.ExecuteWithGraphLogicAsync(uiAction, true);
```

### 4.5 通用数据模型

#### 4.5.1 概述

通用数据模型提供了一些可以被多个框架共享使用的数据模型类，包括基础模型类、通用结果类、分页结果类和分页请求参数类。

#### 4.5.2 核心组件

- `Result<T>`：通用结果类
- `PagedResult<T>`：分页结果类
- `PaginationRequest`：分页请求参数

// 使用基础模型
public class User : BaseModel
{
    public string Name { get; set; }

var successResult = Result<User>.CreateSuccess(new User { Name = "John", Email = "john@example.com" });

### 4.6 依赖注入框架

#### 4.6.1 概述

依赖注入框架提供了一个依赖注入容器，支持服务的注册和解析，以及服务定位器功能。

#### 4.6.2 核心组件

- `DependencyContainer`：依赖注入容器
- `DependencyInjectionExtensions`：依赖注入扩展
- `ServiceLocator`：服务定位器

#### 4.6.3 使用示例

```csharp
// 创建依赖注入容器
var container = new DependencyContainer();

// 注册服务
container.Register<IWorkflowStorage<MyWorkflow>, GenericWorkflowStorage<MyWorkflow>>()
         .Register<WorkflowManager<MyWorkflow>>();

// 构建服务提供程序
var provider = container.Build();

// 解析服务
var workflowManager = container.Resolve<WorkflowManager<MyWorkflow>>();

// 使用依赖注入扩展
var services = new ServiceCollection();
services.AddFrameworkServices()
        .AddEventDrivenServices()
        .AddStorageServices("C:\\Workflows")
        .AddWorkflowServices()
        .AddUIAIServices();

// 初始化服务定位器
var serviceProvider = services.BuildServiceProvider();
ServiceLocator.Initialize(serviceProvider);

// 使用服务定位器
var referenceManager = ServiceLocator.GetService<IEventDrivenReferenceManager>();
```

#### 4.7.1 概述

// 初始化框架
await UniversalFrameworkIntegration.InitializeAsync();

### 4.8 高级图数据库解析框架

#### 4.8.1 概述

高级图数据库解析框架提供了一个灵活的配置系统，允许用户根据不同的需求自定义图数据库的解析和UI展示。它支持多种布局类型、节点和边的自定义配置，以及基于规则的过滤功能。

#### 4.8.2 核心组件

- `IAdvancedGraphDatabaseParser`：高级图数据库解析器接口
- `AdvancedGraphDatabaseParser`：高级图数据库解析器实现
- `AdvancedGraphDatabaseService`：高级图数据库服务
- `MetaReferenceConfiguration`：元引用配置类型

#### 4.8.3 配置系统

框架使用 `MetaReferenceConfiguration` 定义解析和展示规则：

- **引用架构配置**：定义节点类型、边类型和过滤规则
- **UI布局配置**：定义布局类型、画布设置、节点和边的显示属性

#### 4.8.4 布局类型

支持四种布局类型：
- `ForceDirected`：力导向布局（默认）
- `Circular`：环形布局
- `Tree`：树形布局
- `Hierarchical`：层次布局

#### 4.8.5 使用示例

```csharp
// 创建高级图数据库服务
var service = AdvancedGraphDatabaseServiceFactory.Create();

// 解析图数据库
var result = await service.ParseGraphAsync("default", "main");

// 解析特定工作流的引用
var workflowResult = await service.ParseWorkflowReferencesAsync(
    "meta_workflow", 
    "module_project_creator", 
    "meta_workflow"
);

// 注册自定义配置
var customConfig = new MetaReferenceConfiguration
{
    Name = "custom",
    Description = "自定义配置",
    Schema = new ReferenceSchemaConfiguration
    {
        NodeTypes = new List<NodeTypeConfiguration>
        {
            new NodeTypeConfiguration { Type = "workflow", DisplayName = "工作流", Color = "#4CAF50", Visible = true }
        },
        EdgeTypes = new List<EdgeTypeConfiguration>
        {
            new EdgeTypeConfiguration { Type = "depends_on", DisplayName = "依赖", Color = "#666666", Visible = true }
        }
    },
    UILayout = new UILayoutConfiguration
    {
        LayoutType = LayoutType.Circular,
        Canvas = new CanvasConfiguration { Width = 1000, Height = 800 }
    }
};

service.RegisterConfiguration(customConfig);
```

### 4.9 引用关系处理机制

#### 4.9.1 概述

引用关系处理机制是 FrameManage 的核心功能之一，它提供了一套完整的引用管理系统，支持工作流、模块和资源之间的引用关系管理、缓存和事件通知。

#### 4.9.2 核心组件

- **IReferenceManager**：基本引用管理接口，提供创建、删除、查询引用的方法
- **IWorkflowReferenceManager**：工作流专用引用管理接口，处理工作流相关的引用
- **IIntegratedReferenceManager**：集成引用管理接口，提供更高级的引用操作
- **IReferenceProcessManager**：引用处理管理器，处理批量操作和缓存
- **ReferenceManager**：实现基本引用管理功能
- **WorkflowReferenceManager**：实现工作流引用管理，支持事件通知
- **ReferenceProcessManager**：处理批量引用操作，提供缓存机制
- **AdvancedGraphDatabaseParser**：将引用关系解析为图形结构

#### 4.9.3 引用关系处理流程

1. **引用注册**：当工作流创建或更新时，通过 `RegisterWorkflowReferencesAsync` 方法注册引用关系
2. **引用清除**：当工作流删除时，通过 `ClearWorkflowReferencesAsync` 方法清除引用关系
3. **引用查询**：通过 `GetWorkflowReferencesAsync` 方法获取工作流的引用关系
4. **引用缓存**：为提高性能，系统实现了引用缓存机制，缓存过期时间为5分钟
5. **事件通知**：当引用关系发生变化时，通过事件总线发布通知
6. **图数据库解析**：通过 `AdvancedGraphDatabaseParser` 将引用关系解析为图形结构

#### 4.9.4 引用关系数据结构

- **Reference**：表示一个引用关系，包含源、目标、关系类型等信息
- **ResourceIdentifier**：资源标识符，唯一标识一个资源
- **GraphParseResult**：图解析结果，包含节点和边
- **GraphParseNode**：图节点，表示一个资源
- **GraphParseEdge**：图边，表示一个引用关系
- **ReferenceConfiguration**：引用配置，定义解析和展示规则
- **MetaReferenceConfiguration**：元引用配置，包含 schema 和 UI 布局
- **GraphSchemaConfiguration**：图 schema 配置，定义节点类型、边类型和过滤规则
- **GraphLayoutConfiguration**：图布局配置，定义布局类型和画布设置

#### 4.9.5 使用示例

**工作流引用管理**

```csharp
// 创建引用管理器
var referenceManager = new WorkflowReferenceManager(universalReferenceManager, eventBus);

// 注册工作流引用
await referenceManager.RegisterWorkflowReferencesAsync(workflowId, "MetaWorkflow", workflowData);

// 获取工作流引用
var references = await referenceManager.GetWorkflowReferencesAsync(workflowId, "MetaWorkflow");

// 清除工作流引用
await referenceManager.ClearWorkflowReferencesAsync(workflowId, "MetaWorkflow");
```

**批量引用处理**

```csharp
// 创建引用处理管理器
var processManager = new ReferenceProcessManager(workflowReferenceManager, universalReferenceManager);

// 执行批量操作
var operations = new List<ReferenceOperation>
{
    new ReferenceOperation
    {
        WorkflowId = "workflow1",
        WorkflowType = "MetaWorkflow",
        OperationType = ReferenceOperationType.Register,
        WorkflowData = workflowData
    }
};

var result = await processManager.ExecuteBatchAsync(operations);
```

**图数据库解析**

```csharp
// 创建图数据库解析器
var parser = new AdvancedGraphDatabaseParser(universalReferenceManager);

// 解析工作流引用
var result = await parser.ParseWorkflowReferencesAsync("default", workflowId, "MetaWorkflow");

// 解析整个图
var graphResult = await parser.ParseGraphAsync("default", "main");
```
