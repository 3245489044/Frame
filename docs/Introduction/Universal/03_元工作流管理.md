# 元工作流管理

## 1. 元工作流概述

元工作流是 FrameManage 框架中的核心概念，它提供了一种灵活的方式来定义、管理和执行由多个子工作流组成的复杂工作流程。元工作流允许用户通过组合不同框架的工作流来构建更高级的业务流程，实现跨框架的工作流协同。

### 1.1 核心特性
- 支持跨框架工作流编排
- 基于拓扑排序的序列号自动计算
- 通过序列号确定节点依赖关系和执行顺序
- 灵活的数据处理配置
- 支持循环依赖检测
- 模块化项目创建能力
- 引用关系管理和差值计算
- 多维补全功能
- 执行状态监控和性能分析

## 2. 核心组件

### 2.1 元工作流定义

元工作流的核心定义在 `MetaWorkflowDefinition` 类中，包含以下主要属性：

| 属性 | 类型 | 描述 |
|------|------|------|
| `Id` | `string` | 元工作流ID |
| `Name` | `string` | 元工作流名称 |
| `Description` | `string` | 元工作流描述 |
| `Nodes` | `List<MetaWorkflowNode>` | 工作流节点列表 |
| `DataProcessingConfig` | `DataProcessingConfig` | 数据处理配置 |
| `Parameters` | `Dictionary<string, object>` | 元工作流参数 |

### 2.2 元工作流节点

每个元工作流由多个节点组成，节点定义在 `MetaWorkflowNode` 类中：

| 属性 | 类型 | 描述 |
|------|------|------|
| `Id` | `string` | 节点ID |
| `Name` | `string` | 节点名称 |
| `FrameworkName` | `string` | 框架名称 |
| `WorkflowId` | `string` | 工作流ID |
| `Parameters` | `Dictionary<string, object>` | 节点参数 |
| `Sequence` | `int` | 执行序列号（通过拓扑排序自动计算） |
| `PreviousSequences` | `List<int>` | 前置依赖序列号列表（用于拓扑排序计算） |
| `PreviousNodeIds` | `List<string>` | 前置依赖节点ID列表（用于工作流执行顺序） |

### 2.3 数据处理配置

元工作流支持在不同阶段进行数据处理，配置定义在 `DataProcessingConfig` 类中：

| 属性 | 类型 | 描述 |
|------|------|------|
| `EnableDataProcessing` | `bool` | 是否启用数据处理 |
| `Position` | `DataProcessingPosition` | 数据处理位置 |
| `ProcessorType` | `string` | 数据处理器类型 |
| `ProcessorParameters` | `Dictionary<string, object>` | 数据处理器参数 |

数据处理位置枚举 `DataProcessingPosition` 包括：
- `BeforeWorkflow` - 工作流开始前
- `AfterWorkflow` - 工作流结束后
- `BeforeNode` - 每个节点执行前
- `AfterNode` - 每个节点执行后

## 4. 元工作流管理器

`MetaWorkflowManager` 类是元工作流的核心管理类，提供了以下主要功能：

### 4.1 元工作流管理

- **注册元工作流**：`RegisterMetaWorkflowAsync` - 将元工作流定义存储到数据存储中
- **获取元工作流**：`GetMetaWorkflowAsync` - 从数据存储中检索元工作流定义
- **获取所有元工作流**：`GetAllMetaWorkflowsAsync` - 获取所有已注册的元工作流ID列表

### 4.2 元工作流执行

- **执行元工作流**：`ExecuteMetaWorkflowAsync` - 执行指定的元工作流，处理数据并按顺序执行节点

执行过程包括：
1. 检查并执行工作流开始前的数据处理
2. 构建节点索引
3. 计算节点执行序列（基于拓扑排序）
4. 按序列执行每个节点，处理节点前后的数据
5. 检查并执行工作流结束后的数据处理

### 4.3 模块项目创建

- **创建模块项目**：`CreateModuleProjectAsync` - 创建标准Visual Studio模块项目
- **创建并注册模块项目创建元工作流**：`CreateAndRegisterCompletionMetaWorkflowAsync` - 创建并注册用于模块项目创建的元工作流

### 4.4 引用管理

- **计算引用差值**：`CalculateReferenceDiffAsync` - 比较模块的代码和工作流引用差异
- **测试引用差值计算**：`TestReferenceDiffCalculationAsync` - 测试引用差值计算功能
- **同步模块引用关系**：`SyncModuleReferencesToGraphAsync` - 将模块引用关系同步到图数据库
- **清除模块引用关系**：`ClearModuleReferencesAsync` - 清除模块的引用关系

## 5. 元工作流管理器使用


## 6. 元工作流执行流程

1. **初始化**：加载元工作流定义
2. **数据处理**：执行工作流开始前的数据处理（如果配置）
3. **构建节点索引**：为所有节点建立索引
4. **计算执行序列**：基于拓扑排序计算节点执行顺序
5. **执行节点**：按序列执行每个节点，包括：
   - 执行节点前的数据处理（如果配置）
   - 调用框架适配器执行具体工作流
   - 执行节点后的数据处理（如果配置）
6. **数据处理**：执行工作流结束后的数据处理（如果配置）
7. **返回结果**：返回最终执行结果

## 7. 节点逻辑关系

节点逻辑关系是元工作流的核心机制，定义了节点之间的依赖关系和执行顺序。通过合理配置节点依赖关系，可以构建复杂的工作流执行路径。

### 7.1 节点依赖关系结构

每个元工作流节点包含以下与逻辑关系相关的属性：

```csharp
public class MetaWorkflowNode
{
    public string Id { get; set; } = string.Empty;
    public string Name { get; set; } = string.Empty;
    public string FrameworkName { get; set; } = string.Empty;
    public string WorkflowId { get; set; } = string.Empty;
    public Dictionary<string, object> Parameters { get; set; } = new Dictionary<string, object>();
    
    // 执行序列号（通过拓扑排序自动计算）
    public int Sequence { get; set; }
    
    // 前置依赖序列号列表（用于拓扑排序计算）
    public List<int> PreviousSequences { get; set; } = new List<int>();
    
    // 前置依赖节点ID列表（用于工作流执行顺序）
    public List<string> PreviousNodeIds { get; set; } = new List<string>();
}
```

**逻辑关系属性说明：**

| 属性 | 类型 | 描述 | 自动/手动 |
|------|------|------|-----------|
| `Id` | string | 节点唯一标识符 | 手动设置 |
| `Sequence` | int | 执行序列号（从1开始） | 自动计算 |
| `PreviousSequences` | List<int> | 前置依赖节点的序列号列表 | 自动计算 |
| `PreviousNodeIds` | List<string> | 前置依赖节点的ID列表 | 手动设置 |

### 7.2 节点依赖关系类型

元工作流支持多种节点依赖关系类型：

| 依赖类型 | 描述 | 使用场景 | 示例 |
|----------|------|----------|------|
| **顺序依赖** | 节点A必须在节点B之前执行 | 数据处理流水线 | 数据提取 → 数据转换 → 数据加载 |
| **并行依赖** | 多个节点可以并行执行 | 独立任务处理 | 多个数据源同时采集 |
| **条件依赖** | 基于条件决定是否执行 | 分支处理逻辑 | 成功分支和失败分支 |
| **聚合依赖** | 多个节点完成后才能执行 | 汇总处理 | 多个数据处理完成后进行汇总 |

### 7.3 拓扑排序算法

元工作流使用拓扑排序算法来确定节点的执行顺序，确保节点按照依赖关系正确执行。

**拓扑排序实现：**

```csharp
private void CalculateNodeSequences(List<MetaWorkflowNode> nodes)
{
    var nodeMap = nodes.ToDictionary(node => node.Id);
    var visited = new HashSet<string>();
    var temp = new HashSet<string>();
    var sequence = 1;

    void Visit(string nodeId)
    {
        if (temp.Contains(nodeId))
            throw new InvalidOperationException($"检测到循环依赖: {nodeId}");

        if (visited.Contains(nodeId))
            return;

        temp.Add(nodeId);

        var node = nodeMap[nodeId];
        foreach (var prevNodeId in node.PreviousNodeIds)
        {
            if (nodeMap.TryGetValue(prevNodeId, out var prevNode))
            {
                Visit(prevNodeId);
                node.PreviousSequences.Add(prevNode.Sequence);
            }
        }

        temp.Remove(nodeId);
        visited.Add(nodeId);
        node.Sequence = sequence++;
    }

    foreach (var node in nodes)
    {
        if (!visited.Contains(node.Id))
            Visit(node.Id);
    }
}
```

**拓扑排序特点：**

1. **深度优先遍历**：使用DFS算法遍历节点依赖图
2. **循环依赖检测**：通过临时集合检测循环依赖
3. **序列号分配**：按照遍历顺序为节点分配序列号
4. **依赖关系记录**：记录每个节点的前置依赖序列号

### 7.4 循环依赖检测

循环依赖会导致工作流无法正常执行，系统会在拓扑排序过程中自动检测循环依赖。

**循环依赖检测机制：**

```csharp
if (temp.Contains(nodeId))
    throw new InvalidOperationException($"检测到循环依赖: {nodeId}");
```

**循环依赖示例：**

```csharp
// 错误示例：循环依赖
var nodes = new List<MetaWorkflowNode>
{
    new MetaWorkflowNode { Id = "node1", PreviousNodeIds = new List<string> { "node3" } },
    new MetaWorkflowNode { Id = "node2", PreviousNodeIds = new List<string> { "node1" } },
    new MetaWorkflowNode { Id = "node3", PreviousNodeIds = new List<string> { "node2" } }
};
// node1 → node3 → node2 → node1 (循环依赖)
```

**正确的依赖关系：**

```csharp
// 正确示例：无循环依赖
var nodes = new List<MetaWorkflowNode>
{
    new MetaWorkflowNode { Id = "node1", PreviousNodeIds = new List<string>() },
    new MetaWorkflowNode { Id = "node2", PreviousNodeIds = new List<string> { "node1" } },
    new MetaWorkflowNode { Id = "node3", PreviousNodeIds = new List<string> { "node2" } }
};
// node1 → node2 → node3 (正确顺序)
```

### 7.5 节点序列号说明

节点的 `Sequence` 属性表示该节点在执行顺序中的位置（从1开始），由系统根据 `PreviousNodeIds` 通过拓扑排序自动计算。

**序列号计算规则：**

1. **无依赖节点**：序列号为1
2. **单依赖节点**：序列号为依赖节点序列号+1
3. **多依赖节点**：序列号为所有依赖节点序列号的最大值+1
4. **并行节点**：相同依赖的节点具有相同的序列号

**序列号示例：**

```csharp
var nodes = new List<MetaWorkflowNode>
{
    new MetaWorkflowNode { Id = "start", PreviousNodeIds = new List<string>() },           // Sequence: 1
    new MetaWorkflowNode { Id = "process1", PreviousNodeIds = new List<string> { "start" } }, // Sequence: 2
    new MetaWorkflowNode { Id = "process2", PreviousNodeIds = new List<string> { "start" } }, // Sequence: 2
    new MetaWorkflowNode { Id = "merge", PreviousNodeIds = new List<string> { "process1", "process2" } }, // Sequence: 3
    new MetaWorkflowNode { Id = "end", PreviousNodeIds = new List<string> { "merge" } }    // Sequence: 4
};
```

**执行顺序：**
```
1. start (Sequence: 1)
   ↓
2. process1 (Sequence: 2) ←──┐
   ↓                        │
3. process2 (Sequence: 2)   │ (并行执行)
   ↓                        │
4. merge (Sequence: 3) ─────┘
   ↓
5. end (Sequence: 4)
```

### 7.7 插入新节点

在现有工作流中插入新节点时，需要正确设置依赖关系。

**插入节点示例：**

```csharp

var newNode = new MetaWorkflowNode

    FrameworkName = "SomeFramework",
```

### 7.8 依赖关系验证

在注册元工作流时，系统会自动验证节点依赖关系的有效性：

**验证规则：**

1. **节点ID唯一性**：所有节点ID必须唯一
2. **依赖节点存在性**：所有依赖的节点ID必须存在
3. **无循环依赖**：不能存在循环依赖关系
4. **连通性检查**：确保所有节点都是可达的

**验证失败处理：**

```csharp
try
{
    await metaWorkflowManager.RegisterMetaWorkflowAsync(metaWorkflow.Id, metaWorkflow);
}
catch (InvalidOperationException ex)
{
    if (ex.Message.Contains("循环依赖"))
    {
        Console.WriteLine("错误：检测到循环依赖，请检查节点依赖关系");
    }
    else
    {
        Console.WriteLine($"注册失败：{ex.Message}");
    }
}
```

### 7.9 依赖关系最佳实践

1. **设计原则**：
   - 保持依赖关系简单清晰
   - 避免过度复杂的依赖网络
   - 优先使用线性依赖，减少并行依赖
   - 为节点和依赖关系添加清晰的命名

2. **性能优化**：
   - 合理使用并行执行提高性能
   - 避免不必要的依赖关系
   - 考虑节点执行时间，优化执行顺序

3. **错误处理**：
   - 提供详细的依赖关系错误信息
   - 支持依赖关系的可视化展示
   - 实现依赖关系的自动修复建议

4. **测试策略**：
   - 测试各种依赖关系配置
   - 验证循环依赖检测机制
   - 测试节点插入和删除操作
   - 验证序列号计算的正确性

## 8. 数据处理配置

### 8.1 数据处理配置结构

```csharp
public class DataProcessingConfig
{
    public bool EnableDataProcessing { get; set; }
    public DataProcessingPosition Position { get; set; }
    public string ProcessorType { get; set; } = string.Empty;
    public Dictionary<string, object> ProcessorParameters { get; set; } = new Dictionary<string, object>();
}
```

**配置属性说明：**

| 属性 | 类型 | 描述 | 默认值 |
|------|------|------|--------|
| `EnableDataProcessing` | bool | 是否启用数据处理 | false |
| `Position` | DataProcessingPosition | 数据处理位置 | BeforeWorkflow |
| `ProcessorType` | string | 数据处理器类型 | string.Empty |
| `ProcessorParameters` | Dictionary<string, object> | 数据处理器参数 | 空字典 |

### 8.2 数据处理位置

元工作流支持多种数据处理位置：
- `BeforeWorkflow`：工作流开始前
- `AfterWorkflow`：工作流结束后
- `BeforeNode`：每个节点执行前
- `AfterNode`：每个节点执行后

**各处理位置的详细说明：**

| 处理位置 | 执行时机 | 使用场景 | 数据流向 |
|----------|----------|----------|----------|
| `BeforeWorkflow` | 元工作流开始执行前 | 全局数据预处理、参数验证、初始化 | 输入数据 → 处理器 → 元工作流 |
| `AfterWorkflow` | 元工作流执行完成后 | 全局数据后处理、结果格式化、日志记录 | 元工作流 → 处理器 → 输出结果 |
| `BeforeNode` | 每个节点执行前 | 节点级数据验证、参数转换、数据清洗 | 上游数据 → 处理器 → 当前节点 |
| `AfterNode` | 每个节点执行后 | 节点结果处理、数据转换、错误处理 | 当前节点 → 处理器 → 下游节点 |

#### 13.2.3 序列计算

序列计算通过拓扑排序确定节点执行顺序：

```csharp
private void CalculateSequences(Dictionary<string, MetaWorkflowNode> nodeIndex)
{
    var visited = new HashSet<string>();
    var temp = new HashSet<string>();
    var sequence = 1;

    void Visit(string nodeId)
    {
        if (temp.Contains(nodeId))
            throw new InvalidOperationException($"检测到循环依赖: {nodeId}");

        if (visited.Contains(nodeId))
            return;

        temp.Add(nodeId);

        var node = nodeIndex[nodeId];
        foreach (var prevNodeId in node.PreviousNodeIds)
        {
            if (nodeIndex.TryGetValue(prevNodeId, out var prevNode))
            {
                Visit(prevNodeId);
                node.PreviousSequences.Add(prevNode.Sequence);
            }
        }

        temp.Remove(nodeId);
        visited.Add(nodeId);
        node.Sequence = sequence++;
    }

    foreach (var node in nodeIndex.Values)
    {
        if (!visited.Contains(node.Id))
            Visit(node.Id);
    }
}
```

### 13.3 元工作流执行机制

元工作流执行是按照预定义的顺序执行各个节点的过程。

#### 13.3.1 执行流程

元工作流执行包含以下步骤：

```csharp
public async Task<Dictionary<string, object>> ExecuteMetaWorkflowAsync(
    string metaWorkflowId, 
    Dictionary<string, object> inputData)
{
    // 1. 检查并执行工作流开始前的数据处理
    var processedData = inputData;
    if (metaWorkflow.DataProcessingConfig.EnableDataProcessing && 
        metaWorkflow.DataProcessingConfig.Position == DataProcessingPosition.BeforeWorkflow)
    {
        processedData = (Dictionary<string, object>)await ProcessDataAsync(
            processedData, 
            metaWorkflow.DataProcessingConfig);
    }

    // 2. 构建节点索引
    var nodeIndex = BuildNodeIndices(metaWorkflow);

    // 3. 计算节点执行序列
    CalculateSequences(nodeIndex);

    // 4. 按序列执行每个节点
    var orderedNodes = nodeIndex.Values.OrderBy(n => n.Sequence).ToList();
    foreach (var node in orderedNodes)
    {
        // 执行节点前的数据处理
        if (metaWorkflow.DataProcessingConfig.EnableDataProcessing && 
            metaWorkflow.DataProcessingConfig.Position == DataProcessingPosition.BeforeNode)
        {
            processedData = (Dictionary<string, object>)await ProcessDataAsync(
                processedData, 
                metaWorkflow.DataProcessingConfig);
        }

        // 调用框架适配器执行具体工作流
        var adapter = _adapterManager.GetAdapter(node.FrameworkName);
        var result = await adapter.ExecuteWorkflowAsync(node.WorkflowId, node.Parameters);

        // 执行节点后的数据处理
        if (metaWorkflow.DataProcessingConfig.EnableDataProcessing && 
            metaWorkflow.DataProcessingConfig.Position == DataProcessingPosition.AfterNode)
        {
            processedData = (Dictionary<string, object>)await ProcessDataAsync(
                result, 
                metaWorkflow.DataProcessingConfig);
        }
    }

    // 5. 检查并执行工作流结束后的数据处理
    if (metaWorkflow.DataProcessingConfig.EnableDataProcessing && 
        metaWorkflow.DataProcessingConfig.Position == DataProcessingPosition.AfterWorkflow)
    {
        processedData = (Dictionary<string, object>)await ProcessDataAsync(
            processedData, 
            metaWorkflow.DataProcessingConfig);
    }

    // 6. 返回最终执行结果
    return processedData;
}
```

```csharp
public async Task UpdateMetaWorkflowAsync(string metaWorkflowId, MetaWorkflowDefinition metaWorkflow)
{
    await _metaWorkflowManager.RegisterOrUpdateWorkflowAsync(metaWorkflowId, metaWorkflow);
    
    // 重新计算节点序列

    CalculateSequences(nodeIndex);

}
```

```csharp
public class ErrorHandler
{
    public async Task HandleExecutionErrorAsync(Exception exception, ExecutionContext context)
    {
        context.IsSuccessful = false;
        context.ErrorMessage = exception.Message;
        
        // 记录错误日志
        _logger.LogError(exception, "元工作流执行失败: {MetaWorkflowId}", context.MetaWorkflowId);
        
        // 执行错误处理策略
        await ExecuteErrorHandlingStrategyAsync(exception, context);
    }
    
    private async Task ExecuteErrorHandlingStrategyAsync(Exception exception, ExecutionContext context)
    {
        // 根据错误类型执行不同的处理策略
        switch (exception)
        {
            case InvalidOperationException:
                // 业务逻辑错误
                await HandleBusinessLogicErrorAsync(exception, context);
                break;
            case TimeoutException:
                // 超时错误
                await HandleTimeoutErrorAsync(exception, context);
                break;
            default:
                // 其他错误
                await HandleGenericErrorAsync(exception, context);
                break;
        }
    }
}
```

## 14. 框架注册与适配器

框架注册与适配器是元工作流系统的核心组件，提供了框架的注册、管理和适配功能，使元工作流能够与多种框架进行集成和协同工作。

### 14.1 框架适配器接口

所有框架适配器必须实现 `IFrameworkAdapter` 接口：

```csharp
public interface IFrameworkAdapter
{
    string FrameworkName { get; }
    Task<object> ExecuteWorkflowAsync(string workflowId, Dictionary<string, object> parameters);
    Task<bool> ValidateWorkflowAsync(string workflowId);
    Task<List<string>> GetAvailableWorkflowsAsync();
}
```

**接口方法说明：**

| 方法 | 返回值 | 说明 | 异常处理 |
|------|--------|------|----------|
| `FrameworkName` | string | 获取框架唯一名称 | 无 |
| `ExecuteWorkflowAsync` | Task<object> | 执行指定的工作流 | 抛出执行异常 |
| `ValidateWorkflowAsync` | Task<bool> | 验证工作流是否有效 | 返回false表示无效 |
| `GetAvailableWorkflowsAsync` | Task<List<string>> | 获取所有可用的工作流ID | 抛出查询异常 |

### 16.4 整理原则

1. **结果类就近放置**：结果类放在使用它们的管理器文件中
   - `ModuleProjectCreationResult`、`ModuleProjectDeletionResult`、`ModuleProjectUnregistrationResult` 放在 `ModuleProjectCreatorMetaWorkflow.cs` 末尾

2. **共享数据模型集中**：`DataModels.cs` 只包含被多个类共享的数据模型
   - `ModuleAddressInfo` 是唯一保留的共享数据模型

3. **内部工具类保持独立**：`FileOperationsHelper` 和 `TemplateManager` 使用 `internal static` 修饰符
   - 它们是内部使用的工具类，不需要对外暴露

4. **服务接口与实现分离**：使用 `#region` 块分隔接口定义和服务实现
   - 清晰地区分公共API和内部实现
