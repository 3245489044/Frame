# FrameManage 数据库使用逻辑介绍

## 1. 数据存储架构

FrameManage 采用了灵活的数据存储架构，支持多种存储方式，主要包括：

### 1.1 核心接口

- **IDataStorage**：定义了基本的数据存储操作，包括存储、检索、删除、检查存在性和获取所有键等功能
- **IDataStorageFactory**：数据存储工厂接口，支持运行时动态选择存储类型

### 1.2 存储实现

- **SqliteDataStorage**：基于SQLite的数据库存储实现
- **JsonDataStorage**：基于JSON文件的存储实现
- **DataStorageFactory**：数据存储工厂，支持注册和创建不同类型的存储实例

## 2. 数据库表结构

### 2.1 元工作流相关表

- **MetaWorkflows**：存储元工作流基本信息
  - Id (TEXT PRIMARY KEY)
  - Name (TEXT)
  - Description (TEXT)
  - DataProcessingConfig (TEXT) - JSON格式
  - Parameters (TEXT) - JSON格式

- **MetaWorkflowNodes**：存储元工作流节点
  - Id (TEXT PRIMARY KEY)
  - MetaWorkflowId (TEXT) - 外键，关联MetaWorkflows表
  - Name (TEXT)
  - FrameworkName (TEXT)
  - WorkflowId (TEXT)
  - Parameters (TEXT) - JSON格式
  - Sequence (INTEGER)
  - Symbol (TEXT)
  - Label (TEXT)
  - ParameterKeys (TEXT) - JSON格式
  - ResultKeys (TEXT) - JSON格式
  - FuncName (TEXT)
  - NextNodeConfig (TEXT) - JSON格式

- **MetaWorkflowRelationships**：存储元工作流节点关系
  - Id (INTEGER PRIMARY KEY AUTOINCREMENT)
  - MetaWorkflowId (TEXT) - 外键，关联MetaWorkflows表
  - NodeId (TEXT) - 外键，关联MetaWorkflowNodes表
  - PreviousNodeId (TEXT) - 外键，关联MetaWorkflowNodes表

### 2.2 通用数据相关表

- **GenericData**：存储通用数据
  - Id (TEXT PRIMARY KEY)
  - Content (TEXT) - JSON格式

- **InputTemplates**：存储输入模板
  - WorkflowId (TEXT PRIMARY KEY)
  - Template (TEXT)
  - CreatedAt (TEXT)
  - UpdatedAt (TEXT)

### 2.3 工作流相关表

- **Workflows**：存储工作流
  - Id (TEXT PRIMARY KEY)
  - Name (TEXT)
  - Description (TEXT)
  - CreatedAt (TEXT)
  - UpdatedAt (TEXT)

- **Codes**：存储代码
  - Id (TEXT PRIMARY KEY)
  - Name (TEXT)
  - Content (TEXT)
  - Language (TEXT)
  - CreatedAt (TEXT)
  - UpdatedAt (TEXT)

- **DataSchemas**：存储数据模式
  - Id (TEXT PRIMARY KEY)
  - Name (TEXT)
  - SchemaJson (TEXT)
  - CreatedAt (TEXT)
  - UpdatedAt (TEXT)

- **Prompts**：存储提示
  - Id (TEXT PRIMARY KEY)
  - Name (TEXT)
  - Content (TEXT)
  - PromptType (TEXT)
  - CreatedAt (TEXT)
  - UpdatedAt (TEXT)

- **FourDimensionalMappings**：存储四维映射关系
  - Id (TEXT PRIMARY KEY)
  - WorkflowId (TEXT)
  - CodeId (TEXT)
  - DataSchemaId (TEXT)
  - PromptId (TEXT)
  - MappingType (TEXT)
  - CreatedAt (TEXT)

## 3. 数据存储服务

### 3.1 StorageService

基于DataMethod组件的存储服务，提供以下功能：

- 初始化存储（InitializeAsync）
- 加载图数据库（LoadGraphDataAsync）
- 保存图数据库（SaveGraphDataAsync）

#### 3.1.1 图数据库与SQLite的使用关系

**初始化流程（InitializeAsync）**：
1. **SQLite初始化**：`DataBase.DataUniversal.DataBasePath = sqlitePath;` - 设置SQLite数据库路径
2. **SQLite数据库创建**：`DataBase.DataCreate.CreateDataBase();` - 创建SQLite数据库文件
3. **图数据库初始化**：`_graphDb = UniversalReferenceManagerFactory.Create();` - 创建图数据库实例
4. **图数据库初始化**：`await _graphDb.InitializeAsync();` - 异步初始化图数据库
5. **表结构创建**：`InitializeTables();` - 在SQLite中创建必要的表结构

**加载图数据（LoadGraphDataAsync）**：
- 目前仅支持从JSON文件加载：`var jsonContent = await System.IO.File.ReadAllTextAsync(graphDatabasePath);`
- 后续计划支持从SQLite加载图数据

**保存图数据（SaveGraphDataAsync）**：
- 目前为预留接口，计划实现保存数据到SQLite和图数据库的逻辑
- 未来将实现图数据与SQLite数据的双向同步

### 3.2 GenericWorkflowStorage

通用工作流存储管理器，支持：

- 存储工作流（StoreAsync）
- 检索工作流（RetrieveAsync）
- 删除工作流（DeleteAsync）
- 检查工作流是否存在（ExistsAsync）
- 获取所有工作流ID（GetAllWorkflowIdsAsync）

### 3.3 InputTemplateManager

输入模板管理服务，提供：

- 保存工作流的输入模板（SaveInputTemplateAsync）
- 获取工作流的输入模板（GetInputTemplateAsync）
- 删除工作流的输入模板（DeleteInputTemplateAsync）
- 检查工作流是否有输入模板（HasInputTemplateAsync）
- 获取所有输入模板的工作流ID（GetWorkflowsWithTemplatesAsync）
- 为工作流创建默认输入模板（CreateDefaultTemplate）

## 4. 数据存储流程

### 4.1 初始化流程

1. 创建数据存储实例（通过DataStorageFactory）
2. 调用InitializeAsync方法初始化存储
3. 创建必要的数据库表结构

### 4.2 存储流程

1. 根据数据类型确定存储方式
2. 序列化数据（通常使用JSON）
3. 执行存储操作

### 4.3 检索流程

1. 根据键确定数据类型
2. 执行检索操作
3. 反序列化数据

### 4.4 图数据库与SQLite的交互流程

**数据流转关系**：
1. **SQLite作为持久化存储**：所有结构化数据（如工作流、节点、关系等）存储在SQLite数据库中
2. **图数据库作为内存计算**：用于处理和分析工作流的复杂关系和依赖
3. **数据同步机制**：
   - 从SQLite加载数据到图数据库进行分析
   - 分析结果保存回SQLite持久化

**函数级交互**：
- **StorageService.InitializeAsync**：同时初始化SQLite和图数据库
  - 设置SQLite数据库路径：`DataBase.DataUniversal.DataBasePath = sqlitePath`
  - 创建SQLite数据库：`DataBase.DataCreate.CreateDataBase()`
  - 创建图数据库实例：`_graphDb = UniversalReferenceManagerFactory.Create()`
  - 初始化图数据库：`await _graphDb.InitializeAsync()`
  - 创建SQLite表结构：`InitializeTables()`

- **StorageService.LoadGraphDataAsync**：从外部文件加载图数据（未来将支持从SQLite加载）
  - 从JSON文件加载：`var jsonContent = await System.IO.File.ReadAllTextAsync(graphDatabasePath)`
  - 反序列化图数据：`var graphData = System.Text.Json.JsonSerializer.Deserialize<GraphDatabase>(jsonContent, options)`

- **StorageService.SaveGraphDataAsync**：计划实现将图数据保存到SQLite（预留接口）

- **SqliteDataStorage.StoreAsync**：将数据存储到SQLite，包括元工作流、节点、关系等
  - 存储元工作流：`await StoreMetaWorkflowAsync(key, data as MetaWorkflowDefinition)`
  - 存储输入模板：`await StoreInputTemplateAsync(key, data)`
  - 存储通用数据：`await StoreGenericDataAsync(key, data)`

- **SqliteDataStorage.RetrieveAsync**：从SQLite检索数据，支持不同类型的数据格式
  - 检索元工作流：`var metaWorkflow = await RetrieveMetaWorkflowAsync(key)`
  - 检索输入模板：`return await RetrieveInputTemplateAsync<T>(key)`
  - 检索通用数据：`return await RetrieveGenericDataAsync<T>(key)`

**应用程序使用流程**：
1. **启动流程**：
   - 初始化存储服务：`storageService.Initialize(sqlitePath)`
   - 加载图数据库：`var result = await analyzer.AnalyzeAsync(arguments.GraphDatabasePath)`

2. **元工作流管理**：
   - 初始化SQLite数据存储：`var dataStorage = new SqliteDataStorage()`
   - 创建元工作流管理器：`var metaWorkflowManager = new MetaWorkflowManager(dataStorage, adapterManager)`
   - 注册元工作流：`await manager.RegisterMetaWorkflowAsync("module_project_creator", metaWorkflow)`

3. **默认数据库路径**：
   - SQLite数据库：`FrameManage/DataManage/FrameManageData.db`
   - 图数据库：`FrameManage/DataManage/MultiDimensionalWorkflowGraph.db`

### 4.5 图数据库作为引用层的作用

**核心架构角色**：
- **持久化层**：SQLite数据库，存储结构化数据（元工作流、节点、关系等）
- **引用层**：图数据库（UniversalGraphStorage），处理复杂依赖关系
- **文件系统层**：子项目模块文件系统，存储实际模块代码和资源

**数据流转关系**：
1. **从SQLite到图数据库**：加载结构化数据进行关系分析
2. **从文件系统到图数据库**：同步模块引用关系
3. **从图数据库到SQLite**：保存分析结果和引用关系
4. **从图数据库到文件系统**：基于分析结果操作模块文件

**具体实现机制**：

1. **模块引用关系管理**：
   - 同步模块引用到图数据库：`SyncModuleReferencesToGraphAsync`
   - 从SQLite加载模块数据：`_dataStorage.RetrieveAsync`
   - 从文件系统读取模块代码：通过 ModuleAddressManager 获取路径

2. **依赖分析与路径查找**：
   - 获取模块依赖：`GetModuleCodeReferencesAsync`
   - 计算引用差值：`CalculateReferenceDiffAsync`
   - 执行图算法：`ExecuteAsync` (如find_shortest_path, get_dependencies等)

3. **节点数据管理**：
   - 获取节点数据：`GetNodeDataAsync`
   - 更新节点数据：`UpdateNodeDataAsync`
   - 资源管理：`AddResourceAsync`, `UpdateResourceAsync`, `GetResourceAsync`

4. **文件系统集成**：
   - 模块路径管理：`GetModuleProjectPath`, `GetModuleDataPath`, `GetModulePromptsPath`
   - 模块数据库路径：`GetModuleDatabasePath`
   - 模块项目管理：`CreateModuleProjectAsync`, `ModuleProjectExists`

**工作流程**：

1. **模块创建与管理流程**：
   - 创建模块项目：`CreateModuleProjectAsync`
   - 分配模块地址：通过 ModuleAddressManager 分配唯一地址
   - 创建文件系统结构：在指定路径创建模块项目
   - 初始化模块数据：在SQLite中存储模块信息
   - 同步引用关系：将模块引用关系同步到图数据库

2. **引用分析流程**：
   - 从SQLite加载模块数据：`_dataStorage.RetrieveAsync`
   - 从文件系统读取模块代码：通过 ModuleAddressManager 获取路径
   - 同步引用到图数据库：`SyncModuleReferencesToGraphAsync`
   - 分析依赖关系：使用图数据库算法分析依赖
   - 计算引用差值：`CalculateReferenceDiffAsync`
   - 生成补全建议：基于分析结果生成补全建议

3. **数据同步流程**：
   - SQLite到图数据库：加载结构化数据
   - 文件系统到图数据库：同步模块引用
   - 图数据库分析：执行依赖分析和路径查找
   - 分析结果到SQLite：保存分析结果
   - 分析结果到文件系统：基于分析结果更新模块文件

**技术优势**：
1. **高效依赖分析**：图数据库提供高效的依赖关系分析能力
2. **灵活引用管理**：支持复杂的引用关系管理
3. **统一存储接口**：通过 IDataStorage 接口统一访问不同存储方式
4. **模块化设计**：通过 ModuleAddressManager 管理模块文件系统
5. **可扩展性**：支持添加新的存储类型和分析算法

**核心函数关系**：

| 功能 | 核心函数 | 实现文件 |
|------|---------|----------|
| 初始化图数据库 | `InitializeAsync` | StorageService.cs |
| 加载图数据 | `LoadGraphDataAsync` | StorageService.cs |
| 保存图数据 | `SaveGraphDataAsync` | StorageService.cs |
| 同步模块引用 | `SyncModuleReferencesToGraphAsync` | MetaWorkflowManager.cs |
| 获取模块依赖 | `GetModuleCodeReferencesAsync` | MetaWorkflowManager.cs |
| 计算引用差值 | `CalculateReferenceDiffAsync` | MetaWorkflowManager.cs |
| 获取节点数据 | `GetNodeDataAsync` | GraphAlgorithmService.cs |
| 更新节点数据 | `UpdateNodeDataAsync` | GraphAlgorithmService.cs |
| 模块路径管理 | `GetModuleProjectPath` 等 | MetaWorkflowManager.cs |

通过这种架构设计，图数据库作为中间引用层，有效地连接了SQLite的持久化存储和子项目模块的文件系统，提供了高效的依赖分析和引用管理能力。

## 5. 使用示例

### 5.1 创建数据存储实例

```csharp
// 创建SQLite数据存储实例
var dataStorage = new SqliteDataStorage("Data/FrameManageData.db");
await dataStorage.InitializeAsync();

// 或者通过工厂创建
var factory = new DataStorageFactory();
var dataStorage = factory.Create("sqlite", "Data/FrameManageData.db");
await dataStorage.InitializeAsync();
```

### 5.2 存储元工作流

```csharp
var metaWorkflow = new MetaWorkflowDefinition
{
    Id = "workflow1",
    Name = "测试工作流",
    Description = "这是一个测试工作流",
    Parameters = new Dictionary<string, object> { { "param1", "value1" } },
    Nodes = new List<MetaWorkflowNode>
    {
        new MetaWorkflowNode
        {
            Id = "node1",
            Name = "节点1",
            FrameworkName = "TestFramework",
            WorkflowId = "subworkflow1",
            Parameters = new Dictionary<string, object> { { "nodeParam1", "nodeValue1" } },
            Sequence = 1,
            Symbol = "symbol1",
            Label = "标签1",
            ParameterKeys = new List<string> { "param1" },
            ResultKeys = new List<string> { "result1" },
            FuncName = "Function1",
            PreviousNodeIds = new List<string>()
        }
    }
};

await dataStorage.StoreAsync("workflow1", metaWorkflow);
```

### 5.3 存储输入模板

```csharp
var inputTemplateManager = new InputTemplateManager(dataStorage);
var templateJson = inputTemplateManager.CreateDefaultTemplate("workflow1");
await inputTemplateManager.SaveInputTemplateAsync("workflow1", templateJson);
```

### 5.4 使用工作流存储

```csharp
var workflowStorage = new GenericWorkflowStorage<MyWorkflow>(dataStorage, "workflow_");

// 存储工作流
await workflowStorage.StoreAsync("workflow1", myWorkflow);

// 检索工作流
var retrievedWorkflow = await workflowStorage.RetrieveAsync("workflow1");

// 检查工作流是否存在
var exists = await workflowStorage.ExistsAsync("workflow1");

// 获取所有工作流ID
var workflowIds = await workflowStorage.GetAllWorkflowIdsAsync();

// 删除工作流
await workflowStorage.DeleteAsync("workflow1");
```

## 6. 最佳实践

1. **选择合适的存储类型**：根据数据量和性能需求选择SQLite或JSON存储
2. **合理设计键值**：使用有意义的键前缀区分不同类型的数据
3. **错误处理**：在存储和检索操作中添加适当的错误处理
4. **日志记录**：使用日志记录存储操作的状态和错误
5. **数据序列化**：对于复杂数据，使用JSON序列化确保数据一致性
6. **定期备份**：定期备份数据库文件，防止数据丢失

## 7. 注意事项

1. SQLite数据库文件默认存储在应用程序基目录的Data文件夹中
2. 首次使用时会自动创建必要的表结构
3. 对于大型数据，建议使用SQLite存储以获得更好的性能
4. 输入模板使用"input_template_"前缀存储，与其他数据区分
5. 元工作流数据会自动处理节点和关系的存储

## 8. 扩展建议

1. **添加缓存层**：对于频繁访问的数据，添加内存缓存以提高性能
2. **实现数据迁移**：当表结构变更时，实现数据迁移功能
3. **添加索引**：为常用查询的字段添加索引，提高查询性能
4. **支持更多存储类型**：根据需要添加其他存储类型的实现，如内存存储、NoSQL数据库等
5. **实现事务支持**：对于复杂操作，添加事务支持确保数据一致性

通过以上架构和实践，FrameManage 提供了一个灵活、可靠的数据存储系统，支持工作流和相关数据的有效管理。
