# 多维工作流补全框架

## 框架概述

多维工作流补全框架是一个基于**工作流(W)-代码(C)-数据(D)-Prompt(P)**的四维数学映射系统，用于实现工作流的智能补全和管理。该框架采用基于WorkFlow\Porgram\DataMethod组件的架构，通过数学模型描述和处理各维度之间的关系，实现了引用关系与数据内容的高效分离管理，支持从任意维度自动补全其他相关维度的信息。

框架的核心是一个多维空间关系模型，将工作流、代码、数据和Prompt表示为数学对象，并通过映射函数描述它们之间的转换关系，从而实现智能的工作流生成和管理。

## 核心设计理念

### 📐 多维映射架构

框架采用**工作流(W)-代码(C)-数据(D)-Prompt(P)**的四维数学映射模型，构建了一个统一的工作流补全系统：

#### 数学表示

| 维度 | 数学符号 | 数学表示 | 实际含义 |
|------|----------|----------|----------|
| 工作流 | W | 有向图  G = (V, E) | 业务流程的执行逻辑和节点关系 |
| 代码 | C | 函数集合  C = \{ f_1, f_2, ..., f_n \} | 工作流节点的具体功能实现 |
| 数据 | D | 模式集合  D = \{ (s_i, t_i, c_i) \} | 工作流和代码操作的数据结构 |
| Prompt | P | 自然语言集合  P = \{ p_1, p_2, ..., p_k \} | 工作流的自然语言描述 |

#### 补全映射函数

框架支持从任意维度到其他维度的补全，通过以下映射函数实现：

| 补全方向 | 数学表达式 | 含义 |
|----------|------------|------|
| 工作流→其他 |  f(W) → (C, D, P)  | 从工作流补全代码、数据和Prompt |
| 代码→其他 |  g(C) → (W, D, P)  | 从代码补全工作流、数据和Prompt |
| 数据→其他 |  h(D) → (W, C, P)  | 从数据补全工作流、代码和Prompt |
| Prompt→其他 |  k(P) → (W, C, D)  | 从Prompt补全工作流、代码和数据 |

#### 多维空间关系

整体数学模型为：
$$ F(W, C, D, P) = (R_{WC}, R_{WD}, R_{WP}, R_{CD}, R_{CP}, R_{DP}) $$

其中 $R_{XY}$ 表示维度 X 和 Y 之间的关系矩阵，包括：
- 工作流与代码的关系（使用、实现）
- 工作流与数据的关系（访问、使用）
- 工作流与Prompt的关系（引用、基于）
- 代码与数据的关系（处理、操作）
- 代码与Prompt的关系（描述、生成）
- 数据与Prompt的关系（解释、定义）

这种多维空间关系模型允许系统在任意维度之间进行映射和补全，实现智能的工作流生成和管理。

### 🗄️ 数据与引用处理架构

框架采用**统一的数据与引用处理架构**，基于WorkFlow\Porgram\DataMethod中的核心组件构建，实现了引用关系与数据内容的高效管理：

| 组件类型 | 核心实现 | 存储内容 | 核心优势 |
|---------|----------|----------|----------|
| **基础数据处理** | `WorkFlow\Porgram\DataMethod\SqliteRelate.cs` | - 工作流的定义和元数据<br>- 代码的具体实现内容<br>- 数据模式的详细结构<br>- Prompt的自然语言描述<br>- 多维映射的关系记录 | - 完整的SQLite数据库操作封装<br>- 高效的结构化数据存储<br>- 完善的事务支持<br>- 轻量级部署和管理 |
| **通用图处理** | `WorkFlow\Porgram\DataMethod\UniversalReferenceLayer.cs` | - 工作流、代码、数据、Prompt之间的引用关系<br>- 节点间的连接和依赖关系<br>- 多维空间中的关联路径 | - 统一的资源标识符管理<br>- 灵活的关系表示和扩展<br>- 支持复杂的网络分析<br>- 高效的关系查询和路径查找 |

#### 组件协作机制

| 操作场景 | 工作流构建器（WorkflowBuilder）角色 | 运行时管理（WorkflowRuntimeManager）角色 | 通用图处理（UniversalReferenceLayer）角色 | 基础数据处理（SqliteRelate）角色 |
|----------|-----------------------------------|---------------------------------------|-------------------------------------------|----------------------------------|
| 工作流创建 | 构建工作流节点结构 | - | 建立节点引用关系 | 存储工作流定义和元数据 |
| 工作流执行 | - | 控制工作流执行流程 | - | 存储执行数据和状态 |
| 节点执行 | - | 管理节点运行状态 | - | 记录节点执行数据 |
| 代码关联 | - | - | 创建代码与工作流/数据/Prompt的引用关系 | 存储代码的具体实现内容 |
| 数据映射 | - | - | 建立数据模式与工作流/代码/Prompt的引用关系 | 存储数据模式的详细结构 |
| Prompt添加 | - | - | 创建Prompt与工作流/代码/数据的引用关系 | 存储Prompt的自然语言描述 |
| 补全查询 | - | - | 查找多维空间中的关联路径 | 获取实体的具体内容 |

| 运行时监控 | - | 收集执行统计数据和事件 | - | 持久化运行时数据 |

## 多维补全功能示例

### 工作流运行时管理示例

**执行工作流并处理事件**：
```csharp
// 初始化工作流运行时管理器
var runtimeManager = WorkflowRuntimeManager.Instance;

// 订阅运行时事件
runtimeManager.RuntimeEvent += OnRuntimeEvent;

// 执行工作流
var runId = runtimeManager.StartWorkflow(
    workflowType: "UserRegistration",
    parameters: new Dictionary<string, object> {
        { "user_name", "test_user" },
        { "email", "test@example.com" },
        { "password", "secure_password" }
    }
);

// 运行时事件处理方法
private static void OnRuntimeEvent(object sender, WorkflowRuntimeEventArgs e)
{
    switch (e.EventType)
    {
        case WorkflowRuntimeEventType.WorkflowStarted:
            Console.WriteLine($"[事件] 工作流开始 - 类型: {e.WorkflowType}, RunId: {e.RunId}");
            break;
        case WorkflowRuntimeEventType.WorkflowEnded:
            Console.WriteLine($"[事件] 工作流结束 - RunId: {e.RunId}, 成功: {e.Success}");
            break;
        case WorkflowRuntimeEventType.NodeStarted:
            Console.WriteLine($"[事件] 节点开始 - RunId: {e.RunId}, 节点: {e.NodeName} ({e.NodeId})");
            break;
        case WorkflowRuntimeEventType.NodeEnded:
            Console.WriteLine($"[事件] 节点结束 - NodeRunId: {e.NodeRunId}, 成功: {e.Success}");
            break;
    }
}
```

**从字符串定义构建工作流**：
```csharp
// 使用WorkflowBuilder从字符串定义创建工作流
// 格式：symbol:nodeId:funcName:param1,param2:result1,result2:label
var workflow = WorkflowBuilder.BuildFromStrings(
    "Start:node_c0:StartFunction:Input_:Output_:开始节点",
    "Process:node_c1:ProcessFunction:Input_:Processed_:处理节点",
    "Validate:node_c2:ValidateFunction:Processed_:Validated_:验证节点",
    "End:node_c3:EndFunction:Validated_:Result_:结束节点"
);

// 获取工作流摘要
var summary = WorkflowBuilder.GetSummary(workflow);
// 输出：Workflow (4 nodes): [0] Start (node_c0) -> [1] Process (node_c1) -> [2] Validate (node_c2) -> [3] End (node_c3)
```

**添加带有后续节点配置的节点**：
```csharp
var nodes = new List<object>();

// 创建后续节点配置
var nextConfig = new ExpandoObject();
((IDictionary<string, object>)nextConfig)["NextNodeId"] = "node_c1";

// 添加节点
WorkflowBuilder.AddNodeWithNextConfig(
    nodes,
    "Start",
    "node_c0",
    "StartFunction",
    new object[] { "Input_" },
    new object[] { "Output_" },
    nextConfig,
    "开始节点"
);
```

### 多维补全的数学模型

#### 1. 工作流到多维补全 (W → C, D, P)

**数学表达式**：
$$ f(W) \rightarrow (C, D, P) $$

其中：
-  W : 工作流（Workflow），表示为有向图  G = (V, E) ， V  为节点集合， E  为边集合
-  C : 代码（Code），表示为函数集合  C = \{ f_1, f_2, ..., f_n \} 
-  D : 数据（Data），表示为模式集合  D = \{ d_1, d_2, ..., d_m \} 
-  P : Prompt，表示为自然语言描述集合  P = \{ p_1, p_2, ..., p_k \} 

**抽象示例**：
```
# 工作流 (W)：有向图表示
W = (V, E)
V = {v1, v2, v3}  # 节点集合
E = {(v1, v2), (v2, v3)}  # 边集合

# 节点定义
v1 = (id="n1", type="Validation", params=["input"])
v2 = (id="n2", type="DatabaseOperation", params=["processed"])
v3 = (id="n3", type="Notification", params=["result"])

# 系统自动补全：f(W) → (C, D, P)
C = {f1(input), f2(processed), f3(result)}  # 代码函数集合
D = {d_input, d_processed, d_result}        # 数据模式集合
P = {p_workflow_description}                # Prompt集合
```

#### 2. 代码到多维补全 (C → W, D, P)

**数学表达式**：
$$ g(C) \rightarrow (W, D, P) $$

其中：
-  C : 代码（Code），表示为函数序列  C = [f_1, f_2, ..., f_n] 
-  W : 工作流（Workflow），表示为有向图  G = (V, E) 
-  D : 数据（Data），表示为输入输出集合  D = (I, O) 
-  P : Prompt，表示为自然语言描述集合  P = \{ p_1, p_2, ..., p_k \} 

**抽象示例**：
```
# 代码 (C)：函数序列
C = [f1(I1), f2(I2), f3(I3)]

# 函数定义
f1(I1) → O1  # 验证函数
f2(I2) → O2  # 存储函数  
f3(I3) → O3  # 通知函数

# 系统自动补全：g(C) → (W, D, P)
W = (V, E), V={v1, v2, v3}, E={(v1, v2), (v2, v3)}  # 工作流有向图
D = (I={I1, I2, I3}, O={O1, O2, O3})               # 数据输入输出
P = {p_code_description}                           # Prompt集合
```

#### 3. 数据到多维补全 (D → W, C, P)

**数学表达式**：
$$ h(D) \rightarrow (W, C, P) $$

其中：
-  D : 数据（Data），表示为模式集合  D = \{ (s_i, t_i, c_i) \} ， s_i  为字段名， t_i  为类型， c_i  为约束条件
-  W : 工作流（Workflow），表示为有向图  G = (V, E) 
-  C : 代码（Code），表示为函数集合  C = \{ f_1, f_2, ..., f_n \} 
-  P : Prompt，表示为自然语言描述集合  P = \{ p_1, p_2, ..., p_k \} 

**抽象示例**：
```
# 数据 (D)：模式集合
D = { (s1, t1, c1), (s2, t2, c2), (s3, t3, c3) }

# 字段定义
s1 = (name="id", type="string", constraints={"required": true})
s2 = (name="amount", type="number", constraints={"min": 0, "required": true})
s3 = (name="status", type="enum", constraints={"values": ["Pending", "Success", "Failed"]})

# 系统自动补全：h(D) → (W, C, P)
W = (V, E), V={v1, v2, v3, v4}, E={(v1, v2), (v2, v3), (v3, v4)}  # 工作流有向图
C = {f1(validate), f2(process), f3(update), f4(notify)}         # 代码函数集合
P = {p_data_description}                                       # Prompt集合
```

#### 4. Prompt到多维补全 (P → W, C, D)

**数学表达式**：
$$ k(P) \rightarrow (W, C, D) $$

其中：
-  P : Prompt，表示为自然语言描述集合  P = \{ p_1, p_2, ..., p_k \} 
-  W : 工作流（Workflow），表示为有向图  G = (V, E) 
-  C : 代码（Code），表示为函数集合  C = \{ f_1, f_2, ..., f_n \} 
-  D : 数据（Data），表示为模式集合  D = \{ d_1, d_2, ..., d_m \} 

**抽象示例**：
```
# Prompt (P)：自然语言描述集合
P = {p1}

# 描述定义
p1 = "当事件E发生时，执行序列S1, S2, S3，并生成结果R"

# 系统自动补全：k(P) → (W, C, D)
W = (V, E), V={v1, v2, v3, v4}, E={(v1, v2), (v2, v3), (v3, v4)}  # 工作流有向图
C = {f1(event), f2(S1), f3(S2), f4(S3)}                           # 代码函数集合
D = {d_event, d_S1_input, d_S1_output, d_S2_input, ...}           # 数据模式集合
```

#### 5. 多维空间关系模型

**整体数学模型**：
$$ F(W, C, D, P) = (R_{WC}, R_{WD}, R_{WP}, R_{CD}, R_{CP}, R_{DP}) $$

其中：
-  F : 多维映射函数
-  R_{XY} : 维度 X 和 Y 之间的关系矩阵

**关系矩阵定义**：
-  R_{WC} : 工作流与代码之间的关系（使用、实现）
-  R_{WD} : 工作流与数据之间的关系（访问、使用）
-  R_{WP} : 工作流与Prompt之间的关系（引用、基于）
-  R_{CD} : 代码与数据之间的关系（处理、操作）
-  R_{CP} : 代码与Prompt之间的关系（描述、生成）
-  R_{DP} : 数据与Prompt之间的关系（解释、定义）

这种多维空间关系模型允许系统在任意维度之间进行映射和补全，实现智能的工作流生成和管理。

## 版本管理架构

### 🔄 综合版本控制系统

多维工作流补全框架实现了**项目级的综合版本管理**，支持基于不同维度的版本更新策略，提供宏观的项目级版本控制能力。

#### 版本管理架构设计

**双层级版本管理**：
- **细粒度版本管理** (`VersionManagementModule`)：单个资源的版本控制
- **项目级版本管理** (`ProjectVersionManagementModule`)：综合的项目级版本控制

#### 版本更新策略 (VersionUpdateStrategy)

| 策略类型 | 触发条件 | 版本影响范围 | 适用场景 |
|---------|----------|-------------|----------|
| **WorkflowDriven** | 工作流变更 | 整个项目 | 业务流程重构、架构调整 |
| **DataDriven** | 数据模式变更 | 相关组件 | 数据结构优化、验证规则更新 |
| **PromptDriven** | 提示词变更 | 生成内容 | AI模型优化、需求变更 |
| **CodeDriven** | 代码实现变更 | 实现逻辑 | 功能增强、bug修复 |
| **MultiDimensional** | 多维度变更 | 综合影响 | 重大版本发布、综合优化 |

#### 项目版本类型 (ProjectVersionType)

| 版本类型 | 语义版本 | 变更级别 | 发布频率 |
|---------|----------|---------|----------|
| **Major** | X.0.0 | 重大架构变更 | 低 |
| **Minor** | 0.X.0 | 功能增强 | 中 |
| **Patch** | 0.0.X | 问题修复 | 高 |
| **Snapshot** | 快照 | 临时状态保存 | 按需 |

#### 1. 项目级版本操作

### 📊 版本管理数学模型

#### 项目版本状态模型

**项目版本状态定义**：
$$ V_{project} = (W_v, C_v, D_v, P_v, R_v, M_v) $$

其中：
- $W_v$：工作流版本集合
- $C_v$：代码版本集合  
- $D_v$：数据版本集合
- $P_v$：Prompt版本集合
- $R_v$：资源关系版本
- $M_v$：版本元数据

#### 版本更新函数

**基于工作流的版本更新**：
$$ Update_{workflow}(W_{new}) \rightarrow V_{project}^{new} $$

**基于数据的版本更新**：
$$ Update_{data}(D_{new}) \rightarrow V_{project}^{new} $$

**版本比较函数**：
$$ Compare(V_1, V_2) \rightarrow \Delta_{resources} $$

#### 版本恢复函数

**项目级恢复**：
$$ Restore(V_{target}) \rightarrow V_{current} = V_{target} $$
