```csharp
// IWorkflowReferenceManager 接口
```

#### 引用类型枚举 (ReferenceType)

| 类型值 | 说明 | 使用场景 |
|-------|------|---------|
| `Includes` | 包含关系 | 工作流包含节点、模块包含子模块 |
| `DependsOn` | 依赖关系 | 节点A依赖节点B、模块A依赖模块B |
| `InheritsFrom` | 继承关系 | 子类继承父类、元工作流继承基础工作流 |
| `Calls` | 调用关系 | 函数调用函数、节点触发节点 |
| `References` | 引用关系 | 文档引用资源、配置引用模板 |
| `Other` | 其他关系 | 自定义引用类型 |

```csharp
var eventDrivenManager = EventDrivenReferenceManagerFactory.Create();

// 订阅特定类型资源的变更

{
    Console.WriteLine($"New relationship: {args.SourceType}:{args.SourceId} -> {args.TargetType}:{args.TargetId}");
```

## 2. 引用管理流程

### 2.1 工作流引用注册流程

#### 流程序列图

#### 流程步骤

1. **初始化**：创建 `WorkflowReferenceManager` 实例，依赖 `IUniversalReferenceManager`
2. **调用接口**：调用 `RegisterWorkflowReferencesAsync` 方法
3. **资源注册**：创建工作流资源标识符，添加到通用引用管理器
4. **引用处理**：如果工作流数据实现了 `IReferenceable` 接口，调用 `RegisterReferenceableAsync`
5. **对象注册**：为可引用对象创建资源并添加到引用管理器
6. **关系注册**：注册对象的引用关系到通用引用管理器

#### 代码示例

```csharp
var workflowReferenceManager = WorkflowReferenceManagerFactory.Create();

// 创建可引用对象
var myReferenceable = new MyReferenceableObject();
await workflowReferenceManager.RegisterReferenceableAsync(myReferenceable);

// 注册工作流
await workflowReferenceManager.RegisterWorkflowReferencesAsync(
    workflowId: "workflow_001",
    workflowType: "MetaWorkflow",
    workflowData: myWorkflowObject
);
```

## 3. 数据存储流程

### 3.1 工作流数据存储

1. **存储类型判断**：根据数据类型选择存储方式
2. **元工作流存储**：存储到 `MetaWorkflows` 表
3. **节点存储**：存储到 `MetaWorkflowNodes` 表
4. **关系存储**：存储到 `MetaWorkflowRelationships` 表
5. **通用数据存储**：存储到 `GenericData` 表

1. **存储类型判断**：根据数据类型选择获取方式
2. **元工作流获取**：从 `MetaWorkflows` 表获取基本信息
3. **节点获取**：从 `MetaWorkflowNodes` 表获取节点信息
4. **关系获取**：从 `MetaWorkflowRelationships` 表获取节点间关系
5. **数据构建**：构建完整的工作流对象

### 3.3 工作流ID获取

1. **存储类型判断**：根据存储类型选择获取方式

3. **JSON存储**：从文件系统获取所有JSON文件名
4. **前缀处理**：处理带有前缀的键，提取工作流ID
5. **结果返回**：返回工作流ID列表

## 5. 引用管理功能特性

### 5.1 自动默认引用

- 当工作流没有引用关系时，自动创建默认的节点引用
- 确保每个工作流至少有一个引用关系，保证UI显示的完整性
- 默认引用格式：`{workflowId}_default_node`

### 5.2 多存储支持

- 支持SQLite数据库存储
- 支持JSON文件存储
- 自动适配不同存储类型的键格式
- 使用 `ReferenceStorageFactory` 统一创建存储实例

### 5.3 事件驱动支持

- 支持事件驱动的引用管理
- 提供可观察的引用管理器实现 (`ObservableReferenceManager`)
- 支持引用关系的实时更新
- 提供批量变更事件通知

### 5.4 引用校验系统

#### 校验层级

| 校验层级 | 说明 | 校验内容 |
|---------|------|---------|
| `Project` | 项目级校验 | 项目内所有模块的引用完整性 |
| `Module` | 模块级校验 | 单个模块的引用完整性 |
| `Function` | 函数级校验 | 函数间的依赖引用 |
| `File` | 文件级校验 | 文件间的引用关系 |

#### 校验流水线 (ValidationPipeline)

校验流水线提供统一的校验流程编排，支持并行校验和可插拔的校验规则。

**内置校验规则**：
| 规则名称 | 层级 | 说明 |
|---------|------|------|
| `ExistenceValidationRule` | Module | 校验引用目标是否存在 |
| `CycleDetectionValidationRule` | Project | 检测循环依赖 |
| `ReferenceCountValidationRule` | Module | 校验引用数量是否超限 |

**使用示例**：
```csharp
var pipeline = ValidationPipelineFactory.Create();

// 添加自定义规则
pipeline.AddRule(new CustomValidationRule());

// 执行校验
var result = await pipeline.ValidateAsync("module1", ValidationLevel.Module);

// 批量校验
var allResult = await pipeline.ValidateAllAsync();
```

## 6. 常见问题及解决方案

### 6.1 工作流列表显示问题

- **问题**：重新注册工作流后，所有工作流都显示为同一个
- **原因**：存储层键处理逻辑不一致
- **解决方案**：修改 `GenericWorkflowStorage.GetAllWorkflowIdsAsync()` 方法，支持无前缀的键

### 6.2 引用关系缺失问题

- **问题**：工作流的引用关系与实际工作流结构不匹配
- **原因**：引用管理器返回空引用关系
- **解决方案**：修改 `WorkflowReferenceManager.GetWorkflowReferencesAsync()` 方法，添加默认引用关系

### 6.3 节点显示问题

- **问题**：工作流只显示一个节点
- **原因**：数据库中没有存储节点信息，或引用管理器没有获取到节点引用
- **解决方案**：确保工作流注册时正确存储节点信息，或使用默认节点引用

## 7. 代码优化建议

### 7.1 引用管理优化

1. **缓存机制**：添加引用关系缓存，提高性能
   - 使用 `MemoryCache` 或 `ConcurrentDictionary` 缓存热点数据
   - 设置合理的过期时间，避免数据不一致

2. **批量操作**：支持批量注册和清除引用，减少数据库操作

## 10. 总结

工作流引用管理系统是FrameManage项目的核心功能之一，它通过统一的引用管理接口，为工作流提供了完整的引用关系管理能力。系统支持多种存储方式，提供了自动默认引用、事件驱动支持等特性，确保了工作流引用关系的完整性和一致性。

通过优化引用管理流程、存储层实现和UI显示逻辑，系统能够高效地管理工作流的引用关系，为用户提供直观、完整的工作流可视化体验。

### 关键设计模式

1. **工厂模式**：`WorkflowReferenceManagerFactory`、`ReferenceManagerFactory` 统一创建实例
2. **策略模式**：支持多种存储类型（SQLite、JSON、内存）
3. **观察者模式**：`ObservableReferenceManager` 提供事件通知
4. **模板方法模式**：校验系统支持多层级校验

### 扩展点
