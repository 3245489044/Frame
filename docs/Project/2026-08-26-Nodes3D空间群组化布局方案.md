## 摘要

**结论先行：以 Engine 为主体构建自包含 3D 查看模块（路线 B2），Agent 只提供宿主位置。** 关键事实——Engine 项目已通过 `$(OperationCsproj)`（`CsharpPrj\Operation\Operation.csproj` 聚合项目）直接依赖数据层：`DataStoreDriven\Graph\ReferenceGraphCoordinator`（图库）、`DataStoreDriven\Sqlite\SqliteNodeStore` / `SqliteHistoryStore`（nodes/histories 真源）、`HierarchyMethod\History\HistoryRelationManager` / `IHistoryRelationManager`（三层归属读接口）**全部已在 Engine 依赖链内**。因此数据读取无需绕 Agent 的 `AgentUiHost` / FileDriven 门面，Engine 侧直接装配数据层即可。

工作分两半：

1. **布局算法**（构建于 `CsharpPrj\Share\LayoutAnalysis`，复用已有逻辑）：三层归属树 → 嵌套球域布局，纯计算、可独立单测；复用 `RelationCalculator` / `LayoutGraphBuilder` / `LayoutTreeTraversal` / `UIOverlapDetector`，坐标生成作为 LayoutAnalysis 内新增模块。
2. **Engine 侧自包含模块**：数据装配（开库 + 注入 store/coordinator）→ 三层归属树抽取 → 几何渲染通路（引擎当前只有 RayMarch/Slice，**无几何渲染，必须补**）；布局结果由 LayoutAnalysis 计算后供 Engine 消费。
3. **Agent 侧宿主**（最小改动）：AgentRuntimeUI 新增「⑤ 3D 视图」tab，放一个 `EngineRenderControl` 占位；Engine 模块同进程运行，可与 Agent 实时联动。

> 相比 v1（AgentRuntimeUI 嵌 enginecanvas + Agent 门面读数据）：数据/布局/渲染职责分离且各归其位——布局收敛到 `Share\LayoutAnalysis` 复用现有逻辑，Engine 只做装配/抽取/渲染，不污染 FileDriven 声明式体系，且数据通道本就通着。

## 一、背景与目标

### 1.1 背景

- 主对话框目前用 WebView2（`htmlviewer`）渲染 2D 会话树（历史 → 任务两级树 + 气泡历史），文本密集场景下这是合理选择。
- nodes / task / history 三层归属关系天然是**树 + 拓扑**结构，2D 列表只能串行表达；3D 空间能一眼呈现「几个历史、每个历史几个任务、每个任务产出哪些节点、node 间引用关系」。
- 架构选择过程：v1 曾考虑把 3D 视图塞进 AgentRuntimeUI 的 FileDriven 声明体系；确认 Engine 已依赖 Operation 数据层后，改走 **B2：Engine 自包含模块 + 宿主复用**。布局算法独立收敛到 **`CsharpPrj\Share\LayoutAnalysis`**（复用已有关系计算/图聚类/树遍历逻辑），Engine 只负责数据装配、归属抽取与渲染。

### 1.2 目标

1. Engine 侧自装配数据层（开图库 + 注入 store/coordinator），从图库读出 history → task → node 三层归属树（只读）。
2. 用算法把三层结构自动排布到 3D 空间：history 大球域互斥、task 子域分块、node 叶在域内聚集。
3. 补几何渲染通路，在 Engine 视口渲染出来，复用现有相机姿态。
4. AgentRuntimeUI 新增 tab 作宿主（最小改动），与 Agent 同进程联动。

### 1.3 非目标（本期不做）

- 不改动现有 WebView2 主对话框（两条渲染路线共存）。
- 不做 3D 文本标签（引擎无文本渲染层，属后续能力储备）。
- 不写任何图库边（纯读侧投影）。
- 不走 B1（Engine 独立 EXE）：跨进程取数、实时联动断裂，收益最低。

## 三、架构方案（B2）

### 3.1 模块边界

```
Share/LayoutAnalysis（布局，复用已有逻辑）
 ├─ 归属/关系    RelationCalculator.CalculateHierarchyRelations（泛型，直接复用）
 ├─ 图/聚类      LayoutGraphBuilder + GraphFoundation（群组/散点识别）
 ├─ 树遍历      LayoutTreeTraversal（泛型树工具）
 └─ 新增         NodeClusterLayout3D：嵌套球域 + 球填充（坐标生成）
                       │ 布局结果（三维坐标）
Engine 侧（自包含）
 ├─ 数据装配    NodeClusterDataAssembly：开库 + 注入 store/coordinator
 ├─ 数据抽取    NodeClusterProjector：图库只读 → 三层归属树
 └─ 渲染        MeshRenderSystem + PrimitiveMeshGenerator → Engine 帧循环
                       │
Agent 侧（宿主，最小改动）        EngineRenderControl（同进程嵌入）
 └─ AgentRuntimeUI 新增 tab「⑤ 3D 视图」
```

- LayoutAnalysis（`CsharpPrj\Share\LayoutAnalysis`，命名空间 `Modules.LayoutAnalysis`）产出布局结果；Engine 模块不依赖 Agent 的 FileDriven/AgentUiHost，只依赖 Operation 数据层（已在引用链内）。
- Agent 只负责提供一个放 `EngineRenderControl` 的位置 + 可选的刷新触发（复用现有事件通道）。

### 3.2 数据装配（Engine 侧组合根）

- 复用 `DatabaseBootstrapper.ResolveConfigDirectory` 的路径约定（agent-config.json / graph-log.db 定位规则），在 Engine 侧写一个轻量装配函数（纯组合，无业务逻辑）。
- 装配产物：`SqliteNodeStore` + `SqliteHistoryStore` + `ReferenceGraphCoordinator` + `HistoryRelationManager`，生命周期跟随模块（打开/关闭，Dispose 对齐）。
- 空守卫：库不存在/装配失败时模块给出空视图 + 提示，不阻塞宿主 UI（对齐现有「可空守卫」约定）。

### 3.3 数据抽取：三层归属树

```
TreeNode3D(history)
 ├─ 子群 task：沿 history_owns_task 出边
 │    └─ 叶子 node：沿 cross_db_link（主）/ node_to_node（辅）出边
 └─ 散点 node：沿 history_owns_node 出边（跨任务直挂）
```

- 输入：`HistoryRelationManager` + `ReferenceGraphCoordinator` 只读查询。
- 输出：内存 `HistoryGroup[]`，每项含 `taskGroups` 与 `scatterNodes`；作为 `Share\LayoutAnalysis` 布局的输入（经 `CalculateHierarchyRelations` 产出 `HierarchyRelation[]`）。
- 缓存策略：视图打开/刷新时一次性重建（节点规模小，无需增量）。

### 3.4 布局算法：构建于 Share/LayoutAnalysis（复用已有逻辑）

**位置**：`CsharpPrj\Share\LayoutAnalysis`（命名空间 `Modules.LayoutAnalysis`），而非 Engine 侧。新增 3D 坐标生成器（如 `Spatial3D/NodeClusterLayout3D`），最大化复用已有逻辑：

| 已有逻辑 | 位置 | 复用方式 |
|----------|------|----------|
| 层级关系计算 | `RelationCalculator.CalculateHierarchyRelations<T>(elements, getId, getParentId)` | **泛型方法，直接复用**：传入三层归属（history→task→node），产出 `HierarchyRelation[]` |
| 图构建/聚类 | `LayoutGraphBuilder.Build` + GraphFoundation（CoreGraph / GraphTopology） | 归属树灌入 `LayoutCollectionResult`，复用连通分量聚类识别群组/散点、拓扑排序 |
| 树遍历 | `LayoutTreeTraversal`（TreeWalker / TreeIndex） | 泛型树工具，遍历三层树 |
| 重叠/互斥 | `UIOverlapDetector.OverlapCalculator` | 群组互斥验证框架（现有 2D 矩形重叠，3D 化扩展为球域重叠） |
| 数据模型 | `HierarchyRelation` / `NormalizedEntity` / `LayoutCollectionResult` / `LayoutGraphContext` | 直接复用；`ElementPosition` 无 Z 维，新增 3D 位置类型 |

**新增部分（LayoutAnalysis 内）**：`NodeClusterLayout3D` 负责坐标生成（布局语义不变）——

```
第 1 层  history 群 → 大球域，群间互斥不重叠
第 2 层  task 群    → 所属 history 球域内按成员数划分子域
第 3 层  node 叶    → 所属 task 子域内 Fibonacci 球面/均匀填充聚集
散点    node       → history 球域外围环带分布
```

| 层次 | 算法 | 性质 |
|------|------|------|
| history 群位置 | 圆环/网格 + 最小间距约束 | 群间稳定可读 |
| task 子域 | 球内等比切分（按成员数分配子球半径） | 群内数量感直观 |
| node 聚集 | 子球内 Fibonacci 球面/随机填充 | 聚集但不重叠 |
| 可选增强 | 群内 node 间引用边（Calls/NodeToNode）力导向微调 | 二期，反映真实关联 |

布局算法纯计算、与渲染解耦，可独立单测（验证：群内聚集半径约束、群间互斥、散点落环带）。

> 注意：LayoutAnalysis 现有能力是 2D 矩形布局**分析**（收集/验证，不生成坐标）；3D 布局**生成**（坐标排布 + 球域互斥）是本次在 LayoutAnalysis 内的新增，关系/聚类/树遍历骨架复用现有实现，不破坏现有 2D 分析链路。

### 3.5 渲染侧：补几何渲染通路

1. **几何生成**：`PrimitiveMeshGenerator`——球体/立方体（或点精灵）→ 顶点/索引缓冲 → 注册为 `MeshAsset`。
2. **网格渲染系统**：遍历带 `MeshRendererComponent` 的实体，经 `TransformSystem` 世界矩阵 + `CameraComponent` 视图/投影矩阵，提交 `D3D11RenderContext` 绘制（复用现有 IRenderDevice/IRenderContext/IShader 抽象，加最简单纯色/轮廓 shader）。
3. **接入帧循环**：`EngineHost.Frame` 新增几何模式（与 RayMarch/Slice 并列），或作为覆盖层叠在切片场景上。
4. **视口**：`EngineRenderControl` 承载；相机复用 `Engine_SetCamera`。

### 3.6 宿主：AgentRuntimeUI 新增 tab

- AgentRuntimeUI 分页增加「⑤ 3D 视图」tab，内容为 `enginecanvas`（EngineRenderControl）。
- 与 Agent 同进程 → Agent 运行后可通过现有事件通道触发刷新（重新抽取 + 布局）。
- 主对话框 WebView2 保留不动。

### 3.7 交互（可选，分档实现）

| 档 | 能力 | 依赖 |
|----|------|------|
| L0 | 纯自动环绕展示 | 相机时间驱动旋转（最简） |
| L1 | 鼠标拖拽环绕 + 滚轮缩放 | WinForms 鼠标事件 → `Engine_SetCamera` |
| L2 | 点选 node 看详情 | 射线拾取（视口反投影 → 命中 node → 侧栏显示 Json/NodeType） |

建议先 L0/L1，L2 视需要再补。

## 六、风险与待确认

| 风险 | 说明 | 缓解 |
|------|------|------|
| 几何渲染通路缺失（最大） | 引擎从未画过场景网格，矩阵/着色器链路需从零验证 | 步骤①独立小步先行，先画一个球 |
| LayoutAnalysis 现有为 2D 分析 | 现有逻辑只分析 2D 矩形布局、不生成坐标，`ElementPosition` 无 Z 维 | 复用关系/聚类/树遍历骨架；坐标生成与 3D 位置类型作为新增模块，不破坏现有 2D 分析 |
| 数据装配复刻 | Agent 组合根现有开库/注入逻辑，B2 需在 Engine 侧复刻路径约定 | 复用 `DatabaseBootstrapper.ResolveConfigDirectory` 约定，纯组合无业务逻辑 |
| 节点规模 | node 数千时逐实体绘制压力 | 实例化/合并静态几何；本期先按规模 ≤ 千级设计 |
| 群组视觉区分 | 无文本标签，群组边界靠球壳/颜色 | 半透明球壳 + 群组色编码 |
| 3D 文本 | 引擎无文本渲染 | 本期不做；后续能力储备 |
| 数据规模抖动 | 布局重算成本 | 打开/刷新时一次性计算，缓存结果 |
