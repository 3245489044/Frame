# 函数注册表统一迁移方案

> **文档状态**：方案设计稿（已评审）→ 代码实现已完成  
> **创建日期**：2026-06-12  
> **最后更新**：2026-06-12  
> **涉及项目**：`Operation/FunctionStorage`、`Share/CommandFramework`、`BasicMethod/FunctionExecution`、`FileDriven.Execution`

---

## 1. 背景与现状

### 1.1 问题描述

当前系统中存在 **3 个并行的函数注册表实例**，它们各自持有独立的函数集合，互不共享。这导致：

- **架构冗余**：三个注册表实例各自独立，函数注册分散
- **注册不一致**：新增函数时需要决定注册到哪个实例，容易出错
- **查找失败风险**：如果管线中的 `FunctionExecutor` 被错误指向其他实例，将找不到已注册的函数
- **维护成本高**：开发者需要理解三个注册表的关系才能正确使用

### 1.2 三个并行注册表实例

| # | 注册表实例 | 所在文件 | 底层类型 | 注册内容 | 创建方式 |
|---|-----------|---------|---------|---------|---------|
| 1 | `FunctionStorageRegistry._registry` | `Operation/FunctionStorage/FunctionStorageRegistry.cs:27` | `Share.Registry.FunctionRegistry` | 数学函数（Add/Plus/Subtract/Minus/Multiply/Divide）+ UI 函数（ClearOutput/ExecuteWorkflow 等 19 个）+ 工作流函数 | `new FunctionRegistry()` |
| 2 | `CommandFrameworkHost.FunctionRegistry` | `Share/CommandFramework/CommandFrameworkHost.cs:168` | `Share.Registry.FunctionRegistry` | 由 `CommandFrameworkUsage` 通过 `RegisterFunction()` 注册的函数 | `new FunctionRegistry()` |
| 3 | `FunctionExecutionFramework._defaultRegistry` | `BasicMethod/FunctionExecution/FunctionRegistry.cs:571` | `UniversalWorkflowFramework.FunctionExecution.FunctionRegistry` | `BuiltInUnits.RegisterAll()`（ToString/ToInt/ToFloat/ToDouble/ToBool/StringJoin/StringSplit/ListCount/DictGet） | `Lazy<FunctionRegistry>` 延迟初始化 |

### 1.3 底层类型差异

- **实例 1 和 2**：使用 `Share.Registry.FunctionRegistry`（基于 `MetaMapRegistryBase<string, Delegate, FunctionDescriptor>`）
- **实例 3**：使用 `UniversalWorkflowFramework.FunctionExecution.FunctionRegistry`（基于 `ConcurrentDictionary`，完全不同的实现），且注册的是 `IFunctionUnit` 对象而非 `Delegate`

### 1.4 运行时依赖关系

```
ExecuteFunctionStage (Share/CommandFramework/Pipeline/Stages)
  └── 通过 SharedData["FunctionExecutor"] 获取执行器
       └── 实际注入的是 FunctionStorageRegistry.Executor（实例 1 的执行器）
            └── 所以运行时能正确找到数学函数

CommandFrameworkUsage.FunctionRegistry（实例 2）
  └── 通过 CommandFrameworkUsage.RegisterFunction() 注册
       └── 但 FileDriven 管线不使用此实例执行函数

FunctionExecutionFramework._defaultRegistry（实例 3）
  └── 通过 FunctionExecutionFramework.ExecuteAsync() 调用
       └── 与实例 1 和 2 完全隔离
```

---

## 2. 迁移目标

将三个并行的函数注册表实例**统一为 `FunctionStorageRegistry` 一个入口**，实现：

1. **单一事实源**：所有函数（数学、UI、工作流、类型转换）统一注册到 `FunctionStorageRegistry`
2. **架构清晰**：`FunctionStorage` 作为唯一的注册表中心，`Share/CommandFramework` 不直接引用 `FunctionStorage`
3. **向后兼容**：`FunctionExecutionFramework.ExecuteAsync()` 等现有 API 保持可用
4. **最小改动**：不改变现有调用方的使用方式

---

## 3. 迁移方案（最终版）

### 3.1 总体架构

```
迁移前：
  FunctionStorageRegistry._registry  ─── 独立实例 1（数学/UI/工作流函数）
  CommandFrameworkHost.FunctionRegistry ─ 独立实例 2（CommandFramework 内部使用）
  FunctionExecutionFramework._defaultRegistry ─ 独立实例 3（BuiltInUnits 类型转换）

迁移后：
  FunctionStorageRegistry ─── 唯一注册表中心（持有 FunctionRegistry 唯一实例）
    ├── MathLibrary.RegisterAll()         → 数学函数（Add/Plus/Subtract/Minus/Multiply/Divide）
    ├── UIToolbox.RegisterAll()           → UI 操作函数（ClearOutput/ExecuteWorkflow 等 19 个）
    ├── WorkflowLibrary.RegisterAll()     → 工作流函数（CodeReviewWorkflow 等）
    └── BuiltInUnits.RegisterAll()        → 类型转换单元（ToString/ToInt/ToFloat/ToDouble/ToBool/StringJoin/StringSplit/ListCount/DictGet）
         ↑ FunctionStorageRegistry 实现 Core.IFunctionRegistry 接口，可直接传入

  CommandFrameworkHost  ─── 不再持有 FunctionRegistry 实例
  FunctionExecutionFramework ─── 不再自动注册 BuiltInUnits
```

### 3.2 架构层次

```
                    ┌─────────────────────────────┐
                    │   FileDriven.Execution       │  ← 唯一引用 FunctionStorage
                    │  (InitializeFramework)       │
                    │  ① 创建唯一实例              │
                    │  ② 注册所有函数              │
                    │  ③ 注入 SharedData           │
                    └──────────┬──────────────────┘
                               │
              ┌────────────────▼──────────────────┐
              │   Operation/FunctionStorage        │  ← 唯一的注册表中心
              │   FunctionStorageRegistry          │
              │     ├── MathLibrary                │
              │     ├── UIToolbox                  │
              │     ├── WorkflowLibrary            │
              │     └── BuiltInUnits.RegisterAll() │  ← 直接传入 FunctionStorageRegistry
              └────────────────┬──────────────────┘
                               │ 持有 FunctionRegistry 唯一实例
                               ▼
              ┌───────────────────────────────────┐
              │   Share.Registry                   │
              │   FunctionRegistry                 │  ← 底层存储
              └───────────────────────────────────┘

管线执行时：
  ExecuteFunctionStage
    └── SharedData["FunctionExecutor"]
         └── FileDrivenExecutor 注入的 FunctionStorageRegistry.Executor
```

### 3.3 详细改动

#### 改动 1：`Operation/FunctionStorage/FunctionStorageRegistry.cs`

**目标**：改造为唯一的注册表中心，支持外部注入共享实例，实现 `Core.IFunctionRegistry` 接口以支持 `BuiltInUnits.RegisterAll()` 直接传入。

```csharp
// ============================================================
// FunctionStorageRegistry.cs — 统一函数注册入口（唯一注册表中心）
//
// 作为 FunctionStorage 中所有 Library 类的统一注册/执行入口，
// 内部委托给 Share.Registry.FunctionRegistry 实现。
//
// ★ FunctionStorage 是系统中唯一的注册表中心 ★
//   - CommandFrameworkHost 不再创建 FunctionRegistry 实例
//   - FunctionExecutionFramework 不再自动注册 BuiltInUnits
//   - 所有函数统一通过此入口注册
//
// ★ 改造要点 ★
//   1. _registry / _executor 改为延迟初始化，支持外部注入
//   2. 新增 Initialize() 方法，由 FileDrivenExecutor 在初始化时调用
//   3. 实现 Core.IFunctionRegistry 接口，支持 BuiltInUnits.RegisterAll() 直接传入
//   4. 新增 TryGetUnit() 方法，供需要查找 IFunctionUnit 的场景使用
// ============================================================

using System.Collections.Concurrent;
using CommandFramework.Abstractions;
using CommandFramework.Execution;
using Share.Registry;
using UniversalWorkflowFramework.FunctionExecution.Core;
// ★ 使用 using 别名消除 CommandFramework.Abstractions 与 Share.Registry 之间的命名冲突 ★
using IFunctionExecutionResult = Share.Registry.IFunctionExecutionResult;
using IFunctionDescriptor = Share.Registry.IFunctionDescriptor;

namespace FunctionStorage
{
    /// <summary>
    /// 统一函数注册入口（唯一注册表中心）
    /// <para>所有函数统一注册到此入口，供 UI 事件、工作流引擎、CLI 命令调用</para>
    /// <para>★ 系统中唯一的 FunctionRegistry 持有者 ★</para>
    /// </summary>
    public static class FunctionStorageRegistry : IFunctionRegistry  // ★ 实现 IFunctionRegistry 接口
    {
        private static Share.Registry.FunctionRegistry? _registry;
        private static CommandFramework.Execution.FunctionExecutor? _executor;
        private static ConcurrentDictionary<string, IFunctionUnit>? _units;
        private static readonly object _lock = new();

        /// <summary>获取底层注册表实例（供高级场景使用）</summary>
        public static Share.Registry.FunctionRegistry Registry
        {
            get
            {
                if (_registry == null) InitializeDefault();
                return _registry!;
            }
        }

        /// <summary>获取底层执行器实例（供高级场景使用）</summary>
        public static CommandFramework.Execution.FunctionExecutor Executor
        {
            get
            {
                if (_executor == null) InitializeDefault();
                return _executor!;
            }
        }

        /// <summary>
        /// 由外部在框架初始化时调用，传入共享实例
        /// <para>FileDrivenExecutor.InitializeFramework() 中调用此方法</para>
        /// <para>调用后，FunctionStorageRegistry 持有系统中唯一的 FunctionRegistry 实例</para>
        /// </summary>
        public static void Initialize(Share.Registry.FunctionRegistry registry, CommandFramework.Execution.FunctionExecutor executor)
        {
            ArgumentNullException.ThrowIfNull(registry);
            ArgumentNullException.ThrowIfNull(executor);
            lock (_lock)
            {
                _registry = registry;
                _executor = executor;
                _units ??= new ConcurrentDictionary<string, IFunctionUnit>(
                    StringComparer.OrdinalIgnoreCase);
            }
        }

        private static void InitializeDefault()
        {
            lock (_lock)
            {
                _registry ??= new Share.Registry.FunctionRegistry();
                _executor ??= new CommandFramework.Execution.FunctionExecutor(_registry);
                _units ??= new ConcurrentDictionary<string, IFunctionUnit>(
                    StringComparer.OrdinalIgnoreCase);
            }
        }

        /// <summary>注册函数（委托方式）</summary>
        public static void Register(string name, Delegate function, string? description = null)
        {
            Registry.Register(name, function, description);
        }

        /// <summary>注册函数（IFunctionUnit 方式，适配 BuiltInUnits）</summary>
        public static void Register(IFunctionUnit unit)
        {
            ArgumentNullException.ThrowIfNull(unit);
            if (string.IsNullOrWhiteSpace(unit.Name))
                throw new ArgumentException("Function unit name cannot be empty", nameof(unit));

            // 同时注册为 Delegate 和 IFunctionUnit
            Registry.Register(unit.Name, (Func<object, Task<object>>)(async (input) =>
            {
                var result = await unit.ExecuteAsync(input);
                return result.Value!;
            }), unit.Description);

            // 额外存储 IFunctionUnit 引用
            var units = _units;
            if (units == null) { InitializeDefault(); units = _units!; }
            units[unit.Name] = unit;
        }

        /// <summary>尝试获取 IFunctionUnit</summary>
        public static bool TryGetUnit(string name, out IFunctionUnit unit)
        {
            var units = _units ?? new ConcurrentDictionary<string, IFunctionUnit>(
                StringComparer.OrdinalIgnoreCase);
            return units.TryGetValue(name, out unit!);
        }

        /// <summary>注销函数</summary>
        public static void Unregister(string name)
        {
            Registry.Unregister(name);
            _units?.TryRemove(name, out _);
        }

        /// <summary>执行函数</summary>
        public static async Task<IFunctionExecutionResult> ExecuteAsync(string functionName, object? parameters = null)
        {
            return await Executor.ExecuteAsync(functionName, parameters);
        }

        /// <summary>执行委托</summary>
        public static async Task<IFunctionExecutionResult> ExecuteAsync(Delegate function, object? parameters = null)
        {
            return await Executor.ExecuteAsync(function, parameters);
        }

        /// <summary>是否包含指定函数</summary>
        public static bool Contains(string name)
        {
            return Registry.Contains(name);
        }

        /// <summary>获取所有已注册的函数名称</summary>
        public static IEnumerable<string> GetRegisteredNames()
        {
            return Registry.GetRegisteredNames();
        }

        /// <summary>尝试获取函数描述符</summary>
        public static bool TryGetDescriptor(string name, out IFunctionDescriptor descriptor)
        {
            return Registry.TryGetDescriptor(name, out descriptor);
        }

        /// <summary>清空所有注册</summary>
        public static void Clear()
        {
            Registry.Clear();
            _units?.Clear();
        }
    }
}
```

## 5. 风险与注意事项

### 5.1 项目依赖关系

- `Share/CommandFramework` **不引用** `Operation/FunctionStorage`，通过 `SharedData` 和接口解耦
- `Operation/FunctionStorage` 已引用 `BasicMethod/FunctionExecution`，可直接使用 `IFunctionRegistry` 接口和 `BuiltInUnits` 类
- `FileDriven.Execution` 是唯一引用 `FunctionStorage` 的项目，负责初始化触发

### 5.2 初始化顺序

`FunctionStorageRegistry` 必须在 `MathLibrary.RegisterAll()` 等注册调用**之前**完成初始化。由于采用延迟初始化，第一次调用 `FunctionStorageRegistry.Register()` 时会自动创建实例。关键顺序：

1. `MathLibrary.RegisterAll()` → 触发 `FunctionStorageRegistry` 延迟初始化
2. `UIToolbox.RegisterAll()` → 注册到同一实例
3. `BuiltInUnits.RegisterAll(FunctionStorageRegistry)` → 注册到同一实例
4. `CommandFrameworkUsage.Reset()` → 初始化 CommandFramework（不再创建注册表）
5. `SharedData["FunctionExecutor"] = FunctionStorageRegistry.Executor` → 注入执行器

### 5.3 向后兼容

- `FunctionStorageRegistry.Register()` 签名不变，所有调用方无需修改
- `CommandFrameworkUsage.RegisterFunction()` **废弃**，调用方需改为 `FunctionStorageRegistry.Register()`
- `FunctionExecutionFramework.ExecuteAsync()` 仍然可用，但 BuiltInUnits 不再自动注册到其内部注册表
- `ExecuteFunctionStage` 通过 `SharedData["FunctionExecutor"]` 获取执行器，行为不变

### 5.4 测试影响

如果测试项目直接使用 `FunctionExecutionFramework` 并依赖 BuiltInUnits，需要确保测试初始化时调用 `BuiltInUnits.RegisterAll(FunctionStorageRegistry)`。
