# 事件处理逻辑简化方案

## 1. 问题背景

GUI 模式下，手动点击按钮（如 `addButton`）时出现 `No click binding found for 'addButton'` 错误，而通过脚本执行 `click addButton` 却能成功。

**根因**：事件处理逻辑过于复杂，存在两条不同的执行路径，导致绑定查找结果不一致。

---

## 2. 当前架构的复杂性全景

### 2.1 两条执行路径

```
脚本路径：
  RunPipeline() → CreatePipeline() → PipelineFactory.CreateFileDrivenPipeline()
    → BuildCommandPipeline() → bindingFinder 委托 → 执行 click 命令

手动点击路径：
  IEventPipelineExecutor.Execute("addButton", "click", "")
    → BuildEventCommand("addButton", "click") → "click addButton"
    → GetOrCreateSingleCommandPipeline() → PipelineFactory.BuildCommandPipeline()
    → bindingFinder 委托 → 执行 click 命令
```

两条路径都调用 `BuildCommandPipeline()`，但传入的 `BindingResolver` 来源不同，导致绑定查找结果不一致。

### 2.2 两个 IEventBindingInfo 接口

| 接口 | 命名空间 | 属性 |
|------|---------|------|
| `IEventBindingInfo` | `EventTriggerFramework.Abstractions` | `FunctionNames`, `Inputs`, `Output` |
| `IEventBindingInfo` | `CommandFramework.Abstractions` | `CommandName`, `FunctionName`, `Parameter`, `Target` |

**适配器**：
- `EventTriggerToCommandBindingAdapter` — ETF → Cmd（53 行）
- `CommandFrameworkBindingInfoAdapter` — Cmd → ETF（19 行）

两个接口语义重叠，靠双向适配器桥接，增加了理解和调试成本。

### 2.3 两个 IEventBindingResolver 接口

| 接口 | 方法 |
|------|------|
| `IEventBindingResolver` (ETF) | `FindEventBinding()`, `FindEventFunction()`, `GetControlType()`, `ResolveEventType()` |
| `IEventBindingResolver` (Cmd) | `FindBinding()`, `GetLoadedConfigsDictionary()` |

`EventBindingResolver` 同时实现两个接口，通过 `as` 转换和显式接口实现来区分。

### 2.4 多层委托包装

`bindingFinder` 委托的创建链：

```
方式一（PipelineFactory.BuildCommandPipeline）：
  bindingResolver.FindEventBinding(controlName, eventType)  // ETF 接口
  → new EventTriggerToCommandBindingAdapter(info)           // 适配为 Cmd 接口

方式二（ToFindBindingFunc 扩展方法）：
  resolver.FindEventBinding(controlName, eventType)
  → return (FunctionName, Inputs, Output)  // 元组
```

两种包装方式并存，功能重叠。

### 2.5 非事件命令双重注册

- `ExecuteCommandStage.HandleNonEvent()` 中硬编码了 `sideload/sleep/close/exit/echo` 等命令的处理逻辑
- `FileDrivenExecutor.RegisterNonEventCommands()` 中又通过 `FunctionStorageRegistry.NonEventRegistry` 注册了同样的命令

同一套命令在两个地方有实现，维护时需要同步修改两处。

### 2.6 废弃代码残留

`EventTriggerFramework/Pipeline/EventBindingStage.cs` 中的 `FindBindingStage` 已标记为 `[Obsolete]`，但仍然存在于代码库中。

---

## 3. 简化目标

1. **消除两条执行路径的差异** — 手动点击路径复用脚本路径的完整管线
2. **消除接口冗余** — 合并两个 `IEventBindingInfo` 和两个 `IEventBindingResolver`
3. **消除适配器** — 移除 `EventTriggerToCommandBindingAdapter` 和 `CommandFrameworkBindingInfoAdapter`
4. **消除非事件命令双重注册** — 统一通过 `FunctionStorageRegistry.NonEventRegistry` 查找
5. **清理废弃代码** — 删除 `[Obsolete]` 的 `FindBindingStage`

---

## 4. 简化方案

### 4.1 步骤一：统一两条执行路径（P0 — 修复 Bug）

**目标**：手动点击路径复用脚本路径的完整管线，消除两条路径的差异。

**当前代码**：

`ExecutionPipelineEntry.cs` 中 `IEventPipelineExecutor.Execute` 方法：

```csharp
public async Task<CommandFileLineResult> Execute(string controlName, string eventType, string parameter)
{
    var command = BuildEventCommand(controlName, eventType);
    var commandPipeline = GetOrCreateSingleCommandPipeline();
    var context = CreateMinimalContext(command, targetForm);
    await commandPipeline.ExecuteAsync(context, ct);
    // ...
}
```

**修改方案**：

将手动点击路径改为复用 `RunPipeline` 的完整管线：

```csharp
public async Task<CommandFileLineResult> Execute(string controlName, string eventType, string parameter)
{
    var command = BuildEventCommand(controlName, eventType);
    // 复用完整管线，而不是创建独立的单命令管线
    var pipeline = GetOrCreateFullPipeline();
    var context = CreateFullContext(command, targetForm);
    await pipeline.ExecuteAsync(context, ct);
    // ...
}
```

**关键点**：确保 `GetOrCreateFullPipeline()` 和脚本路径的 `CreatePipeline()` 返回完全相同的管线实例。

### 4.2 步骤二：合并 IEventBindingInfo 接口（P2）

**目标**：消除两个 `IEventBindingInfo` 接口的冗余，移除适配器。

**方案**：保留 `EventTriggerFramework.Abstractions.IEventBindingInfo`，让 `CommandFramework` 直接引用它。

**修改**：

1. 在 `CommandFramework.Abstractions` 中添加对 `EventTriggerFramework.Abstractions.IEventBindingInfo` 的引用
2. 将 `CommandFramework.Abstractions.IEventBindingInfo` 标记为 `[Obsolete]`，指向 ETF 版本
3. 移除 `EventTriggerToCommandBindingAdapter`
4. 移除 `CommandFrameworkBindingInfoAdapter`
5. 更新所有引用处

**合并后的接口**：

```csharp
// EventTriggerFramework.Abstractions.IEventBindingInfo（保留）
public interface IEventBindingInfo
{
    string ControlName { get; }
    string EventType { get; }
    string FunctionName { get; }
    List<string> FunctionNames { get; }
    List<string> Inputs { get; }
    string Output { get; }
}

// CommandFramework.Abstractions.IEventBindingInfo（废弃）
[Obsolete("Use EventTriggerFramework.Abstractions.IEventBindingInfo instead")]
public interface IEventBindingInfo { /* ... */ }
```

### 4.3 步骤三：合并 IEventBindingResolver 接口（P2）

**目标**：消除两个 `IEventBindingResolver` 接口的冗余。

**方案**：保留 `EventTriggerFramework.Abstractions.IEventBindingResolver`，`CommandFramework` 直接使用它。

**合并后的接口**：

```csharp
// EventTriggerFramework.Abstractions.IEventBindingResolver（保留并扩展）
public interface IEventBindingResolver
{
    IEventBindingInfo? FindEventBinding(string controlName, string eventType);
    IEventBindingInfo? FindEventFunction(string functionName);
    Type? GetControlType(string controlName);
    string ResolveEventType(string controlName, string eventType);
    IDictionary<string, object> GetLoadedConfigsDictionary();
    IEventBindingInfo? FindBinding(string controlName, string action);
}
```

### 4.4 步骤四：消除非事件命令双重注册（P1）

**目标**：统一非事件命令的处理方式。

**方案**：移除 `ExecuteCommandStage.HandleNonEvent()` 中的硬编码处理逻辑，统一通过 `FunctionStorageRegistry.NonEventRegistry` 查找处理函数。

**修改**：

```csharp
// ExecuteCommandStage.cs
private async Task HandleNonEvent(CommandContext context, string action, string? target)
{
    // 统一通过 NonEventRegistry 查找处理函数
    var handler = FunctionStorageRegistry.NonEventRegistry.GetHandler(action);
    if (handler != null)
    {
        await handler(context);
        context.SetStageResult(Name, true);
    }
    else
    {
        context.SetStageResult(Name, false, $"Unknown non-event command: {action}");
    }
}
```

**同时**：确保 `FileDrivenExecutor.RegisterNonEventCommands()` 中注册了所有需要的非事件命令处理函数。

### 4.5 步骤五：消除委托双重包装（P3）

**目标**：统一 `bindingFinder` 委托的创建方式。

**方案**：统一使用 `Func<string, string, IEventBindingInfo?>` 委托，消除 `ToFindBindingFunc()` 扩展方法。

**修改**：

1. 移除 `EventBindingResolverExtensions.ToFindBindingFunc()` 扩展方法
2. 所有使用 `ToFindBindingFunc()` 的地方改为直接使用 `bindingFinder` 委托
3. `PipelineFactory.BuildCommandPipeline()` 中统一使用 `bindingFinder` 委托

### 4.6 步骤六：清理废弃代码（P4）

**目标**：删除已标记为 `[Obsolete]` 的代码。

**删除**：
- `EventTriggerFramework/Pipeline/EventBindingStage.cs` 中的 `FindBindingStage` 类
- `CommandFramework.Pipeline.PipelineEntry` 中的旧签名重载（`CreateDefaultPipeline` 和 `CreateCliPipeline` 的 `[Obsolete]` 版本）

## 5. 实施计划

| 优先级 | 步骤 | 描述 | 工作量 | 依赖 |
|--------|------|------|--------|------|
| P0 | 步骤一 | 统一两条执行路径 | 小 | 无 |
| P1 | 步骤四 | 消除非事件命令双重注册 | 中 | 无 |
| P2 | 步骤二+三 | 合并接口 | 大 | 步骤一 |
| P3 | 步骤五 | 消除委托双重包装 | 小 | 步骤二+三 |
| P4 | 步骤六 | 清理废弃代码 | 小 | 步骤二+三 |

### 建议执行顺序

```
步骤一（P0）→ 步骤四（P1）→ 步骤二+三（P2）→ 步骤五（P3）→ 步骤六（P4）
```

---

## 6. 预期效果

1. **Bug 修复**：手动点击按钮能正确找到事件绑定
2. **代码简化**：消除 2 个适配器、2 个冗余接口、1 个废弃类
3. **维护性提升**：非事件命令只需在 `NonEventRegistry` 中注册一次
4. **一致性**：手动点击和脚本执行走完全相同的管线路径
