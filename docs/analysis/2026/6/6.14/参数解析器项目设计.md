# 参数解析器项目设计文档

## 1. 概述

### 1.1 背景

当前项目中参数处理逻辑**严重分散**，涉及多个文件、两套独立的实现，且职责边界模糊：

| 文件 | 职责 | 问题 |
|------|------|------|
| `Share/CommandFramework/ArgumentMatcher.cs` | 参数匹配器策略链（4个匹配器 + TypeConverter） | 只负责"匹配"，不负责"提取" |
| `Operation/FunctionStorage/Utilities.cs` | 旧版 `ArgumentBuilder` + 旧版 `ArgumentMatcherPipeline` | 与 CommandFramework 版本功能重叠，已标记 `[Obsolete]` |
| `Share/CommandFramework/Pipeline/Stages/ExecuteCommandStage.cs` | HandleClick 中临时拼凑的值提取逻辑 | 值提取逻辑与执行逻辑耦合 |
| `Share/CommandFramework/Abstractions/IEventBindingInfo.cs` | 绑定信息接口（Parameter 是逗号分隔的控件名） | 只有数据，没有处理逻辑 |

### 1.2 核心问题

```
参数处理链路（当前）：
  IEventBindingInfo.Parameter = "valueATextBox,valueBTextBox"  (控件名列表)
       │
       ▼
  ExecuteCommandStage.HandleClick()  ← 临时拼凑
       │  1. 分割控件名
       │  2. 从 GUI/VirtualStore 读取值
       │  3. 构建 object[] 数组
       ▼
  FunctionExecutor.ExecuteAsync(functionName, object[])
       │
       ▼
  ArgumentMatcherPipeline.BuildArguments()  ← 另一套逻辑
       │  4. PositionalMatcher 按位匹配
       │  5. TypeConverter 类型转换
       ▼
  DynamicInvoke(10.0, 25.0)
```

**三个核心问题：**

1. **值提取与参数匹配分离**：步骤 1-3（值提取）在 `ExecuteCommandStage` 中临时拼凑，步骤 4-5（参数匹配）在 `ArgumentMatcherPipeline` 中，两者不在同一组件
2. **两套重复实现**：`ArgumentMatcherPipeline`（CommandFramework）和 `ArgumentBuilder`（FunctionStorage）功能重叠
3. **职责过重**：`ExecuteCommandStage.HandleClick` 同时负责绑定查找、值提取、函数执行、结果写入

### 1.3 目标

设计一个**独立的参数解析器项目**，统一所有参数处理逻辑，实现：

1. **职责单一**：参数解析器只负责"从绑定信息到实际参数值"的转换
2. **统一入口**：所有参数构建都通过同一个组件完成
3. **可扩展**：支持 GUI/CLI 不同值来源，支持按名/按位不同匹配策略
4. **可测试**：接口清晰，易于单元测试

### 2.2 核心接口设计

#### 2.2.1 IParameterSource — 参数源接口

```csharp
/// <summary>
/// 参数源 — 从不同环境读取控件的当前值
/// </summary>
public interface IParameterSource
{
    /// <summary>
    /// 读取指定控件名称的当前值
    /// </summary>
    /// <param name="controlName">控件名称</param>
    /// <returns>控件的当前值，控件不存在时返回 null</returns>
    string? ReadValue(string controlName);
}
```

**实现类：**

| 实现 | 说明 |
|------|------|
| `GuiControlSource` | 通过反射从 WinForms Form 中查找控件并读取 Text 属性 |
| `VirtualStoreSource` | 从 `Dictionary<string, string?>` 虚拟存储中读取值 |
| `CompositeSource` | 组合多个源，按优先级依次尝试（先 GUI 后 CLI 等） |

#### 2.2.2 IParameterMatcher — 参数匹配器接口

```csharp
/// <summary>
/// 参数匹配器 — 将原始参数值按策略匹配到函数参数列表
/// </summary>
public interface IParameterMatcher
{
    /// <summary>
    /// 尝试匹配参数
    /// </summary>
    /// <param name="parameters">函数参数描述符列表</param>
    /// <param name="source">原始参数值（可能是字典、列表、单个值等）</param>
    /// <param name="args">输出：构建后的参数数组</param>
    /// <param name="matchedFlags">输出：各参数是否已匹配</param>
    /// <param name="matchInfos">输出：各参数的匹配信息</param>
    void TryMatch(
        IReadOnlyList<IParameterDescriptor> parameters,
        object? source,
        object?[] args,
        bool[] matchedFlags,
        ParameterMatchInfo[] matchInfos);
}
```

**匹配器链（按优先级）：**

```
DictionaryMatcher  →  按参数名精确匹配（如 {"a": "10", "b": "25"}）
PositionalMatcher  →  按位置匹配（如 ["10", "25"]）
SingleValueMatcher →  单参数直接传入（如 "10" → (double a)）
DefaultValueMatcher → 默认值回退（可选参数使用默认值）
```

#### 2.2.3 ParameterBuildRequest — 构建请求

```csharp
/// <summary>
/// 参数构建请求 — 描述如何从绑定信息构建参数
/// </summary>
public class ParameterBuildRequest
{
    /// <summary>函数参数描述符列表（来自 IFunctionDescriptor）</summary>
    public IReadOnlyList<IParameterDescriptor> FunctionParameters { get; init; }
    
    /// <summary>绑定信息中的参数（控件名列表，逗号分隔）</summary>
    public string? BindingParameter { get; init; }
    
    /// <summary>参数源（从哪读取控件的实际值）</summary>
    public IParameterSource Source { get; init; }
}
```

#### 2.2.4 ParameterBuildResult — 构建结果

```csharp
/// <summary>
/// 参数构建结果
/// </summary>
public class ParameterBuildResult
{
    public bool IsSuccess { get; }
    public object?[] Args { get; }
    public IReadOnlyList<ParameterMatchInfo> MatchInfos { get; }
    public string? ErrorMessage { get; }
}
```

#### 2.2.5 ParameterBuilder — 统一构建入口

```csharp
/// <summary>
/// 参数构建器 — 统一入口，将绑定信息转换为实际参数值数组
/// </summary>
public class ParameterBuilder
{
    private readonly IParameterMatcher[] _matchers;
    
    public ParameterBuilder()
    {
        _matchers = new IParameterMatcher[]
        {
            new DictionaryMatcher(),
            new PositionalMatcher(),
            new SingleValueMatcher(),
            new DefaultValueMatcher()
        };
    }
    
    /// <summary>
    /// 构建参数
    /// </summary>
    /// <param name="request">构建请求</param>
    /// <returns>构建结果</returns>
    public ParameterBuildResult Build(ParameterBuildRequest request)
    {
        // 1. 从绑定参数解析控件名列表
        var controlNames = ParseControlNames(request.BindingParameter);
        
        // 2. 从参数源读取控件的实际值
        var rawValues = ReadValues(request.Source, controlNames);
        
        // 3. 构建原始参数对象（按位置构建数组）
        object? parameters = rawValues.Length > 0 ? rawValues : null;
        
        // 4. 通过匹配器链匹配到函数参数
        return MatchParameters(request.FunctionParameters, parameters);
    }
    
    /// <summary>
    /// 简化重载：直接传入已提取的值数组
    /// </summary>
    public ParameterBuildResult Build(
        IReadOnlyList<IParameterDescriptor> functionParameters,
        object? parameters)
    {
        return MatchParameters(functionParameters, parameters);
    }
}
```

### 2.3 核心流程

```
ParameterBuilder.Build(request)
    │
    ├── 1. 解析控件名
    │      request.BindingParameter = "valueATextBox,valueBTextBox"
    │      → ["valueATextBox", "valueBTextBox"]
    │
    ├── 2. 读取实际值
    │      request.Source.ReadValue("valueATextBox")  → "10"
    │      request.Source.ReadValue("valueBTextBox")  → "25"
    │      → ["10", "25"]
    │
    ├── 3. 匹配参数
    │      DictionaryMatcher:  ["10","25"] is not IDictionary → skip
    │      PositionalMatcher:  ["10","25"] is IList → match
    │        → a ← "10"  (Convert → 10.0)
    │        → b ← "25"  (Convert → 25.0)
    │      SingleValueMatcher: 参数数 != 1 → skip
    │      DefaultValueMatcher: 全部已匹配 → skip
    │
    └── 4. 返回结果
           Args = [10.0, 25.0]
           IsSuccess = true
```

### 2.4 类型转换器

合并两套现有的 `TypeConverter` 实现：

| 特性 | CommandFramework 版 | FunctionStorage 版 | 新版本 |
|------|-------------------|-------------------|--------|
| 注册式 TryParse | ✅ | ❌ | ✅ |
| IConvertible | ✅ | ✅ | ✅ |
| JsonSerializer | ✅ | ❌ | ✅ |
| TypeDescriptor | ❌ | ✅ | ✅ |
| Enum 处理 | ✅ | ✅ | ✅ |
| Nullable 处理 | ✅ | ✅ | ✅ |

新版本取两者之长，支持所有转换路径。

## 3. 在原项目中的应用

### 3.1 在 ExecuteCommandStage 中的应用

**改造前**（当前临时拼凑的代码）：

```csharp
// ExecuteCommandStage.HandleClick() 中
object? parameters = null;
var inputControls = binding.Parameter;
if (!string.IsNullOrEmpty(inputControls))
{
    var controlNames = inputControls.Split(',', ...);
    if (controlNames.Length > 0)
    {
        if (context.IsGuiMode && ...)
        {
            var values = new List<string?>();
            foreach (var ctrlName in controlNames)
            {
                var control = FindControlReflection(formObj, ctrlName);
                values.Add(control != null ? GetControlTextReflection(control) : null);
            }
            parameters = values.ToArray();
        }
        else if (context.IsCliMode && ...)
        {
            // 类似的 VirtualStore 读取逻辑
        }
    }
}
var result = await executor.ExecuteAsync(functionName, parameters);
```

**改造后**：

```csharp
// ExecuteCommandStage 构造函数注入 ParameterBuilder
private readonly ParameterBuilder _parameterBuilder;

// HandleClick() 中
var source = context.IsGuiMode
    ? (IParameterSource)new GuiControlSource(formObj)
    : new VirtualStoreSource(context.VirtualStore);

var request = new ParameterBuildRequest
{
    FunctionParameters = descriptor.Parameters,
    BindingParameter = binding.Parameter,
    Source = source
};

var buildResult = _parameterBuilder.Build(request);
if (!buildResult.IsSuccess)
{
    context.SetStageResult(Name, false,
        $"Parameter building failed: {buildResult.ErrorMessage}");
    return;
}

var result = await executor.ExecuteAsync(functionName, buildResult.Args);
```

### 3.2 在 FunctionExecutor 中的应用

**改造前**：

```csharp
// FunctionExecution.cs
var buildResult = ArgumentMatcherPipeline.BuildArguments(descriptor, parameters);
```

**改造后**：

```csharp
// FunctionExecution.cs
var buildResult = _parameterBuilder.Build(descriptor.Parameters, parameters);
```

`ParameterBuilder` 直接替代 `ArgumentMatcherPipeline`，接口更清晰。

### 3.3 依赖关系变化

```
改造前：
  FileDriven.Execution
    → CommandFramework (含 ArgumentMatcherPipeline)
    → FunctionStorage (含 ArgumentBuilder, 已废弃)

改造后：
  FileDriven.Execution
    → CommandFramework
      → ParameterResolver (新项目)  ← 统一参数处理
    → FunctionStorage
      → ParameterResolver (新项目)  ← 替代 ArgumentBuilder
```

## 6. 数据流

### 6.1 事件命令完整数据流（click addButton）

```
命令: "click addButton"
    │
    ▼
ExecuteCommandStage.HandleClick("addButton")
    │
    ├── 1. 查找绑定
    │      FindBinding("addButton", "click")
    │      → IEventBindingInfo { FunctionName="Plus", Parameter="valueATextBox,valueBTextBox", Target="resultTextBox" }
    │
    ├── 2. 构建参数
    │      source = context.IsGuiMode ? new GuiControlSource(form) : new VirtualStoreSource(store)
    │      
    │      request = ParameterBuildRequest {
    │          FunctionParameters = [ {Name="a", Type=double}, {Name="b", Type=double} ],
    │          BindingParameter = "valueATextBox,valueBTextBox",
    │          Source = source
    │      }
    │      
    │      _parameterBuilder.Build(request)
    │      ├── ParseControlNames → ["valueATextBox", "valueBTextBox"]
    │      ├── ReadValues:
    │      │     source.ReadValue("valueATextBox") → "10"
    │      │     source.ReadValue("valueBTextBox") → "25"
    │      │     → ["10", "25"]
    │      ├── MatchParameters:
    │      │     DictionaryMatcher:  ["10","25"] is not IDictionary → skip
    │      │     PositionalMatcher:  ["10","25"] is IList → match
    │      │       → a ← "10" → Convert("10", double) → 10.0
    │      │       → b ← "25" → Convert("25", double) → 25.0
    │      │     SingleValueMatcher: 参数数 != 1 → skip
    │      │     DefaultValueMatcher: 全部已匹配 → skip
    │      └── → ParameterBuildResult { Args=[10.0, 25.0], IsSuccess=true }
    │
    ├── 3. 执行函数
    │      executor.ExecuteAsync("Plus", [10.0, 25.0])
    │      → DynamicInvoke(10.0, 25.0) → 35.0
    │
    └── 4. 写回结果
         WriteResult("resultTextBox", "35")
```

### 6.2 CLI 模式数据流（set + click）

```
命令: "set valueATextBox 10"
    → HandleSet → VirtualStore["valueATextBox"] = "10"

命令: "set valueBTextBox 25"
    → HandleSet → VirtualStore["valueBTextBox"] = "25"

命令: "click addButton"
    → HandleClick
      → source = new VirtualStoreSource(VirtualStore)
      → source.ReadValue("valueATextBox") → "10"
      → source.ReadValue("valueBTextBox") → "25"
      → ParameterBuilder.Build → [10.0, 25.0]
      → FunctionExecutor.ExecuteAsync("Plus", [10.0, 25.0]) → 35.0
      → VirtualStore["resultTextBox"] = "35"
```
