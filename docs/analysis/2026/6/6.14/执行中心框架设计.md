# 执行中心（ExecutionCenter）框架设计文档

## 概述

执行中心（ExecutionCenter）是一个基于消息队列和消息处理管线的统一任务调度框架，位于 `Share/ExecutionCenter/` 项目下。

### 设计目标

1. **解耦配置加载与命令执行** — 消除当前架构中 `LoadedConfigs` 副本导致的状态不一致问题
2. **统一任务调度** — GUI 点击事件、脚本命令、配置加载统一通过消息队列调度
3. **优先级管理** — GUI 交互事件最高优先级，确保界面响应流畅
4. **状态隔离** — 每个 Worker 持有独立状态，天然线程安全
5. **可观测性** — 消息队列天然支持追踪、监控、重试

### 设计原则

- **复用现有基础设施** — 基于 `BasicMethod/BasicAlgorithm/MessageQueue.cs`（优先级队列）和 `BasicMethod/BasicAlgorithm/MessageHandling.cs`（消息通道）构建
- **渐进式集成** — 不破坏现有架构，通过适配器模式逐步替换
- **接口驱动** — 所有组件面向接口编程，便于测试和扩展

## 一、核心理念提炼（从 WorkFlowMethod 迁移）

### 1.1 从 Execution 提炼：执行会话模式

**核心理念**：每次执行创建一个独立会话，封装所有状态。引擎无状态，状态全在 Session 中。

| 概念 | WorkFlowMethod 实现 | 执行中心（ExecutionCenter）对应 |
|------|-------------------|-------------------|
| 执行会话 | `ExecutionSession`（状态容器） | `WorkerContext`（Worker 独立状态） |
| 状态机 | `ExecutionStateMachine`（生命周期） | 任务生命周期（Pending→Running→Completed/Faulted） |
| 数据上下文 | `DataContext`（键值存储） | `WorkerContext.LoadedConfigs` |
| 节点状态 | `NodeExecutionState`（节点追踪） | 任务追踪（TaskTracker） |

**关键设计**：
- 每个 Worker 持有独立的 `WorkerContext`，类似 `ExecutionSession`
- Worker 内部单线程处理任务，无需锁
- 状态外置：WorkerContext 由外部传入，Worker 本身无状态

### 1.2 从 ExecutionEngine 提炼：步骤管线模式

**核心理念**：每个任务的执行分解为固定步骤管线，每个步骤只做一件事，可组合、可重写。

```
NodeExecutor 步骤管线（WorkFlowMethod）：
  ResolveInput → ExecuteFunction → RecordCallFrame → ResolveNextNodes

执行中心（ExecutionCenter）任务处理管线：
  ParseCommand → ResolveBinding → ExecuteCommand → CollectResult
```

**关键设计**：
- 每个 `ITaskHandler` 内部可包含多个步骤
- 步骤通过 `IExecutionStep` 接口定义，可组合
- 步骤管线通过参数控制行为差异（单一执行模式）

### 1.3 从 GraphFramework 提炼：快照模式

**核心理念**：不可变快照作为执行凭证，确保执行过程不受外部变更影响。

| 概念 | GraphFramework 实现 | 执行中心（ExecutionCenter）对应 |
|------|-------------------|-------------------|
| 图快照 | `GraphSnapshot`（不可变） | 任务消息快照（创建后不可变） |
| 节点定义 | `NodeDefinition`（纯配置） | `ITaskMessage`（纯数据） |
| 边定义 | `EdgeDefinition`（连接关系） | 任务依赖关系（DAG） |
| 版本控制 | `Version`（乐观并发） | 任务版本号 |

**关键设计**：
- 任务消息一旦创建不可变
- Worker 处理任务时基于消息快照，不受后续变更影响
- 支持任务版本追踪

### 2.3 核心实现

#### TaskQueue — 任务队列实现

```csharp
/// <summary>
/// 任务队列实现
/// 包装 PriorityMessageQueue，添加请求-响应模式支持
/// </summary>
public class TaskQueue : ITaskQueue
{
    private readonly PriorityMessageQueue<ITaskMessage> _innerQueue;
    private readonly ConcurrentDictionary<Guid, TaskCompletionSource<ITaskResponse>> _pendingResults = new();
    
    public TaskQueue()
    {
        _innerQueue = new PriorityMessageQueue<ITaskMessage>();
    }
    
    public async Task<ITaskResponse> EnqueueAsync(ITaskMessage task, CancellationToken ct = default)
    {
        var tcs = new TaskCompletionSource<ITaskResponse>(
            TaskCreationOptions.RunContinuationsAsynchronously);
        
        _pendingResults[task.MessageId] = tcs;
        
        using var ctr = ct.Register(() =>
        {
            if (_pendingResults.TryRemove(task.MessageId, out var pending))
                pending.TrySetCanceled(ct);
        });
        
        // 按优先级入队
        _innerQueue.StoreMessage(task, task.TaskType, (int)task.Priority);
        
        return await tcs.Task;
    }
    
    // 消费者完成处理后调用
    public void CompleteTask(ITaskResponse response)
    {
        if (_pendingResults.TryRemove(response.RequestMessageId, out var tcs))
            tcs.TrySetResult(response);
    }
}
```

#### TaskExecutorPool — 任务执行池实现

```csharp
/// <summary>
/// 任务执行池实现
/// 管理多个 Worker，支持任务路由
/// </summary>
public class TaskExecutorPool : ITaskExecutorPool
{
    private readonly ITaskQueue _queue;
    private readonly List<QueueWorker> _workers;
    private readonly TaskRouter _router;
    private readonly ConcurrentDictionary<string, ITaskHandler> _handlers = new();
    
    public int WorkerCount => _workers.Count;
    public int PendingTaskCount => _queue.Count;
    
    public TaskExecutorPool(int workerCount = 1)
    {
        _queue = new TaskQueue();
        _workers = new List<QueueWorker>(workerCount);
        _router = new TaskRouter();
        
        for (int i = 0; i < workerCount; i++)
        {
            _workers.Add(new QueueWorker($"Worker-{i}", _queue, this));
        }
    }
    
    public void RegisterHandler(ITaskHandler handler)
    {
        foreach (var taskType in handler.SupportedTaskTypes)
        {
            _handlers[taskType] = handler;
        }
    }
    
    // 由 QueueWorker 内部调用
    internal async Task<ITaskResponse> ExecuteAsync(ITaskMessage task, IWorkerContext context)
    {
        if (_handlers.TryGetValue(task.TaskType, out var handler))
        {
            return await handler.HandleAsync(task, context, CancellationToken.None);
        }
        return new TaskResponse(task.MessageId, false, error: $"No handler for task type: {task.TaskType}");
    }
    
    // 完成任务（回调结果给等待的调用方）
    internal void CompleteTask(ITaskResponse response) => _queue.CompleteTask(response);
    
    public async Task<ITaskResponse> SubmitAsync(ITaskMessage task, CancellationToken ct = default)
    {
        return await _queue.EnqueueAsync(task, ct);
    }
    
    public void Start()
    {
        foreach (var worker in _workers)
            worker.Start();
    }
    
    public void Stop()
    {
        _queue.Stop();
        foreach (var worker in _workers)
            worker.Stop();
    }
    
    public void Dispose()
    {
        Stop();
        _queue.Dispose();
    }
}
```

#### QueueWorker — 队列工作者

```csharp
/// <summary>
/// 队列工作者
/// 从队列中取出任务，在独立上下文中执行
/// 设计理念：Worker 无状态，状态全在 WorkerContext 中
/// </summary>
internal class QueueWorker
{
    private readonly string _name;
    private readonly ITaskQueue _queue;
    private readonly TaskExecutorPool _pool;
    private readonly IWorkerContext _context;
    private Task? _workTask;
    private CancellationTokenSource? _cts;
    
    public QueueWorker(string name, ITaskQueue queue, TaskExecutorPool pool)
    {
        _name = name;
        _queue = queue;
        _pool = pool;
        _context = new WorkerContext(name);
    }
    
    public void Start()
    {
        _cts = new CancellationTokenSource();
        _workTask = Task.Run(() => WorkLoopAsync(_cts.Token));
    }
    
    private async Task WorkLoopAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            try
            {
                var task = _queue.Dequeue(ct);
                var response = await _pool.ExecuteAsync(task, _context);
                _pool.CompleteTask(response);
            }
            catch (OperationCanceledException) { break; }
            catch (Exception ex)
            {
                // 记录异常，继续处理下一个任务
            }
        }
    }
    
    public void Stop()
    {
        _cts?.Cancel();
    }
}
```

#### TaskRouter — 任务路由器

```csharp
/// <summary>
/// 任务路由器
/// 根据 RoutingKey 将任务路由到指定的 Worker
/// </summary>
public class TaskRouter
{
    private readonly ConcurrentDictionary<string, int> _routingTable = new();
    
    /// <summary>
    /// 注册路由：指定 RoutingKey 路由到指定 Worker
    /// </summary>
    public void RegisterRoute(string routingKey, int workerIndex)
        => _routingTable[routingKey] = workerIndex;
    
    /// <summary>
    /// 获取目标 Worker 索引
    /// 未注册的路由键使用轮询（Round-Robin）
    /// </summary>
    public int GetTargetWorker(string? routingKey, int workerCount)
    {
        if (routingKey != null && _routingTable.TryGetValue(routingKey, out var index))
            return index;
        
        // 轮询负载均衡
        return Interlocked.Increment(ref _roundRobin) % workerCount;
    }
    
    private int _roundRobin = -1;
}
```

```csharp
public class LoadConfigHandler : ITaskHandler
{
    public IReadOnlyCollection<string> SupportedTaskTypes => new[] { "LoadConfig" };
    
    public async Task<ITaskResponse> HandleAsync(ITaskMessage task, IWorkerContext context, CancellationToken ct)
    {
        if (task is not LoadConfigMessage msg)
            return new TaskResponse(task.MessageId, false, error: "Invalid message type");
        
        try
        {
            var result = context.LoadConfig(msg.ConfigPath, msg.ShowForm);
            return new TaskResponse(task.MessageId, result.IsSuccess, 
                error: result.ErrorMessage,
                result: result);
        }
        catch (Exception ex)
        {
            return new TaskResponse(task.MessageId, false, error: ex.Message);
        }
    }
}
```

```csharp
    private readonly CommandParser _parser;
    
    public IReadOnlyCollection<string> SupportedTaskTypes => new[] { "ExecuteCommand" };
    
    public ExecuteCommandHandler(CommandParser parser)
    {
        _parser = parser;
    }
    
    public async Task<ITaskResponse> HandleAsync(ITaskMessage task, IWorkerContext context, CancellationToken ct)
    {
        if (task is not ExecuteCommandMessage msg)
            return new TaskResponse(task.MessageId, false, error: "Invalid message type");
        
        try
        {
            // 1. 解析命令
            var parsed = _parser.Parse(msg.Command);
            
            // 2. 创建管线上下文
            var pipelineCtx = new CommandContext
            {
                CurrentCommand = msg.Command,
                ParsedCommand = parsed,
                LoadedConfigs = context.LoadedConfigs,
                BindingResolver = context.BindingResolver,
                FunctionExecutor = context.FunctionExecutor
            };
            
            // 3. 执行管线
            var pipeline = CreatePipeline(context);
            await pipeline.ExecuteAsync(pipelineCtx, ct);
            
            return new TaskResponse(task.MessageId, !pipelineCtx.HasError,
                error: pipelineCtx.GetErrorMessage(),
                result: pipelineCtx.FunctionResultValue);
        }
        catch (Exception ex)
        {
            return new TaskResponse(task.MessageId, false, error: ex.Message);
        }
    }
    
    private IStagePipeline<CommandContext> CreatePipeline(IWorkerContext context)
    {
        // 创建 bindingFinder 委托（使用 Worker 上下文中的 BindingResolver）
        Func<string, string, ExecuteCommandStage.BindingResult?>? bindingFinder = null;
        if (context.BindingResolver != null)
        {
            bindingFinder = (controlName, eventType) =>
            {
                var info = context.BindingResolver.FindEventBinding(controlName, eventType);
                if (info == null) return null;
                return new ExecuteCommandStage.BindingResult(
                    FunctionName: info.FunctionName,
                    Parameter: info.Inputs?.Count > 0 ? string.Join(",", info.Inputs) : null,
                    Target: info.Output);
            };
        }
        
        return PipelineEntry.CreateDefaultPipeline(
            parser: _parser,
            bindingFinder: bindingFinder,
            functionExecutor: context.FunctionExecutor as IFunctionExecutor);
    }
}
```

## 五、消息通道（IPC 通信，Phase 4）

### 5.1 PipelineMessageChannel

基于 `MessageHandling.cs` 中的 `MessageChannel<TRequest, TResponse>`，实现进程间通信。

```csharp
/// <summary>
/// 管线消息通道
/// 用于 CLI 进程 ↔ GUI 进程之间的通信
/// </summary>
public class PipelineMessageChannel : MessageChannel<CommandRequest, CommandResponse>
{
    private readonly ITaskExecutorPool _pool;
    
    public PipelineMessageChannel(IMessageTransport transport, IMessageSerializer serializer, ITaskExecutorPool pool)
        : base(transport, serializer)
    {
        _pool = pool;
    }
    
    protected override async Task HandleRequestAsync(CommandRequest request, CancellationToken ct)
    {
        ITaskResponse result;
        
        switch (request.Operation.ToLowerInvariant())
        {
            case "load":
                result = await _pool.SubmitAsync(new LoadConfigMessage
                {
                    ConfigPath = request.Target,
                    ShowForm = request.ShowForm
                }, ct);
                break;
                
            case "click":
                result = await _pool.SubmitAsync(
                    ExecuteCommandMessage.CreateGuiClick(request.ControlName, "click"), ct);
                break;
                
            case "set":
                result = await _pool.SubmitAsync(new ExecuteCommandMessage
                {
                    ControlName = request.ControlName,
                    EventType = "set",
                    Command = $"set {request.ControlName}"
                }, ct);
                break;
                
            default:
                result = new TaskResponse(request.MessageId, false, error: $"Unknown operation: {request.Operation}");
                break;
        }
        
        await SendResponseAsync(new CommandResponse
        {
            MessageId = request.MessageId,
            Success = result.Success,
            Error = result.Error,
            Result = result.Result?.ToString()
        }, ct);
    }
}
```

## 七、与现有架构的对比

| 维度 | 当前架构 | 执行中心（ExecutionCenter）架构 |
|------|---------|-------------------|
| **状态管理** | 全局共享 `_loadedConfigs`，多处副本 | Worker 内独立状态，天然一致 |
| **任务调度** | 直接方法调用 | 优先级队列调度 |

## 八、关键设计决策

### 8.1 为什么复用 PriorityMessageQueue 而非 Channel<T>？

`PriorityMessageQueue` 已支持：
- 优先级调度（Critical > High > Normal > Low）
- 暂停/恢复（Pause/Resume）
- 终止当前任务（TerminateCurrent）
- 超时控制

`System.Threading.Channels` 不支持优先级，需要额外包装。

### 8.2 为什么每个 Worker 持有独立 PipelineEntry？

- **状态隔离**：一个 Worker 的配置加载不影响其他 Worker
- **消除副本**：不再需要 `LoadedConfigs` 的副本
- **线程安全**：每个 Worker 单线程处理任务，无需锁

### 8.3 为什么 GUI 点击事件使用 Critical 优先级？

- WinForms 事件需要同步返回，不能阻塞 UI 线程
- Critical 优先级确保 GUI 事件被立即处理
- 避免 UI 线程等待导致的界面卡死

### 8.4 为什么 Worker 无状态，状态全在 WorkerContext 中？

- **可复用**：Worker 可被多个任务复用
- **可测试**：Worker 逻辑与状态解耦，易于单元测试
- **可恢复**：WorkerContext 可序列化/恢复

### 8.5 为什么任务消息是不可变快照？

- **一致性**：处理过程中消息内容不会变化
- **可追踪**：消息快照可作为审计日志
- **可重试**：失败后可基于原始消息重新执行
