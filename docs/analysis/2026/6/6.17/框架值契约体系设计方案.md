# 框架值契约体系设计方案

> **日期：** 2026-06-16
> **状态：** 设计阶段
> **关键词：** IControlValue, ListData, 值类型契约, 控件值传递, 类型感知

---

## 1. 问题背景

### 1.1 现象

GUI 模式下 `MathFunctionBrowser` 的 ListView 控件不显示数学域和函数列表。

### 1.2 根因

**数据格式约定不一致** — 整个调用链中，数据以 `string` 类型传递，消费方和提供方对字符串格式的预期不同：

| 角色 | 位置 | 预期格式 | 实际格式 |
|------|------|---------|---------|
| 数据提供方 | `MathBrowserFunctions.cs` | 任意 | 逗号分隔（旧）/ 换行符分隔（新） |
| 数据消费方 | `RegisterListViewAdapter` | 换行符 `\n` | 逗号 `,` |
| 传递层 | `exec handler` / `EventTriggerService` | 不关心 | 调用 `.ToString()` 转为 string |

### 1.3 本质问题

**框架缺少值类型契约。** 所有数据通过 `string` 传递，类型信息在 `object → .ToString() → string` 的转换中丢失，消费方只能通过字符串格式猜测数据含义。

---

## 2. 设计目标

### 2.1 核心原则

> **数据提供方返回结构化类型 → 传递层保持原始类型 → 消费方按类型识别处理**

### 2.2 具体目标

| # | 目标 | 说明 |
|---|------|------|
| 1 | **消除 .ToString()** | 调用链中任何环节都不应主动将结构化数据转为 string |
| 2 | **类型感知传递** | 数据以原始类型在层间传递，消费方按类型识别 |
| 3 | **向后兼容** | 现有 string 路径完全保留，不影响已有功能 |
| 4 | **可扩展** | 未来可添加 TableData、TreeData 等新值类型 |
| 5 | **最小改动** | 每个改动点独立且风险可控 |

---

## 3. 架构设计

### 3.1 值类型体系

```
IControlValue (标记接口)
│
├── ListData          → 列表数据（ListView、ComboBox、ListBox）
├── TableData         → 表格数据（DataGridView）[未来扩展]
└── TreeData          → 树形数据（TreeView）[未来扩展]
```

### 3.2 调用链全景

```
┌──────────────────────────────────────────────────────────┐
│                    数据提供层（函数）                       │
│  MathBrowserFunctions                                    │
│    → 返回 ListData（结构化类型，不 ToString）               │
└──────────────────────┬───────────────────────────────────┘
                       │ object? value (保持原始类型)
                       ▼
┌──────────────────────────────────────────────────────────┐
│                    值传递层（中间件）                       │
│  exec handler (FileDrivenExecutor)                      │
│    → controlService.TrySetControlValue(output, result.Value) │
│                                                         │
│  EventTriggerService.WriteOutputAsync                   │
│    → valueWriter.WriteValue(control, value)             │
└──────────────────────┬───────────────────────────────────┘
                       │ object? value (保持原始类型)
                       ▼
┌──────────────────────────────────────────────────────────┐
│                    值消费层（适配器）                       │
│  IControlValueWriter.WriteValue(Control, object?)        │
│    ├── 识别 ListData  → 直接设置 Items                   │
│    ├── 识别 string    → 回退到字符串逻辑                  │
│    └── 识别其他       → ToString() 回退                   │
└──────────────────────────────────────────────────────────┘
```

### 3.3 关键接口设计

#### 3.3.1 IControlValue（值类型标记接口）

```csharp
namespace FrameworkAbstractions.Controls;

/// <summary>
/// 控件值类型标记接口
/// <para>所有框架级值类型实现此接口，使 IControlValueWriter 能按类型识别处理。</para>
/// </summary>
public interface IControlValue
{
    /// <summary>
    /// 序列化为字符串（用于日志、剪贴板等场景）
    /// </summary>
    string Serialize();
}
```

#### 3.3.2 IControlValueWriter（扩展）

```csharp
public interface IControlValueWriter
{
    // 原有 string 接口（保持向后兼容）
    bool WriteValue(Control control, string? value);
    string? ReadValue(Control control);
    
    // ★ 新增：类型感知写入
    bool WriteValue(Control control, object? value);
}
```

#### 3.3.3 IControlService（扩展）

```csharp
public interface IControlService
{
    // 原有
    bool TrySetControlValue(string controlName, string? value, Control? container = null);
    
    // ★ 新增：类型感知版本

}
```

### 4.2 WinFormsControlValueWriter — 类型感知写入

**位置：** `FileDriven/FileDriven.Execution/Command/ControlServices.cs`

```csharp
public class WinFormsControlValueWriter : IControlValueWriter
{
    // ★ 新增：类型感知写入
    public bool WriteValue(Control control, object? value)
    {
        if (value == null) return WriteValue(control, (string?)null);
        
        // 识别框架值类型
        if (value is IControlValue cv)
            return WriteControlValue(control, cv);
        
        // 回退：走 string 路径
        return WriteValue(control, value.ToString());
    }
    
    // ★ 新增：值类型分发
    private bool WriteControlValue(Control control, IControlValue value)
    {
        switch (value)
        {
            case ListData listData:
                return WriteListData(control, listData);
            // 未来可扩展 TableData、TreeData 等
            default:
                return WriteValue(control, value.Serialize());
        }
    }
    
    // ★ 新增：ListData 写入
    private bool WriteListData(Control control, ListData data)
    {
        switch (control)
        {
            case ListView listView:
                listView.BeginUpdate();
                listView.Items.Clear();
                foreach (var item in data.Items)
                    listView.Items.Add(new ListViewItem(item));
                listView.EndUpdate();
                return true;
                
            case ComboBox comboBox:
                comboBox.Items.Clear();
                foreach (var item in data.Items)
                    comboBox.Items.Add(item);
                return true;
                
            case ListBox listBox:
                listBox.Items.Clear();
                foreach (var item in data.Items)
                    listBox.Items.Add(item);
                return true;
                
            default:
                return WriteValue(control, data.Serialize());
        }
    }
}
```

### 4.3 UnifiedControlService — 类型感知服务

**位置：** `FileDriven/FileDriven.Execution/Command/ControlServices.cs`

```csharp
public class UnifiedControlService : IControlService
{
    // ★ 新增：类型感知版本
    public bool TrySetControlValue(string controlName, object? value, Control? container = null)
    {
        var control = FindControl(controlName, container);
        if (control == null)
        {
            LogControlNotFound(controlName);
            return false;
        }
        
        var writer = ComponentRegistry.Instance.Resolve<IControlValueWriter>();
        if (writer == null)
        {
            LogWriterNotFound(controlName);
            return false;
        }
        
        return writer.WriteValue(control, value);
    }
}
```

## 6. 向后兼容性

### 6.1 string 路径完全保留

所有现有使用 `string` 接口的代码不受影响：

```csharp
// 这些调用继续正常工作
controlService.TrySetControlValue("textBox1", "hello", container);
valueWriter.WriteValue(textBox, "world");
```

### 6.2 回退策略

当 `object` 重载无法识别类型时，自动回退到 `string` 路径：

```
WriteValue(Control, object?)
  ├── null → WriteValue(Control, (string)null)
  ├── IControlValue → WriteControlValue(Control, IControlValue)
  │     ├── ListData → 直接设置 Items
  │     └── 其他 → Serialize() → WriteValue(Control, string)
  └── 其他类型 → .ToString() → WriteValue(Control, string)
```

### 6.3 函数返回值兼容

- 返回 `string` 的函数 → 走 string 路径，不受影响
- 返回 `ListData` 的函数 → 走 ListData 路径，类型感知
- 返回其他类型 → `.ToString()` 回退

## 8. 与现有 ListData.Parse 的关系

当前已实现的 `ListData.Parse` 方案是**补丁级修复**，仅在 `RegisterListViewAdapter` 层面做智能分割。

本方案是**框架级修复**，在值传递层面建立类型契约。

两者可以共存：

| 场景 | 当前方案 | 框架方案 |
|------|---------|---------|
| 函数返回 `ListData` | `ListData.ToString()` → string → `ListData.Parse(string)` | 直接传递 `ListData` |
| 函数返回 `string`（逗号分隔） | `ListData.Parse(string)` 智能分割 | `ListData.Parse(string)` 智能分割 |
| 函数返回 `string`（换行分隔） | `ListData.Parse(string)` 智能分割 | `ListData.Parse(string)` 智能分割 |

`ListData.Parse` 作为 string 路径的兜底策略，即使函数返回 string 也能正确解析。
