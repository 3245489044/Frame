# 图逻辑整体重构方案

> 日期：2026-06-19
> 目标：消除 Operation 层图逻辑的重复包装，精简架构

---

## 一、现状分析

### 1.1 当前架构

```
BasicMethod/GraphFoundation/     ← 图核心（IGraph, CoreGraph, Commands, Chain, Topology...）
  ├── Abstractions/              ← IGraph, IReadOnlyGraph, ICoreGraph 等核心接口
  ├── Chain/                     ← 链处理（IChainNodeHandler, ChainInfo, ChainProcessing）
  ├── Commands/                  ← 命令模式（AddNodeCommand, RemoveNodeCommand...）
  ├── Core/                      ← 核心实现（CoreGraph, GraphFrame, GraphCloneExtensions）
  ├── Navigation/                ← 导航扩展（GetSuccessorKeys, GetAllPaths...）
  ├── Topology/                  ← 拓扑算法（CriticalPath, GraphTopology）
  └── Snapshots/                 ← 快照（GraphSnapshot）

Share/GraphFramework/            ← 图框架门面（对 BasicMethod 的包装）
  ├── Operations/                ← 通用图操作（GraphOperationSkeleton<TKey,TNode,TEdge>）
  ├── Pipeline/                  ← 管线步骤（IGraphPipelineStep, GraphPipeline）
  ├── Bridge/                    ← 桥接（静态泛型 GraphFoundationBridge<T>）
  ├── Systems/                   ← ECS 系统（ValidationSystem, TopologySystem...）
  └── Services/                  ← 服务门面（ReferenceService, NormalizationService...）

Operation/WorkFlowMethod/GraphProcess/  ← 图处理（问题区域）
  ├── SkeletonBridge/            ← 6 个 Skeleton（过度包装）
  ├── Pipeline/                  ← 管线（GraphFoundationBridge 实例类 + 管线步骤）
  ├── Services/                  ← 服务（GraphUpdateService, DirectiveApplier...）
  ├── Deduplication/             ← 去重（业务逻辑，保留）
  ├── Snapshots/                 ← 快照（业务逻辑，保留）
  └── Directives/                ← 指令（业务逻辑，保留）
```

### 1.2 核心问题

#### 问题 1：Skeleton 层过度包装

Operation 层有 **6 个 Skeleton**，其中 5 个是纯委托包装：

| Skeleton | 实际做的事 | 行数 | 结论 |
|---|---|---|---|
| `ChainToGraphSkeleton` | 创建 `GraphFoundationBridge` → 调 `ChainToGraph()` | 80 | **可废弃**，纯委托 |
| `GraphToChainSkeleton` | 创建 `GraphFoundationBridge` → 调 `ExtractComponents()` | 78 | **可废弃**，纯委托 |
| `GraphOperationSkeleton` | switch 分发 Merge/Filter/Subgraph → 委托给 Share 层 | 170 | **可废弃**，纯委托 |
| `GraphUpdateSkeleton` | 指令转换 + 指令应用（有实际业务逻辑） | 430 | **需迁移**，逻辑移到 GraphUpdateService |
| `GraphValidationSkeleton` | 调 `GraphFrame.CreateValidator()` → 验证 | 84 | **可废弃**，纯委托 |
| `CycleDetectionSkeleton` | 调 `GraphAnalyzer.HasCycle()` + `GraphTopology.TopologicalSort()` | 88 | **可废弃**，纯委托 |

#### 问题 2：GraphNavigationExtensions 是扩展方法包装

`GraphNavigationExtensions`（102 行）是**扩展方法**（`this IGraph<string, NodeConfig, object>`），调用方代码如 `graph.GetSuccessorKeys(key)` 依赖它。不能简单废弃，需要改为 using 指向 `GraphFoundation.Navigation.GraphNavigationExtensions`。

#### 问题 3：重复的 IGraphPipelineStep 接口

| 位置 | 接口签名 | 命名空间 |
|---|---|---|
| Operation 层 | `Task ExecuteAsync(IGraph, IGraphPipelineContext)` | `WorkFlowMethod.GraphFramework.Pipeline` |
| Share 层 | `IGraph Execute(IGraph, IPipelineContext)` | `GraphFramework.Pipeline` |

两者功能完全重叠，Operation 层的异步版本没有实际异步操作。

---

## 二、重构目标

1. **废弃 5 个纯委托 Skeleton**，移到 `Destoried/` 目录，消除过度包装
2. **迁移 GraphUpdateSkeleton 的业务逻辑**到 GraphUpdateService（统一使用新版 NodeConfig）
3. **统一管线接口**，消除异步/同步重复
4. **GraphNavigationExtensions 改为委托**到 BasicMethod 层

---

## 三、执行顺序

**重要原则：先更新引用方，再移动被引用方到废弃目录。**

```
步骤 1：修改 GraphUpdateService.cs    ← 先迁移逻辑（吸收 GraphUpdateSkeleton 的功能）
步骤 2：修改 GraphCoreSkeleton.cs     ← 先修改引用（删除对 Skeleton 的引用）
步骤 3：修改 GraphPipelineStep.cs     ← 先修改（删除异步接口）
步骤 4：修改 GraphPipelineSteps.cs    ← 先修改（改用同步接口）
步骤 5：修改 GraphNavigationExtensions.cs ← 先修改（改为委托）
步骤 6：移动 6 个 Skeleton 文件到 Destoried/  ← 最后移动（此时已无引用）
步骤 7：构建验证
步骤 8：更新测试文件
```

### 步骤 1：修改 GraphUpdateService.cs

从 `GraphUpdateSkeleton` 迁移以下方法到 `GraphUpdateService`，**统一使用新版 `NodeConfig`**（不保留 `OldNodeConfig` 重载）：

**迁移的 public static 方法：**
- `ConvertConfigToDirective(ConnectNodeConfig config)` → 保持 public static

**迁移的 private static 方法：**
- `ConvertConfigCore(...)` → 保持 private
- `ParseChainConfigs(List<object>?)` → 保持 private
- `GetMapKeyCount(List<object>?)` → 保持 private
- `ParseMatchMode(string)` → 保持 private

**迁移的指令应用方法（统一使用 NodeConfig）：**
- `ApplyDirective(GraphFoundationBridge<string, NodeConfig, object>, IGraph<string, NodeConfig, object>, GraphUpdateDirective, ...)`
- `ApplyInsertChain(...)` → 内部调 `bridge.InsertNodesAfter/Before`
- `ApplyInsertNode(...)` → 内部调 `bridge.InsertNodesAfter/Before` 或直接 `graph.AddNode`
- `ApplyDeleteNode(...)` → 内部调 `bridge.DeleteNode`
- `ApplyReplaceNode(...)` → 内部调 `bridge.ReplaceNode`
- `ApplyRedirectEdge(...)` → 内部调 `bridge.RedirectEdge`
- `ApplyComposite(...)` → 递归调 `ApplyDirective`

### 步骤 2：修改 GraphCoreSkeleton.cs

将对 Skeleton 的引用改为直接调用底层 API：

```csharp
// 原：var chainToGraph = new ChainToGraphSkeleton(context);
// 改为：
var bridge = new GraphFoundationBridge<string, NodeConfig, object>(context);
var graph = bridge.ChainToGraph(inputChains);

// 原：var cycleDetection = new CycleDetectionSkeleton();
// 改为：
var analyzer = new GraphAnalyzer();
var hasCycle = analyzer.HasCycle(graph);
var topoResult = GraphTopology.TopologicalSort(graph);

// 原：var validation = new GraphValidationSkeleton();
// 改为：
var validator = GraphFrame.CreateValidator(graph);
var result = validator.Validate();
```

### 步骤 3：修改 GraphPipelineStep.cs

- 删除异步 `IGraphPipelineStep<TKey, TNodeData, TEdgeData>` 接口
- 删除 `IGraphPipelineContext` 接口
- 删除 `DefaultGraphPipelineContext` 实现
- 添加 using 引用 `GraphFramework.Pipeline.IGraphPipelineStep`

### 步骤 4：修改 GraphPipelineSteps.cs

- `GraphCloneStep` → 实现 Share 层的同步接口
- `GraphDeduplicateStep` → 实现 Share 层的同步接口
- `GraphValidateStep` → 实现 Share 层的同步接口
- `GraphAnalyzeStep` → 实现 Share 层的同步接口

### 步骤 5：修改 GraphNavigationExtensions.cs

改为 using 指向 `GraphFoundation.Navigation.GraphNavigationExtensions`，保留扩展方法签名。

### 步骤 6：移动 6 个文件到 Destoried/

## 五、风险与注意事项

### 5.1 逻辑保全

所有 Skeleton 的实质逻辑要么是纯委托（直接调底层），要么会被迁移到 `GraphUpdateService`。**重构不会丢失任何逻辑。**

### 5.2 外部引用

需要搜索以下引用并更新：

```
搜索 "ChainToGraphSkeleton"     → GraphCoreSkeleton.cs
搜索 "GraphToChainSkeleton"     → GraphCoreSkeleton.cs
搜索 "GraphOperationSkeleton"   → GraphCoreSkeleton.cs
搜索 "GraphUpdateSkeleton"      → Integration.cs
搜索 "GraphValidationSkeleton"  → GraphCoreSkeleton.cs
搜索 "CycleDetectionSkeleton"   → GraphCoreSkeleton.cs
```

### 5.3 测试文件

`CentralConsole/Operation.Tests/` 中的测试需要同步更新。
