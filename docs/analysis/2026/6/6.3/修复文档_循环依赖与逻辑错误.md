# 修复文档：循环依赖与逻辑错误

## 一、循环依赖问题

### 1.1 问题描述

```
FileDriven.Pipeline.csproj
  └── ProjectReference → FileDriven.UI.csproj  (骨架需要 ControlHelper)
  
FileDriven.UI.csproj
  └── ProjectReference → FileDriven.Pipeline.csproj  (EventPipelineExecutor 需要 PipelineEntry)

结果：循环依赖！MSB4006 构建错误
```

### 1.2 修复方案

**方案：将 `ControlHelper` 下沉到 `FileDriven.Utilities` 项目**

`ControlHelper` 只是一个纯工具类（递归查找控件），不依赖 UI 事件或管线逻辑，适合放在 Utilities 层。

#### 步骤 1：移动 `ControlHelper`

```
移动：FileDriven.UI\Helpers\ControlHelper.cs
  →  FileDriven.Utilities\Helpers\ControlHelper.cs
```

命名空间从 `FileDriven.UI.Helpers` 改为 `FileDriven.Utilities.Helpers`。

#### 步骤 2：更新引用方

| 文件 | 修改内容 |
|------|---------|
| `FileDriven.Pipeline\Skeletons\ParseCommandSkeleton.cs` | `using FileDriven.UI.Helpers` → `using FileDriven.Utilities.Helpers` |
| `FileDriven.Pipeline\Skeletons\ExtractValuesSkeleton.cs` | `using FileDriven.UI.Helpers` → `using FileDriven.Utilities.Helpers` |
| `FileDriven.Pipeline\Skeletons\WriteResultSkeleton.cs` | `using FileDriven.UI.Helpers` → `using FileDriven.Utilities.Helpers` |

#### 步骤 3：移除循环引用

- `FileDriven.Pipeline.csproj`：移除 `FileDriven.UI.csproj` 引用（第 29-30 行）
- `FileDriven.UI.csproj`：保留 `FileDriven.Pipeline.csproj` 引用（EventPipelineExecutor 需要 PipelineEntry）

#### 步骤 4：验证依赖方向

```
修复后的依赖方向（单向）：
FileDriven.Pipeline → FileDriven.Utilities  ✓
FileDriven.UI      → FileDriven.Pipeline    ✓
FileDriven.UI      → FileDriven.Utilities   ✓ (通过 Pipeline 间接)
```

## 二、逻辑错误修复

### 错误 1：click 命令在 GUI 模式下被双重执行

**严重程度：** 🔴 严重

**问题：** `ParseCommandSkeleton` 中 GUI 模式的 click 命令通过 `HandleClickViaWinForms()` 模拟点击，触发 `WinFormsEventBinder` → `EventPipelineExecutor` 管线。但 `GuiPipelineRunner` 的管线在 `ParseCommandSkeleton` 执行完后，还会继续执行 `FindBindingSkeleton` → `ExtractValuesSkeleton` → `ExecuteFunctionSkeleton` → `WriteResultSkeleton`，导致 click 命令被执行两次。

**修复方案：** 在 `ParseCommandSkeleton` 中，GUI 模式的 click 命令标记 `IsNonEventCommand = true` 后，**直接 return**，不再继续执行后续骨架。但需要确保 `FunctionExecuteSuccess` 和 `FunctionResultValue` 已正确设置。

**修改文件：** `FileDriven.Pipeline\Skeletons\ParseCommandSkeleton.cs`

```csharp
// 第 123-127 行修改为：
if (IsClickCommand(input.ParsedVerb, input.ParsedAction) && input.IsGuiMode)
{
    HandleClickViaWinForms(input);
    input.IsNonEventCommand = true;
    // ★ 修复：直接 return，避免后续骨架重复执行
    //   HandleClickViaWinForms 已通过 EventPipelineExecutor 完成了完整管线流程
    return input;
}
```

### 错误 2：手动点击时 `EventPipelineExecutor` 缺少 `LoadedConfigs`

**严重程度：** 🔴 严重

**问题：** `EventPipelineExecutor.Execute()` 第 56-65 行创建 `FileDrivenPipelineContext` 时，没有设置 `LoadedConfigs` 属性。手动点击触发的管线执行中，`FindBindingSkeleton` 无法从 `LoadedConfigs` 中查找事件绑定。

**修复方案：** 在 `EventPipelineExecutor` 中添加 `LoadedConfigs` 属性，并在创建 context 时传入。

**修改文件：** `FileDriven.UI\Event\EventPipelineExecutor.cs`

```csharp
// 添加属性
public ConcurrentDictionary<string, object>? LoadedConfigs { get; set; }

// 构造函数中接收
public EventPipelineExecutor(
    IEventBindingResolver bindingResolver,
    IFunctionExecutor functionExecutor,
    Form targetForm,
    ConcurrentDictionary<string, object>? loadedConfigs = null)  // ★ 新增参数
{
    _bindingResolver = bindingResolver;
    _functionExecutor = functionExecutor;
    _targetForm = targetForm;
    _loadedConfigs = loadedConfigs;  // ★ 保存
    _pipeline = PipelineEntry.BuildCommandPipeline(bindingResolver, functionExecutor);
}

// Execute 方法中传入 context
var context = new FileDrivenPipelineContext
{
    ParsedTarget = controlName,
    ParsedAction = eventType,
    TargetForm = _targetForm,
    BindingResolver = _bindingResolver,
    FunctionExecutor = _functionExecutor,
    LoadedConfigs = _loadedConfigs,  // ★ 修复：传入 LoadedConfigs
    IsNonEventCommand = false,
    ParseSuccess = true
};
```

**同时修改：** `FileDriven.Launcher\GuiModeRunner.cs` 第 49-50 行传入 `loadedConfigs`：

```csharp
var eventPipelineExecutor = new EventPipelineExecutor(
    bindingResolver, functionExecutor, mainForm,
    loadedConfigs: loadedConfigs);  // ★ 传入共享字典
```

### 错误 3：`EnsureSharedLoadedConfigs` 创建的新 resolver 未同步回 GuiModeRunner

**严重程度：** 🟡 中等

**问题：** `GuiPipelineRunner.EnsureSharedLoadedConfigs()` 创建了新的 `EventBindingResolver`，但只在 `GuiPipelineRunner` 内部使用。`GuiModeRunner` 中的原始 `resolver` 仍然使用独立的字典，导致脚本执行后手动点击时找不到配置。

**修复方案：** 在 `GuiModeRunner` 中，将 `GuiPipelineRunner.RunAsync()` 返回的 `effectiveBindingResolver` 同步回 `GuiModeRunner` 的变量。或者更简单：让 `GuiModeRunner` 直接使用 `GuiPipelineRunner` 内部创建的 resolver。

**修改文件：** `FileDriven.Launcher\Runners\GuiPipelineRunner.cs`

将 `EnsureSharedLoadedConfigs` 改为 `public static` 并返回新的 resolver，让调用方可以获取。

或者更彻底的方案：**移除 `EnsureSharedLoadedConfigs` 方法**，让 `GuiModeRunner` 直接创建共享字典的 `EventBindingResolver`，并同时传给 `EventPipelineExecutor` 和 `GuiPipelineRunner`。

**修改文件：** `FileDriven.Launcher\GuiModeRunner.cs`

```csharp
// ★ 修复：直接使用共享字典创建 EventBindingResolver
//   不再需要 EnsureSharedLoadedConfigs 的二次包装
var loadedConfigs = new ConcurrentDictionary<string, object>(StringComparer.OrdinalIgnoreCase);
var loadedConfigsLock = new object();
var resolver = new EventBindingResolver(loadedConfigs, loadedConfigsLock);
var bindingResolver = (IEventBindingResolver)resolver;

// 传给 EventPipelineExecutor（手动点击使用）
var eventPipelineExecutor = new EventPipelineExecutor(
    bindingResolver, functionExecutor, mainForm,
    loadedConfigs: loadedConfigs);

// 传给 GuiPipelineRunner（脚本执行使用）
var results = await GuiPipelineRunner.RunAsync(
    options, actualCommandFile, stepCoordinator,
    mainForm, bindingResolver, functionExecutor, uiCommandManager,
    winFormsEventBinder: winFormsEventBinder,
    sharedLoadedConfigs: loadedConfigs);  // 同一个字典实例
```

### 错误 4：手动点击时 `TryGetError` 因未初始化字段误判失败

**严重程度：** 🔴 严重

**问题：** `EventPipelineExecutor` 设置 `ParseSuccess = true`，但 `BindingFound`、`ExtractSuccess`、`FunctionExecuteSuccess`、`WriteResultSuccess` 默认为 false。`TryGetError()` 依次检查这些字段，全部为 false，导致管线执行成功也被判为失败。

**修复方案：** `EventPipelineExecutor` 执行完管线后，直接检查 `context.FunctionExecuteSuccess` 和 `context.WriteResultSuccess`，而不是调用 `TryGetError`。因为手动点击走的是 `BuildCommandPipeline()` 子管线，该管线中的骨架会正确设置这些字段。

**修改文件：** `FileDriven.UI\Event\EventPipelineExecutor.cs`

```csharp
public bool Execute(string controlName, string eventType, string value)
{
    var context = new FileDrivenPipelineContext
    {
        ParsedTarget = controlName,
        ParsedAction = eventType,
        TargetForm = _targetForm,
        BindingResolver = _bindingResolver,
        FunctionExecutor = _functionExecutor,
        LoadedConfigs = _loadedConfigs,
        IsNonEventCommand = false,
        ParseSuccess = true
    };

    try
    {
        _pipeline.Execute(context);
        
        // ★ 修复：直接检查 FunctionExecuteSuccess（管线骨架已正确设置）
        //   不再使用 TryGetError，因为 ParseSuccess=true 但其他字段为默认 false
        if (!context.FunctionExecuteSuccess)
        {
            var errorMsg = context.FunctionErrorMessage 
                ?? context.BindingErrorMessage 
                ?? context.ExtractErrorMessage 
                ?? "Manual click execution failed";
            System.Diagnostics.Debug.WriteLine(
                $"[手动点击] 执行失败: {controlName}.{eventType}, 错误: {errorMsg}");
            return false;
        }
        return true;
    }
    catch (Exception ex)
    {
        System.Diagnostics.Debug.WriteLine(
            $"[手动点击] 执行异常: {controlName}.{eventType}, 异常: {ex.Message}");
        return false;
    }
}
```

### 错误 5：click 命令 `BeginInvoke` 异步执行导致状态不一致

**严重程度：** 🟡 中等

**问题：** `ParseCommandSkeleton` 第 235 行使用 `form.BeginInvoke()` 异步执行模拟点击，不等待完成就设置 `FunctionExecuteSuccess = true`。后续骨架可能读取到错误的状态。

**修复方案：** 使用 `Invoke()` 替代 `BeginInvoke()`，确保模拟点击同步完成后再继续管线执行。

**修改文件：** `FileDriven.Pipeline\Skeletons\ParseCommandSkeleton.cs`

```csharp
// 第 233-240 行修改为：
if (form.InvokeRequired)
{
    // ★ 修复：使用 Invoke 而非 BeginInvoke，确保模拟点击同步完成
    //   BeginInvoke 是异步的，会导致管线在模拟点击完成前继续执行
    form.Invoke(new Action(() => PerformClickOnControl(form, target)));
}
else
{
    PerformClickOnControl(form, target);
}
```

## 三、修复优先级

| 优先级 | 修复项 | 影响 |
|--------|--------|------|
| P0 | 循环依赖（ControlHelper 下沉） | 构建失败，必须先修复 |
| P1 | 错误 4：TryGetError 误判 | 手动点击功能完全不可用 |
| P1 | 错误 2：LoadedConfigs 缺失 | 手动点击找不到事件绑定 |
| P2 | 错误 1：click 双重执行 | 功能异常（执行两次） |
| P2 | 错误 3：resolver 未同步 | 脚本执行后手动点击失效 |
| P3 | 错误 5：BeginInvoke 异步 | 偶发状态不一致 |
| P3 | 错误 6：注释错误 | 不影响运行 |

## 四、修复顺序

1. **P0**：下沉 ControlHelper → 解除循环依赖 → 构建通过
2. **P1**：修复 EventPipelineExecutor（LoadedConfigs + TryGetError）
3. **P2**：修复 click 双重执行 + resolver 同步
4. **P3**：修复 BeginInvoke + 注释
