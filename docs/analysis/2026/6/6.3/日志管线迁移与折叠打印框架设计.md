# 日志管线迁移与折叠打印框架设计

## 一、背景与问题

### 1.1 当前日志架构概览

FileDriven 框架的日志系统经历了多次重构，目前存在**两条并行的日志输出路径**：

```
路径一（新架构 — PlaceholderLogHelper 体系）：
  调用方（Skeleton / LogEntryBuilder / FileDrivenLogPlaceholderHandler）
    → PlaceholderLogHelper.Log(level, category, module, message)
      → LogRepository.Write(entry)
        → [Console 模式] Console.WriteLine(...)  ← 输出点 A
        → [Database 模式] 写入内存队列 → 后续刷入 SQLite

路径二（旧架构 — Logger 体系）：
  调用方（旧版 Logger 使用者）
    → Logger.Info/Warn/Error/Debug(category, message)
      → WriteToRepository(level, category, message)  → LogRepository.Write(entry)  ← 也走 LogRepository
      → WriteToTargets(level, category, message)      → Console.WriteLine(...)      ← 输出点 B（重复！）
```

### 1.2 重复日志问题

从实际运行日志可以看到大量重复输出：

```
[19:26:22.044] [DEBUG] [FileDriven] [TemplateResolver] Expanding template 'math-operation'
[19:26:22.045] [DEBUG] [FileDriven] [TemplateResolver] Expanding template 'math-operation'
[19:26:22.045] [DEBUG] [FileDriven] [TemplateResolver] Expanding template 'math-operation'
[19:26:22.046] [DEBUG] [FileDriven] [TemplateResolver] Expanding template 'math-operation'
[19:26:22.047] [DEBUG] [FileDriven] [TemplateResolver] Expanding template 'math-operation'
[19:26:22.047] [DEBUG] [FileDriven] [TemplateResolver] Expanding template 'math-operation'
[19:26:22.048] [DEBUG] [FileDriven] [TemplateResolver] Expanding template 'echo-section'
```

这些日志的**前缀**（`[时间] [级别] [模块]`）完全相同，只有消息内容不同。连续 6 条 `[DEBUG] [FileDriven] [TemplateResolver]` 前缀的日志，每条都完整打印了前缀，造成大量视觉噪音。

### 1.3 重复输出的根因

从启动日志可以看到，`[TemplateResolver]` 的日志是通过 `PlaceholderLogHelper.Log()`（路径一）输出的。当 `LogRepository.OutputMode == Console` 时，路径一已经在输出点 A 打印了一次。但如果旧版 Logger 的 `WriteToTargets()` 也被触发（输出点 B），就会产生第二次输出。

**关键问题**：`LogRepository.Write()` 在 Console 模式下已经 `Console.WriteLine` 后 `return` 了，但旧版 Logger 的 `WriteToTargets()` 并不知道这一点，它仍然会执行自己的 Console 输出。

### 1.4 目标

分两步解决：

**第一步（P0）— 架构合并**：消除双路径重复输出，统一输出出口。
**第二步（P1）— 折叠打印**：在统一出口的基础上，构建日志折叠打印器，减少视觉噪音。

## 二、第一步：日志管线架构合并

### 2.1 核心原则

**统一输出出口**：所有日志的 Console 输出统一经过 `LogRepository.Write()`，消除 `Logger.WriteToTargets()` 的重复 Console 输出。

### 2.2 当前管线问题

| 问题 | 描述 | 影响 |
|------|------|------|
| **双路径输出** | 路径二的 `Logger.WriteToTargets()` 在路径一已经输出后**再次输出** | 每条日志可能打印两次 |
| **格式不一致** | 两条路径的 Console 输出格式略有差异 | 日志格式不统一 |
| **分类控制分散** | 路径一受 `LogController` 控制，路径二受实例级 `EnabledCategories` 控制 | 控制逻辑分散 |
| **Console 模式短路** | `LogRepository.Write()` 在 Console 模式下直接 `Console.WriteLine` 后 `return` | 路径二的 `WriteToTargets()` 仍会执行 |

### 2.3 合并后的管线架构

```
合并后（统一输出出口）：
  调用方
    → PlaceholderLogHelper.Log() / Logger.Info()
      → LogRepository.Write(entry)          ← 统一入口
        → [Console 模式] LogCollapser.Write() ← 唯一 Console 输出点（带折叠）
        → [Database 模式] 写入内存队列

  Logger.WriteToTargets()                    ← 仅输出到 Debug/UI
    → System.Diagnostics.Debug.WriteLine()
    → _uiLogAction?.Invoke()
```

### 2.4 具体改动

#### 改动 1：修改 `Logger.WriteToTargets()` — 消除重复 Console 输出

**文件**：`BasicMethod\Logging\LogCore.cs`

```csharp
private void WriteToTargets(string level, LogCategory category, string message)
{
    // ★ 分类开关判断逻辑（保持不变）
    if (EnabledCategories != LogCategory.None)
    {
        if (!EnabledCategories.HasFlag(category))
            return;
    }
    else
    {
        if (!LogController.IsOutputEnabled(category))
            return;
    }

    var timestamp = DateTime.Now.ToString("HH:mm:ss.fff");
    var formatted = $"[{timestamp}] [{level}] [{_moduleName}] {message}";

    // ★ 修改：Console 输出已由 LogRepository.Write() 统一处理，此处跳过避免重复
    // 仅输出到 Debug 和 UI 回调
    if (ActiveTargets.HasFlag(LogOutputTarget.Debug))
        System.Diagnostics.Debug.WriteLine(formatted);

    if (ActiveTargets.HasFlag(LogOutputTarget.UI))
        _uiLogAction?.Invoke(formatted);
}
```

#### 改动 2：明确 `LogOutputTarget.Console` 标志的语义

**文件**：`BasicMethod\Logging\LogCore.cs`

```csharp
[Flags]
public enum LogOutputTarget
{
    /// <summary>
    /// 输出到 Console
    /// <para>★ 注意：此标志仅控制旧版 Logger 的 Console 输出</para>
    /// <para>新架构统一走 LogRepository.OutputMode，不受此标志控制</para>
    /// </summary>
    Console = 1 << 0,

    Repository = 1 << 3,

    /// <summary>默认：输出到 Console + Debug + Repository</summary>
    Default = Console | Debug | Repository
}
```

## 三、第二步：日志折叠打印框架设计

### 3.1 设计思路

折叠打印的核心思路是**基于消息内容的去重折叠**，而非基于前缀的折叠。具体来说：

- 对**完全相同的消息内容**进行折叠（而非仅比较前缀）
- 使用 `ConcurrentDictionary` 跟踪每条消息的重复次数
- 使用 `Timer` 定时刷新折叠缓冲区，避免程序退出时丢失日志
- 支持配置折叠阈值、超时时间、摘要格式

### 3.2 核心类：`LogCollapser`

**位置**：`BasicMethod\Logging\LogCollapser.cs`
**命名空间**：`Common.Diagnostics`

```csharp
// ====================================================================
// LogCollapser.cs — 折叠打印控制器
//
// 功能：
//   1. 对连续重复的日志消息进行折叠，避免 Console 刷屏
//   2. 支持配置折叠阈值（重复 N 次后折叠）
//   3. 支持配置折叠超时（超过 T 时间后强制输出）
//   4. 支持配置最大折叠行数（折叠后最多显示 M 行）
//
// 使用方式：
//   LogCollapser 由 LogRepository.Write() 自动调用，
//   外部无需手动调用。
//
// 设计原则：
//   - 线程安全：使用 ConcurrentDictionary + lock 确保并发安全
//   - 零侵入：LogRepository 只需将 Console 输出委托给 LogCollapser
//   - 可配置：通过 LoggingConfiguration.CollapserConfig 配置
// ====================================================================

namespace Common.Diagnostics
{
    /// <summary>
    /// 折叠打印配置
    /// </summary>
    public class CollapserConfig
    {
        public bool Enabled { get; set; } = true;
        public int Threshold { get; set; } = 3;
        public int FlushTimeoutMs { get; set; } = 5000;
        public int MaxCollapsedLines { get; set; } = 5;
        public string SummaryFormat { get; set; } = "[折叠] {0} (x{1})";
    }

    /// <summary>
    /// 折叠打印控制器
    /// </summary>
    public static class LogCollapser
    {
        // 配置
        public static CollapserConfig Config { get; set; } = new();

        // 核心方法
        public static bool Write(string message);
        public static void Flush();
        public static void Reset();
    }
}
```

### 3.3 折叠逻辑详解

`LogCollapser.Write(message)` 的工作流程：

1. **未启用折叠**：直接 `Console.WriteLine(message)`，返回 `true`
2. **新消息**：创建 `CollapseState`，输出消息，启动定时器
3. **重复消息（未达阈值）**：递增计数，正常输出
4. **重复消息（刚好达到阈值）**：输出折叠摘要 `[折叠] 原始消息 (xN)`
5. **重复消息（超过阈值）**：不输出，仅递增计数

定时器每 `FlushTimeoutMs` 毫秒触发一次 `Flush()`，输出所有当前折叠中的消息摘要。

### 3.4 集成点：修改 `LogRepository.Write()`

**文件**：`BasicMethod\Logging\LogRepository.cs`

## 五、配置方式

### 5.1 代码配置

```csharp
// 启用折叠（默认启用）
LogCollapser.Config.Enabled = true;

// 设置折叠阈值（连续 5 条相同消息才折叠）
LogCollapser.Config.Threshold = 5;

// 禁用折叠（恢复逐条打印）
LogCollapser.Config.Enabled = false;
```

### 5.2 通过 `LoggingConfiguration` 配置

```csharp
// 在 LoggingConfiguration 中新增属性
public class LoggingConfiguration
{
    // ... 现有属性 ...

    /// <summary>
    /// 是否启用日志折叠打印
    /// <para>默认启用。关闭后恢复逐条完整打印</para>
    /// </summary>
    public bool EnableLogCollapse { get; set; } = true;

    /// <summary>
    /// 日志折叠阈值
    /// <para>连续相同消息超过此数量时才显示折叠摘要行</para>
    /// <para>默认 3 条</para>
    /// </summary>
    public int LogCollapseThreshold { get; set; } = 3;
}

// 在 Apply() 方法中应用
public void Apply()
{
    // ... 现有配置 ...

    LogCollapser.Config = new CollapserConfig
    {
        Enabled = EnableLogCollapse,
        Threshold = LogCollapseThreshold
    };
}
```

### 6.2 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 多线程竞争 | 折叠状态可能错乱 | 使用 `ConcurrentDictionary` + `lock` 保证线程安全 |
| 程序崩溃时最后一批日志丢失 | 日志不完整 | 使用 `Timer` 定时刷新，`FlushTimeoutMs` 默认 5 秒 |
| 折叠后丢失时间精度 | 无法精确知道每条日志的时间 | 折叠摘要中显示重复次数 |
| 旧版 Logger 的 Console 输出重复 | 每条日志打印两次 | 步骤 1 消除 `WriteToTargets()` 的 Console 输出 |

## 八、编译修复记录

### 8.1 Error/Fatal 方法二义性（CS0121）

**问题**：`Logger` 类中 `Error(LogCategory, string, Exception? = null)` 和 `Error(LogCategory, string, params object?[])` 在调用 `_logger.Error(category, "msg")` 时产生二义性。

**修复**：
- 将 `Exception?` 可选参数改为非可选参数 `Exception`
- 添加不带 Exception 的重载 `Error(LogCategory, string)` / `Fatal(LogCategory, string)`
- 同步更新 `ILogger` 接口中的对应签名
- 同步更新测试文件 `CustomTestLogger` 中的接口实现

### 8.2 旧管线骨架中的 `_logger.xxx()` 调用

**问题**：`LogPipelineSkeletons.cs` 和 `LoggingSkeletonWrapper.cs` 中的旧骨架使用了 `_logger.xxx()` 调用，在新签名下编译失败。

**修复**：将所有旧骨架中的 `_logger.xxx()` 替换为直接调用 `LogRepository.Write(new LogEntry { ... })`，统一输出路径。

### 8.3 LogCollapser 不存在

**问题**：`LogRepository.Write()` 和 `LoggingSetup.Reset()` 中引用了 `LogCollapser`，但该文件尚未创建。

**修复**：新建 `BasicMethod/Logging/LogCollapser.cs`，实现折叠打印控制器。
