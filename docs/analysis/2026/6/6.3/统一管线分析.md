# 统一管线分析：WinForms 手动操作与脚本测试路径不一致问题

## 问题现象

- **`交互启动.bat` 运行 `math_functions_test.json`**：`click addButton` 命令通过 ✅，`Plus` 函数正确执行，结果写入 `resultTextBox`
- **`UI启动.bat` 手动点击 `addButton`**：按钮无响应 ❌，`Plus` 函数未执行

## 两条路径的完整链路

### 路径A：脚本测试路径（`交互启动.bat` → `math_functions_test.json` → `click addButton`）

```
math_functions_test.json
  → load-config-show MathFunctions.json（加载 UI 配置并显示窗口）
  → math-operation（模板展开为三条命令）
      → set valueATextBox 10
          → ParseCommandSkeleton.HandleSetValue()
          → WinFormsEventBinder.IsScriptExecutionMode = true（抑制事件触发）
          → 设置 control.Text = "10"
          → WinFormsEventBinder.IsScriptExecutionMode = false
      → set valueBTextBox 25（同上）
      → click addButton
          → ParseCommandSkeleton 解析为 "do click addButton"
          → FindBindingSkeleton
              → resolver.FindEventBinding("addButton", "click")
              → EventBindingResolver 从 LoadedConfigs 中查找配置
              → 找到 functionName: "Plus" ✅
          → ExtractValuesSkeleton → 从 valueATextBox/valueBTextBox 提取值
          → ExecuteFunctionSkeleton → 执行 Plus(10, 25) ✅
          → WriteResultSkeleton → 写入 resultTextBox ✅
```

### 路径B：WinForms 手动操作路径（`UI启动.bat` → 手动点击 `addButton`）

```
手动点击按钮
  → WinForms 原生 Click 事件触发
  → 需要 WinFormsEventBinder 事先绑定了 control.Click += handler
  → handler 中调用 FireAndForgetTriggerAsync
      → IEventTriggerService.TriggerEventAsync("addButton", "click", "")
      → EventTriggerServiceBase.TriggerEventCoreAsync
      → BindingResolver.FindEventBinding("addButton", "click")
      → 查找配置中的 events.click 属性
      → 如果 events 不存在 → 返回 null ❌
      → 错误被 try-catch 吞掉，只写到 Debug.WriteLine
```

## 根本原因

### 两条路径走的是不同的查找方式

| 环节 | 路径A（脚本 click 命令） | 路径B（手动点击） |
|------|------------------------|-------------------|
| 入口 | `FindBindingSkeleton` | `WinFormsEventBinder` 的 handler |
| 查找方式 | `IEventBindingResolver.FindEventBinding()` | `IEventTriggerService.TriggerEventAsync()` → 内部也调 `IEventBindingResolver.FindEventBinding()` |
| 依赖的数据 | 配置中的 `functionName` 属性 | 配置中的 `events` 对象 |
| 错误处理 | 返回错误信息到管线 | 被 `try-catch` 吞掉，只写 `Debug.WriteLine` |

**关键问题：两条路径最终都调用 `IEventBindingResolver.FindEventBinding()`，但脚本路径能查到绑定，手动路径查不到。**

### 为什么脚本路径能查到？

`FindBindingSkeleton`（第115-116行）：
```csharp
var binding = resolver.FindEventBinding(
    input.ParsedTarget, eventType);
```

`EventBindingResolver.FindEventBinding("addButton", "click")` 查找的是配置中展开后的完整 JSON 中的 `functionName` 属性。

### 为什么手动路径查不到？

`WinFormsEventBinder.BindControlEvents`（第64-113行）：
```csharp
public void BindControlEvents(Control control, EventConfig eventsConfig)
{
    if (eventsConfig.Click is { Count: > 0 })
    {
        BindSingleEvent(control, "click", eventsConfig.Click[0]);
    }
    // ...
}
```

`EventConfig.Click` 是 `List<string>` 类型。但 `TemplateResolver.BuildEvents()` 生成的 events 结构是：
```json
{
  "click": "Plus",        // ← 字符串，不是数组
  "bindings": { ... }
}
```

**`"click": "Plus"`（字符串）反序列化为 `EventConfig` 时，`Click` 属性为 null（类型不匹配），所以 `eventsConfig.Click is { Count: > 0 }` 为 false，跳过绑定。**

### 根本原因总结

**`TemplateResolver.BuildEvents()` 生成的 events 结构中的 `"click": "Plus"` 是字符串格式，但 `EventConfig.Click` 属性是 `List<string>` 类型，反序列化不匹配，导致 `Click` 为 null，`WinFormsEventBinder` 没有绑定按钮的 `Click` 事件。**

## 修复方案

### 方案一：修复 `BuildEvents` 生成的 events 结构（推荐）

在 `TemplateResolver.BuildEvents()` 中，将 `eventName` 的值改为数组格式：

```csharp
// 修改前
var events = new JsonObject
{
    [eventName] = functionName  // "click": "Plus"（字符串）
};

// 修改后
var events = new JsonObject
{
    [eventName] = new JsonArray { functionName }  // "click": ["Plus"]（数组）
};
```

这样反序列化为 `EventConfig` 时，`Click` 属性就是 `["Plus"]`，`eventsConfig.Click is { Count: > 0 }` 为 true，`WinFormsEventBinder` 正确绑定按钮的 `Click` 事件。

### 方案二：在 `WinFormsEventBinder.BindControlEvents` 中增加对字符串类型的兼容处理

在 `BindControlEvents` 中，除了检查 `eventsConfig.Click is { Count: > 0 }`，也检查字符串类型的兼容格式。但此方案治标不治本，不推荐。

## 统一管线目标

**WinForms 手动操作路径应该和脚本测试路径完全一致：**

```
手动点击按钮
  → WinForms 原生 Click 事件触发
  → WinFormsEventBinder 的 handler
  → IEventTriggerService.TriggerEventAsync("addButton", "click", "")
  → EventTriggerServiceBase.TriggerEventCoreAsync
  → BindingResolver.FindEventBinding("addButton", "click")
  → 找到 functionName: "Plus" ✅
  → ExtractInputValuesAsync → 从 valueATextBox/valueBTextBox 提取值
  → ExecuteFunctionAsync → 执行 Plus(10, 25) ✅
  → WriteOutputAsync → 写入 resultTextBox ✅
```

**实现此目标的前提：`WinFormsEventBinder` 必须正确绑定按钮的 `Click` 事件。** 而正确绑定的前提是 `BuildEvents` 生成的 events 结构能被 `EventConfig` 正确反序列化。
