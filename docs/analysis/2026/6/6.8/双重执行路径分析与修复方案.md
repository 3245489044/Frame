# 双重执行路径分析与修复方案

## 1. 问题概述

在 GUI 模式下，`set`/`click` 命令存在两条执行路径：

- **路径 1（管线路径）**：`StagePipelineSkeleton` → `ParseCommandStage` → `ExtractValuesStage` → `ExecuteFunctionStage` → `WriteResultStage`
- **路径 2（GuiCommandAdapter 路径）**：`GuiCommandAdapter.DoSetAsync()` / `DoClickAsync()`

但这两条路径**从未协同工作**，导致 `set`/`click` 命令在 GUI 模式下执行失败。

---

## 2. 架构全景图

### 2.1 启动流程

```
GuiModeRunner.Run()
  ├── new PipelineEntry()                    // 创建总管线入口
  ├── new WinFormsEventBinder(pipelineEntry) // 创建事件绑定器（实现 IEventPipelineExecutor）
  ├── pipelineEntry.CreateEventTriggerService(mainForm) // 创建事件触发服务
  ├── new GuiCommandAdapter(uiManager, eventTriggerService, loadConfigFunc) // 创建 GUI 适配器
  └── pipelineEntry.RunPipeline(options, commandFile, targetForm, uiCommandManager, winFormsEventBinder)
       └── CreatePipeline(options)
            └── CreateFileDrivenPipeline(options, bindingResolver, functionExecutor)
                 └── BuildCommandPipeline(bindingResolver, functionExecutor)
```

### 2.2 管线结构

```
CentralPipeline<FileDrivenPipelineContext>
  ├── PreProcessing: ScriptLoadSkeleton
  └── Execution: ForEachPipeline (CommandLoop)
       └── 对每条命令执行:
            └── StagePipelineSkeleton
                 └── StagePipeline<CommandContext> (CommandPipeline)
                      ├── ParseCommandStage
                      ├── ExtractValuesStage
                      ├── ExecuteFunctionStage
                      └── WriteResultStage
                      ★ FindBindingStage 不在其中！
```

### 2.3 命令分类

```
命令字符串 "set valueATextBox 10"
  → CommandParser.Normalize(): "set" → "do set" → "do set valueATextBox 10"
  → ParsedCommand { Verb="do", Action="set", Target="valueATextBox", IsNonEventCommand=false }
  → IsEventCommand = true（因为 "set" 不在 _nonEventCommands 列表中）
```

**非事件命令列表**（`CommandParser.DefaultNonEventCommands`）：
```
load, close, echo, sleep, show, look, wait, assert, discover, list, validate, exit
```

**事件命令**（不在上述列表中的 `do` 动词）：
```
set, click, type, select, check, uncheck
```

## 3. 双重执行路径的详细分析

### 3.1 路径 1：管线路径（StagePipelineSkeleton）

**入口：** `FileDriven/FileDriven.Pipeline/PipelineEntry.cs` 第 533-638 行

```
命令 "set valueATextBox 10"
  → ParseCommandStage
    → CommandParser.Parse("do set valueATextBox 10")
    → ParsedCommand { Verb="do", Action="set", Target="valueATextBox", Parameters={}, IsNonEventCommand=false }
    → context.SetStageResult("ParseCommand", true) ✓

  → ExtractValuesStage
    → CanExecute: IsEventCommand(context) = true → 继续
    → BoundInputs = null（因为 FindBindingStage 未执行）
    → 第 50-55 行：BoundInputs 为空 → 设置空字典 → SetStageResult("ExtractValues", true) ✓
    → 注意：这里标记为成功，但实际没有提取任何值

  → ExecuteFunctionStage
    → CanExecute: IsEventCommand(context) = true → 继续
    → BoundFunctionName = null（因为 FindBindingStage 未执行）
    → 第 52-56 行：BoundFunctionName 为空 → 报错 "BoundFunctionName is required"
    → context.SetStageResult("ExecuteFunction", false, "BoundFunctionName is required") ✗

  → WriteResultStage
    → CanExecute: IsEventCommand(context) = true → 继续
    → BoundOutputTarget = null（因为 FindBindingStage 未执行）
    → 第 47-51 行：BoundOutputTarget 为空 → 标记为成功 ✓
    → 注意：这里标记为成功，但实际没有写入任何结果

  → TryGetError()（CommandContext.cs 第 135-160 行）
    → 遍历 ["ParseCommand", "FindBinding", "ExtractValues", "ExecuteFunction", "WriteResult"]
    → FindBinding: GetStageSuccess("FindBinding") = false（从未设置）
    → 报错 "FindBinding failed (no detailed error message)" ✗
```

**结果：** 管线路径执行了 4 个阶段，但 `ExecuteFunctionStage` 失败，`TryGetError()` 报错。**真实控件没有被设置任何值。**

### 3.2 路径 2：GuiCommandAdapter 路径

**入口：** `FileDriven/FileDriven.UI/Commands/Adapters/GuiCommandAdapter.cs`

```
GuiCommandAdapter.DoSetAsync("valueATextBox", parameters)
  → ValueExtractionHelper.ExtractValue() → value = "10"
  → _uiManager.SetControlValue("valueATextBox", "10")  // 设置真实控件值 ✓
  → EventTypeMapper.GetEventTypeForControl() → eventType = "textchanged"
  → _eventTriggerService.TriggerEventAsync("valueATextBox", "textchanged", "10")
    → BindingResolver.FindEventBinding("valueATextBox", "textchanged")  // 查找绑定
    → base.TriggerEventAsync()  // 执行函数管线
    → WriteOutputAsync()  // 写入真实控件
  → return SuccessResult ✓
```

**但这条路径从未被管线调用！** 它只存在于：
- `WinFormsEventBinder` 中作为用户手动操作 UI 时的运行时事件触发
- 但 `WinFormsEventBinder.IsScriptExecutionMode=true` 时，运行时事件被跳过

### 3.3 两条路径的关系

```
管线路径（由命令循环触发）                    GuiCommandAdapter 路径（独立存在）
┌─────────────────────────────┐            ┌─────────────────────────────┐
│ ParseCommandStage           │            │ DoSetAsync()                │
│   → 解析命令 ✓              │            │   → SetControlValue() ✓     │
│ ExtractValuesStage          │            │   → TriggerEventAsync() ✓   │
│   → BoundInputs=null → 跳过 │            │   → WriteOutputAsync() ✓    │
│ ExecuteFunctionStage        │            └─────────────────────────────┘
│   → BoundFunctionName=null  │                        ★
│   → 报错 ✗                 │                 从未被管线调用！
│ WriteResultStage            │
│   → BoundOutputTarget=null  │
│   → 跳过                    │
│ TryGetError()               │
│   → FindBinding 未设置 → 报错│
└─────────────────────────────┘
```

**关键问题：** 两条路径是**完全独立**的，管线路径不知道 `GuiCommandAdapter` 的存在，`GuiCommandAdapter` 也不知道管线的执行。

## 4. 修复方案

### 4.1 方案选择

**方案 G（推荐）：新增 FindBindingStage + 增强各阶段 GUI 能力 + 移除 GuiCommandAdapter**

核心思路：**将 GuiCommandAdapter 中的所有逻辑拆解到管线路径的各个阶段中，然后完全移除 GuiCommandAdapter，使管线路径成为唯一的命令执行入口。**

```
GuiCommandAdapter 中的逻辑拆解：
  ┌──────────────────────────────────────────────────┐
  │ DoSetAsync / DoClickAsync                        │
  │   ├── ValueExtractionHelper.ExtractValue()       │ → ExtractValuesStage
  │   ├── EventTypeMapper.GetEventTypeForControl()   │ → FindBindingStage（新增）
  │   ├── _uiManager.SetControlValue()               │ → ExecuteFunctionStage
  │   └── _eventTriggerService.TriggerEventAsync()   │
  │       ├── FindEventBinding()                     │ → FindBindingStage（新增）
  │       ├── ExtractInputValuesAsync()              │ → ExtractValuesStage
  │       ├── ExecuteFunctionAsync()                 │ → ExecuteFunctionStage
  │       └── WriteOutputAsync()                     │ → WriteResultStage
  ├──────────────────────────────────────────────────┤
  │ DoLoadAsync                                      │ → NonEventCommandHandler.HandleLoad（已有）
  │ DoClose                                          │ → NonEventCommandHandler.HandleClose（已有）
  │ DoSleepAsync                                     │ → NonEventCommandHandler.HandleSleep（已有）
  │ DoShow                                           │ → NonEventCommandHandler.HandleShow（已有）
  │ DoLook                                           │ → NonEventCommandHandler.HandleLook（已有）
  │ DoWait                                           │ → NonEventCommandHandler.HandleWait（已有）
  │ DoAssert                                         │ → NonEventCommandHandler.HandleAssert（已有）
  │ DoDiscover                                       │ → NonEventCommandHandler.HandleDiscover（已有）
  │ DoList                                           │ → NonEventCommandHandler.HandleList（已有）
  │ DoValidate                                       │ → NonEventCommandHandler.HandleValidate（已有）
  │ DoExit                                           │ → NonEventCommandHandler.HandleExit（已有）
  │ GetAsync                                         │ → NonEventCommandHandler.HandleLook（已有）
  └──────────────────────────────────────────────────┘
```

### 4.2 关键设计约束

1. **`Share/CommandFramework` 项目不能引用 `FileDriven` 项目**。管线阶段在 `Share` 中，`FileDrivenPipelineContext` 在 `FileDriven` 中。所有跨项目数据传递必须通过 `CommandContext.SharedData` 字典或 `CommandContext` 基类已有的属性。

2. **`CommandContext.TryGetError()` 检查 `"FindBinding"` 阶段**（第 117 行）。必须设置 `SetStageResult("FindBinding", true)` 才能通过错误检查。

3. **`ExtractValuesStage` 和 `WriteResultStage` 已通过 `ExecuteForMode` 基类方法支持 GUI/CLI 模式**，通过 `SharedData["TargetForm"]` 获取 Form 对象。

4. **`NonEventCommandHandler` 已覆盖所有非事件命令**，通过 `context.UICommandManager`（`object` 类型，动态调用）操作 UI，不再需要 `GuiCommandAdapter`。

### 4.3 需要修改的文件

#### 文件 1：`Share/CommandFramework/Pipeline/Stages/FindBindingStage.cs`（新增）

**新增阶段：查找事件绑定**

```csharp
// ============================================================
// FindBindingStage.cs — 事件绑定查找阶段
//
// 查找控件的事件绑定，填充 BoundFunctionName/BoundInputs/BoundOutputTarget。
// GUI 模式：从 BindingResolver 查找
// CLI 模式：从 BindingResolver 查找（如果存在）
//
// ★ 新增：将 GuiCommandAdapter 中的 FindEventBinding 逻辑迁移至此 ★
//
// ★ 设计约束：Share/CommandFramework 不能引用 EventTriggerFramework，
//   因此使用 Func 委托替代 IEventBindingResolver 接口。
//   通过 SharedData["FindBindingFunc"] 传递查找函数。
// ============================================================

using CommandFramework.Abstractions;
using CommandFramework.Models;

namespace CommandFramework.Pipeline.Stages;

/// <summary>
/// 事件绑定查找阶段
/// <para>查找控件的事件绑定，填充 BoundFunctionName/BoundInputs/BoundOutputTarget</para>
/// <para>输入：CommandContext.ParsedCommand / SharedData["FindBindingFunc"]</para>
/// <para>输出：CommandContext.BoundFunctionName / BoundInputs / BoundOutputTarget</para>
/// </summary>
public class FindBindingStage : CommandStageBase
{
    /// <summary>
    /// 绑定查找函数委托
    /// <para>参数：(controlName, eventType) → (functionName, inputs, output)</para>
    /// <para>通过 SharedData["FindBindingFunc"] 传递</para>
    /// </summary>
    private readonly Func<string, string, (string? FunctionName, List<string>? Inputs, string? Output)>? _findBindingFunc;

    /// <summary>
    /// 创建事件绑定查找阶段
    /// </summary>
    /// <param name="findBindingFunc">绑定查找函数（可选，优先使用上下文中的实例）</param>
    public FindBindingStage(
        Func<string, string, (string? FunctionName, List<string>? Inputs, string? Output)>? findBindingFunc = null)
        : base("FindBinding", "Find event binding for control")
    {
        _findBindingFunc = findBindingFunc;
    }

    /// <summary>
    /// 判断是否应执行
    /// <para>非事件命令和注释行跳过</para>
    /// </summary>
    public override bool CanExecute(CommandContext context)
    {
        return IsEventCommand(context);
    }

    /// <summary>
    /// 执行事件绑定查找
    /// </summary>
    protected override Task ExecuteCoreAsync(CommandContext context, CancellationToken cancellationToken)
    {
        var action = context.ParsedCommand?.Action?.ToLowerInvariant();
        var target = context.ParsedCommand?.Target;

        if (string.IsNullOrEmpty(action) || string.IsNullOrEmpty(target))
        {
            context.SetStageResult(Name, true);
            return Task.CompletedTask;
        }

        // 解析查找函数（构造函数注入 → SharedData）
        var findBindingFunc = ResolveDependency(
            context,
            _findBindingFunc,
            sharedDataKey: "FindBindingFunc");

        if (findBindingFunc == null)
        {
            // 没有查找函数时，标记为成功（让后续阶段自行处理）
            context.SetStageResult(Name, true);
            return Task.CompletedTask;
        }

        try
        {
            // 推断事件类型
            var eventType = InferEventType(action, target, findBindingFunc);

            // 查找事件绑定
            var binding = findBindingFunc(target, eventType);
            if (binding.FunctionName == null)
            {
                // 未找到绑定时，标记为成功（让后续阶段自行处理）
                context.SetStageResult(Name, true);
                return Task.CompletedTask;
            }

            // 填充绑定信息
            context.BoundFunctionName = binding.FunctionName;
            context.BoundInputs = binding.Inputs;
            context.BoundOutputTarget = binding.Output;

            context.SetStageResult(Name, true);
        }
        catch (Exception ex)
        {
            context.SetStageResult(Name, false, $"Find binding error: {ex.Message}");
        }

        return Task.CompletedTask;
    }

    /// <summary>
    /// 推断事件类型
    /// <para>set → textchanged（或根据控件类型动态推断）</para>
    /// <para>click → click</para>
    /// <para>其他 → 直接使用 action 作为事件类型</para>
    /// </summary>
    private static string InferEventType(string action, string target,
        Func<string, string, (string? FunctionName, List<string>? Inputs, string? Output)> findBindingFunc)
    {
        return action switch
        {
            "set" => InferSetEventType(target, findBindingFunc),
            "click" => "click",
            _ => action
        };
    }

    /// <summary>
    /// 推断 set 命令的事件类型
    /// <para>优先通过查找函数检查已注册的事件类型，回退到 "textchanged"</para>
    /// </summary>
    private static string InferSetEventType(string target,
        Func<string, string, (string? FunctionName, List<string>? Inputs, string? Output)> findBindingFunc)
    {
        try
        {
            if (findBindingFunc(target, "textchanged").FunctionName != null)
                return "textchanged";
            if (findBindingFunc(target, "valuechanged").FunctionName != null)
                return "valuechanged";
            if (findBindingFunc(target, "selectedindexchanged").FunctionName != null)
                return "selectedindexchanged";
        }
        catch
        {
            // 忽略查找异常
        }

        return "textchanged";
    }
}

```

**增强：GUI 模式下从命令参数提取值**

```csharp
protected override Task ExecuteCoreAsync(CommandContext context, CancellationToken cancellationToken)
{
    // ★ GUI 模式：set 命令需要从命令参数中提取值
    if (context.IsGuiMode)
    {
        var action = context.ParsedCommand?.Action?.ToLowerInvariant();
        if (action == "set")
        {
            var target = context.ParsedCommand?.Target;
            var parameters = context.ParsedCommand?.Parameters;

            // 从 Parameters 中提取值（替代 GuiCommandAdapter.ValueExtractionHelper.ExtractValue）
            var value = ExtractValueFromParameters(target, parameters);
            if (value != null && target != null)
            {
                context.ExtractedValues = new Dictionary<string, string?> { [target] = value };
                context.SetStageResult(Name, true);
                return Task.CompletedTask;
            }
        }
        else if (action == "click")
        {
            context.ExtractedValues = new Dictionary<string, string?>();
            context.SetStageResult(Name, true);
            return Task.CompletedTask;
        }
    }

    // CLI 模式 / 非 set/click 命令：原有逻辑
    if (context.BoundInputs == null || context.BoundInputs.Count == 0)
    {
        context.ExtractedValues = new Dictionary<string, string?>();
        context.SetStageResult(Name, true);
        return Task.CompletedTask;
    }

    // ... 原有提取逻辑（通过 ExecuteForMode）
}

/// <summary>
/// ★ 新增：从命令参数中提取值
/// <para>替代 GuiCommandAdapter.ValueExtractionHelper.ExtractValue</para>
/// </summary>
private static string? ExtractValueFromParameters(string? target,
    Dictionary<string, object>? parameters)
{
    if (parameters == null || parameters.Count == 0)
        return target;

    if (parameters.TryGetValue("value", out var val) && val != null)
        return val.ToString();

    return parameters.Values.FirstOrDefault()?.ToString();
}
```

> **注意**：`ExtractValueFromParameters` 的具体实现需要根据 `CommandParser` 的实际解析结果来调整。

**将 FindBindingStage 加入默认管线，使用 Func 委托替代 IEventBindingResolver**

```csharp
public static BP.IStagePipeline<CommandContext> CreateDefaultPipeline(
    string name = "DefaultCommandPipeline",
    Action<BP.IStagePipeline<CommandContext>>? configure = null,
    Func<string, string, (string? FunctionName, List<string>? Inputs, string? Output)>? findBindingFunc = null)  // ★ 新增参数（Func 委托）
{
    var pipeline = new BP.StagePipeline<CommandContext>(name, "Default command execution pipeline");

    pipeline
        .Register(new ParseCommandStage())
        .Register(new FindBindingStage(findBindingFunc))  // ★ 新增：传入 Func 委托
        .Register(new ExtractValuesStage())
        .Register(new ExecuteFunctionStage())
        .Register(new WriteResultStage());

    configure?.Invoke(pipeline);

    return pipeline;
}
```

#### 文件 5：`FileDriven/FileDriven.Pipeline/PipelineEntry.cs`

**将 IEventBindingResolver 包装为 Func 委托后传入 CreateDefaultPipeline**

```csharp
public static CentralPipeline<FileDrivenPipelineContext> BuildCommandPipeline(
    IEventBindingResolver? bindingResolver,
    IFunctionExecutor? functionExecutor)
{
    // ★ 将 IEventBindingResolver 包装为 Func 委托
    //   避免 Share/CommandFramework 对 EventTriggerFramework 的项目引用
    Func<string, string, (string? FunctionName, List<string>? Inputs, string? Output)>? findBindingFunc = null;
    if (bindingResolver != null)
    {
        findBindingFunc = (controlName, eventType) =>
        {
            var binding = bindingResolver.FindEventBinding(controlName, eventType);
            if (binding == null)
                return (null, null, null);
            return (binding.FunctionName, binding.Inputs?.ToList(), binding.Output);
        };
    }

    // ★ 传入 findBindingFunc，使 FindBindingStage 能查找事件绑定
    var stagePipeline = CommandFramework.Pipeline.PipelineEntry.CreateDefaultPipeline(
        "CommandPipeline",
        findBindingFunc: findBindingFunc);

    return new PipelineBuilder<FileDrivenPipelineContext>("CommandPipeline")
        .Register(PipelineStage.Execution, new StagePipelineSkeleton(stagePipeline))
        .Build();
}
```

### 4.4 修复后的执行流程

```
命令 "set valueATextBox 10"（GUI 模式）

管线路径（命令循环）
  → ParseCommandStage
    → 解析命令 ✓
    → ParsedCommand { Action="set", Target="valueATextBox", Parameters={} }

  → FindBindingStage（★ 新增）
    → action="set" → InferEventType → "textchanged"
    → FindEventBinding("valueATextBox", "textchanged")
    → context.BoundFunctionName = "SomeFunction" ✓
    → context.BoundInputs = ["inputControl1"] ✓
    → context.BoundOutputTarget = "outputControl1" ✓
    → SetStageResult("FindBinding", true) ✓

  → ExtractValuesStage（★ 增强：GUI 模式从命令参数提取值）
    → action="set" → 从 Parameters 提取 value="10"
    → context.ExtractedValues = { "valueATextBox" → "10" } ✓
    → SetStageResult("ExtractValues", true) ✓
```

## 5. 影响范围

### 5.1 修改的文件

| 文件 | 修改内容 | 影响 |
|------|---------|------|
| `Share/CommandFramework/Pipeline/Stages/FindBindingStage.cs` | **新增**：事件绑定查找阶段 | 所有使用默认管线的调用方 |
| `Share/CommandFramework/Pipeline/Stages/ExtractValuesStage.cs` | GUI 模式下从命令参数提取值 | 仅影响 GUI 模式的 set 命令 |
| `Share/CommandFramework/Pipeline/Stages/ExecuteFunctionStage.cs` | GUI 模式下先设置控件值，再执行函数 | 仅影响 GUI 模式的 set 命令 |
| `Share/CommandFramework/Pipeline/PipelineEntry.cs` | `CreateDefaultPipeline` 新增 `findBindingFunc` 参数（Func 委托），注册 `FindBindingStage` | 所有使用默认管线的调用方 |
| `FileDriven/FileDriven.Pipeline/PipelineEntry.cs` | `BuildCommandPipeline` 将 `IEventBindingResolver` 包装为 Func 委托后传入 | 启用 FindBindingStage |
| `FileDriven/FileDriven.UI/Commands/Adapters/GuiCommandAdapter.cs` | **删除**：完全移除 | 所有引用 GuiCommandAdapter 的代码 |

| `FileDriven/FileDriven.Launcher/GuiModeRunner.cs` | 移除 GuiCommandAdapter 的创建和注入 | 仅影响 GUI 模式启动流程 |

### 5.2 不受影响的功能

- **CLI 模式**：不受影响，`IsGuiMode=false`，走原有逻辑（操作虚拟控件）
- **非事件命令**（`load`/`echo`/`sleep` 等）：不受影响，走 `NonEventCommandHandler`
- **用户手动操作 UI**：不受影响，走 `WinFormsEventBinder` 的运行时事件触发
- **`IEventPipelineExecutor`**：不受影响，手动点击仍然通过 `PipelineEntry.Execute()` 走管线

### 5.3 风险

1. **`ExtractValueFromParameters` 的实现依赖 `CommandParser` 的解析结果**：需要确认 `ParsedCommand.Parameters` 中值的存储方式。
2. **`FindBindingStage.InferEventType` 与 `EventTypeMapper.GetEventTypeForControl` 的一致性**：需要确保推断逻辑与 `GuiCommandAdapter` 中的 `EventTypeMapper` 保持一致。
3. **线程安全**：`SetRealControlValue` 操作真实控件需要在 UI 线程上执行。当前管线执行在后台线程，需要使用 `Control.BeginInvoke` 封送到 UI 线程。
4. **`GuiCommandAdapter` 的引用清理**：需要搜索所有引用 `GuiCommandAdapter` 的代码，确保删除后无编译错误。

```csharp
// Share/Adapters/IGuiControlAccessor.cs
public interface IGuiControlAccessor
{
    bool SetControlValue(string controlName, string value);
    string? GetControlValue(string controlName);
}
```

由 `GuiModeRunner` 将实现注入到管线上下文的 `SharedData` 中。
