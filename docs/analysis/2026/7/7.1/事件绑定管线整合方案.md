# 事件绑定管线整合方案（方案三：彻底整合）

> **目标**：将 sideload 事件绑定纳入渲染管线的统一生命周期管理，消除两条独立管线。

---

## 1. 现状分析

### 1.1 两条管线

```
管线A：渲染管线（WinFormsRenderPipeline）
  FrameworkInitializer.Initialize()
    → new DefaultEventBindingService()
    → FileDrivenWdUIBridge.InjectEventBinder()
    → WinFormsRenderPipeline.EventBinder = eventBindingService
    → ExecuteBindEventsStage()  ← MainLayout.json 加载时自动调用

管线B：sideload 事件绑定（MainForm.LoadSideContainerAsync）
  FileDrivenGuiInitializer.CreateAndConfigure()
    → ComponentRegistry.Resolve<IEventBindingService>()  ← 找不到实例！
    → mainForm.EventBindingService = null
    → LoadSideContainerAsync()
    → EventBindingService?.BindEventsAsync(this, config)  ← 跳过！
```

### 1.2 根因

- `DefaultEventBindingService` 实例在 `FrameworkInitializer` 中创建，但**未注册到 `ComponentRegistry`**
- `FileDrivenGuiInitializer` 通过 `ComponentRegistry.Resolve<IEventBindingService>()` 查找，找不到实例
- 导致 `MainForm.EventBindingService` 为 `null`，sideload 事件绑定被跳过

### 1.3 关键文件

| 文件 | 角色 |
|------|------|
| `CsharpPrj/Operation/WdUI/WdUI.RenderPipeline.cs` | 渲染管线，持有 `_eventBinder` |
| `CsharpPrj/Operation/EventTriggerFramework/DefaultEventBindingService.cs` | 事件绑定服务实现 |
| `CsharpPrj/FileDriven/FileDriven.UI/Core/MainForm.cs` | MainForm，sideload 入口 |
| `CsharpPrj/FileDriven/FileDriven.UI/WinForms/Loading/ConfigLoader.cs` | 配置加载器 |

---

## 2. 整合方案

### 2.1 核心思路

sideload 加载完成后，**不直接调用 `EventBindingService.BindEventsAsync()`**，而是通过渲染管线的 `BindEventsAsync(Control)` 方法执行事件绑定，与 MainLayout 加载时走同一路径。

```
sideload 加载完成
    → 通过渲染管线创建会话（CreateSession）
    → 执行事件绑定（ExecuteBindEventsStage）
    → 复用 _eventBinder + FindForm + Transformers 管线
```

### 2.2 改动点

#### 2.2.1 MainForm.cs — `LoadSideContainerAsync` 方法

**当前代码**（第 648-672 行）：

```csharp
// ★ 2026-06-30 新增：sideload 完成后显式触发事件绑定
if (EventBindingService != null)
{
    try
    {
        await ((UniversalMiddleware.Abstractions.IEventBindingService)EventBindingService)
            .BindEventsAsync(this, config);
    }
    catch (Exception ex) { ... }
}
else
{
    FileDrivenLogPlaceholderHandler.Log("MainForm_LoadSideContainerAsync_event_binding_skipped",
        new { configPath, reason = "EventBindingService 未注入" });
}
```

**改为**：

```csharp
// ★ 整合：通过渲染管线执行事件绑定，与 MainLayout 走同一路径
var pipeline = WdUIUsage.RenderPipeline;
if (pipeline.EventBinder != null)
{
    try
    {
        // 1. 创建渲染会话（使 GetActiveSession 能找到）
        pipeline.Render(_sideContainer, config);

        // 2. 应用布局
        pipeline.ApplyLayout(_sideContainer);

        // 3. 绑定事件（走 ExecuteBindEventsStage，使用 _eventBinder）
        await pipeline.BindEventsAsync(_sideContainer);
    }
    catch (Exception ex)
    {
        FileDrivenLogPlaceholderHandler.Log("MainForm_LoadSideContainerAsync_pipeline_binding_error",
            new { configPath, error = ex.Message });
    }
}
else
{
    FileDrivenLogPlaceholderHandler.Log("MainForm_LoadSideContainerAsync_pipeline_binding_skipped",
        new { configPath, reason = "RenderPipeline.EventBinder 未注入" });
}
```

#### 2.2.2 MainForm.cs — 删除 `EventBindingService` 属性

删除 `MainForm.EventBindingService` 属性及其所有引用，因为事件绑定不再通过此属性。

需要删除/修改的位置：
1. `MainForm.cs` 中的 `EventBindingService` 属性定义
2. `FileDrivenGuiInitializer.cs` 中设置 `mainForm.EventBindingService` 的代码
3. `ComponentRegistry.Resolve<IEventBindingService>()` 调用

#### 2.2.3 WinFormsRenderPipeline.cs — 新增 `Render(Control, UIConfiguration)` 重载

当前 `Render` 方法签名是 `Render(Control target, UIConfiguration config)`，但需要确认它是否接受 sideload 场景下的 `_sideContainer`（ConfigContainer 类型）作为 target。

检查 `ExecuteCreateStage` 中的逻辑：
- `CreateLayoutPanelSkeleton` 会创建 LayoutPanel
- `_layoutPipeline.SubscribeResize` 会订阅 Resize

对于 sideload 场景，`_sideContainer` 已经是 ConfigContainer，可能不需要再创建 LayoutPanel。需要添加一个**轻量级渲染模式**，只创建会话不创建 LayoutPanel：

```csharp
/// <summary>
/// 轻量级渲染 — 仅创建会话，不创建 LayoutPanel
/// <para>用于 sideload 场景：_sideContainer 已是 ConfigContainer，无需再创建 LayoutPanel</para>
/// </summary>
public void RenderSessionOnly(Control target, UIConfiguration config)
{
    // 清理旧会话
    DisposeSession(target);
    // 创建新会话
    var wdSession = new WdUI.Layout.RenderSession(config);
    _sessions[target] = wdSession;
}
```

#### 2.2.4 WinFormsRenderPipeline.cs — `ExecuteBindEventsStage` 增强 sideload 支持

当前 `ExecuteBindEventsStage` 通过 `FindForm(target)` 查找 Form：

```csharp
var form = FindForm(target);
if (form != null)
{
    await _eventBinder.BindEventsAsync(form, config).ConfigureAwait(false);
}
```

对于 sideload 场景，`_sideContainer` 的 Form 就是 `MainForm` 实例，`FindForm` 应该能正确找到。但需要验证 `DefaultEventBindingService.BindEvents(Form, UIConfiguration)` 是否能正确处理 sideload 的控件查找。

查看 `DefaultEventBindingService.BindEvents` 签名（第 97-101 行）：

```csharp
public void BindEvents(
    Form form,
    UIConfiguration config,
    Control? searchRoot = null,
    Func<string, Control?>? customControlFinder = null)
```

sideload 场景需要传入 `searchRoot = _sideContainer`，但渲染管线调用时没有传这个参数。需要增强：

```csharp
// ExecuteBindEventsStage 中：
var form = FindForm(target);
if (form != null)
{
    // ★ sideload 场景：传入 target（_sideContainer）作为 searchRoot
    //   确保控件在 _sideContainer 内被正确查找
    if (_eventBinder is DefaultEventBindingService defaultBinder)
    {
        defaultBinder.BindEvents(form, config, searchRoot: target);
    }
    else
    {
        await _eventBinder.BindEventsAsync(form, config).ConfigureAwait(false);
    }
}
```

## 3. 影响范围

### 3.1 需要修改的文件

| 文件 | 修改内容 | 风险 |
|------|---------|------|
| `MainForm.cs` | `LoadSideContainerAsync` 中改用渲染管线 | 中 — 需验证会话创建 |
| `MainForm.cs` | 删除 `EventBindingService` 属性 | 低 — 纯删除 |
| `FileDrivenGuiInitializer.cs` | 删除 `EventBindingService` 注入 | 低 — 纯删除 |
| `WinFormsRenderPipeline.cs` | 新增 `RenderSessionOnly` 方法 | 低 — 新增方法 |
| `WinFormsRenderPipeline.cs` | `ExecuteBindEventsStage` 增强 sideload 支持 | 中 — 需验证 searchRoot |

### 3.2 不需要修改的文件

- `DefaultEventBindingService.cs` — 接口不变，只是调用方式变化
- `ConfigLoader.cs` — 加载逻辑不变
- `FrameworkInitializer.cs` — 注入逻辑不变

### 3.3 风险点

1. **会话生命周期**：sideload 完成后创建的会话，在 `ClearSideContainer` 时需要清理
2. **LayoutPanel 创建**：sideload 场景不需要 LayoutPanel，需要轻量级渲染模式
3. **控件查找**：`DefaultEventBindingService.BindEvents` 的 `searchRoot` 参数需要正确传入
4. **Resize 订阅**：sideload 场景可能不需要 Resize 订阅

---

## 4. 实施步骤

### Step 1：WinFormsRenderPipeline 新增轻量级渲染方法

在 `WdUI.RenderPipeline.cs` 中添加 `RenderSessionOnly` 方法，只创建会话不创建 LayoutPanel。

### Step 2：WinFormsRenderPipeline 增强 ExecuteBindEventsStage

修改 `ExecuteBindEventsStage`，当 `_eventBinder` 是 `DefaultEventBindingService` 时，传入 `searchRoot` 参数。

### Step 3：MainForm.LoadSideContainerAsync 改用渲染管线

替换当前直接调用 `EventBindingService.BindEventsAsync` 的代码，改为通过渲染管线执行。

### Step 4：清理废弃代码

删除 `MainForm.EventBindingService` 属性、`FileDrivenGuiInitializer` 中的注入代码。

### Step 5：验证

1. sideload 加载后事件正确绑定
2. MainLayout 加载后事件绑定不受影响
3. `ClearSideContainer` 正确清理会话
4. 多次 sideload 加载（切换配置）时会话正确重建

---

## 5. 回退方案

如果整合后出现问题，可以回退到**方案一（最小修复）**：

在 `FrameworkInitializer.Initialize()` 中，创建 `DefaultEventBindingService` 后注册到 `ComponentRegistry`：

```csharp
FrameworkAbstractions.ComponentRegistry.ComponentRegistry.Instance.Register(
    eventBindingService,
    serviceName: "DefaultEventBindingService",
    criticality: FrameworkAbstractions.ComponentRegistry.CriticalityLevel.High,
    description: "事件绑定服务，用于 sideload 配置的事件绑定");
```

这样 `FileDrivenGuiInitializer` 就能通过 `ComponentRegistry.Resolve<IEventBindingService>()` 找到实例，`MainForm.EventBindingService` 不为 null，sideload 事件绑定正常执行。
