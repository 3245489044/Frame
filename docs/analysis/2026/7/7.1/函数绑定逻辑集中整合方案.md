# 函数绑定逻辑集中整合方案

> **目标**：将所有"函数绑定"逻辑集中到 `FileDriven.Execution.EventBinding` 模块
> **本质**：UI 事件 → 后端函数执行的绑定逻辑，无论代码驱动还是配置驱动，统一归口管理
> **日期**：2026-07-01

---

## 1. 现状分析

### 1.1 事件绑定逻辑分布全景

当前函数绑定逻辑分散在 **3 个项目、6 个文件** 中：

```
┌─────────────────────────────────────────────────────────────────────────┐
│ Operation/ForntEndDriven/Implementation/                                │
│   UIEventBinder.cs                    ← 配置选择器 6 个事件 + KeyPress  │
│     (BindCommandEvents)               ← commandTextBox.KeyPress 绑定    │
│     (BindConfigSelectorEvents)        ← 6 个控件事件注册                │
├─────────────────────────────────────────────────────────────────────────┤
│ FileDriven.Execution/EventBinding/    ← 已有基础设施                    │
│   WinFormsEventBinder.cs              ← 底层反射绑定器                  │
│   WinFormsEventRegistrar.cs           ← 控件事件注册器（返回取消委托）  │
│   EventBindingResolver.cs             ← 配置模型事件解析器              │
│   IEventBindingService.cs             ← 事件绑定服务接口                │
│   EventHelper.cs / ControlTreeWalker.cs / WinFormsControlFinder.cs      │
├─────────────────────────────────────────────────────────────────────────┤
│ FileDriven.Execution/EventPipeline/   ← 事件→管线执行路由              │
│   EventPipelineExecutor.cs            ← 事件触发→管线执行               │
│   EventHub.cs                         ← 生命周期事件中心                │
│   EventTriggerService.cs              ← 事件触发服务                    │
├─────────────────────────────────────────────────────────────────────────┤
│ FileDriven.UI/WinForms/Services/                                        │
│   FileDrivenWdUIBridge.cs             ← WdUI 桥接层（职责过载）        │
│     RegisterSideContainerControls     ← 控件注册到 ControlRegistry      │
│     BindSideContainerEventsAsync      ← 渲染管线事件绑定                │
│     ClearSideContainer                ← 侧边容器清理（含会话清理）     │
├─────────────────────────────────────────────────────────────────────────┤
│ FileDriven.UI/Core/                                                     │
│   MainForm.cs                         ← 应用层编排（职责过载）         │
│     LoadSideContainerAsync            ← 加载+注册+InitCmd+绑定 4 步    │
│     OnConfigSelectorLoaded            ← 创建 UIEventBinder 并绑定      │
├─────────────────────────────────────────────────────────────────────────┤
│ FileDriven.Execution/Gui/                                               │
│   FileDrivenGuiInitializer.cs         ← 注入 WinFormsEventRegistrar     │
│                                          + EventHub + StageCoordinator  │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.2 核心问题

| 问题 | 描述 |
|------|------|
| **职责分散** | 同属"函数绑定"的逻辑散落在 3 个项目，违反单一职责原则 |
| **FileDrivenWdUIBridge 职责过载** | 同时承担容器管理 + 控件注册 + 事件绑定 3 个职责 |
| **MainForm 编排过重** | `LoadSideContainerAsync` 内联 4 个步骤，难以单元测试 |
| **UIEventBinder 位置不当** | 在 `Operation/ForntEndDriven` 而非 `FileDriven.Execution` |
| **依赖方向混乱** | FileDriven.UI 直接依赖 WdUI.RenderPipeline |

### 1.3 本质归类

所有上述逻辑的本质都是 **函数绑定（Function Binding）**：

| 逻辑 | 绑定方式 | 绑定目标 |
|------|---------|---------|
| `commandTextBox.KeyPress` | 代码驱动 | → `_commandHandler.HandleKeyPress` |
| 配置选择器 6 个事件 | 代码驱动 | → 刷新/加载/浏览等操作 |
| `RegisterSideContainerControls` | 配置驱动 | → ControlRegistry 注册 |
| `BindSideContainerEventsAsync` | 配置驱动 | → 渲染管线事件绑定 |
| `WinFormsEventBinder.BindControlEvent` | 底层工具 | → 反射绑定事件处理器 |
| `WinFormsEventRegistrar.*` | 高层工具 | → 类型安全的事件注册 |

## 2. 整合目标

### 2.1 目标架构

```
FileDriven.Execution/
├── EventBinding/                          ← 所有函数绑定逻辑集中在此
│   ├── IEventBindingService.cs            ← 已有：事件绑定服务接口
│   ├── EventBindingResolver.cs            ← 已有：配置模型事件解析器
│   ├── WinFormsEventBinder.cs             ← 已有：底层反射绑定器
│   ├── WinFormsEventRegistrar.cs          ← 已有：控件事件注册器
│   ├── WinFormsControlFinder.cs           ← 已有：控件查找
│   ├── ControlTreeWalker.cs               ← 已有：控件树遍历
│   ├── EventHelper.cs                     ← 已有：事件工具
│   │
│   ├── UIEventBinder.cs                   ← [迁移] 从 ForntEndDriven 迁入
│   │   (BindCommandEvents + BindConfigSelectorEvents)
│   │
│   ├── SideContainerBinder.cs             ← [新建] 从 FileDrivenWdUIBridge 提取
│   │   (RegisterSideContainerControls + BindSideContainerEventsAsync)
│   │
│   └── IWinFormsEventBinder.cs            ← [迁移] 接口定义
│
├── EventPipeline/                         ← 已有：事件管线
│   ├── EventPipelineExecutor.cs
│   ├── EventHub.cs
│   └── EventTriggerService.cs
│
└── Gui/
    └── FileDrivenGuiInitializer.cs        ← [简化] 注入逻辑简化
```

### 2.2 整合后调用链

```
MainForm.LoadSideContainerAsync
  ├─ ConfigLoader.LoadSideContainerAsync          (加载配置)
  ├─ ConfigRegistrar.RegisterLoadedConfig          (注册配置)
  ├─ SideContainerBinder.RegisterSideContainerControls  (注册控件)
  ├─ InitCommands 执行
  └─ SideContainerBinder.BindSideContainerEventsAsync  (绑定事件)
       ├─ WinFormsRenderPipeline.RenderSessionOnly
       └─ WinFormsRenderPipeline.BindEventsAsync

MainForm.OnConfigSelectorLoaded
  └─ UIEventBinder.BindAll()                      (绑定 UI 事件)
       ├─ BindCommandEvents()                     (commandTextBox.KeyPress)
       └─ BindConfigSelectorEvents()              (6 个控件事件)
            └─ WinFormsEventRegistrar.*           (注册/取消注册)
```

### 2.3 依赖关系变化

```
迁移前：
  FileDriven.UI → ForntEndDriven (UIEventBinder)
  FileDriven.UI → WdUI (RenderPipeline)
  FileDriven.UI → FileDriven.Execution.EventBinding (WinFormsEventRegistrar)

迁移后：
  FileDriven.UI → FileDriven.Execution.EventBinding (UIEventBinder + SideContainerBinder)
  FileDriven.Execution.EventBinding → WdUI (RenderPipeline)
  FileDriven.Execution.EventBinding → ForntEndDriven.Abstractions (IUIEventBinder)
```

### 步骤 3：统一 `WinFormsEventRegistrar` 和 `WinFormsEventBinder` 职责

**操作**：
1. 明确 `WinFormsEventRegistrar` 依赖 `WinFormsEventBinder` 作为底层实现
2. `WinFormsEventRegistrar` 保持高层 API 风格（按控件类型查找 + 注册）
3. `WinFormsEventBinder` 保持纯底层反射绑定

**当前关系**：
```
WinFormsEventRegistrar.RegisterClick(container, name, handler)
  → FindControl<Button>(container, name)
  → button.Click += handler
  → return () => button.Click -= handler

WinFormsEventBinder.BindControlEvent(control, eventName, handler)
  → 反射查找 EventInfo
  → eventInfo.AddEventHandler(control, handler)
```

**目标关系**：两者保持独立，`WinFormsEventRegistrar` 可选择性地使用 `WinFormsEventBinder` 作为底层实现。

### 步骤 4：简化 `FileDrivenWdUIBridge`

**操作**：
1. 删除 `RegisterSideContainerControls` 方法（转发到 `SideContainerBinder`）
2. 删除 `BindSideContainerEventsAsync` 方法（转发到 `SideContainerBinder`）
3. 保留：容器管理（Create/Get/Remove/Dispose）+ 生命周期（Initialize/Shutdown）+ 容器绑定（FindAndBindContainers）+ 容器清理（ClearSideContainer）

**简化后职责**：
```
FileDrivenWdUIBridge
  ├── 生命周期管理（Initialize / Shutdown）
  ├── 容器管理（Create / Get / Remove / Dispose）
  ├── 主布局容器绑定（FindAndBindContainers）
  ├── 配置选择器控件查找（FindConfigSelectorControls）
  └── 侧边容器清理（ClearSideContainer）
```

### 步骤 5：简化 `MainForm.LoadSideContainerAsync`

**操作**：
1. 将 `LoadSideContainerAsync` 中的 4 个步骤提取为 `SideContainerBinder.LoadAndBindAsync`
2. `MainForm.LoadSideContainerAsync` 简化为调用 `SideContainerBinder.LoadAndBindAsync`

**代码示例**：

```csharp
// SideContainerBinder.cs
public static async Task<UIConfiguration?> LoadAndBindAsync(
    ConfigContainer sideContainer,
    string configPath,
    SemaphoreSlim loadLock,
    Action<string> logAction,
    IConfigRegistrar? configRegistrar,
    IControlRegistry controlRegistry,
    Func<string, Task<CommandResult?>>? commandExecutor)
{
    // 1. 加载配置
    var config = await ConfigLoader.LoadSideContainerAsync(
        sideContainer, configPath, loadLock, logAction);
    if (config == null) return null;

    // 2. 注册配置
    configRegistrar?.RegisterLoadedConfig(config);

    // 3. 注册控件
    RegisterSideContainerControls(config, sideContainer, controlRegistry);

    // 4. 执行 InitCommands
    if (config.InitCommands?.Count > 0 && commandExecutor != null)
    {
        // ... 执行初始化命令 ...
        // InitCommands 执行后再次注册控件
        RegisterSideContainerControls(config, sideContainer, controlRegistry);
    }

    // 5. 绑定事件
    await BindSideContainerEventsAsync(sideContainer, config, configPath);

    return config;
}
```
