# 初始化控制反转重构方案

> **目标**：将 CsharpPrj 中所有初始化逻辑的控制权反转到 FileDriven，彻底消除时序依赖问题。
>
> **核心原则**：CsharpPrj 只提供组件/服务，不主动初始化。FileDriven 作为编排者，控制所有初始化流程。
>
> **策略**：最彻底的重构手段，不留补丁，不设回退。

## 1. 问题背景

### 1.1 错误现象

```
[ERROR] ExecuteContainerBinderPipelineAsync 执行失败:
System.InvalidOperationException: [LazyEventBindingServiceProxy] BindEventsAsync 被调用但
IEventBindingService 尚未注册到 AppServiceProvider。
```

### 1.2 根因分析

**时序问题**：`EventTriggerFrameworkInitializer.InitializeWinForms()` 执行时，其依赖的 `IUISubsystemInitializer` 尚未注册到 `AppServiceProvider`，导致 `WinFormsEventBus` 和 `DefaultEventBindingService` 未被创建。

**架构根因**：CsharpPrj 中的初始化器（`EventTriggerFrameworkInitializer`）承担了过多的职责，既负责基础设施初始化，又负责 UI 子系统初始化，导致跨层依赖和时序耦合。

### 1.3 调用链全景

```
FileDrivenExecutor.Run()
  └─ FrameworkExecutor.ExecuteMode()
       └─ StartGuiModePipeline.ExecuteAsync()
            ├─ [Block 1] CreateExecutionEntryBlock
            ├─ [Block 2] CreateAndConfigureBlock
            │    ├─ [第65行] EventTriggerFrameworkInitializer.InitializeWinForms()
            │    │    └─ Resolve<IUISubsystemInitializer>() → null ✗
            │    │    └─ WinFormsEventBus 未创建
            │    │    └─ DefaultEventBindingService 未创建
            │    │
            │    ├─ [第93行] 创建 MainForm
            │    │    └─ WdUIComposer.Initialize() → 注册 IUISubsystemInitializer ✓
            │    │    └─ 但太晚了！
            │    │
            │    └─ [第198行] 依赖验证
            │
            └─ [Block 3] ApplicationRunBlock
                 └─ Form.Shown → LoadSideContainerAsync
                      └─ BindEventsAsync()
                           └─ Resolve<IEventBindingService>() → null → 异常！
```

## 2. 当前架构分析

### 2.1 CsharpPrj 中的主动初始化逻辑

#### 2.1.1 `EventTriggerFrameworkInitializer`（Operation 层）

```csharp
// EventTriggerFrameworkInitializer.cs
public static FrameworkContext Initialize(FrameworkOptions options)
{
    lock (_lock)
    {
        var ctx = new FrameworkContext(options);
        ctx.CommandFrameworkHost = CommandFrameworkHost.Create(...);

        if (options.EnableEventBus)    InitializeEventBus(ctx);
        if (options.EnableCommandSystem) InitializeCommands(ctx);
        if (options.EnablePipeline)    InitializePipeline(ctx);
        if (options.EnableCore)        InitializeCore(ctx);
        if (options.EnableWinForms)    InitializeWinForms(ctx);  // ✗ UI 相关

        _context = ctx;
        return ctx;
    }
}
```

**问题**：
- 自己决定初始化顺序
- 自己管理生命周期（`_context`）
- 自己持有 `_context` 单例
- 包含 WinForms 初始化（跨层污染）

#### 2.1.2 `WinFormsInitializer`（WdUI 层）

```csharp
// WinFormsInitializer.cs
public class WinFormsInitializer : IUISubsystemInitializer
{
    public void Initialize(FrameworkContext ctx)
    {
        ctx.WinFormsAccessor = new WinFormsControlValueAccessor();
        ctx.WinFormsNameResolver = new WinFormsEventNameResolver();
        ctx.WinFormsReflectionBinder = new ReflectionEventBinder<Control>(...);
        ctx.WinFormsEventBus = new WinFormsEventBus() as IEventBus;
        AppServiceProvider.Register<IControlFinder>(new WinFormsControlFinderService());
        AppServiceProvider.Register(typeof(IEventBus), ctx.WinFormsEventBus!);
    }
}
```

**问题**：
- 依赖 `FrameworkContext`，但 `FrameworkContext` 由 `EventTriggerFrameworkInitializer` 创建
- 注册 `IUISubsystemInitializer` 的时机在 `WdUIComposer.Initialize()` 中，由 `MainForm` 构造函数触发

#### 2.1.3 `WdUIContainerManager.Initialize()`（FrontEndDriven 层）

```csharp
// WdUIContainerManager.cs
public static void Initialize()
{
    if (_isInitialized) return;
    WdUIUsage.Initialize();
    _isInitialized = true;
}
```

**问题**：
- 在 `MainForm` 构造函数中被触发（通过 `FileDrivenWdUIBridge.Initialize()`）
- 时机不可控，晚于 `InitializeWinForms()` 的执行

#### 2.1.4 `CommandFrameworkUsage.Initialize()`（CommandFramework 层）

```csharp
CommandFrameworkUsage.Initialize(options => { ... });
```

**问题**：
- 在 `CreateAndConfigureBlock` 和 `StartCliMode` 中都有调用
- 初始化调用分散在各处

### 2.2 当前初始化时序图

```
时间线 →
│
├─ FrameworkInitializer.Initialize()
│   ├─ 步骤 1: 设置项目根目录
│   ├─ 步骤 2: 注入 LazyEventBindingServiceProxy（占位符）
│   ├─ 步骤 3-5: UnifiedRegistryCenter
│   ├─ 步骤 6: 初始化 AppServiceProvider
│   ├─ 步骤 7: 创建 UICommandManager
│   ├─ 步骤 8: 注册 ExecutionCenter
│   └─ 步骤 9: 设置模板处理器
│
├─ CreateAndConfigureBlock.ExecuteAsync()
│   ├─ [65] InitializeWinForms() → 需要 IUISubsystemInitializer → null ✗
│   ├─ [93] 创建 MainForm
│   │    └─ WdUIComposer.Initialize() → 注册 IUISubsystemInitializer ✓
│   └─ [198] 依赖验证
│
└─ Form.Shown → LoadSideContainerAsync
     └─ BindEventsAsync() → Resolve<IEventBindingService>() → null ✗
```

### 2.3 问题总结

| 问题 | 说明 |
|------|------|
| **职责过载** | `EventTriggerFrameworkInitializer` 既管基础设施又管 UI |
| **跨层依赖** | Operation 层依赖 WdUI 层的 `IUISubsystemInitializer` |
| **时序耦合** | `InitializeWinForms()` 需要 `IUISubsystemInitializer`，但后者在 `MainForm` 构造函数中才注册 |
| **代理补丁** | `LazyEventBindingServiceProxy` 的存在是为了掩盖时序问题 |
| **初始化分散** | `CommandFrameworkUsage.Initialize()` 在多个地方被调用 |
| **控制权错位** | CsharpPrj 自己决定初始化顺序，FileDriven 被动接受 |

## 3. 目标架构

### 3.1 核心设计原则

1. **控制反转**：FileDriven 编排所有初始化流程，CsharpPrj 只提供组件
2. **职责单一**：每个初始化器只负责一个子系统
3. **明确阶段**：初始化分为清晰的阶段，每个阶段完成后才能进入下一阶段
4. **消除代理**：删除 `LazyEventBindingServiceProxy`
5. **幂等安全**：所有初始化器支持多次调用

### 步骤 2：修改 `FrameworkInitializer.cs`（FileDriven）

**目标**：新增 WinForms 初始化步骤，接管 `DefaultEventBindingService` 的创建和注入。

**具体修改**：

1. **新增步骤 2**：初始化 WdUI 系统（`WdUIContainerManager.Initialize()`）
2. **新增步骤 5**：初始化 `EventTriggerFramework`（仅基础设施）
3. **新增步骤 6**：初始化 WinForms 子系统（`InitializeWinFormsSubsystem()`）
4. **新增步骤 7**：注入 `IEventBindingService` 到渲染管线（真实实例）
5. **移除步骤 2 的 `LazyEventBindingServiceProxy` 注入**

**新增方法**：

```csharp
// ★ 新增：初始化 WinForms 子系统
private static void InitializeWinFormsSubsystem()
{
    // 1. 创建 FrameworkContext（仅用于 WinForms 初始化）
    var ctx = new FrameworkContext(new FrameworkOptions());

    // 2. 通过 IUISubsystemInitializer 初始化 WinForms 组件
    var initializer = AppServiceProvider.Resolve<IUISubsystemInitializer>();
    if (initializer == null)
    {
        throw new InvalidOperationException(
            "IUISubsystemInitializer 未注册。请确保 WdUIContainerManager.Initialize() 已执行。");
    }

    initializer.Initialize(ctx);

    // 3. 创建 DefaultEventBindingService
    var winFormsEventBus = ctx.WinFormsEventBus;
    if (winFormsEventBus == null)
    {
        throw new InvalidOperationException(
            "WinFormsEventBus 未创建。请检查 WinFormsInitializer.Initialize()。");
    }

    var executionEngine = AppServiceProvider.Resolve<IExecutionEngine>();
    Func<IEventExecutionService?> executionServiceResolver =
        () => AppServiceProvider.Resolve<IEventExecutionService>();

    var eventBindingService = new DefaultEventBindingService(
        winFormsEventBus,
        executionEngine: executionEngine,
        executionServiceResolver: executionServiceResolver);

    // 4. 注册到 AppServiceProvider
    AppServiceProvider.Register(typeof(IEventBindingService), eventBindingService);
}
```
