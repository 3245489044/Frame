# 日志框架调用链优化方案

> 基于 `日志框架调用链修复分析.md` 的后续整理，解决调用链过长、分类解析入口不统一等架构问题。

## 1. 当前调用链全景

### 1.1 完整调用链

```
WdUILog.Log(msgId, data)                              [WdUILog.cs]
  → LogPlaceholderHandlerBase.Log(msgId, module, keyPrefix, data)  [HandlersService.cs:152]
    → loader.TryGetMessage(msgId, out msgDef)         [从 wdui_log_messages.json 查找]
    → PlaceholderTemplateFormatter.ConvertParameters(parameters)
    → PlaceholderTemplateFormatter.Format(msgDef.Template, paramDict)
    → LogRepository.Write(msgDef.Level, msgDef.Category, moduleName, message)  [HandlersService.cs:209]
      → Write(string level, string category, string module, string message)    [LogRepository.cs:97]
        → Enum.TryParse<LogCategory>(category)         ← 分类解析点①
        → LoggingSetup.ResolveEnumName?(category)      ← 分类解析点②
        → Write(LogEntry entry)                        [LogRepository.cs:134]
          → LogFilterLoader.ShouldPrint(entry)         [LogFilterLoader.cs:165]
            → _disabledCategories.Contains(entry.Category)
```

### 1.2 调用链层级

| 层级 | 文件 | 职责 |
|------|------|------|
| L1 | `WdUILog.cs` | 模块日志入口，清理 msgId 前缀 |
| L2 | `HandlersService.cs` (LogPlaceholderHandlerBase.Log) | JSON 查找、模板格式化、参数转换 |
| L3 | `LogRepository.cs` (Write string 重载) | 分类字符串→枚举解析 |
| L4 | `LogRepository.cs` (Write LogEntry) | 过滤判断、输出/存储 |

## 2. 核心问题

### 问题 1：分类解析入口不统一（过滤失效的根因）

有两处独立的分类解析逻辑，且初始化时序不同：

| 位置 | 解析方式 | 初始化时序 |
|------|---------|-----------|
| `LogRepository.Write(string,string,string,string)` | `Enum.TryParse` → `LoggingSetup.ResolveEnumName` | 运行时（`ResolveEnumName` 可能已注册） |
| `LogFilterLoader.ParseCategory(string)` | `Enum.TryParse` → `LoggingSetup.ResolveEnumName` | `Load()` 时（`ResolveEnumName` 可能尚未注册） |

**失效场景**：

1. `LogFilterLoader.Load()` 在 `LogCategoryRegistry` 静态构造函数之前调用
2. `LoggingSetup.ResolveEnumName` 为 null
3. `ParseCategory("WdUI_Layout")` 返回 `LogCategory.System`
4. `_disabledCategories` 中包含 `LogCategory.System`
5. 运行时 `LogRepository.Write` 中 `ResolveEnumName` 已注册
6. `"WdUI_Layout"` 被正确解析为 `(LogCategory)(1UL << 17)`（非 System）
7. `_disabledCategories.Contains(位17)` → false → **过滤失败**

### 问题 2：调用链过长（4 层间接）

```
WdUILog.Log → LogPlaceholderHandlerBase.Log → LogRepository.Write(string) → Write(LogEntry)
```

每层都做一次分类解析/传递，增加了出错概率和性能开销。

### 问题 3：LogPlaceholderHandlerBase 承担双重职责

- **职责 A**：作为 `IPlaceholderHandler`，供 Skeleton 框架的 Placeholder 处理流程使用
- **职责 B**：提供静态 `Log()` 方法，供非 Skeleton 代码（如 `WdUILog.Log`）直接调用

静态 `Log()` 方法内部做了 JSON 查找、模板格式化、参数转换等完整工作，但非 Skeleton 场景下这些步骤是多余的。

## 3. 优化方案

### 方案：精简调用链 + 统一分类解析

#### 步骤 1：WdUILog.Log 直接调用 LogRepository.Write

跳过 `LogPlaceholderHandlerBase.Log` 的中间层，直接构造 `LogEntry` 写入仓库。

```
WdUILog.Log(msgId, data)
  → 从 wdui_log_messages.json 查找 msgDef（缓存）
  → 解析分类（缓存）
  → LogRepository.Write(level, category, module, message)
    → Write(LogEntry)
      → LogFilterLoader.ShouldPrint(entry)
```

**改动点**：

- `WdUILog` 内部持有 `LogMessageLoader` 实例（或共享缓存）
- 直接调用 `LogRepository.Write(string level, string category, string module, string message)`
- 不再经过 `LogPlaceholderHandlerBase.Log`

#### 步骤 2：LogFilterLoader 使用字符串匹配

`LogFilterLoader` 不再将分类字符串解析为 `LogCategory` 枚举，而是保留原始字符串，在 `ShouldPrint` 时直接比较字符串。

```csharp
// LogFilterLoader.Load():
_disabledCategoryStrings = new HashSet<string>(
    _config.Categories?.Disabled ?? [],
    StringComparer.OrdinalIgnoreCase);

// LogFilterLoader.ShouldPrint(entry):
_disabledCategoryStrings.Contains(entry.CategoryString)  // 字符串比较
```

**改动点**：

- `LogFilterLoader` 新增 `_disabledCategoryStrings`（`HashSet<string>`）
- 移除 `_disabledCategories`（`HashSet<LogCategory>`）
- `ShouldPrint` 改为比较 `entry.CategoryString`
- 移除 `ParseCategory` 方法（不再需要枚举解析）

#### 步骤 3：LogEntry 新增 CategoryString 属性

`LogEntry` 新增 `CategoryString` 属性，`Write(string,string,string,string)` 将原始分类字符串存入。

```csharp
public class LogEntry
{
    // ... 现有属性 ...
    
    /// <summary>
    /// 原始分类字符串（如 "WdUI_Layout"）
    /// <para>用于日志过滤的字符串匹配，避免枚举解析时序问题</para>
    /// </summary>
    public string? CategoryString { get; set; }
}
```

**改动点**：

- `LogEntry` 新增 `CategoryString` 属性
- `Write(string,string,string,string)` 中设置 `entry.CategoryString = category`
- `Write(LogEntry entry)` 中保留 `entry.CategoryString`（如果调用方已设置）

#### 步骤 4：LogPlaceholderHandlerBase.Log 简化

`LogPlaceholderHandlerBase.Log` 保留但简化，不再做分类解析，直接传递字符串。

```csharp
// 改动前
LogRepository.Write(msgDef.Level, msgDef.Category, moduleName, message);

// 改动后（不变，msgDef.Category 本身就是字符串）
LogRepository.Write(msgDef.Level, msgDef.Category, moduleName, message);
```

`LogRepository.Write(string,string,string,string)` 中保留分类字符串到 `entry.CategoryString`。

## 4. 优化后调用链

```
WdUILog.Log(msgId, data)
  → 从 wdui_log_messages.json 查找 msgDef（缓存）
  → LogRepository.Write(msgDef.Level, msgDef.Category, moduleName, message)
    → Write(string, string, string, string)
      → entry.CategoryString = category  // 保留原始字符串
      → Write(LogEntry)
        → LogFilterLoader.ShouldPrint(entry)
          → _disabledCategoryStrings.Contains(entry.CategoryString)  // 字符串匹配
```

**层级减少**：4 层 → 2 层

| 层级 | 文件 | 职责 |
|------|------|------|
| L1 | `WdUILog.cs` | 模块日志入口 + JSON 查找 + 模板格式化 |
| L2 | `LogRepository.cs` | 过滤判断、输出/存储 |

## 5. 涉及文件清单

| 文件 | 改动类型 | 说明 |
|------|---------|------|
| `CsharpPrj/BasicMethod/Logging/LogEntry.cs` | 修改 | 新增 `CategoryString` 属性 |
| `CsharpPrj/BasicMethod/Logging/LogRepository.cs` | 修改 | `Write(string,string,string,string)` 中设置 `CategoryString` |
| `CsharpPrj/BasicMethod/Logging/LogFilterLoader.cs` | 修改 | 改用字符串匹配，移除 `ParseCategory` |
| `CsharpPrj/Operation/WdUI/Diagnostics/WdUILog.cs` | 修改 | 直接调用 `LogRepository.Write`，跳过中间层 |
| `CsharpPrj/Operation/WorkFlowMethod/Diagnostics/WorkFlowMethodLog.cs` | 修改 | 同上（如果存在类似调用） |
| `CsharpPrj/Share/PlaceholderFramework/Handlers/HandlersService.cs` | 不改 | `LogPlaceholderHandlerBase.Log` 保持兼容 |

## 6. 风险与注意事项

1. **向后兼容**：`LogPlaceholderHandlerBase.Log` 保持现有签名不变，其他调用方不受影响
2. **Skeleton 路径**：`LogPlaceholderHandlerBase.Handle()`（非静态方法）仍走原有 Placeholder 处理流程，不受影响
3. **缓存一致性**：`WdUILog` 中的 JSON 消息缓存应与 `LogPlaceholderHandlerBase` 共享，避免重复加载
4. **测试覆盖**：修改后需验证过滤配置的黑名单/白名单模式均正常工作
