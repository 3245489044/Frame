# 日志框架调用链修复分析

> 分析日期：2026-07-11
> 涉及文件：`LogRepository.cs`、`LogFilterLoader.cs`、`WdUILog.cs`、`PlaceholderLogHelper.cs`、`LogPlaceholderHandlerBase.cs`、`MainForm.cs`

---

## 一、调用链总览

```
WdUILog.Log(msgId, data)
  │
  ├─ 路径 A（正常路径）
  │   └─ LogPlaceholderHandlerBase.Log(msgId, "WdUI", "wdui:", data)
  │        ├─ loader.TryGetMessage(msgId) → msgDef
  │        └─ LogRepository.Write(msgDef.Level, msgDef.Category, "WdUI", message)
  │             └─ LogRepository.Write(LogEntry)
  │                  ├─ [Console 模式]
  │                  │   ├─ LogFilterLoader.ShouldPrint(entry) → true/false
  │                  │   │   └─ LogCollapser.Write(formatted)
  │                  │   └─ LogWritten?.Invoke(entry)          ← 不受过滤控制 ✗
  │                  │
  │                  └─ [Database 模式]
  │                      ├─ [Error/Warning] LogFilterLoader.ShouldPrint(entry)
  │                      │   └─ LogCollapser.Write(formatted)
  │                      ├─ 写入内存仓库
  │                      └─ LogWritten?.Invoke(entry)          ← 不受过滤控制 ✗
  │
  └─ 路径 B（降级路径）← 冗余，应删除
      └─ PlaceholderLogHelper.Log("DEBUG", "WdUI_Diagnostic", "WdUI", msg)
           └─ LogCategoryResolver.Resolve("WdUI_Diagnostic")
           └─ LogRepository.Write(logEntry)
                └─ (同上)

MainForm.OnLogWritten(entry)
  └─ LogFilterLoader.ShouldPrint(entry)  ← 二次过滤，冗余
      └─ UILogger.AppendTextSafe(...)
```

## 二、错误逻辑

### B1. `WdUILog.Log()` 存在两条输出路径

**文件**：`WdUILog.cs:29-35`

**问题**：正常路径（`LogPlaceholderHandlerBase.Log`）失败后走降级路径（`PlaceholderLogHelper.Log`），降级路径使用硬编码分类 `"WdUI_Diagnostic"`，导致：
- 丢失原始消息应有的分类信息（如 `WdUI_Render`、`WdUI_Layout`）
- `LogFilterConfig.json` 的过滤规则无法正确作用于降级日志
- 两条路径最终都走到 `LogRepository.Write()`，但分类不一致

**修复**：删除降级路径，`WdUILog.Log()` 只有一条路径。`LogPlaceholderHandlerBase.Log()` 失败时（消息 ID 不存在），这是配置错误，应由日志框架自身记录，而非静默降级输出。

```csharp
public static void Log(string messageId, object? data = null)
{
    var cleanMsgId = messageId.StartsWith("wdui:") ? messageId.Substring(5) : messageId;
    LogPlaceholderHandlerBase.Log(cleanMsgId, "WdUI", "wdui:", data);
}
```

---

### B2. `LogWritten` 事件绕过日志过滤

**文件**：`LogRepository.cs:141-154`（Console 模式）、`LogRepository.cs:156-195`（Database 模式）

**问题**：`LogWritten?.Invoke(entry)` 在 `if (LogFilterLoader.ShouldPrint(entry))` 块之外，无论日志是否被过滤都会触发事件。虽然 `MainForm.OnLogWritten()` 内部有二次过滤，但事件本身被不必要触发，浪费性能。

**修复**：Console 模式下将 `LogWritten?.Invoke(entry)` 移到 `if` 块内，只有通过过滤的日志才触发事件。

```csharp
if (OutputMode == LogOutputMode.Console)
{
    if (LogFilterLoader.ShouldPrint(entry))
    {
        LogCollapser.Write(formatted);
        LogWritten?.Invoke(entry);  // 移到 if 块内
    }
    return;
}
```

---

### B3. `ParseCategory` 委托未初始化时返回 `LogCategory.None`

**文件**：`LogFilterLoader.cs:256-259`

**问题**：当 `LoggingSetup.ResolveEnumName` 为 null 时，模块扩展分类（如 `WdUI_Render`）解析为 `LogCategory.None`，导致 `ShouldPrint` 中的分类比较全部不匹配，过滤行为异常。

**修复**：返回 `LogCategory.System` 而非 `LogCategory.None`。`System` 不会被任何模块级 blacklist 匹配，保证日志不被错误过滤。

```csharp
if (LoggingSetup.ResolveEnumName != null)
{
    return LoggingSetup.ResolveEnumName(name);
}
return LogCategory.System;  // 而非 LogCategory.None
```

## 三、重复逻辑

### R1. 分类解析重复

**文件**：`LogRepository.Write(string,string,string,string):101-113` 和 `PlaceholderLogHelper.Log():26`

**问题**：两个入口各自解析分类字符串为 `LogCategory`：
- `LogRepository` 使用 `Enum.TryParse` + `LoggingSetup.ResolveEnumName`
- `PlaceholderLogHelper` 使用 `LogCategoryResolver.Resolve`

两套解析器并存，解析结果可能不一致。

**修复**：`LogRepository.Write(string,string,string,string)` 统一委托给 `LogCategoryResolver.Resolve()`。

---

### R2. `ShouldPrint` 双重过滤

**文件**：`LogRepository.Write():145` 和 `MainForm.OnLogWritten():776`

**问题**：日志写入时过滤一次，`LogWritten` 事件处理中又过滤一次。如果 B2 修复后（`LogWritten` 只在过滤后触发），第二次过滤完全多余。

**修复**：消除 `OnLogWritten` 中的二次过滤，同时统一消息格式。

```csharp
private void OnLogWritten(LogEntry entry)
{
    if (Interlocked.CompareExchange(ref _logRecursionDepth, 1, 0) != 0)
        return;
    try
    {
        var message = $"[{entry.Timestamp:HH:mm:ss.fff}] [{entry.Level}] [{entry.Module}] {entry.Message}";
        UILogger.AppendTextSafe(_outputTextBox, message);
    }
    finally
    {
        Interlocked.Exchange(ref _logRecursionDepth, 0);
    }
}
```

---

### R3. 日志格式化重复

**文件**：`LogRepository.Write():138` 和 `MainForm.OnLogWritten():783`

**问题**：两处各自格式化日志文本，格式不一致：
- `Write`：`[HH:mm:ss.fff] [{Level}] [{Module}] {message}`
- `OnLogWritten`：`[{Level}] [{Module}] {message}`

UI 日志栏缺少毫秒时间戳。

**修复**：统一使用 `[HH:mm:ss.fff] [{Level}] [{Module}] {message}` 格式（见 R2 修复代码）。

---

## 四、冗余逻辑

### S1. `WdUILog.Log()` 的降级路径

**文件**：`WdUILog.cs:30-35`

**问题**：整个 `if (!logged)` 分支冗余。`LogPlaceholderHandlerBase.Log()` 失败说明消息 ID 不存在于 `wdui_log_messages.json`，这是配置错误，不应静默降级输出。

**修复**：删除该分支（见 B1 修复）。

---

### S2. `LogFilterLoader` 统计代码无消费者

**文件**：`LogFilterLoader.cs:72-74, 94-97`

**问题**：`_totalChecked`/`_totalFiltered`/`_totalPrinted` 三个字段和 `GetStats()` 方法仅在 `AutoInitialize` 中输出一次后无任何消费者调用。

**修复**：删除统计字段和方法。

---

### S3. `LogPlaceholderHandlerBase.Log()` 降级双重输出

**文件**：`HandlersService.cs:156-161`

**问题**：loader 未初始化时输出 `Debug.WriteLine`，紧接着 `WdUILog.Log()` 又通过 `PlaceholderLogHelper` 输出到 `LogRepository`，同一错误被输出两次。

**修复**：删除 B1 的降级路径后，此问题自然消除。
