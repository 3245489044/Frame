# 事件绑定管线整合重构方案

> 以 `EventBindingOrchestrator` 为中心，彻底重构事件绑定管线，消除所有冗余逻辑。

---

## 1. 现状分析

### 1.1 五条管线的职责

| 管线 | 位置 | 层级 | 职责 |
|------|------|------|------|
| **WinFormsRenderPipeline** | `Operation/WdUI/WdUI.RenderPipeline.cs` | Operation | 三阶段生命周期编排（Create → Layout → **BindEvents**） |
| **DefaultEventBindingService** | `Operation/BackEndDriven/EventTriggerFramework/` | Operation | IEventBindingService 接口实现，参数组装/日志/诊断 |
| **EventBindingPipelineRunner** | `Share/EventBindingOrchestrator/Transformers/` | Share | 创建上下文 → 调用 GenericEventBindingPipeline |
| **GenericEventBindingPipeline** | `Share/EventBindingOrchestrator/Transformers/` | Share | 3 步 Transformer 链（查找→元数据→绑定） |
| **EventBindingOrchestrator** | `Share/EventBindingOrchestrator/` | Share | 声明驱动绑定入口 + 累计统计（当前无活跃调用方） |

### 1.2 当前调用链

```
WinFormsRenderPipeline.ExecuteBindEventsStage()
  → _eventBinder.BindEventsAsync(target, config, searchRoot: target)
    → DefaultEventBindingService.BindEvents()  [UniversalMiddleware 接口]
      → _pipelineRunner.Execute(target, config, searchRoot)
        → EventBindingPipelineRunner.Execute()
          → 创建 EventBindingContext
          → _genericPipeline.ExecuteWithWalk(context, config)
            → GenericEventBindingPipeline.WalkAndBind()
              → ConfigToDeclarationMapper.Map(controlConfig)  ← 冗余！
              → foreach (decl) Execute(context)
                → ControlFinderTransformer
                → BindingMetadataTransformer
                → EventBinderTransformer
```

### 1.3 冗余点

| # | 位置 | 问题 | 原因 |
|---|------|------|------|
| R1 | `GenericEventBindingPipeline.WalkAndBind` | `ConfigToDeclarationMapper.Map()` 调用 | 旧管线遗留，声明被创建后丢弃（EventBinderTransformer 走 ForEachBoundEvent 路径） |
| R2 | `DefaultEventBindingService` | 同时实现两个 IEventBindingService 接口 | 历史遗留，`UniversalMiddleware.Abstractions.IEventBindingService` 已废弃 |
| R3 | `DefaultEventBindingService` 构造函数 | 创建 `OnEventResult` 回调 + 日志逻辑 | 应属于 `EventBindingOptions` 的默认值配置 |
| R4 | `EventBindingPipelineRunner` | 与 `EventBindingOrchestrator` 职责完全重叠 | 两者都做"创建上下文→执行管线→收集结果" |
| R5 | `WinFormsRenderPipeline` | `_eventBinder` 字段 + `EventBinder` 属性 | 事件绑定职责应委托给 Orchestrator |
| R6 | `WinFormsRenderPipeline` | `BindEventsAsync` 重写（第 445-470 行） | 基类已有，WdUI 特殊处理可委托给 Orchestrator |
| R7 | `WinFormsRenderPipeline` | `DisposeSession` 中的 `_eventBinder.UnbindEventsAsync` 调用 | `UniversalMiddleware` 接口的 `UnbindEventsAsync` 实现为空操作（第 257-260 行） |
| R8 | `WinFormsRenderPipeline` | `CreateOrUpdateSession` 方法 | 会话管理应与事件绑定解耦 |

### 1.5 关键问题

**`_eventBinder` 的职责边界**：`WinFormsRenderPipeline` 中的 `_eventBinder` 字段承担了两个职责：
1. **事件绑定执行** — `ExecuteBindEventsStage()` 中调用 `_eventBinder.BindEventsAsync()`
2. **事件解绑** — `DisposeSession()` 中调用 `_eventBinder.UnbindEventsAsync()`

但 `UniversalMiddleware.Abstractions.IEventBindingService.UnbindEventsAsync()` 的实现是**空操作**（第 257-260 行）：

```csharp
Task UniversalMiddleware.Abstractions.IEventBindingService.UnbindEventsAsync(object target)
{
    return Task.CompletedTask;  // 什么都不做！
}
```

这意味着 `DisposeSession` 中的解绑调用是**无效代码**，事件绑定实际上从未被解绑。

**会话管理 vs 事件绑定的耦合**：`_sessions` 字典同时服务于布局阶段、事件绑定阶段、sideload 场景，导致 `BindEventsAsync` 重写中需要先查 `_sessions` 再决定走哪条路径，`CreateOrUpdateSession` 本质上是绕过渲染管线直接注册会话。

## 2. 目标架构

### 2.1 核心原则

1. **EventBindingOrchestrator 升级为事件绑定总控**，统一所有事件绑定入口
2. **WinFormsRenderPipeline 只保留渲染职责**，事件绑定阶段直接调用 Orchestrator
3. **删除中间层**：EventBindingPipelineRunner 和 DefaultEventBindingService
4. **清理 WalkAndBind 冗余代码**：移除 ConfigToDeclarationMapper.Map 调用
5. **会话管理与事件绑定解耦**：WinFormsRenderPipeline 不再持有 `_eventBinder`

### 2.2 反转逻辑

#### 反转前：WinFormsRenderPipeline 持有事件绑定服务

```
WinFormsRenderPipeline (Operation)
├── _eventBinder: IEventBindingService          ← 持有事件绑定服务
├── ExecuteBindEventsStage()
│   └── _eventBinder.BindEventsAsync(target, config, searchRoot)
│       └── DefaultEventBindingService.BindEvents()
│           └── _pipelineRunner.Execute()
│               └── EventBindingPipelineRunner.Execute()
│                   └── GenericEventBindingPipeline.ExecuteWithWalk()
└── DisposeSession()
    └── _eventBinder.UnbindEventsAsync(target)  ← 空操作！
```

#### 反转后：EventBindingOrchestrator 成为事件绑定总控

```
WinFormsRenderPipeline (Operation)
├── _orchestrator: EventBindingOrchestrator     ← 持有编排器
├── ExecuteBindEventsStage()
│   └── _orchestrator.ExecuteWithWalk(target, config)
│       └── EventBindingOrchestrator.ExecuteWithWalk()
│           ├── 创建 EventBindingContext
│           ├── 诊断插桩
│           ├── GenericEventBindingPipeline.ExecuteWithWalk()
│           └── 累计统计
└── DisposeSession()
    └── 不再调用事件解绑（原 UnbindEventsAsync 为空操作）
```

### 2.3 目标调用链

```
WinFormsRenderPipeline.ExecuteBindEventsStage()
  → _orchestrator.ExecuteWithWalk(target, config)
    → EventBindingOrchestrator.ExecuteWithWalk()
      → 创建 EventBindingContext
      → 诊断插桩（Start）
      → _genericPipeline.ExecuteWithWalk(context, config)
        → GenericEventBindingPipeline.WalkAndBind()
          → Execute(context)  ← 直接执行，不再 Map
            → ControlFinderTransformer
            → BindingMetadataTransformer
            → EventBinderTransformer
      → 诊断插桩（Complete）
      → 累计统计
      → 返回 EventBindingContext
```


## 3. 重构步骤

### 步骤 1：EventBindingOrchestrator 新增 ExecuteWithWalk 方法

**文件**：`CsharpPrj/Share/EventBindingOrchestrator/EventBindingOrchestrator.cs`

**变更**：新增 `ExecuteWithWalk()` 方法，覆盖 `EventBindingPipelineRunner.Execute()` 和 `DefaultEventBindingService.BindEvents()` 的职责。

```csharp
/// <summary>
/// 执行事件绑定（带控件遍历）
/// <para>统一入口：替代 EventBindingPipelineRunner.Execute() 和 DefaultEventBindingService.BindEvents()。</para>
/// </summary>
public EventBindingContext ExecuteWithWalk(
    object targetObject,
    UIConfiguration config,
    EventBindingOptions? options = null)
{
    if (targetObject == null) throw new ArgumentNullException(nameof(targetObject));
    if (config == null) throw new ArgumentNullException(nameof(config));

    var mergedOptions = options ?? _options;

    // 空视图检查
    if (config.Views == null || config.Views.Count == 0)
    {
        _logger.LogWarning("UIConfiguration.Views is null or empty, target={Target}", targetObject.GetType().Name);
        return new EventBindingContext();
    }

    // 创建 EventBindingContext
    var context = new EventBindingContext
    {
        TargetObject = targetObject,
        Config = config,
        IsScriptExecutionMode = mergedOptions.IsScriptExecutionMode,
        SearchRoot = mergedOptions.SearchRoot,
        CustomControlFinder = mergedOptions.CustomControlFinder,
        EventBus = mergedOptions.EventBus
    };

    // 诊断作用域
    using var diagScope = EventBindingDiagnosticContext.BeginScope();

    _logger.LogInformation("开始事件绑定: Target={Target}, Views={ViewCount}",
        targetObject.GetType().Name, config.Views.Count);

    EventBindingDiagnosticContext.Record(EventNames.PipelineExecuteWithWalkStart, new
    {
        targetType = targetObject.GetType().Name,
        viewCount = config.Views?.Count ?? 0,
        hasSearchRoot = mergedOptions.SearchRoot != null
    });

    // 执行管线
    _genericPipeline.ExecuteWithWalk(context, config);

    EventBindingDiagnosticContext.Record(EventNames.PipelineExecuteWithWalkComplete, new
    {
        boundCount = context.BoundCount,
        skippedCount = context.SkippedCount
    });

    _logger.LogInformation("事件绑定完成: {BoundCount} 成功, {SkippedCount} 跳过",
        context.BoundCount, context.SkippedCount);

    // 累计统计
    lock (_statsLock)
    {
        _bindingResults.Add(new BindingResult
        {
            BoundControls = context.BoundControls.ToList(),
            SkippedControls = context.SkippedControls.ToList()
        });
    }

    return context;
}
```

### 步骤 2：清理 WalkAndBind 冗余代码

```csharp
private void WalkAndBind(EventBindingContext context, List<ControlConfig> controls)
{
    foreach (var control in controls)
    {
        _controlWalker.Walk(control, (controlConfig, _) =>
```

### 步骤 5：简化 WinFormsRenderPipeline

**文件**：`CsharpPrj/Operation/WdUI/WdUI.RenderPipeline.cs`

**变更**：
1. 删除 `_eventBinder` 字段和 `EventBinder` 属性
2. 构造函数接受 `EventBindingOrchestrator` 替代 `IEventBindingService`
3. `ExecuteBindEventsStage` 直接调用 `_orchestrator.ExecuteWithWalk()`
4. 删除 `BindEventsAsync(object target)` 重写
5. 删除 `CreateOrUpdateSession` 方法
6. `DisposeSession` 中删除事件解绑逻辑
7. 删除 `FindForm` 私有方法

```csharp
public class WinFormsRenderPipeline : RenderPipelineBase<Control>
{
    private readonly EventBindingOrchestrator _orchestrator;
    private readonly IWinFormsLayoutContext _context;
    private readonly TConfig.IConfigLoader? _configLoader;
    private readonly ConcurrentDictionary<Control, WdUI.Layout.RenderSession> _sessions = new();
    private readonly LayoutPipeline _layoutPipeline;

    public WinFormsRenderPipeline(
        IWinFormsLayoutContext context,
        EventBindingOrchestrator orchestrator)
        : base(WdUISettings.Instance.Pipelines.RenderPipeline)
    {
        _context = context;
        _orchestrator = orchestrator ?? throw new ArgumentNullException(nameof(orchestrator));
        _configLoader = WdUIComposer.Middleware.ConfigLoader;
        _layoutPipeline = new LayoutPipeline();
    }

    // 三阶段管线
    protected override Task ExecuteCreateStage(Control target, IRenderSession session) { /* 保持不变 */ }
    protected override Task ExecuteLayoutStage(Control target, IRenderSession session) { /* 保持不变 */ }

    protected override Task ExecuteBindEventsStage(Control target, IRenderSession session)
    {
        if (session.Config is UIConfiguration config)
        {
            _orchestrator.ExecuteWithWalk(target, config);
        }
        return Task.CompletedTask;
    }

    // 会话管理
    protected override IRenderSession CreateSession(object target, object? config) { /* 保持不变 */ }
    public WdUI.Layout.RenderSession? GetActiveSession(Control target) { /* 保持不变 */ }

    public void DisposeSession(Control target)
    {
        if (_sessions.TryRemove(target, out var session))
        {
            foreach (var panel in session.CreatedPanels)
            {
                if (target.Controls.Contains(panel))
                {
                    target.Controls.Remove(panel);
                    panel.Dispose();
                }
            }
            _layoutPipeline.Cleanup(target);
            session.Dispose();
        }
    }

    // 分步 API
    public async Task RenderFullAsync(Control target, UIConfiguration config) { /* 保持不变 */ }
    public void Render(Control target, UIConfiguration config) { /* 保持不变 */ }
    public void RenderSessionOnly(Control target, UIConfiguration config) { /* 保持不变 */ }
    public bool ApplyLayout(Control target) { /* 保持不变 */ }
    public void Relayout(Control target) { /* 保持不变 */ }

    public async Task BindEventsAsync(Control target)
    {
        var session = GetActiveSession(target);
        if (session != null)
        {
            await ExecuteBindEventsStage(target, session).ConfigureAwait(false);
        }
    }

    // 删除：_eventBinder 字段、EventBinder 属性
    // 删除：BindEventsAsync(object target) 重写
    // 删除：CreateOrUpdateSession() 方法
    // 删除：FindForm() 私有方法
}
```

### 步骤 6：EventBindingOptions 增加默认 OnEventResult

**文件**：`CsharpPrj/Share/EventBindingOrchestrator/Abstractions/EventBindingOptions.cs`

**变更**：将 `DefaultEventBindingService` 构造函数中的 `OnEventResult` 回调创建逻辑移到 `EventBindingOptions` 的默认值。

```csharp
public class EventBindingOptions
{
    // ... 现有属性保持不变

    public Action<string, string, object?>? OnEventResult { get; set; }

    public Action<string, string, object?> GetOrCreateOnEventResult()
    {
        if (OnEventResult != null) return OnEventResult;

        return (functionName, status, detail) =>
        {
            var logData = new Dictionary<string, object?>
            {
                ["functionName"] = functionName,
                ["status"] = status
            };

            if (detail is Dictionary<string, object?> detailDict)
            {
                foreach (var kvp in detailDict)
                    logData[kvp.Key] = kvp.Value;
                logData["executionPath"] = detailDict.ContainsKey("stepCount")
                    ? "workflow_multi" : "workflow_single";
            }
            else if (detail != null)
            {
                logData["detail"] = detail;
                logData["executionPath"] = "unknown";
            }
            else
            {
                logData["executionPath"] = "unknown";
            }

            EventTriggerLog.Log("EventBindingFunctionResult", logData);

            if (status == "failed" || status == "exception" || status == "timeout")
            {
                FrameworkErrors.Report($"EventBinding.{functionName}",
                    $"函数 '{functionName}' 执行{status}: {detail?.ToString() ?? "Unknown error"}",
                    severity: ErrorSeverity.Warning);
            }
        };
    }
}
```

## 4. 整合后架构

### 4.1 调用链

```

├── CreateSession / DisposeSession（会话管理）
├── ExecuteCreateStage（创建 LayoutPanel）
├── ExecuteLayoutStage（布局）
└── ExecuteBindEventsStage（事件绑定）
    └── _orchestrator.ExecuteWithWalk(target, config)
```
