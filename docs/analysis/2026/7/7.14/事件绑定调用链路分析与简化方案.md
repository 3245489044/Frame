## 二、完整调用链路追踪

### 2.1 阶段一：事件绑定（配置→绑定）

```
WinFormsRenderPipeline.ExecuteBindEventsStage (WdUI.RenderPipeline.cs:319)
  └─ EventBindingOrchestrator.ExecuteWithWalkAsync (EventBindingOrchestrator.cs:492)
      └─ EventBindingOrchestrator.ExecuteWithWalk (EventBindingOrchestrator.cs:134)
          ├─ ExecuteCore → 创建 EventBindingContext + 编排器管线
          └─ GenericEventBindingPipeline.ExecuteWithWalk (GenericEventBindingPipeline.cs:97)
              └─ WalkAndBind (遍历控件树)
                  └─ 对每个控件执行管线链:
                      1. ControlFinderTransformer (查找控件实例)
                      2. BindingMetadataTransformer (提取绑定元数据)
                      3. EventBinder分支:
                         a. ConfigBindingStage (Config路径, Order=10)
                         b. DeclarationBindingStage (Declaration路径, Order=20)
```

**关键点**：`ConfigBindingStage` 遍历 `EventsDictionary`，对每个事件名+函数名调用 `_eventHandlerFactory.CreateEventHandler` 创建事件处理器，然后通过 `_eventBinder.TryBindEvent` 绑定到 `IEventBus`。

### 2.2 阶段二：事件触发（用户点击→函数执行）

```
用户点击 "Add" 按钮
  └─ WinFormsEventBus 触发 Click 事件
      └─ EventBindingStageBase.CreateEventHandler 创建的委托 (EventBindingStageBase.cs)
          └─ Task.Run 异步执行
              ├─ 1. 构建 EventContext (EventContextScope.cs)
              │   ├─ EventContext.Current = new EventContext (AsyncLocal)
              │   ├─ ctx.FunctionName = "Add"
              │   ├─ ctx.Sender = addButton
              │   ├─ ctx.OutputTarget = "resultTextBox"  (来自 ResolveOutput)
              │   └─ ctx.OutputKey = null
              │
              ├─ 2. 构建参数字典
              │   └─ ParameterBuilder.Build(sender, parameterBindings)
              │       ├─ 从 valueATextBox.Text 读取 → "valueA"
              │       ├─ 从 valueBTextBox.Text 读取 → "valueB"
              │       └─ 返回 { "valueA": "10", "valueB": "20" }
              │
              ├─ 3. 执行函数
              │   └─ IEventExecutionService.ExecuteFunctionAsync("Add", parameters)
              │       └─ WorkflowMethodExecutionService
              │           └─ NodeExecutor.Execute (含Polly重试)
              │               └─ 反射调用 MathFunctions.Add(valueA, valueB)
              │                   └─ 返回 Dictionary { "result": 30 }
              │
              └─ 4. HandleExecutionResult (处理结果)
                  ├─ result.IsSuccess = true
                  ├─ result.ReturnValue = Dictionary { "result": 30 }
                  └─ onResult?.Invoke("Add", "success", detail)
                      └─ 仅日志记录 ❌ 未写回 UI
```

### 2.3 阶段三：结果回写（缺失环节）

```
HandleExecutionResult 完成后，应该执行:
  └─ 从 result.ReturnValue 提取 "result" = 30
      └─ 查找 resultTextBox 控件
          └─ resultTextBox.Text = "30"
```

**但这段代码不存在。**

## 三、根因定位

### 3.1 代码变更历史

通过分析代码注释，可以追溯结果回写功能的演变：

| 时间 | 变更 | 结果 |
|------|------|------|
| 2026-07-14 之前 | `EventBindingStageBase` 中有 `_outputWriter.WriteOutput` 调用 | ✅ 结果正常写回 UI |
| 2026-07-14 | 删除 `_outputWriter` 相关代码 | ❌ 结果回写断裂 |
| 2026-07-15 | `EventBindingOptions` 中注释："删除 OutputWriter 赋值，输出写入由 onResult 回调处理" | ❌ 但 onResult 只做日志 |
| 2026-07-15 | `ResolveOutput` 重构为返回 `(outputTarget, outputKey)` 元组 | ✅ 输出目标信息完整 |
| 当前 | `HandleExecutionResult` 中只有 `onResult` 回调 | ❌ 没有写回 UI |

### 3.2 关键代码位置

**`EventBindingStageBase.cs`** — `HandleExecutionResult` 方法：

```csharp
// 当前代码（简化）：
private void HandleExecutionResult(...)
{
    if (result.IsSuccess)
    {
        // ★ 2026-07-15 重构：删除 _outputWriter.WriteOutput 调用
        //   输出写入由调用方通过 onResult 回调处理
        
        onResult?.Invoke(functionName, "success", detail);
        // ↑ 只做了日志记录，没有写回 UI
    }
}
```

**`WinFormsRenderPipeline.cs`** — fallback 初始化：

```csharp
// 当前代码（简化）：
var fallbackOptions = new EventBindingOptions
{
    EventBus = eventBus,
    ParameterBuilder = (sender, bindings) => new ParameterBuilder().Build(...),
    Registry = ...,
    // ★ 没有注册 WriteOutputToControl 或类似的回写委托
};
```

### 3.3 根因总结

**根本原因**：`HandleExecutionResult` 中删除了 `_outputWriter.WriteOutput` 调用后，没有替代的机制将函数返回值写回到 UI 控件。`onResult` 回调只负责日志记录，不负责 UI 更新。

**直接原因**：`EventBindingOptions` 中没有任何属性或委托用于"将结果写回 UI 控件"。

**间接原因**：IoC 注入点分散在 `EventBindingOptions`、`EventBindingPipelineFactory`、`EventBindingOrchestrator`、`WinFormsRenderPipeline` 等多个文件中，新增一个功能需要修改多个文件。

## 五、简化方案：EventBindingServiceLocator

### 5.1 设计目标

1. **集中管理**：所有调用链路的 IoC 注入点集中在一个文件中
2. **修复结果回写**：新增 `WriteOutputToControl` 委托，将函数结果写回 UI
3. **消除分散依赖**：替代当前分散在 5+ 个文件中的参数透传
4. **降低耦合**：`WorkFlowMethod` 层不再直接依赖 `WinForms`，通过委托解耦

### 5.2 文件位置

```
CsharpPrj/Operation/BackEndDriven/
  └── EventBindingServiceLocator.cs  ← 新增：IoC 控制反转中心
```

### 5.3 核心设计

```csharp
// ============================================================
// EventBindingServiceLocator.cs — IoC 控制反转中心
//
// 设计目标：
//   1. 集中管理所有调用链路的 IoC 注入点
//   2. 消除分散在多个文件中的参数透传
//   3. 提供结果回写 UI 的委托（修复当前"无运行结果"问题）
//   4. 降低 WorkFlowMethod 层对 WinForms 的依赖
//
// 使用方式：
//   在应用程序启动时（如 WinFormsRenderPipeline 单例初始化），
//   注册所有委托的实现。各组件通过此类的静态属性获取依赖。
// ============================================================

using System;
using System.Collections.Generic;
using Modules.EventFramework.Abstractions;
using TConfig;

namespace BackEndDriven;

/// <summary>
/// IoC 控制反转中心 — 集中管理事件绑定调用链路的依赖注入
/// <para>所有组件通过此类的静态属性获取依赖，消除参数透传链。</para>
/// </summary>
public static class EventBindingServiceLocator
{
    // ================================================================
    // 1. 参数构建
    // ================================================================
    
    /// <summary>
    /// 参数构建委托
    /// <para>签名：(sender, bindings) → 参数字典</para>
    /// <para>sender: 触发事件的控件</para>
    /// <para>bindings: 参数绑定列表（来自 JSON 配置）</para>
    /// <para>返回值: 参数字典（键为参数名，值为参数值）</para>
    /// </summary>
    public static Func<object, IReadOnlyList<ParameterBinding>?, Dictionary<string, object>>? 
        ParameterBuilder { get; set; }

    // ================================================================
    // 2. 函数执行
    // ================================================================
    
    /// <summary>
    /// 事件执行服务（统一函数/工作流执行路径）
    /// <para>提供 ExecuteFunctionAsync 方法，支持单函数和工作流执行。</para>
    /// </summary>
    public static IEventExecutionService? ExecutionService { get; set; }

    // ================================================================
    // 3. 函数注册表
    // ================================================================
    
    /// <summary>
    /// 函数注册表
    /// <para>用于 ParameterBuilder 感知函数签名，过滤多余的参数键。</para>
    /// </summary>
    public static IFunctionRegistry? Registry { get; set; }

    // ================================================================
    // 4. 事件总线
    // ================================================================
    
    /// <summary>
    /// 事件总线
    /// <para>用于绑定/解绑事件。</para>
    /// </summary>
    public static IEventBus? EventBus { get; set; }

    // ================================================================
    // 5. 结果回写（★ 关键修复：当前缺失的环节）
    // ================================================================
    
    /// <summary>
    /// 将函数执行结果写回到 UI 控件
    /// <para>签名：(sender, outputTarget, value) → void</para>
    /// <para>sender: 触发事件的控件（用于 FindForm 获取父窗体）</para>
    /// <para>outputTarget: 目标控件名（如 "resultTextBox"）</para>
    /// <para>value: 要写入的值（函数的返回值）</para>
    /// <para>实现示例：通过 sender.FindForm() 获取窗体，递归查找目标控件，</para>
    /// <para>根据控件类型（TextBox/Label 等）设置对应的属性。</para>
    /// </summary>
    public static Action<object, string, object?>? WriteOutputToControl { get; set; }

    // ================================================================
    // 6. 事件执行结果回调
    // ================================================================
    
    /// <summary>
    /// 事件执行结果回调
    /// <para>签名：(functionName, status, detail) → void</para>
    /// <para>functionName: 函数名（如 "Add"）</para>
    /// <para>status: 状态（"success"/"failed"/"exception"/"timeout"）</para>
    /// <para>detail: 详细信息（Dictionary 或字符串）</para>
    /// <para>用途：日志记录、错误报告到 UI</para>
    /// </summary>
    public static Action<string, string, object?>? OnEventResult { get; set; }

    // ================================================================
    // 7. 初始化验证
    // ================================================================
    
    /// <summary>
    /// 验证所有必需的委托是否已注册
    /// <para>在应用程序启动时调用，确保所有依赖已就绪。</para>
    /// <para>必需的委托：ParameterBuilder、ExecutionService、EventBus</para>
    /// <para>可选的委托：WriteOutputToControl、OnEventResult、Registry</para>
    /// </summary>
    /// <returns>true 表示所有必需委托已注册</returns>
    public static bool Validate()
    {
        if (ParameterBuilder == null)
        {
            System.Diagnostics.Debug.WriteLine("[EventBindingServiceLocator] ParameterBuilder 未注册");
            return false;
        }
        if (ExecutionService == null)
        {
            System.Diagnostics.Debug.WriteLine("[EventBindingServiceLocator] ExecutionService 未注册");
            return false;
        }
        if (EventBus == null)
        {
            System.Diagnostics.Debug.WriteLine("[EventBindingServiceLocator] EventBus 未注册");
            return false;
        }
        return true;
    }

    /// <summary>
    /// 重置所有注册（用于测试和清理）
    /// </summary>
    public static void Reset()
    {
        ParameterBuilder = null;
        ExecutionService = null;
        Registry = null;
        EventBus = null;
        WriteOutputToControl = null;
        OnEventResult = null;
    }
}
```

### 6.2 WriteOutputToControl 的默认实现

**文件**：`CsharpPrj/Operation/WdUI/WdUI.RenderPipeline.cs`（在单例初始化中注册）

```csharp
// 在 WinFormsRenderPipeline 单例初始化中注册
EventBindingServiceLocator.WriteOutputToControl = (sender, outputTarget, value) =>
{
    if (sender is not Control control) return;
    
    // 获取父窗体
    var form = control.FindForm();
    if (form == null) return;
    
    // 递归查找目标控件
    var target = FindControlRecursive(form, outputTarget);
    if (target == null)
    {
        System.Diagnostics.Debug.WriteLine(
            $"[WriteOutputToControl] 未找到目标控件: '{outputTarget}'");
        return;
    }
    
    // 根据控件类型设置值
    // 对于 Dictionary 类型的返回值，尝试提取 "result" 键
    object? displayValue = value;
    if (value is System.Collections.IDictionary dict && dict.Contains("result"))
    {
        displayValue = dict["result"];
    }
    
    switch (target)
    {
        case TextBox textBox:
            textBox.Text = displayValue?.ToString() ?? "";
            break;
        case Label label:
            label.Text = displayValue?.ToString() ?? "";
            break;
        case RichTextBox richTextBox:
            richTextBox.Text = displayValue?.ToString() ?? "";
            break;
        case ListView listView:
            // 处理 ListView 写入（如需要）
            break;
        default:
            // 通过反射尝试设置 Text 属性
            var textProp = target.GetType().GetProperty("Text");
            if (textProp != null && textProp.CanWrite)
            {
                textProp.SetValue(target, displayValue?.ToString());
            }
            break;
    }
};

// 辅助方法：递归查找控件
static Control? FindControlRecursive(Control parent, string name)
{
    if (parent.Name == name) return parent;
    foreach (Control child in parent.Controls)
    {
        var found = FindControlRecursive(child, name);
        if (found != null) return found;
    }
    return null;
}
```

### 6.3 处理 Dictionary 返回值

`Add` 函数的返回值是 `Dictionary<string, object>`，包含 `{ "result": 30 }`。WriteOutputToControl 需要：

1. 检测返回值是否为 `IDictionary`
2. 如果是，尝试提取 `"result"` 键的值
3. 将提取的值显示到目标控件

```csharp
// 值提取逻辑
object? resolvedValue = value;
if (value is System.Collections.IDictionary dict)
{
    // 优先使用 outputKey（如果配置了）
    if (!string.IsNullOrEmpty(ctx.OutputKey) && dict.Contains(ctx.OutputKey))
    {
        resolvedValue = dict[ctx.OutputKey];
    }
    // 回退到 "result" 键
    else if (dict.Contains("result"))
    {
        resolvedValue = dict["result"];
    }
    // 如果只有一个键值对，直接使用该值
    else if (dict.Count == 1)
    {
        var enumerator = dict.GetEnumerator();
        enumerator.MoveNext();
        resolvedValue = enumerator.Value;
    }
}
```

## 八、总结

### 8.1 问题根因

| 问题 | 原因 | 影响 |
|------|------|------|
| 函数执行成功但结果不显示 | `_outputWriter.WriteOutput` 被删除后无替代 | 所有函数结果无法回显 |
| IoC 注入点分散 | 参数透传链跨 5+ 个文件 | 新增功能需要修改多个文件 |
| 调用链路不清晰 | 多层抽象导致难以追踪 | 调试困难 |

### 8.2 修复方案

| 修复项 | 方案 | 文件 |
|--------|------|------|
| 新增 IoC 中心 | `EventBindingServiceLocator` 静态类 | `BackEndDriven/EventBindingServiceLocator.cs` |
| 修复结果回写 | 在 `HandleExecutionResult` 中调用 `WriteOutputToControl` | `EventBindingStageBase.cs` |
| 注册回写实现 | 在 `WinFormsRenderPipeline` 中注册委托 | `WdUI.RenderPipeline.cs` |

### 8.3 预期效果

修复后，MathFunctions 界面的调用链路变为：

```
用户点击 Add 按钮
  → 参数构建 (valueA=10, valueB=20)
  → 函数执行 (Add → 返回 { "result": 30 })
  → WriteOutputToControl (resultTextBox.Text = "30")  ← 新增
  → OnEventResult (日志记录)
```

用户将在 resultTextBox 中看到计算结果 "30"。
