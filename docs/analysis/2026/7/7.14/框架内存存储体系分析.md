# 框架内存存储体系分析

> 分析日期：2026-07-13
> 分析目的：梳理框架中所有内存存储体系，定位数据归属权混乱、跨体系访问困难、快照机制误清除等问题

---

## 概述

当前框架中存在 **4 套独立的内存存储体系**，它们各自为政，数据互不互通，导致数据归属权混乱、跨体系访问困难、快照机制误清除等问题。

---

### 快照机制

**文件**：`CsharpPrj/Share/EventBindingOrchestrator/Transformers/GenericEventBindingPipeline.cs`

**位置**：`WalkAndBind` 方法（第 124-152 行）

```csharp
private void WalkAndBind(EventBindingContext context, List<ControlConfig> controls)
{
    foreach (var control in controls)
    {
        _controlWalker.Walk(control, (controlConfig, _) =>
        {
            context.CurrentControlConfig = controlConfig;
            
            // 创建快照 → 执行管线 → 恢复快照
            var snapshot = context.CreateSnapshot();   // 收集所有 SetData 数据
            Execute(context);                          // 执行 3 个 Transformer
            context.RestoreSnapshot(snapshot);         // 恢复快照，清除所有变更
            context.CurrentControlConfig = controlConfig;  // 保留 CurrentControlConfig
        });
    }
}
```

**快照实现**（`ContextExtensions.cs`）：

- `CreateDataSnapshot`（第 137 行）：通过 `CollectAllData` 递归收集当前上下文及父上下文的所有数据
- `RestoreDataFromSnapshot`（第 156 行）：遍历快照中的所有键值对，逐个调用 `SetData` 恢复

**问题**：`RestoreSnapshot` 会**无差别恢复所有 `SetData` 存储的数据**，包括配置级的 `WorkflowDefinitions`。`BindingMetadataTransformer` 在第 121 行设置了 `WorkflowDefinitions`，但紧接着被 `RestoreSnapshot` 清除。

**提取逻辑**（`BindingMetadataTransformer.cs` 第 111-131 行）：

```csharp
var bindings = config.Events?.Bindings;
if (bindings?.ExtensionData != null &&
    bindings.ExtensionData.TryGetValue("workflows", out var workflowsElement))
{
    var workflows = JsonSerializer.Deserialize<
        Dictionary<string, Parameters.Binding.WorkflowDefinitionEntry>>(
        workflowsElement.GetRawText(),
        new JsonSerializerOptions { PropertyNameCaseInsensitive = true });
```

### 问题

- `workflows` 是核心业务数据（工作流定义），却通过 `[JsonExtensionData]` 隐式存储，没有类型安全的属性
- 提取方通过硬编码字符串 `"workflows"` 访问，无编译期检查
- 提取后通过 `SetData` 存入体系一，依赖快照机制的正确性

### 使用方

| 使用位置 | 键名 | 值类型 | 用途 |

### 问题

- `SharedData` 与 `SetData`/`GetData` 是两套独立的键值存储，但用途重叠
- `SharedData` 不受快照机制影响（不会被 `RestoreSnapshot` 清除），而 `SetData` 存储的数据受快照影响
- 开发者需要自行判断数据应该存入 `SharedData` 还是 `SetData`，无明确规则

## 核心问题总结

| 问题 | 描述 | 涉及体系 |
|------|------|----------|
| **数据归属权混乱** | `WorkflowDefinitions` 是配置级数据，却被放在控件级的 `SetData` 中，被快照误清除 | 体系一 |
| **快照机制无差别恢复** | `RestoreSnapshot` 不区分配置级/控件级数据，所有 `SetData` 存储的数据一视同仁 | 体系一 |
| **隐式存储核心数据** | `workflows` 通过 `[JsonExtensionData]` 隐式存储，无类型安全属性 | 体系三 |
| **硬编码字符串访问** | `"workflows"` 字符串在 `BindingMetadataTransformer` 中硬编码 | 体系三 → 体系一 |
| **数据双重拷贝** | `EventBindingOptions` 和 `EventBindingContext` 存储相同数据，无同步机制 | 体系二 → 体系一 |
| **两套键值存储重叠** | `SharedData` 和 `SetData` 用途重叠，开发者无明确选择规则 | 体系一 |
| **父子级联副作用** | `GetData` 级联到父上下文，可能导致意外的数据共享 | 体系一 |

## 复用 InternalStorage 方案

> 本节分析如何用 `Modules/InternalStorage` 模块解决上述 4 套存储体系的问题。
> 详细设计文档见 [`InternalStorage复用分析.md`](./InternalStorage复用分析.md)。

### 方案总览

`InternalStorage` 模块已按 [`InternalStorage复用分析.md`](./InternalStorage复用分析.md) 的设计完整实现，提供以下核心组件：

| 组件 | 文件 | 解决的问题 |
|------|------|-----------|
| `IStorageCell`（三层存储） | `CsharpPrj/Modules/InternalStorage/Abstractions/IStorageCell.cs` | 体系一（SetData/GetData）+ 体系四（SharedData） |
| `IStorageEngine`（统一入口） | `CsharpPrj/Modules/InternalStorage/Abstractions/IStorageEngine.cs` | 体系二（EventBindingOptions） |
| `IStorageRegistry`（类型安全注册） | `CsharpPrj/Modules/InternalStorage/Abstractions/IStorageRegistry.cs` | 体系三（[JsonExtensionData]） |
| `ISnapshotManager`（分层快照） | `CsharpPrj/Modules/InternalStorage/Abstractions/ISnapshotManager.cs` | 体系一的快照误清除问题 |

### 三层存储设计

| 层级 | 生命周期 | 快照行为 | 覆盖的现有体系 | 用途示例 |
|------|---------|----------|---------------|---------|
| **Config Layer** | 应用级 | `Preserve`（不受快照影响） | 体系二 + 体系三 | `WorkflowDefinitions`、`EventBus`、`SearchRoot` |
| **Session Layer** | 管线级 | `Snapshot`（受快照管理） | 体系一（控件级属性） | `CurrentControlConfig`、`CurrentView`、`CurrentOutput` |
| **Transient Layer** | 单次操作级 | `Exclude`（不参与快照） | 体系四（SharedData） | `SkipPipeline`、`DiagnosticsScope` |

### 各体系复用方式

#### 体系一：`EventBindingContext` → `IStorageCell`

```csharp
// 当前问题：19 个属性混存同一 ConcurrentDictionary，快照无差别恢复
// 复用 InternalStorage 后：

public class EventBindingContext
{
    private readonly IStorageCell _cell;

    // Config 层（不受快照影响）— 原被快照误清除的 WorkflowDefinitions
    public Dictionary<string, WorkflowDefinitionEntry>? WorkflowDefinitions
    {
        get => _cell.Get<Dictionary<string, WorkflowDefinitionEntry>>(
            nameof(WorkflowDefinitions), StorageLayer.Config);
        set => _cell.Set(nameof(WorkflowDefinitions), value, StorageLayer.Config);
    }

    // Session 层（受快照管理）— 原控件级临时状态
    public ControlConfig? CurrentControlConfig
    {
        get => _cell.Get<ControlConfig>(nameof(CurrentControlConfig), StorageLayer.Session);
        set => _cell.Set(nameof(CurrentControlConfig), value, StorageLayer.Session);
    }

    // Transient 层（不参与快照）— 原 SharedData 用途
    public bool SkipCurrentControl
    {
        get => _cell.Get<bool>(nameof(SkipCurrentControl), StorageLayer.Transient);
        set => _cell.Set(nameof(SkipCurrentControl), value, StorageLayer.Transient);
    }
}
```

### 快照修复：`GenericEventBindingPipeline`


### 迁移步骤

| 阶段 | 步骤 | 涉及文件 |
|------|------|---------|
