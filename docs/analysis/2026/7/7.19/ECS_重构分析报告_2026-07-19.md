## 一、重复逻辑

### 1.1 `EcsWorld.CreateQueryBuilder` 与 `EntityQueryBuilder.Builder`

- **位置**: `ECSFrame.cs:364` vs `Query/EntityQuery.cs:90-168`
- **问题**: `EcsWorld` 中定义了 `CreateQueryBuilder()` 方法，但 `EntityQueryBuilder.Builder` 已有完整的链式构建 API
- **处理**: ✅ 已删除 `CreateQueryBuilder()`，统一使用 `CreateQuery()` 返回 `EntityQueryBuilder.Builder`

### 1.2 `EntityManager` 泛型方法与非泛型方法

- **位置**: `ECSFrame.cs` 中 `GetEntities<T>()`、`GetEntities<T1, T2>()`
- **问题**: 这些泛型方法直接委托给非泛型 `GetEntities(typeof(T))`，逻辑正确，无重复
- **结论**: ✅ 无重复，设计合理

## 二、冗余逻辑

### 2.1 `ArchetypeManager.CreateEntity` 中的冗余检查

- **位置**: `Archetype/ArchetypeManager.cs`
- **问题**: `CreateEntity` 中先调用 `_archetypeManager.CreateEntity()`，然后立即 `_entityArchetype.TryGetValue(entity, out var archetype)` 检查刚创建的 Entity 是否存在——这是冗余的，因为 `CreateEntity` 内部已确保 Entity 被添加到 Archetype
- **处理**: ✅ 已移除冗余检查

### 2.2 `EntityManagerEventSource.ComponentUpdated` 事件

- **位置**: `Relations/RelationComponent.cs:1051`
- **问题**: 定义了 `ComponentUpdated` 事件但从未订阅 `_em.ComponentUpdated`，导致事件永远不会被触发
- **处理**: ✅ 已添加 `_em.ComponentUpdated += (e, t, old, nw) => ComponentUpdated?.Invoke(e, t, old, nw);`

---

## 三、错误逻辑

### 3.1 `ComponentTypeId.GetType` 参数验证错误

- **位置**: `ComponentTypeId.cs`
- **问题**: `GetType(int typeId)` 中验证逻辑为 `if (typeId <= 0)`，但 `typeId == 0` 是合法的（第一个 Component 类型的 ID 为 0）
- **处理**: ✅ 已修复为 `if (typeId < 0)`

### 3.2 `RelationManager.Dispose` 未取消订阅事件

- **位置**: `Relations/RelationComponent.cs`
- **问题**: `Dispose()` 方法中未取消订阅 `_em.EntityDestroyed` 事件，导致已释放的 `RelationManager` 实例仍会被回调
- **处理**: ✅ 已添加 `_em.EntityDestroyed -= OnEntityDestroyed;`

### 3.3 `EcsContext` 构造函数缺少 `IECSStorage` 参数

- **位置**: `Relations/RelationComponent.cs` 中 `EcsContext` 构造函数
- **问题**: 构造函数未接受 `IECSStorage` 参数，但 `EcsWorld` 构造函数需要它
- **处理**: ✅ 已添加 `IECSStorage ecsStorage` 参数并传递给 `EcsWorld`

### 3.4 `ECSFrame.cs` 命名空间冲突

- **位置**: `ECSFrame.cs`
- **问题**: `TConfig.ContextFrame.Abstractions` 与 `BasicMethod.ContextFrame.Abstractions` 命名空间冲突
- **处理**: ✅ 已添加 `using TConfigContextFrame = TConfig.ContextFrame.Abstractions;` 别名

## 四、未重构完全的储存逻辑

### 4.1 `ComponentTypeId` 静态调用（核心问题）

- **问题**: `ComponentTypeId` 原本是静态类，所有方法通过 `ComponentTypeId.GetId()` / `ComponentTypeId.GetType()` 静态调用。这违反了依赖注入原则，且无法在测试中替换实现
- **影响范围**: 以下类型/方法使用了静态调用：
  - `ArchetypeManager` — `HasComponent<T>()`, `GetComponent<T>()`, `AddComponent<T>()`, `RemoveComponent<T>()`, `QueryChunks()`, `DestroyEntity()`
  - `ArchetypeSignature` — 构造函数, `ToString()`
  - `ArchetypeQueryResult` — `GetAccessor<T>()`, `GetSpan<T>()`
  - `EntityQueryBuilder.Builder` — `WithAny<T>()`, `WithNone<T>()`
  - `ChunkJob` — `ForEach<T>()`
  - `Chunk` — `GetComponentSpan<T>()`, `GetComponent<T>()`, `SetComponent<T>()`
  - `Archetype` — `AddEntity()`, `MoveEntity()`
- **处理**: ✅ **全部已修复**。`ComponentTypeId` 改为实例类，通过构造函数注入 `IStorageRegistry`。所有调用方改为通过构造函数注入的实例调用

### 4.2 重构后的依赖注入链

```
EcsWorld
  └─ ComponentTypeId (new ComponentTypeId(storageRegistry))
  └─ EntityManager
       └─ ArchetypeManager (注入 ComponentTypeId)
            └─ ArchetypeSignature (构造函数传入 ComponentTypeId)
            └─ Chunk (方法参数传入 ComponentTypeId)
  └─ EntityQueryBuilder.Builder (构造函数传入 ComponentTypeId)
       └─ EntityQueryBuilder (持有 ComponentTypeId)
            └─ ArchetypeQueryResult (构造函数传入 ComponentTypeId)
                 └─ ChunkJob.ForEach (通过 ArchetypeQueryResult 内部持有)
```
