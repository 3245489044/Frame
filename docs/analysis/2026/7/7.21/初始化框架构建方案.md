# 初始化框架构建方案

> 基于 InternalStorage 构建统一的初始化编排框架，解决当前初始化流程中的顺序依赖、硬编码步骤号、重复初始化等问题。

---

## 1. 问题分析

### 1.1 当前初始化痛点

| 问题 | 表现 | 根因 |
|------|------|------|
| **硬编码步骤号** | `FrameworkInitializer` 中步骤 0~9 顺序写死 | 无依赖解析，手动维护顺序 |
| **重复初始化检查** | 每个组件各自实现 `IsInitialized` 标志 | 无统一生命周期管理 |
| **初始化顺序耦合** | WdUI → Registry → CommandFramework → WinForms 顺序硬编码 | 组件间隐式依赖未显式声明 |
| **初始化失败难定位** | 步骤 2 失败后步骤 3~9 全部跳过 | 无分步执行 + 错误隔离 |
| **初始化器散落** | `WdUIContainerManager.Initialize()`、`CommandFrameworkUsage.Initialize()`、`UnifiedRegistryCenter.Initialize()` 分散在各处 | 无统一注册机制 |

### 1.2 根因分析（参考 MainLayout_contentContainer_FATAL）

```
FATAL 路径：
  MainForm.OnHandleCreated
    → FileDrivenWdUIBridge.Initialize()
      → WdUIContainerManager.Initialize()
        → WdUIUsage.Initialize()
          → WdUIComposer.Initialize()
            → 创建 WdUIComposer 实例
              → 构造函数中 new DefaultRenderPipeline()
                → DefaultRenderPipeline 构造函数
                  → 访问 WdUISettings.Instance
                    → WdUISettings 静态构造函数
                      → 访问 ConfigContainer 的静态成员
                        → ConfigContainer 静态构造函数
                          → 访问 contentContainer（null）
                            → NullReferenceException → FATAL

根因：WdUIComposer 构造函数中 new DefaultRenderPipeline() 过早触发
      WdUISettings 的静态初始化，而此时 contentContainer 尚未就绪。
```

**初始化框架解决思路**：将 `DefaultRenderPipeline` 的创建延迟到所有依赖就绪后，通过依赖声明自动排序。

### 2.2 核心接口

```csharp
// ─── IInitializer.cs ───

/// <summary>
/// 初始化器接口
/// <para>每个需要初始化的组件实现此接口，声明依赖关系。</para>
/// </summary>
public interface IInitializer
{
    /// <summary>组件名称（唯一标识，如 "WdUI", "ECSStorage", "CommandFramework"）</summary>
    string Name { get; }

    /// <summary>依赖的组件名称列表（初始化顺序保证：依赖先初始化）</summary>
    string[] DependsOn { get; }

    /// <summary>执行初始化</summary>
    Task ExecuteAsync(IInitializationContext context);
}

// ─── IInitializationContext.cs ───

/// <summary>
/// 初始化上下文
/// <para>包装 StorageCell 和 StorageRegistry，提供初始化过程中的存储能力。</para>
/// </summary>
public interface IInitializationContext
{
    /// <summary>存储单元（Config 层存持久配置，Session 层存初始化状态）</summary>
    IStorageCell Storage { get; }

    /// <summary>存储注册中心（类型安全注册初始化结果）</summary>
    IStorageRegistry Registry { get; }

    /// <summary>取消令牌</summary>
    CancellationToken CancellationToken { get; }
}
```

### 2.3 编排器核心逻辑

```csharp
// ─── InitializationOrchestrator.cs ───

public class InitializationOrchestrator
{
    private readonly List<IInitializer> _initializers = new();
    private readonly IStorageEngine _engine;

    public InitializationOrchestrator(IStorageEngine engine)
    {
        _engine = engine;
    }

    /// <summary>注册初始化器（lambda 形式，应用方无需新增文件）</summary>
    public void Register(string name, Func<Task> initialize,
        string[]? dependsOn = null) { ... }

    /// <summary>注册初始化器（lambda 同步形式）</summary>
    public void Register(string name, Action initialize,
        string[]? dependsOn = null) { ... }

    /// <summary>注册初始化器（接口形式，框架内部使用）</summary>
    public void Register(IInitializer initializer) { ... }

    /// <summary>
    /// 执行所有初始化器（拓扑排序 → 分步执行）
    /// </summary>
    public async Task<InitializationResult> ExecuteAsync(
        IStorageCell? storage = null,
        CancellationToken ct = default)
    {
        // 1. 拓扑排序（Kahn 算法）
        var sorted = TopologicalSort();

        // 2. 创建初始化上下文
        var context = new InitializationContext(
            storage ?? _engine.RootCell,
            new StorageRegistry(),
            ct);

        // 3. 分步执行
        var results = new List<InitializerResult>();
        foreach (var initializer in sorted)
        {
            try
            {
                await initializer.ExecuteAsync(context);
                results.Add(new InitializerResult(initializer.Name, true, null));
            }
            catch (Exception ex)
            {
                results.Add(new InitializerResult(initializer.Name, false, ex));
                // 默认 FailFast，可配置为 ContinueOnError
                if (_failFast) throw;
            }
        }

        return new InitializationResult(results);
    }

    /// <summary>拓扑排序（Kahn 算法）</summary>
    private List<IInitializer> TopologicalSort() { ... }
}
```

### 2.4 拓扑排序算法

```
Kahn 算法：
  1. 计算每个节点的入度（依赖数）
  2. 入度为 0 的节点入队列
  3. 出队列 → 加入结果 → 减少依赖节点的入度
  4. 重复直到队列为空
  5. 如果结果数 < 总节点数 → 存在循环依赖 → 抛出异常
```

### 步骤 3：重构 FrameworkInitializer

**应用方零新增文件**，直接在 `FrameworkInitializer.Initialize()` 中用 lambda 注册：

```csharp
public static void Initialize(bool cliMode, out ...)
{
    try
    {
        ExecutionLog.Log("FrameworkInitializer_Initialize_start", ...);

        // 1. 创建存储引擎 + 编排器
        var engine = new StorageEngine("FrameworkInit");
        var orchestrator = new InitializationOrchestrator(engine);

        // 2. 注册所有初始化器（lambda 形式，零新增文件）
        orchestrator.Register("Validation",
            () => InitializeValidationEngine());

        orchestrator.Register("ECSStorage",
            () => {
                var cell = engine.RootCell;
                var registry = new StorageRegistry();
                var ecsStorage = new ECSStorage(cell, registry);
                // 注册到 AppServiceProvider 或 UnifiedRegistryCenter
            });

        orchestrator.Register("CommandFramework",
            () => CommandFrameworkUsage.Initialize(options => { ... }));

        orchestrator.Register("Registry",
            () => {
                var unifiedRegistry = UnifiedRegistryCenter.Instance;
                unifiedRegistry.WorkflowFactory = (f) => new DefaultWorkflowRegistry(f);
                unifiedRegistry.ExecutorFactory = (f) => new FunctionExecutor(f, ...);
                unifiedRegistry.PipelineFactory = (w) => new PipelineExecutor(w);
                unifiedRegistry.RegisterRegistry("FunctionLibrary", new FunctionLibraryLifecycle());
                FileDrivenMethodUsage.Instance.Initialize();
                AppServiceProvider.Register<IMethodUsageProvider>(FileDrivenMethodUsage.Instance);
                unifiedRegistry.Initialize();
                AppServiceProvider.Register<ITrConfigRegistry>(unifiedRegistry.Functions);
            },
            dependsOn: ["CommandFramework"]);

        orchestrator.Register("AppService",
            () => InitializeAppServiceProvider(),
            dependsOn: ["Registry"]);

        orchestrator.Register("WdUI",
            () => {
                if (!WdUIContainerManager.IsInitialized)
                    WdUIContainerManager.Initialize();
            },
            dependsOn: ["ECSStorage"]);

        orchestrator.Register("WinForms",
            () => InitializeWinFormsSubsystem(),
            dependsOn: ["WdUI", "CommandFramework"]);

        orchestrator.Register("ExecutionCenter",
            () => {
                var pool = RegisterExecutionCenterHandler();
                // 设置 out 参数
                executionPool = pool;
            },
            dependsOn: ["AppService"]);

        // 3. 自动拓扑排序执行
        var result = orchestrator.ExecuteAsync().GetAwaiter().GetResult();

        // 4. 检查结果
        if (!result.Success)
        {
            var errors = string.Join("; ", result.Errors.Select(e => $"[{e.InitializerName}] {e.Message}"));
            throw new InvalidOperationException($"框架初始化失败: {errors}");
        }

        // 5. 设置其他 out 参数
        projectRoot = ProjectPathManager.FindProjectRoot();
        commandManager = new UICommandManager();
        templateProcessor = (path) => JsonTemplateProcessor.Process(path: path);
        functionStorageLifecycle = null;
        fileDrivenLifecycle = null;

        ExecutionLog.Log("FrameworkInitializer_Initialize_complete", ...);
    }
    catch (Exception ex)
    {
        ExecutionLog.Log("FrameworkInitializer_Initialize_error", ...);
        throw new InvalidOperationException("框架初始化失败", ex);
    }
}
```

## 6. 设计决策

### 6.1 为什么选择 InternalStorage 作为宿主？

| 理由 | 说明 |
|------|------|
| **已有生命周期管理** | `StorageEngine` 已有 `Created→Running→Disposed` 状态机 |
| **已有三层存储** | `StorageCell` 的 Config/Session/Transient 层适合存储初始化状态和结果 |
| **已有类型安全注册** | `StorageRegistry` 的 `Register<T>()/Resolve<T>()` 适合注册初始化结果 |
| **无循环依赖** | InternalStorage 只依赖 TConfig，不依赖任何上层模块 |
| **架构定位** | InternalStorage 是"通用运行时内存存储管理框架"，初始化编排是其自然扩展 |

### 6.2 为什么用拓扑排序而非手动排序？

| 方式 | 缺点 | 拓扑排序优势 |
|------|------|------------|
| 手动排序 | 新增组件需手动插入正确位置，容易出错 | 声明依赖后自动排序 |
| 配置文件排序 | 配置与代码分离，维护成本高 | 依赖声明在代码中，IDE 可追踪 |
| 反射扫描 | 隐式依赖，难以调试 | 显式声明，清晰可查 |

### 6.3 错误处理策略

```
分步执行模式：
  - 默认：失败即中断（FailFast）
  - 可选：收集所有错误（ContinueOnError）
  
结果模型：
  InitializationResult
  ├── Success: bool
  ├── Results: List<InitializerResult>
  │   ├── Name: string
  │   ├── Success: bool
  │   ├── Error: Exception?
  │   └── Duration: TimeSpan
  └── Errors: List<InitializationError>
      ├── InitializerName: string
      ├── Message: string
      └── InnerException: Exception?
```

## 7. 迁移策略

### 7.1 渐进式迁移

```
Phase 1：创建框架基础设施（IInitializer + Orchestrator）— 5 个文件
Phase 2：重构 FrameworkInitializer，lambda 注册所有初始化点 — 1 个文件修改
Phase 3：编译验证
Phase 4：可选 — 将部分复杂初始化点提取为 IInitializer 实现类
```

### 7.2 兼容性保证

- `FrameworkInitializer.Initialize()` 签名不变，调用方无需修改
- 现有 `XxxUsage.Initialize()` 方法保留，编排器直接调用
- 新增 `InitializationOrchestrator` 不破坏现有代码

## 9. 总结

| 指标 | 当前 | 迁移后 |
|------|------|--------|
| 初始化步骤数 | 10 步硬编码 | 自动拓扑排序 |
| 框架层新增文件 | — | 5 个（InternalStorage/Initialization/） |
| 应用方新增文件 | — | **0 个** ✅ |
| 依赖管理 | 手动维护顺序 | 显式声明 `dependsOn` |
| 错误处理 | 步骤失败 → 全部跳过 | 分步执行 + 错误收集 |
| 新增组件成本 | 需找到正确插入位置 | 只需 `Register(name, lambda, dependsOn)` |
| 可测试性 | 低（静态方法耦合） | 中（编排器可单元测试） |
