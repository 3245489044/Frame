# 容器即 Entity 重构方案

> **日期：** 2026-07-21
> **状态：** 待实施
> **背景：** 容器应直接作为 Entity 存在，而非 Entity 的属性或附属物

---

## 1. 核心思想

**容器不是 Entity 的属性，容器本身就是 Entity。**

当前设计中 `EcsConfigContainer`（WinForms Panel）是主体，Entity 是它的"影子"；重构后反过来——**Entity 是主体**，容器只是 Entity 的一种类型（带有 `IsContainer = true` 标记），WinForms Panel 只是容器的物理表现。

---

## 2. 当前架构 vs 目标架构

### 2.1 当前架构

```
EcsConfigContainer (WinForms Panel)  ← 主体
  ├── ContainerIndex (Dictionary)     ← 容器查找依赖此字典
  ├── ContainerNode (树结构)          ← 与 Entity 树重复
  ├── ContainerLifecycle              ← 生命周期管理
  ├── ContainerEventManager           ← 事件管理
  └── Entity (ECS 影子)              ← 附属物

容器查找链路：
  MainForm
    → rootContainer.FindSubContainer("contentContainer")
    → EcsContainer._containerIndex.FindContainer(name)
    → ContainerIndex._nameIndex[name]  ← WinForms 字典，非 ECS
```

### 2.2 目标架构

```
Entity (ECS 主体)  ← 容器即 Entity
  ├── ContainerAncestorComponent { IsContainer=true, Name="contentContainer" }
  ├── ControlHierarchyComponent { Children=[...] }
  └── Panel (WinForms 物理表现)  ← 附属物，通过 ControlPool 关联

容器查找链路：
  MainForm
    → EntityRegistry.FindContainer("contentContainer")
    → EntityManager 按名称查找 Entity
    → 检查 ContainerAncestorComponent.IsContainer
    → ControlPool.GetControl(entity) 返回 Panel
```

### 4.7 `EntityRegistry.cs` — 新增 ECS 容器查找，移除 ContainerIndex 注册

**文件：** `CsharpPrj/Operation/FrontEndDriven/ECS/EntityRegistry.cs`

**新增方法：**

```csharp
/// <summary>
/// 通过 ECS Entity 树查找容器（替代 EcsContainer.FindSubContainer）
/// <para>纯 ECS 查询，不依赖 WinForms 控件树或 ContainerIndex 字典。</para>
/// </summary>
public Control? FindContainer(string name)
{
    if (string.IsNullOrEmpty(name)) return null;

    // 遍历 Entity 树，按名称查找
    var entity = FindEntityByName(_rootEntity, name);
    if (!entity.IsValid) return null;

    // 检查是否为容器
    if (!_entityManager.TryGetComponent<ContainerAncestorComponent>(entity, out var comp))
        return null;
    if (!comp.IsContainer) return null;

    // 通过 ControlPool 获取物理控件
    return _controlPool.GetControl(entity);
}

/// <summary>
/// 递归遍历 Entity 树，按名称查找 Entity
/// </summary>
private Entity FindEntityByName(Entity parent, string name)
{
    if (!_entityManager.IsEntityValid(parent))
        return Entity.Invalid;

    // 检查当前 Entity 是否匹配
    if (_entityManager.TryGetComponent<ControlHierarchyComponent>(parent, out var hierarchy))
    {
        // 通过 ControlPool 获取控件名称
        var controlName = _controlPool.GetControlName(parent);
        if (string.Equals(controlName, name, StringComparison.OrdinalIgnoreCase))
            return parent;

        // 递归子节点
        foreach (var child in hierarchy.Children)
        {
            var found = FindEntityByName(child, name);
            if (found.IsValid)
                return found;
        }
    }

    return Entity.Invalid;
}
```

- `RegisterRoot` — 根容器注册由管线完成，不再注册到 ContainerIndex
- `RegisterAllSubContainers` — 不再需要，容器注册由 ECS Component 关系隐式表达

## 7. 风险与注意事项

### 7.1 `ContainerNode` 是否保留
`EcsContainer` 中 `ContainerNode` 构建了容器树结构，与 Entity 树的 `ControlHierarchyComponent` 功能重叠。但 `ContainerNode` 可能被 `ContainerOrchestrator`、`ContainerEventManager` 等其他组件使用，需要确认后再决定是否移除。

**建议：** 本次重构暂不处理 `ContainerNode`，仅移除 `ContainerIndex`。

### 7.2 `IContainer` 接口的其他实现者
已确认：**只有 `EcsContainer` 一个实现者**。`ContainerManager` 实现的是 `IContainerManager`（不同接口），不受影响。接口变更安全。

### 7.3 `FindSubContainer` 的调用方
所有调用 `FindSubContainer` 的地方都已确认并规划了修改：
- `FileDrivenWdUIBridge.FindAndRegisterContainer` ✓
- `WdUI.EventManagement.FindSubContainerByScopeId` ✓
- `EntityRegistry.FindContainer`（自身实现）✓

### 7.4 性能影响
ECS Entity 树遍历查找（`FindEntityByName`）是 O(n)，而原来的 `ContainerIndex` 是 O(1)。如果容器数量不大（通常 < 100），性能差异可忽略。如果未来容器数量增长，可以在 Entity 级别增加名称索引。

### 7.5 `WdUI.EventManagement.cs` 的 `GetSubContainers` 委托
`FindSubContainerByScopeId` 当前通过 `GetSubContainers?.Invoke()` 委托获取子容器列表。该委托由 `EcsConfigContainer` 在初始化时设置。重构后需要改为通过 `EntityRegistry` 直接查询，消除对委托的依赖。
