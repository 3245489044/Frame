# Entity 生命周期事件机制实施方案

> **日期：** 2026-07-22
> **背景：** `ControlCreateSystem.Update()` 中 `RemoveEntityFromTree` 销毁 Entity 后，`sortedEntities` 快照中的悬挂引用导致 `Invalid entity: Entity(23:0)` 异常。
> **根因分析：** 见 `docs/analysis/2026-07-22-日志错误分析.md`

---

## 1. 设计目标

在 Entity 被销毁前，通知所有持有 Entity 引用的组件有机会清理引用，避免悬挂引用导致的 `Invalid entity` 异常。

### 核心原则

1. **事件在写锁内触发** — 确保事件处理器执行时，Entity 状态尚未改变
2. **事件处理器不应抛出异常** — 防止破坏销毁流程
3. **事件处理器不应长时间阻塞** — 防止写锁持有时间过长
4. **订阅/取消订阅配对** — 防止内存泄漏

---

## 2. 实施步骤

### 步骤 1：`EntityManager` 新增 `EntityDestroying` 事件

**文件：** `CsharpPrj/BasicMethod/ECS/ECSFrame.cs`

#### 1.1 新增事件声明

在 `EntityManager` 类的 `EntityCreated` / `EntityDestroyed` 事件附近新增：

```csharp
// ========== 生命周期事件 ==========

/// <summary>
/// Entity 创建事件（已有）
/// </summary>
public event Action<Entity>? EntityCreated;

/// <summary>
/// Entity 销毁前事件（★ 新增）
/// <para>在 Entity 被实际销毁前触发，通知所有持有该 Entity 引用的组件清理引用。</para>
/// <para>触发时机：在 ArchetypeManager.DestroyEntity 之前，写锁保护下。</para>
/// <para>用途：让快照持有者、缓存持有者等有机会在 Entity 失效前移除引用。</para>
/// <para>注意事项：</para>
/// <para>  1. 事件在写锁内触发，处理器不应长时间阻塞</para>
/// <para>  2. 处理器不应抛出异常，否则会中断销毁流程</para>
/// <para>  3. 此时 Entity 仍然有效（IsEntityValid 返回 true），处理器可以安全地访问其 Component</para>
/// </summary>
public event Action<Entity>? EntityDestroying;

/// <summary>
/// Entity 销毁后事件（已有）
/// </summary>
public event Action<Entity>? EntityDestroyed;
```

#### 1.2 修改 `DestroyEntity` 方法

在 `ArchetypeManager.DestroyEntity` 调用前触发 `EntityDestroying` 事件：

```csharp
public void DestroyEntity(Entity entity)
{
    WithWriteLock(() =>
    {
        if (!_archetypeManager.IsEntityValid(entity)) return;

        // ★ 新增：在销毁前触发事件，通知所有监听者
        // 此时 Entity 仍然有效，监听者可以安全地访问其 Component
        EntityDestroying?.Invoke(entity);

        _archetypeManager.DestroyEntity(entity);
        EntityDestroyed?.Invoke(entity);
    });
}
```

**关键设计决策：** 事件在写锁内触发。这意味着：
- 事件处理器执行时，其他线程无法同时修改 Entity 状态
- 事件处理器不应长时间阻塞（写锁持有时间增加）
- 事件处理器不应尝试获取读锁（会导致死锁）

### 步骤 2：`ControlCreateSystem` 监听 `EntityDestroying` 事件

**文件：** `CsharpPrj/Operation/FrontEndDriven/ControlRender/Creation/Systems/ControlCreateSystem.cs`

#### 2.1 修改 `Update()` 方法

在遍历 `sortedEntities` 之前订阅事件，遍历结束后取消订阅：

```csharp
public void Update()
{
    // 查询所有有 ControlTypeComponent 但未创建的 Entity
    var entities = _entityManager.GetEntities<ControlTypeComponent, ControlStateComponent>()
        .Where(e => !_entityManager.GetComponent<ControlStateComponent>(e).IsCreated)
        .ToList();

    // 拓扑排序，保证父 Entity 先于子 Entity
    var sortedEntities = TopologicalSort(entities);

    // ★ 新增：使用 HashSet 跟踪被销毁的 Entity
    //   通过 EntityDestroying 事件实时跟踪，避免修改 sortedEntities 列表
    var destroyedEntities = new HashSet<Entity>();
    void OnEntityDestroying(Entity e) => destroyedEntities.Add(e);
    _entityManager.EntityDestroying += OnEntityDestroying;

    try
    {
        // ============================================================
        // 阶段 1：创建所有控件并注册到 ControlPool
        // ============================================================
        var created = new List<(Entity entity, System.Windows.Forms.Control control)>();
        foreach (var entity in sortedEntities)
        {
            // ★ 新增：跳过已被 RemoveEntityFromTree 销毁的 Entity
            if (destroyedEntities.Contains(entity))
                continue;

            var typeComp = _entityManager.GetComponent<ControlTypeComponent>(entity);

            // 处理 SplitterPanel 类型
            if (string.Equals(typeComp.Type, "splitterpanel", StringComparison.OrdinalIgnoreCase))
            {
                var panelControl = CreateSplitterPanelControl(entity);
                if (panelControl != null)
                {
                    created.Add((entity, panelControl));
                }
                else
                {
                    RemoveEntityFromTree(entity);
                    System.Diagnostics.Debug.WriteLine(
                        $"[ControlCreateSystem] SplitterPanel 创建失败，已从 Entity 树移除: Entity={entity}, Name={typeComp.Name}");
                }
                continue;
            }

            var control = _strategy.CreateControl(typeComp.Type);
            if (control == null)
            {
                RemoveEntityFromTree(entity);
                System.Diagnostics.Debug.WriteLine(
                    $"[ControlCreateSystem] 控件创建失败，已从 Entity 树移除: Entity={entity}, Type={typeComp.Type}, Name={typeComp.Name}");
                continue;
            }

            control.Name = typeComp.Name;

            // 注册三向映射到 ControlPool
            _controlPool.Register(entity, typeComp.Name, control);
            created.Add((entity, control));
        }

        // ============================================================
        // 阶段 2：建立父子关系（此时所有控件已在 ControlPool 中）
        // ============================================================
        foreach (var (entity, control) in created)
        {
            // ★ 新增：跳过已被销毁的 Entity
            if (destroyedEntities.Contains(entity))
                continue;

            // 跳过 SplitterPanel，其父子关系由 SplitContainer 自身管理
            if (_entityManager.TryGetComponent<ControlTypeComponent>(entity, out var typeComp) &&
                string.Equals(typeComp.Type, "splitterpanel", StringComparison.OrdinalIgnoreCase))
            {
                var panelState = _entityManager.GetComponent<ControlStateComponent>(entity);
                panelState.IsCreated = true;
                panelState.LastUpdated = DateTime.UtcNow;
                _entityManager.SetComponent(entity, panelState);
                continue;
            }

            // 查找父控件（拓扑排序保证父控件一定已在 ControlPool 中）
            var parent = _strategy.FindParent(entity);

            if (parent != null)
            {
                parent.Controls.Add(control);
            }
            else
            {
                System.Diagnostics.Debug.WriteLine(
                    $"[ControlCreateSystem] 未找到父控件: Entity={entity}, Control={control.Name}");
            }

            // 标记为已创建
            var state = _entityManager.GetComponent<ControlStateComponent>(entity);
            state.IsCreated = true;
            state.LastUpdated = DateTime.UtcNow;
            _entityManager.SetComponent(entity, state);
        }
    }
    finally
    {
        // ★ 新增：确保事件被取消订阅，防止内存泄漏
        _entityManager.EntityDestroying -= OnEntityDestroying;
    }
}
```

**设计要点：**
- 使用 `HashSet<Entity>` 而非修改 `sortedEntities` 列表，避免遍历时修改集合
- 使用 `try/finally` 确保事件被取消订阅，防止内存泄漏
- 使用局部函数 `void OnEntityDestroying(Entity e)` 而非 lambda，避免闭包捕获问题

### 步骤 3：`ControlPool` 监听 `EntityDestroying` 事件（可选增强）

**文件：** `CsharpPrj/BasicMethod/ECS/Bridge/ControlPool.cs`

当前 `RemoveEntityFromTreeInternal` 手动调用 `_controlPool.Unregister(entity)`。如果其他代码路径也销毁 Entity 但忘记调用 `Unregister`，会导致 ControlPool 中的悬挂引用。

让 `ControlPool` 监听 `EntityDestroying` 事件自动清理：

```csharp
public class ControlPool : IDisposable
{
    private readonly EntityManager _entityManager;
    private bool _disposed;

    public ControlPool(EntityManager entityManager)
    {
        _entityManager = entityManager ?? throw new ArgumentNullException(nameof(entityManager));

        // ★ 新增：监听 Entity 销毁事件，自动清理
        _entityManager.EntityDestroying += OnEntityDestroying;
    }

    public void Dispose()
    {
        if (!_disposed)
        {
            // ★ 新增：取消订阅事件
            _entityManager.EntityDestroying -= OnEntityDestroying;
            _disposed = true;
        }
    }

    // ★ 新增：Entity 销毁时自动从 ControlPool 注销
    private void OnEntityDestroying(Entity entity)
    {
        Unregister(entity);
    }

    // ... 其余代码不变
}
```

**注意：** 此步骤是可选增强。如果实施，需要确保：
1. `ControlPool` 的构造函数接收 `EntityManager` 参数（当前已接收）
2. `ControlPool` 实现 `IDisposable` 接口（当前已实现）
3. `RemoveEntityFromTreeInternal` 中的手动 `Unregister` 调用可以保留（重复调用无害），也可以移除

## 3. 影响范围

| 文件 | 改动类型 | 风险 | 说明 |
|------|---------|------|------|
| `CsharpPrj/BasicMethod/ECS/ECSFrame.cs` | 新增事件 + 修改 `DestroyEntity` | 低 | 仅新增事件触发，不影响现有逻辑 |
| `CsharpPrj/Operation/FrontEndDriven/ControlRender/Creation/Systems/ControlCreateSystem.cs` | 订阅事件 + 遍历时检查 | 低 | 仅新增跳过逻辑，不影响正常流程 |
| `CsharpPrj/BasicMethod/ECS/Bridge/ControlPool.cs` | 可选 — 订阅事件自动清理 | 低 | 仅新增自动清理，不影响手动清理 |

### 不受影响的组件

以下组件通过 `GetEntities` 查询 Entity，而 `GetEntities` 不会返回已销毁的 Entity（`ArchetypeManager` 中已删除），因此天然安全：

- `LayoutSystem` — 通过 `GetEntities` 查询
- `StyleSystem` — 通过 `GetEntities` 查询
- `EventBindingSystem` — 通过 `GetEntities` 查询
- `ControlSyncSystem` — 通过 `GetEntities` 查询
- `ControlValueSyncSystem` — 通过 `GetEntities` 查询

## 4. 测试验证

### 4.1 单元测试

在 `EntityManagerTests.cs` 中新增测试：

```csharp
[TestMethod]
public void DestroyEntity_ShouldTriggerEntityDestroyingEvent()
{
    var entity = _entityManager.CreateEntity();
    bool eventTriggered = false;
    Entity destroyedEntity = default;

    _entityManager.EntityDestroying += (e) =>
    {
        eventTriggered = true;
        destroyedEntity = e;
        // 验证事件触发时 Entity 仍然有效
        Assert.IsTrue(_entityManager.IsEntityValid(e));
    };

    _entityManager.DestroyEntity(entity);

    Assert.IsTrue(eventTriggered);
    Assert.AreEqual(entity, destroyedEntity);
    Assert.IsFalse(_entityManager.IsEntityValid(entity));
}

[TestMethod]
public void DestroyEntity_EntityDestroyingEvent_ShouldFireBeforeEntityDestroyedEvent()
{
    var entity = _entityManager.CreateEntity();
    var firingOrder = new List<string>();

    _entityManager.EntityDestroying += (e) => firingOrder.Add("Destroying");
    _entityManager.EntityDestroyed += (e) => firingOrder.Add("Destroyed");

    _entityManager.DestroyEntity(entity);

    Assert.AreEqual(2, firingOrder.Count);
    Assert.AreEqual("Destroying", firingOrder[0]);
    Assert.AreEqual("Destroyed", firingOrder[1]);
}
```

## 5. 回滚方案

如果实施后出现问题，可以：

1. **回退 `ECSFrame.cs`**：删除 `EntityDestroying` 事件声明，恢复 `DestroyEntity` 方法
2. **回退 `ControlCreateSystem.cs`**：删除 `destroyedEntities` 相关代码
3. **回退 `ControlPool.cs`**：删除 `OnEntityDestroying` 订阅

回滚后，短期修复（`IsEntityValid` 检查）仍然有效，不会出现回归。

## 6. 后续优化方向

1. **Entity 快照安全包装器**：创建一个 `EntitySnapshot` 类，在遍历期间自动跟踪 Entity 有效性
2. **Entity 引用计数**：引入引用计数机制，Entity 被引用时不能销毁
3. **Entity 状态查询缓存**：在 `EntityManager` 层缓存 `IsEntityValid` 结果，减少锁竞争
