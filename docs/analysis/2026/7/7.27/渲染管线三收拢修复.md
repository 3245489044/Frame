# 渲染管线三收拢修复 — 2026-07-26

## 背景

CSG 三收拢点重构后，发现三个数据断裂问题：

| 问题 | 表现 | 严重度 |
|------|------|--------|
| **Text 不渲染** | UI 控件没有文字 | 高 |
| **边框不渲染** | 控件无边框（BorderStyle=None） | 中 |
| **事件不绑定** | 按钮点击无响应 | 高 |

---

## 问题一：Text 不渲染

### 根因

`ControlFactory.CreateFromConfig`（ECS 项目层）初始化了 `ControlTypeComponent { Type, Name, Text, Enabled }`，但 `ControlInfoComponent { Name, Text, Enabled, Visible }`（FrontEndDriven 项目层）从未被初始化。CSG 收集中唯一读取 `ControlInfoComponent`，导致 Text 始终为空字符串。

### 数据流

```
ControlFactory.CreateFromConfig
  └→ 写入 ControlTypeComponent.Text ✅
  └→ 不写入 ControlInfoComponent ❌

CsgEntryPoint.CollectControlDescriptor
  └→ TryGetComponent<ControlInfoComponent> → false → Text="" ❌

WinFormApplier.ApplyPropertiesFromDict
  └→ control.Text = "" → 控件无文字
```

### 修复

**`ConfigDrivenControlFactory.cs`** — 在 `FrontEndDriven` 项目层补齐 `ControlInfoComponent`：

```csharp
private void AddControlInfoComponent(Entity entity, string name, string text, bool enabled)
{
    _entityManager.AddComponent(entity, new ControlInfoComponent
    {
        Name = name ?? string.Empty,
        Text = text ?? string.Empty,
        Enabled = enabled,
        Visible = true
    });
}
```

在三个 Entity 创建入口的 `CreateFromConfig` 调用后立即调用：
- `CreateRootEntity`（根容器）
- `ConvertControl`（普通控件）
- `CreateSplitterPanelEntity`（Splitter 面板）

**`Ports.cs` (CsgEntryPoint)** — Fail Fast：

```csharp
if (!_entityManager.TryGetComponent<ControlInfoComponent>(entity, out var infoComp))
    throw new InvalidOperationException(
        $"Entity {entity} 缺少 ControlInfoComponent。CSG 收集时不支持回退，必须一次通过。");
```

### 改动文件

| 文件 | 改动 |
|------|------|
| `ConfigDrivenControlFactory.cs` | 新增 `AddControlInfoComponent` 方法 + 3 处调用 |
| `Ports.cs` | `CollectControlDescriptor` 和 `CollectAllInOnePass` 中移除 `hasInfo` 回退，改为抛出异常 |

## 问题二：边框不渲染

### 根因

`MergedStyleComponent.BorderColor/BorderWidth` 在 `CollectStyleProps` 中被收集到属性字典，但下游 `PropertyApplier.ApplyProperties` 中没有边框处理逻辑，`IWinFormsControlAdapter` 也没有 `SetBorderStyle` 方法。

### 数据流

```
MergedStyleComponent.BorderColor/BorderWidth
  └→ CSG CollectStyleProps → mergedProps (端口 ✅，但此前缺失)

PropertyApplier.ApplyProperties
  └→ 只处理布局/Text/字体/颜色/Splitter ❌ 缺少边框

WinFormsControlAdapter
  └→ 没有 SetBorderStyle 方法 ❌
```

### 修复

**新增协议常量** `UIProtocol.cs`：

```csharp
public const string Prop_BorderWidth = "borderWidth";
public const string Prop_BorderColor = "borderColor";
```

**新增接口方法** `IWinFormsControlAdapter.cs`：

```csharp
void SetBorderStyle(object control, int borderWidth, string borderColor);
```

**新增实现** `WinFormsControlAdapter.cs`：

```csharp
public void SetBorderStyle(object control, int borderWidth, string borderColor)
{
    // WinForms 使用 BorderStyle 枚举
    ctrl.BorderStyle = borderWidth > 0 ? BorderStyle.FixedSingle : BorderStyle.None;
}
```

**应用端** `PropertyApplier.cs`：

```csharp
if (properties.TryGetValue(UIProtocol.Prop_BorderWidth, out var bw) && bw != null
    && properties.TryGetValue(UIProtocol.Prop_BorderColor, out var bclr) && bclr != null
    && int.TryParse(bw.ToString(), out var borderWidth))
{
    adapter.SetBorderStyle(control, borderWidth, bclr.ToString()!);
}
```

**CSG 收集补齐**：

- `CollectStyleProps`（CanonicalForm 路径）写入 `mergedProps`
- `CollectControlDescriptor`（Snapshot 路径）写入 `ControlDescriptor`
- `BuildPropertyDict`（WinFormApplier）读取 `ControlDescriptor`

### 改动文件

| 文件 | 改动 |
|------|------|
| `UIProtocol.cs` | 新增 `Prop_BorderWidth`/`Prop_BorderColor` |
| `WinFormSnapshot.cs` | `ControlDescriptor` 新增 `BorderWidth`/`BorderColor` |
| `Ports.cs` | `CollectStyleProps` + `CollectControlDescriptor` 收集边框属性 |
| `WinFormApplier.cs` | `BuildPropertyDict` + `LogSnapshot` 包含边框 |
| `PropertyApplier.cs` | `ApplyProperties` 新增边框处理 |
| `IWinFormsControlAdapter.cs` | 新增 `SetBorderStyle` |
| `WinFormsControlAdapter.cs` | 实现 `SetBorderStyle` |

## 问题三：事件不绑定（待重构）

### 根因

当前架构中事件绑定走独立路径：

```
EventBindingsComponent
  └→ EventBindingSystem.Update()         [管线独立阶段]
  └→ WinFormsOutputPort.BindEvent()      [回调委托]
  └→ _eventBindHandler?.Invoke(...)      [始终 null，从未被注入]
```

`EventBindHandler` 定义在 `EcsRenderPipeline` 上但从未被外部赋值，`EventBindingSystem.Update()` 遍历 `PendingEventBindingComponent` 时调用 `WinFormsOutputPort.BindEvent()`，但内部 `_eventBindHandler` 始终为 null，绑定静默跳过。

### 重构方案：事件绑定并入 Entity 属性传递

当前三收拢后的数据流：

```
ECS Component → CSG Collect → ControlDescriptor → WinFormApplier.Apply
                                                    ├─ 布局 SetBounds
                                                    ├─ 文字 SetText
                                                    ├─ 颜色 SetBackColor
                                                    ├─ 边框 SetBorderStyle
                                                    └─ 事件 BindEvents ← 收拢此处
```

事件绑定和其他属性一样，作为 Entity 属性在 CSG 中收集，由 `WinFormApplier` 统一写入。

### 具体步骤

#### 步骤①：ControlDescriptor 添加事件绑定字段

```csharp
public sealed class ControlDescriptor
{
    // ... 现有字段
    
    // ── 事件绑定 ──
    public List<EventBindingDescriptor>? EventBindings { get; set; }
}

public sealed class EventBindingDescriptor
{
    public string EventName { get; set; } = "";
    public string FunctionName { get; set; } = "";
}
```

#### 步骤②：CSG 收集时从 EventBindingsComponent 填入

```csharp
// CsgEntryPoint.CollectControlDescriptor
if (_entityManager.TryGetComponent<EventBindingsComponent>(entity, out var bindComp)
    && bindComp.Bindings is { Count: > 0 })
{
    desc.EventBindings = bindComp.Bindings
        .Select(b => new EventBindingDescriptor
        {
            EventName = b.EventName,
            FunctionName = b.FunctionName
        })
        .ToList();
}
```

#### 步骤③：WinFormApplier 构造函数注入事件绑定能力

`WinFormApplier` 不需要直接依赖 `EventBindingOrchestrator`，而是通过一个轻量接口委托：

```csharp
public interface IWinFormEventBinder
{
    void BindEvent(object control, string eventName, string functionName);
}
```

`WinFormApplier` 构造函数接受 `IWinFormEventBinder?`，Apply 时在创建新控件后调用：

```csharp
private void ApplyControls(List<ControlDescriptor> controls)
{
    foreach (var desc in controls)
    {
        // ... 现有逻辑：查找/创建控件
        ApplyPropertiesFromDict(control, props);
        
        // ★ 新控件且有事件绑定时触发
        if (desc.EventBindings != null && existingControl == null && _eventBinder != null)
        {
            foreach (var binding in desc.EventBindings)
                _eventBinder.BindEvent(control, binding.EventName, binding.FunctionName);
        }
    }
}
```

#### 步骤④：FileDriven 层提供 IWinFormEventBinder 实现

在 `FileDrivenApplicationService` 或 `FileDrivenGuiInitializerOrchestrator` 中：

```csharp
public class FileDrivenEventBinder : IWinFormEventBinder
{
    private readonly EventBindingOrchestrator _orchestrator;
    
    public void BindEvent(object control, string eventName, string functionName)
    {
        _orchestrator.LoadAndBindDeclarations(new[]
        {
            new EventBindingDeclaration
            {
                ControlName = (control as Control)?.Name ?? "",
                EventName = eventName,
                FunctionName = functionName
            }
        });
    }
}
```

#### 步骤⑤：消除 EventBindingSystem 管线阶段

`EcsRenderPipeline.ExecuteRenderStage` 中移除事件绑定阶段（`_eventBindingSystem?.Update()`），`EventBindingSystem` 类不再需要。

仅保留 `PendingEventBindingComponent` 和 `EventsBoundComponent` 用于 CSG 收集阶段的事件绑定信息传递，管线不再有独立的"事件绑定阶段"。

### 收拢前后对比

```diff
- 管线阶段 4：EventBindingSystem.Update()
-   └→ WinFormsOutputPort.BindEvent() → _eventBindHandler?.Invoke()
-   └→ EventBindHandler 始终 null，事件静默跳过 ❌

+ CSG Apply 阶段：WinFormApplier.Apply()
+   └→ ApplyPropertiesFromDict(control, props)     // 字体、颜色、边框…
+   └→ _eventBinder.BindEvent(control, ...)         // 事件绑定 ✅
```

|------|------|

## 总结

| 问题 | 原因 | 修复策略 | 数据面统一 |
|------|------|---------|-----------|
| Text 不渲染 | `ControlInfoComponent` 未初始化 | `ConfigDrivenControlFactory` 补齐初始化 | ✅ |
| 边框不渲染 | `PropertyApplier` 无边框处理 | 新增 `SetBorderStyle` 全链路 | ✅ |
| 事件不绑定 | `EventBindHandler` 未注入 | 收拢到 `WinFormApplier.Apply` | ✅（本次重构） |
