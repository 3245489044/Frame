# 事件绑定「三聚拢点」重构设计

> **目标**：消除委托挂载与统计分离导致的 boundCount=0 矛盾，收敛分散的声明构建与函数执行路径，实现「统计恒等于真实委托」的可靠性保证。
> **参考**：项目已有「三聚拢点」模式（`EventBindingSystem` 注释的 JsonEventBindingConverter 聚拢点①②③）
> **层级**：L2-L3（策略+流程）
> **关联**：`[CR: axioms.md]` | `[CR: engine.md §四]` | `[CR: rules.md]`

## 一、现状缺陷分析

### 1.1 整体运行路径（当前）

```
① 配置加载 (MainLayout.json: events.click + buildEvents)
② ECS Entity 化 (ControlFactory -> EventBindingsComponent, 仅数据)
③ 渲染阶段 (ExecuteRenderStage -> ApplySnapshot 创建控件 -> _eventBindingSystem.Update)
④ EventBindingSystem.Update -> 构建 EventBindingDeclaration(6) -> LoadAndBindDeclarations
⑤ Orchestrator.LoadAndBindDeclarations -> 逐条管线绑定 -> BindingResult.BoundCount
⑥ 函数执行: btn.PerformClick -> handler -> ExecuteFunctionDelegate -> FunctionExecutionSystem
```

### 1.2 严重缺陷

| # | 缺陷 | 后果 |
|---|------|------|
| **D1** | 委托挂载(`TryBindEvent`)与统计(`RecordBoundControl`)分离，依赖 `eventBinder?` 回调 | `boundCount=0` 而委托已挂 -> 统计失真 |
| **D2** | `DeclarationBindingStep` 依赖 5 个隐式注入(EventBus/Resolver/Binder/Delegate)，任一 null 静默失败 | 难以排查，违背 Fail-Fast |
| **D3** | 声明构建途径分散(`EventBindingSystem` / `LoadAndBindFromConfig`) | 重复 + 数据中转丢失风险 |
| **D4** | 函数执行双路径(点击异步 Idle 轮询 vs exec 同步直调) | 语义不一致，测试难统一 |
| **D5** | CSG `EventBindingDescriptor` 收集了但无人消费(仅元数据) | 死数据 + 混淆 |

### 1.3 缺陷证据（2026-07-31 运行记录）

```
[INFO] [FrontEndDriven] EventBindingSystem: 委托 6 个声明到 Orchestrator, 目标窗体=MainForm
[INFO] [FrontEndDriven] EventBindingSystem: 编排器执行结果 — boundCount=0, skippedCount=0, errorCount=0
[断言] assert event-bound helpButton -> PASS（实际委托存在，ShowHelp 弹窗成功）
```

## 二、重构核心：三聚拢点

### 聚拢点①：声明构建收敛（EventBindingDeclarationFactory）

**新建** `Share/EventBindingOrchestrator/Binding/EventBindingDeclarationFactory.cs`

统一从以下来源构建标准 `EventBindingDeclaration` 列表：
- `EventBindingsComponent`（ECS 路径）
- `UIConfiguration`（LoadAndBindFromConfig 路径）
- JSON 配置

**消除**：`EventBindingSystem.Update` 的 inline 构建逻辑 + `LoadAndBindFromConfig` 的重复构建。

### 聚拢点②：执行 + 统计合一（BindSingleEvent 内联记录）

**修改** `EventBindingPipelineFactory.DeclarationBindingStep`

```
BindSingleEvent 成功 -> 立即 ctx.AddBoundControl(...)
  （不再依赖 eventBinder?.RecordBoundControl 回调）
```

**核心变革**：`BoundControls` 记录与委托挂载**同一函数体完成**，统计恒等于真实委托。

### 聚拢点③：绑定状态可验证（BindingVerifier）

**新建** `Share/EventBindingOrchestrator/Binding/BindingVerifier.cs`

以**实际委托为准**核算，不受统计链路影响：
```csharp
public static int VerifyBound(Control target, string eventName)
    // 反射检查 EventClick 委托是否有订阅者（同 ClickSystem.HasClickSubscription）
```

`EventBindingSystem.Update` 绑定后调用，输出 `boundCount = VerifyBound(...)`——统计=真实。

## 三、重构后的路径

```
EventBindingSystem.Update()
  ├--> EventBindingDeclarationFactory.Build(EventBindingsComponent)     聚拢点①
  ├--> Orchestrator.LoadAndBindDeclarations(decls, form)
  │      └--> 每条:
  │            EventBindingExecutor.BindSingleEvent(...)                 聚拢点②
  │               ├─ TryBindToControl -> btn.Click += handler (真委托)
  │               └─ ctx.AddBoundControl -> 同一处记录 (统计=真实)
  └--> boundCount = BindingVerifier.VerifyBound(...)                    聚拢点③
```

**收益**：
- 统计与委托始终一致（聚拢点②合流）
- 隐式依赖 Fail-Fast（聚拢点②统一校验，缺依赖即抛）
- 测试可依赖 boundCount=真实委托数（聚拢点③可验证）
- 函数执行路径统一

## 七、★ 2026-07-31 框架级重构：聚拢点控制输入/输出

> **核心思想**：在既有三聚拢点基础上，进一步将「输入路径」与「输出路径」聚拢为门控（Gate），
> 使绑定链路呈现「输入聚拢 → 执行统一 → 输出聚拢」的框架级架构。

### 7.1 输入聚拢点 — `EventBindingInputGate`（新建）

**文件**：`Share/EventBindingOrchestrator/Gates/EventBindingInputGate.cs`

统一三种输入源（ECS Component / UIConfiguration / Declaration 列表）的归一化与校验：

```
EnterFromEcs(component, controlName)      → EventBindingDeclarationFactory.Build(component, controlName)
EnterFromConfig(config)                   → EventBindingDeclarationFactory.Build(config)
EnterFromDeclarations(declarations)       → 直接校验 + 过滤无效声明
                        ↓
              FinalizeInput（统一校验：SourceName/EventType/FunctionName 非空）
                        ↓
              EventBindingDiagnosticContext.Record("inputgate.enter", ...)  // 输入审计
```

**消除**：`EventBindingSystem.Update` 手写声明构建 + 输入格式二义性。

### 7.2 输出聚拢点 — `EventBindingOutputGate`（新建）

**文件**：`Share/EventBindingOrchestrator/Gates/EventBindingOutputGate.cs`

统一四种输出（统计 / 快照 / 诊断 / 状态更新）的载体：

```
BuildFromRaw(boundControls, skippedControls, snapshot?, verifiedBoundCount?)
  → EventBindingOutput { Result, Snapshot, VerifiedBoundCount, TotalDeclarationCount }
```

**架构约束**：反射验证（`BindingVerifier`）由调用方（FrontEndDriven 层）执行后传入 `verifiedBoundCount`，
输出聚拢点只做数据聚合，**消除 Share 对 FrontEndDriven 的跨层依赖**。

### 7.3 绑定与解析解耦 — `EventBindingSystem.Update`（重构）

**文件**：`FrontEndDriven/ControlInteraction/EventBinding/EventBindingSystem.cs`

**架构缺陷修复**：此前 `IFunctionHub.Resolve()` 预验证失败会 `return`（整个绑定被阻断，委托从未挂载）。

**重构后**：
```
预验证：函数无法解析 → 仅记录 warning（LogUnresolvedFunctionsWarning）
绑定：委托照常挂载（不依赖函数是否可解析）
执行：触发时 CreateEventHandler 内检查可解析性
```

### 7.4 状态机完整化 — `EventBindingStateComponent`（扩展）

**文件**：`FrontEndDriven/ControlRender/Components/PipelineStateComponents.cs`

```
状态：Pending → Bound | Failed（新增 Failed）
附加：RetryCount（重试计数）+ ErrorMessage（失败原因）
```

### 7.5 重构后的绑定链路

```
EventBindingSystem.Update()
  ├─ 输入聚拢点：EventBindingInputGate.EnterFromEcs()     聚拢点输入
  │    └─ LogUnresolvedFunctionsWarning（不再阻断）
  ├─ 执行：EventBindingOrchestrator.LoadAndBindDeclarations()  聚拢点②
  │    └─ BindingVerifier 反射核对真实委托数                聚拢点③
  └─ 输出聚拢点：EventBindingOutputGate.BuildFromRaw()      聚拢点输出
       ├─ BindingResult（统计）
       ├─ EventBindingOutput（统一载体）
       └─ DiagnosticEvent（结构化日志）
```
