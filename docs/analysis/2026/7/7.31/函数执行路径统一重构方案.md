# 函数执行路径统一重构方案

> **日期**：2026-07-29
> **范围**：跨项目重构 — Share、FrontEndDriven、CommandFramework、FileDriven.Business、FileDriven.Execution
> **目标**：消除 5 条分散的执行路径，统一为单一工作流基底路径
> 
> **状态**：Step 0-3 已完成（全部路径已统一），Step 4 待清理

---

## 一、当前架构问题

### 1.1 5 条独立执行路径

```
路径1: UI 按钮点击
  EventBindingOrchestrator → IFunctionResolver.ResolveDelegate → DynamicInvoke

路径2: UI Execute 按钮
  UIToolbox.Execute → 反射 → AppService.ExecuteCommandAsync
    → CommandExecutionService → CommandInputPort(entityManager)
      → ECS 管线

路径3: CLI 单命令（commandTextBox）
  同路径2，经过 CommandInputPort

路径4: CLI 脚本（ExecutionCenter）
  ExecutionCenter Handler → FileDrivenPipelineRunner
    → CommandInputPort → ECS 管线

路径5: 工作流定义执行
  WorkflowMethodExecutionService → CentralPipeline（三阶段）
    → IStepExecutor → IFunctionExecutor → DynamicInvoke
```

### 1.2 核心问题

1. **同一条函数（如 LoadConfig）有 3 条不同的执行链**，调试和维护困难
2. `PipelineFunctions` 下的 9 个 `IPipelineStage` 与 `WorkflowMethodExecutionService` 功能完全重复（都从 `ITrConfigRegistry` 查找并调用）
3. `WorkflowMethodExecutionService` 已有自动包装逻辑（单函数自动包装为工作流），但 UI 按钮和 CLI 命令绕过了它
4. ECS 层的 `FunctionExecutionSystem` 使用 `Modules.Pipeline.Pipeline` 而非工作流引擎，存在第二个管线执行框架

## 二、目标架构

```
                              ┌──────────────────────────────────────┐
                              │      IEventExecutionService          │
                              │   (WorkflowMethodExecutionService)    │
                              │                                      │
                              │   ① 查 _workflows[functionName]     │
                              │   ② 未找到 → 查 ITrConfigRegistry   │
                              │   ③ 找到 → 自动包装为单节点工作流    │
                              │   ④ 注册到 _workflows                │
                              │   ⑤ CentralPipeline 执行            │
                              └──────────────┬───────────────────────┘
                                             │
                                             ▼
                              ┌──────────────────────────────────────┐
                              │      CentralPipeline                 │
                              │  Initialization →                    │
                              │  Execution(IStepExecutor) →          │
                              │  Finalization                        │
                              └──────────────┬───────────────────────┘
                                             │ IStepExecutor.ExecuteStepAsync
                                             ▼
                              ┌──────────────────────────────────────┐
                              │      IFunctionExecutor                │
                              │  → ITrConfigRegistry.Find(name)      │
                              │  → DynamicInvoke                     │
                              └──────────────────────────────────────┘

触发源 → 统一入口：
  UI 按钮   → EventBindingOrchestrator → click handler → IEventExecutionService
  UI Execute→ UIToolbox.Execute        → IEventExecutionService
  CLI 命令  → CommandFramework Pipeline→ IEventExecutionService
  CLI 脚本  → ExecutionCenter → handler→ IEventExecutionService
  ECS 请求  → ExecutionComponent       → FunctionExecutionSystem → IEventExecutionService
```

### 2.1 单一路径流程图

```
[触发源]
    │
    ▼
[IEventExecutionService.ExecuteFunctionAsync(functionName, params)]
    │
    ├── _workflows.TryGetValue(functionName) → 有定义？
    │      ├── 是 → 使用现有 WorkflowDefinition
    │      └── 否 → _registry.Find(functionName) → 找到？
    │              ├── 是 → 自动包装为单节点工作流，注册到_workflows
    │              └── 否 → 抛错：函数未注册
    │
    ▼
[CentralPipeline.CreateSession()]
    │
    ├── Stage: Initialization（初始化上下文）
    ├── Stage: Execution（遍历工作流节点）
    │        └── IStepExecutor.ExecuteStepAsync(stepDef, context)
    │              └── IFunctionExecutor.ExecuteAsync
    │                    └── ITrConfigRegistry.Find(name).DynamicInvoke
    └── Stage: Finalization（清理/日志）
    │
    ▼
[ExecutionResult]
    │
    ├── UI 按钮 → EventBindingOrchestrator 处理结果
    ├── ECS → ExecutionResultComponent → 触发再渲染
    └── CLI → CommandContext.Result
```

## 五、风险与回退

### 5.1 风险矩阵

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| `WorkflowMethodExecutionService` 自动包装逻辑覆盖不全 | 低 | 单元测试覆盖所有注册函数 |

## 六、统一后的架构总结

### 6.1 单一路径

```
任何触发源
  ↓
IEventExecutionService.ExecuteFunctionAsync(functionName, params)
  ↓
WorkflowMethodExecutionService
  ├── 查 _workflows 缓存
  ├── 未命中 → 查 ITrConfigRegistry
  ├── 查到 → 自动包装为单节点工作流，注册到 _workflows
  └── 未查到 → 抛错
  ↓
CentralPipeline
  ├── Stage: Initialization
  ├── Stage: Execution（IStepExecutor → IFunctionExecutor → DynamicInvoke）
  └── Stage: Finalization
  ↓
ExecutionResult → 返回给调用方
```

### 6.2 保留组件

| 组件 | 保留理由 |
|------|---------|
| `CommandFramework Pipeline` | 保留作为命令文本调度器（set/click/non-event 分发），但不直接执行函数 |
| `CommandParser` | 命令文本→结构化对象的解析能力 |
| `INonEventCommandLookup` | 非事件命令注册表 |
| `FunctionExecutionSystem` | ECS 层消费 ExecutionRequestComponent 并触发再渲染 |
| `EventBindingOrchestrator` | 事件绑定完整流程（参数绑定、诊断收集） |
| `FunctionResolver` | IFunctionResolver 实现（bridge 到 ITrConfigRegistry + WorkflowMethodExecutionService） |
| `IStepExecutor` | 工作流节点执行器（中央管线内部使用） |

### 6.3 删除组件

| 组件 | 替代 |
|------|------|
| `PipelineFunctions/*.cs` 9 IPipelineStage | `WorkflowMethodExecutionService` 自动包装为工作流 |
| `Modules.Pipeline.Pipeline` 在 FunctionExecutionSystem 中的使用 | `IEventExecutionService` |

## 七、附录：调用链对照

### 重构前

```
UI LoadConfig 按钮点击
  → EventBindingOrchestrator 绑定
    → IFunctionResolver.ResolveDelegate("LoadConfig")
      → ITrConfigRegistry.Find("LoadConfig")
        → 返回 UIToolbox.LoadConfig 委托
          → DynamicInvoke → 打开文件对话框
```

### 重构后

```
UI LoadConfig 按钮点击
  → EventBindingOrchestrator 绑定
    → IEventExecutionService.ExecuteFunctionAsync("LoadConfig", {})
      → WorkflowMethodExecutionService
        → _workflows["LoadConfig"] 未找到
        → _registry.Find("LoadConfig") 找到 → 自动包装为单节点工作流
        → CentralPipeline.ExecuteAsync(wfContext)
          → Stage: Initialization
          → Stage: Execution
            → IStepExecutor.ExecuteStepAsync(stepDef)
              → IFunctionExecutor.ExecuteAsync("LoadConfig")
                → ITrConfigRegistry.Find("LoadConfig").DynamicInvoke
                  → 打开文件对话框
          → Stage: Finalization
        → 返回 ExecutionResult
      → EventBindingOrchestrator 处理结果
