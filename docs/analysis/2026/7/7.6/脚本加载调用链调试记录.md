## 1. 当前架构（方案C+D实施后）

### 1.1 完整调用链

```
ExecutionPipelineEntry.ExecutePipeline()
  └─ BackEndPipelineRunner.ExecutePipelineSafe()
       └─ FileDrivenPipelineRunner.CreateContext()
            └─ 创建 FileDrivenPipelineContext 实例
       └─ FileDrivenPipelineRunner.CreatePipeline()
            └─ PipelineFactory.CreateFileDrivenPipeline()
                 ├─ CentralPipeline.Register(Initialization, ScriptLoadSkeleton)
                 └─ CentralPipeline.Register(Execution, ForEachSkeleton)
       └─ CentralPipeline.Execute(input, pipelineContext)
            └─ Build() → 组合所有阶段 Pipeline
                 ├─ [Initialization] SkeletonToPipelineAdapter(ScriptLoadSkeleton)
                 │    └─ ScriptLoadSkeleton.ExecuteCore(input, skelCtx)
                 │         ├─ ScriptConverter.ConvertJsonScriptToCommands(scriptPath) → string[]
                 │         └─ input.CommandLines = commands
                 │         └─ input.TotalCommands = commands.Length
                 └─ [Execution] SkeletonToPipelineAdapter(ForEachSkeleton)
                      └─ ForEachSkeleton.ExecuteCore(input, skelCtx)
                           ├─ items = input.CommandLines  // 36条命令
                           └─ for i=0..35:
                                ├─ input.CurrentIndex = i
                                └─ _itemPipeline.Execute(input)  // DelegatePipeline

                                     ├─ ExecuteCommandStage.Process(ctx)
                                     └─ ResultCollectStage.Process(ctx)
```

## 2. 关键代码关系

### 2.1 类型继承关系

```
SkeletonContext (SkeletonFlow)
  └─ PipelineContext (Modules.Pipeline) : IPipelineContext
       └─ 管线执行上下文，含 StageSuccess/StageErrors/Items/CancellationToken

  └─ PipelineBase<TIn, TOut> (Modules.Pipeline) : IPipeline<TIn, TOut>

            └─ BridgeToSkeletonContext(context) → SkeletonContext
            └─ base.Execute(input, skelCtx)
       └─ DelegatePipeline<TIn, TOut> : PipelineBase<TIn, TOut>
            └─ 委托驱动的管线实现

SyncSkeletonBase<TIn, TOut> (SkeletonFlow)
  └─ ScriptLoadSkeleton : SyncSkeletonBase<FileDrivenPipelineContext, FileDrivenPipelineContext>
  └─ ForEachSkeleton<TContext, TItem> : SyncSkeletonBase<TContext, TContext>
       where TContext : class, IBackEndPipelineContext
```

### 2.2 PipelineContext ↔ SkeletonContext 桥接

**Core.cs:237-241** — `PipelineBase.BridgeToSkeletonContext()`:
```csharp
private static SkeletonContext BridgeToSkeletonContext(PipelineContext? pipelineCtx)
{
    if (pipelineCtx == null) return new SkeletonContext();
    return pipelineCtx; // PipelineContext 继承自 SkeletonContext，直接使用

```

**关键点**：`PipelineContext` 继承自 `SkeletonContext`，所以 `SkeletonToPipelineAdapter` 可以无缝桥接。

### 2.3 SkeletonToPipelineAdapter 适配

**SkeletonToPipelineAdapter.cs:51-54**:

**关键点**：`input` 是直接传递的，没有创建副本。所有骨架操作的是同一个 `input` 实例。

**关键点**：调用的是 `IPipeline.Execute(TInput input)` 重载（context=null），不传递 `SkeletonContext`。`PipelineBase.Execute` 在 context=null 时会创建新的 `SkeletonContext` 实例。

## 6. 架构决策记录

### 6.1 PipelineContext 继承 SkeletonContext

**决策**：`Modules.Pipeline.PipelineContext` 继承自 `SkeletonFlow.SkeletonContext`。

**理由**：
- `SkeletonToPipelineAdapter` 需要将 `PipelineContext` 桥接到 `SkeletonContext`
- 继承关系使得桥接零成本（直接向上转型）
- `SkeletonContext` 提供了 `Items`、`CancellationToken`、`ServiceProvider` 等核心功能

**影响**：
- `PipelineBase.Execute()` 在 context=null 时创建新的 `SkeletonContext` 实例
- `ForEachSkeleton` 调用 `_itemPipeline.Execute(input)` 不传递 context，子管线获得新的 `SkeletonContext`

### 6.2 ForEachSkeleton 不传递 SkeletonContext

**决策**：`ForEachSkeleton.ExecuteCore` 调用 `_itemPipeline.Execute(input)` 不传递 `SkeletonContext`。

**理由**：
- 子管线主要依赖 `input`（`FileDrivenPipelineContext`）中的属性（`CommandLines`、`CurrentIndex`）
- `SkeletonContext` 中的 `CancellationToken`、`ServiceProvider`、`Items` 在子管线中可能不需要

**影响**：
- 如果子管线需要 `SkeletonContext` 中的信息，需要修改为传递 `context`
- 当前子管线（`DelegatePipeline`）在 context=null 时创建新的 `SkeletonContext` 实例

## 7. 2026-07-05 调用链整理优化记录

### 7.1 优化概览

| 优先级 | 文件 | 优化内容 | 影响 |
|--------|------|----------|------|
| P0 | `ScriptConverter.cs` | 提取 5 个私有方法，消除两个公共方法之间 ~80% 重复代码 | 从 260 行精简到 ~160 行 |

| P2 | `ResultCollectStage.cs` | 使用 `ctx.RecordCommandResult()` 统一结果收集 | 消除手动操作 |
| B3 | `ScriptConverter.cs` | `EnsurePipelineConfigured()` 失败时添加错误日志 | 提高可调试性 |

### 7.2 ScriptConverter.cs 重构详情

**重构前**：两个公共方法 `ConvertJsonScriptToCommands()` 和 `ConvertJsonScriptToCommandFile()` 几乎完全重复（~80% 重复代码）。

**重构后**：
- `ConvertJsonScriptToCommandFile()` 委托给 `ConvertJsonScriptToCommands()`，然后写临时文件
- 提取 5 个私有辅助方法：
  1. `EnsurePipelineConfigured()` — 确保 JsonPipelineRegistry 已配置
  2. `PreprocessJson(jsonContent)` — JSON 预处理（解析 + FileDrivenAdapter 转换）
  3. `FallbackConvert(jsonContent, result)` — 降级策略
  4. `ConvertToLines(processedJson)` — 命令文本转换 + 按行分割过滤
  5. `LogException(ex)` — 异常日志记录

### 7.3 ScriptLoadSkeleton.cs 重构详情

**重构前**：3 处相同的错误处理模式（设置 `ScriptLoadSuccess=false` + 设置 `ScriptLoadErrorMessage` + 记录日志 + `return input`）。

**重构后**：
- 提取 `SetLoadError(input, reason)` 辅助方法，统一错误处理
- 3 处调用点从 4 行缩减为 1 行

### 7.4 ParseCommandStage.cs 修复详情

**修复前**：当 `CurrentIndex` 无效时，静默回退到 `ctx.CurrentCommand`，可能掩盖索引错误。

**修复后**：在回退路径中添加日志警告，记录 `CurrentIndex`、`CommandLines.Length`、回退命令等信息。

### 7.5 ResultCollectStage.cs 优化详情

**优化前**：手动操作 `ctx.CommandResults.Add(result)` + `ctx.SuccessCount++` / `ctx.FailCount++`。

**优化后**：调用 `ctx.RecordCommandResult(result)`，由上下文统一管理结果收集和计数更新。
