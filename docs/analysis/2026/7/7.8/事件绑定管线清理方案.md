# 事件绑定管线清理方案

> 目标：统一事件绑定入口，消除冗余的 3 条事件绑定路径

## 背景

当前事件绑定存在 **3 条并行路径**，是历史演进过程中多次重构叠加的结果。每次重构都新增了路径但未清理旧路径，导致：

1. 事件绑定行为难以预测（不知道哪条路径实际生效）
2. 调试困难（`boundCount: 0` 的原因可能是路径 A 被跳过、路径 B 未就绪、路径 C 幂等性拦截）
3. 维护成本高（3 条路径都需要维护和兼容）

## 当前 3 条路径

### 路径 1：渲染管线内部事件绑定（旧体系）

| 项目 | 值 |
|------|-----|
| **文件** | `CsharpPrj/Operation/WdUI/UI/WdUI.Container.cs` |
| **类** | `ConfigContainer` |
| **方法** | `RenderConfigAsync`（第 253-360 行） |
| **触发点** | 第 281-282 行：`_orchestrator.RenderFullAsync(this, config, null)` |
| **说明** | `ContainerOrchestrator` 内部使用 `WinFormsRenderPipeline`，渲染 UI 的同时触发事件绑定 |
| **状态** | 旧体系，仍活跃 |

### 路径 2：`ContainerBinderPipeline` 阶段 2a（新管线）

| 项目 | 值 |
|------|-----|
| **文件** | `CsharpPrj/Share/EventBindingOrchestrator/ContainerBinderPipeline.cs` |
| **类** | `ContainerBinderPipeline` |
| **方法** | `BindEventsAsync`（第 288-306 行） |
| **触发点** | 第 114-117 行：`_eventBindingService.BindEventsAsync(config)` |
| **说明** | 使用 `IEventBindingService` 接口，走 `DefaultEventBindingService.BindEvents` |
| **状态** | 无参构造模式下 `_eventBindingService` 为 null → **被跳过** |

### 路径 3：`ContainerBinderPipeline` 阶段 2b（旧管线包装）

| 项目 | 值 |
|------|-----|
| **文件** | `CsharpPrj/Share/EventBindingOrchestrator/ContainerBinderPipeline.cs` |
| **类** | `ContainerBinderPipeline` |
| **方法** | `InvokeRenderPipelineAsync`（第 320-361 行） |
| **触发点** | 第 349-352 行：`renderPipeline.RenderSessionOnly` + `renderPipeline.BindEventsAsync` |
| **说明** | 通过 `WinFormsRenderPipelineAdapter` 包装旧渲染管线 |
| **状态** | 实际执行路径（因为路径 2 被跳过） |

## 调用链全景

```
MainForm.LoadSideContainerAsync(configPath)
  └─ ConfigLoader.LoadSideContainerAsync(sideContainer, configPath, ...)
       └─ sideContainer.LoadConfigAsync(config)
            └─ RenderConfigAsync(config)           ← 路径 1：渲染管线内部绑定
                 └─ _orchestrator.RenderFullAsync
  └─ ExecuteContainerBinderPipelineAsync(config, configPath)
       └─ new ContainerBinderPipeline()            ← 无参构造
            └─ ExecuteAsync(context)
                 ├─ 阶段 2a: BindEventsAsync        ← 路径 2：被跳过（_eventBindingService=null）
                 └─ 阶段 2b: InvokeRenderPipelineAsync ← 路径 3：实际执行
                      └─ renderPipeline.BindEventsAsync(container)
```

## 清理步骤

### Step 1：搜索确认依赖 ✅

搜索以下内容，确认清理范围：

- `EventsBound` 事件的订阅者 — **仅在 `WdUI.Container.cs` 内部使用（子容器传播），无外部订阅者**
- `WinFormsRenderPipelineAdapter` 的引用 — **仅 3 处：自身定义 + WdUI.Container 注释 + IRenderPipeline 注释**
- `_boundTargets` 的引用 — **仅在 `DefaultEventBindingService.cs` 内部使用**
- `RenderFullAsync` 返回值的消费方 — **仅在 `WdUI.Container.cs` 的 `RenderConfigAsync` 中消费**

### Step 2：移除幂等性检测 ✅

**文件：** `CsharpPrj/Operation/BackEndDriven/EventTriggerFramework/DefaultEventBindingService.cs`

已删除：
- `_boundTargets` 字段
- `BindEvents` 方法中的幂等性检查代码块
- `_boundTargets[target] = new WeakReference<UIConfiguration>(config)`
- `UnbindEventsAsync` 中的 `_boundTargets.TryRemove`
- `HasBoundEvents` 中的 `_boundTargets.ContainsKey`
- `ClearAll` 中的 `_boundTargets.Clear()`

### Step 3：移除 `ContainerBinderPipeline` 阶段 2b ✅

**文件：** `CsharpPrj/Share/EventBindingOrchestrator/ContainerBinderPipeline.cs`

已删除：
- `InvokeRenderPipelineAsync` 方法
- `ExecuteAsync` 中对 `InvokeRenderPipelineAsync` 的调用
- 更新了相关注释（`InvokeRenderPipeline` → `BindEventsAsync`）

### Step 4：让 `ContainerBinderPipeline` 阶段 2a 始终可用 ✅

**文件：** `FileDriven/FileDriven.UI/Core/MainForm.cs`

已修改 `ExecuteContainerBinderPipelineAsync`：
- 使用有参构造的 `ContainerBinderPipeline`
- 注入 `_eventBindingService`（即 `DefaultEventBindingService` 实例）

```csharp
// 修改后
var pipeline = new ContainerBinderPipeline(
    logger: NullLogger<ContainerBinderPipeline>.Instance,
    eventBindingService: _eventBindingService,  // 注入 DefaultEventBindingService
    configLoader: null,                          // 不需要
    commandExecutor: null);                      // 通过 context 传入
await pipeline.ExecuteAsync(context);
```

### Step 5：移除 `RenderConfigAsync` 中的事件绑定职责 ✅

**文件：** `CsharpPrj/Operation/WdUI/UI/WdUI.Container.cs`

已修改 `RenderConfigAsync`：
- `_orchestrator.RenderFullAsync` 只负责 UI 渲染
- 事件绑定由外部 `ContainerBinderPipeline` 统一管理
- `eventsBoundSuccess` 始终为 `true`（因为事件绑定已由外部管线负责）
- 更新了注释说明

### Step 6：清理依赖 ✅

- **`WinFormsRenderPipelineAdapter.cs`** — 已删除（无其他调用方）
- **`IRenderPipeline.cs`（EventBindingOrchestrator 层）** — 已删除
- **`IContainerBinderContext.RenderPipeline` 属性** — 已移除
- **`ContainerBinderContext.RenderPipeline` 属性** — 已移除
- **`EventsBound` 事件** — 保留（内部通知机制，不影响外部行为）
- **`UniversalMiddleware/Abstractions.cs` 中的 `IRenderPipeline`** — 保留（通用层接口，与 `ContainerOrchestrator` 配合使用）

## 预期结果

清理后的事件绑定调用链：

```
MainForm.LoadSideContainerAsync(configPath)
  └─ ConfigLoader.LoadSideContainerAsync(sideContainer, configPath, ...)
       └─ sideContainer.LoadConfigAsync(config)
            └─ RenderConfigAsync(config)           ← 只渲染 UI，不绑定事件
  └─ ExecuteContainerBinderPipelineAsync(config, configPath)
       └─ new ContainerBinderPipeline(             ← 有参构造，注入 _eventBindingService
              eventBindingService: _eventBindingService)
            └─ ExecuteAsync(context)
                 └─ 阶段 2a: BindEventsAsync        ← 唯一的事件绑定路径
                      └─ _eventBindingService.BindEventsAsync(config)
                           └─ DefaultEventBindingService.BindEvents(target, config)
```

## 风险与回退

| 风险 | 影响 | 回退方案 |
|------|------|---------|
| `EventsBound` 事件被外部订阅 | 事件绑定状态通知丢失 | 保留 `EventsBound` 事件触发，但移除内部绑定逻辑 |
| `WinFormsRenderPipelineAdapter` 被其他模块引用 | 编译错误 | 保留类定义，标记 `[Obsolete]` |
| `RenderFullAsync` 返回值被依赖 | 事件绑定状态判断错误 | 修改调用方，从 `BindEvents` 返回值获取绑定状态 |
