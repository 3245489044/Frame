| `FindControlByNameReflection` | 4 | ~15 行/份 |

**修复**：提取到 `EventBindingHelper.cs` 静态类，4 个文件统一委托调用。

**涉及文件**：
- `EventBinderTransformer.cs` ✅ 已修复

### 1.2 EventHandlerFactoryTransformer 与 EventBinderTransformer（P1-4）

**问题**：`EventHandlerFactoryTransformer` 是 `EventBinderTransformer` 的配置化副本，两者核心逻辑完全相同（遍历事件 → 创建处理器 → 绑定事件 → 写回结果），区别仅在于 `EventHandlerFactoryTransformer` 使用 `EventBindingFrameworkOptions` 配置超时。

**修复**：将 `EventBindingFrameworkOptions` 集成到 `EventBinderTransformer`，删除 `EventHandlerFactoryTransformer`。

### 1.3 ControlValueWriterTransformer 与 EventBinderTransformer（P1-5）

**问题**：`ControlValueWriterTransformer` 的写回逻辑与 `EventBinderTransformer.CreateEventHandler` 中的写回逻辑完全重复。

**修复**：删除 `ControlValueWriterTransformer`，写回逻辑统一由 `EventBinderTransformer` 和 `EventBindingHelper` 处理。

## 二、冗余逻辑（已修复）

### 2.1 ReentryGuard 反射调用（P0-1）

**问题**：`EventBinderTransformer` 和 `EventHandlerFactoryTransformer` 通过反射调用 `ReentryGuard.Enter()` 和 `ReentryGuard.IsReentering()`，但 `ReentryGuard` 是同一程序集（`Share.EventBindingOrchestrator`）的 `internal` 类，可以直接调用。

**修复**：改为直接调用 `ReentryGuard.Enter()` 和 `ReentryGuard.IsReentering()`。

### 2.2 ProcessControls 递归丢失子控件状态（P0-2）

**问题**：`EventBindingPipelineRunner.ProcessControls` 递归处理子控件时，`ResetCurrent()` 将 `CurrentControlConfig` 设为 `null`，导致子控件的 `ScriptModeGuardTransformer` 和 `BindingMetadataTransformer` 检查失效。

**修复**：`ResetCurrent()` 不再重置 `CurrentControlConfig`，由调用方在递归时重新设置。

## 三、错误逻辑（已修复）

### 3.1 跨线程写回 UI 控件静默失败

**问题**：`EventBinderTransformer.CreateEventHandler` 在 `Task.Run` 中执行函数，结果写回 UI 控件时没有检测跨线程调用。当函数在后台线程执行时，直接设置 `Control.Text` 会抛出 `InvalidOperationException`（跨线程操作异常），但被 `catch (Exception ex)` 捕获后仅记录日志，导致用户看到 UI 没有更新但没有任何错误提示。

**修复**：在 `WriteOutputToControl` 中通过反射检测 `InvokeRequired` 属性，为 `true` 时调用 `BeginInvoke` 封送到 UI 线程执行。

### 3.2 BoundControls 记录缺失

**问题**：`EventBinderTransformer.Transform()` 中绑定事件后没有将结果记录到 `BoundControls`，导致 `boundCount` 始终为 0。

**修复**：在绑定事件后创建 `ControlBindingInfo` 并添加到 `input.BoundControls`。

### 3.3 事件绑定结果不显示在 UI 上

**问题**：`CreateEventHandler` 将函数执行结果写回 `sender`（触发事件的控件），而非 `output` 指定的目标控件。

**修复**：写回 `output` 参数指定的目标控件（如 `resultTextBox`）。

### 3.4 parameterBindings 始终为 null

**问题**：`BuildParametersFromBindings` 从 `Control.Tag` 读取参数绑定信息，但 Share 层的 `BindingMetadataTransformer` 没有写入 `Tag`，导致 `parameterBindings` 始终为 null。

**修复**：`parameterBindings` 和 `output` 通过闭包参数传入，从 `EventBindingContext` 获取。

## 四、设计问题（建议改进）

### 4.1 EventBusFacade 委托模板代码

**问题**：`EventBusFacade` 中 `IEventBusCore` 接口的 11 个方法（第 146-173 行）是纯委托模板代码，每个方法只是简单调用 `_eventBus` 的同名方法。

**建议**：使用 Castle.Core `DispatchProxy` 或 `System.Reflection.DispatchProxy` 创建动态代理类，自动将 `IEventBusCore` 方法委托给 `_eventBus` 实例。可减少约 30 行模板代码。

### 4.2 FrameworkOptions 与 EventBindingFrameworkOptions 职责边界

**分析**：两者职责已经清晰分离：
- `FrameworkOptions`（106 行）：框架级初始化配置，控制事件总线、命令系统、管线等模块的启用/禁用
- `EventBindingFrameworkOptions`（38 行）：事件绑定引擎运行时配置，控制超时、重入守卫、诊断等

**结论**：不需要合并。保持分离是正确的设计。

### 4.3 ParameterBuilderTransformer 与 EventBinderTransformer 职责重叠

**问题**：`ParameterBuilderTransformer` 的 `Transform()` 方法解析参数但不存储结果（仅记录日志），而 `EventBinderTransformer.BuildParametersFromBindings` 在事件触发时重新解析参数。`ParameterBuilderTransformer` 实际上没有产生任何有效输出。

**建议**：考虑将 `ParameterBuilderTransformer` 的解析结果存储到 `EventBindingContext.State` 字典中，供 `EventBinderTransformer` 在事件触发时直接读取，避免重复解析。
