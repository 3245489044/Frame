## 二、根本原因：注册表实例不一致

### 2.1 关键代码路径

**`WorkflowMethodExecutionService.ExecuteFunctionAsync()`** (第 78-80 行):

```csharp
var basicRegistry = WorkFlowMethodUsage.BasicRegistry;
// basicRegistry 指向 RegistryCoordinator.Registry（FunctionRegistry）
if (basicRegistry != null && basicRegistry.TryGetConfig(functionName, out var config))
```

这里**只用于查找**，查找失败后进入回退逻辑。

**第 191 行** — 实际执行时：

```csharp
var nodeExecutor = new NodeExecutor(WorkFlowMethodUsage.Executor);
```

`WorkFlowMethodUsage.Executor` 返回的是 `_functionExecutor`，它在 `Initialize()` 中创建：

```csharp
_functionExecutor = new FunctionExecutor(
    _workflowRegistry,  // ← 这是 IWorkflowRegistry，不是 FunctionRegistry！
    new NullParameterProcessor(),
    typeConverter: new TypeConverterAdapter());
```

### 2.2 两个不同的注册表实例

```
WorkFlowMethodUsage.BasicRegistry
    → RegistryCoordinator.Registry (FunctionRegistry)
    → 函数在此注册（通过 FunctionStorageLifecycle → FunctionStorageRegistry）

WorkFlowMethodUsage.Executor
    → _functionExecutor → _workflowRegistry (IWorkflowRegistry)
    → 函数不在此注册！
```

**`WorkFlowMethodUsage.Executor` 和 `WorkFlowMethodUsage.BasicRegistry` 指向不同的注册表实例！**

### 2.3 函数注册链路

```
FunctionStorageLifecycle.Initialize()
    → FunctionStorageRegistry.Initialize(_registry, _executor)
        → _registry = RegistryCoordinator.Registry (FunctionRegistry)
        → 注册 Add、Subtract、Multiply、Divide 等函数到 RegistryCoordinator.Registry
```

函数注册到了 `RegistryCoordinator.Registry`，但 `WorkFlowMethodUsage.Executor` 内部使用的是 `_workflowRegistry`（`IWorkflowRegistry`），所以执行时找不到这些函数。

### 2.4 日志中的证据

日志中 `Registry lookup` 显示 `RegistryType=Modules.Registry.FunctionRegistry`，说明 `BasicRegistry` 属性确实指向了 `FunctionRegistry`。但 `Registry fallback` 日志显示 `BasicRegistry not found or not contain`，说明该 `FunctionRegistry` 实例中确实没有 `Add` 函数。

**关键线索**：日志中输出了 `RegistryHash`，如果后续能对比 `FunctionStorageRegistry` 注册时使用的 `RegistryCoordinator.Registry` 的哈希值，就能确认是否是同一个实例。

## 四、修复方案

### 方案 A：让 `WorkFlowMethodUsage.Executor` 使用共享的 `RegistryCoordinator.Executor`

修改 `WorkFlowMethodUsage.Initialize()`，让 `_functionExecutor` 使用 `RegistryCoordinator.Registry` 而不是新建的 `_workflowRegistry`：

```csharp
// 修改前
_functionExecutor = new FunctionExecutor(
    _workflowRegistry,
    new NullParameterProcessor(),
    typeConverter: new TypeConverterAdapter());

// 修改后
_functionExecutor = new FunctionExecutor(
    RegistryCoordinator.Registry,  // ← 使用共享的 FunctionRegistry
    new NullParameterProcessor(),
    typeConverter: new TypeConverterAdapter());
```

**优点**：改动最小，只改一行。
**缺点**：`WorkFlowMethodUsage` 仍然维护自己的 `_functionExecutor`，与 `RegistryCoordinator.Executor` 重复。

### 方案 B：`WorkFlowMethodUsage.Executor` 直接委托给 `RegistryCoordinator.Executor`

```csharp
public static FunctionExecutor Executor
{
    get { return RegistryCoordinator.Executor; }
}
```

**优点**：消除重复实例，确保始终使用同一个执行器。
**缺点**：需要确保 `RegistryCoordinator` 在 `WorkFlowMethodUsage` 之前初始化。

### 方案 C：`NodeExecutor` 构造函数接收 `IFunctionRegistry` 而非 `FunctionExecutor`

修改 `NodeExecutor` 的构造函数，让它直接接收 `IFunctionRegistry`，而不是 `FunctionExecutor`。这样调用方可以传入 `RegistryCoordinator.Registry`。

**优点**：职责更清晰，`NodeExecutor` 自己管理 `FunctionExecutor` 的创建。
**缺点**：改动较大，涉及多个调用方。

2. 与现有架构兼容

## 七、补充修复：RegistryCoordinator 重构

### 7.1 问题发现

在实施方案 A 后，编译通过（0 警告 0 错误），但运行程序后日志显示：

```
[WARNING] [WorkflowMethodExecution] Registry fallback: Add (Reason=BasicRegistry not found or not contain)
```

`BasicRegistry` 仍然找不到 `Add` 函数，说明 `RegistryCoordinator.Registry` 返回的实例是空的（`RegisteredCount=0`）。

### 7.2 根因分析

`FunctionStorageLifecycle` 持有自己的 `_registry` 字段（`Modules.Registry.FunctionRegistry`），而 `WorkFlowMethodUsage.BasicRegistry` 通过 `RegistryCoordinator.Registry` 获取注册表。虽然 `FunctionStorageLifecycle.Initialize()` 调用了 `FunctionStorageRegistry.Initialize(_registry)` 把 `_registry` 同步到 `RegistryCoordinator`，但存在**类型转换问题**：

1. `FunctionStorageLifecycle._registry` 是 `Modules.Registry.FunctionRegistry` 类型
2. `FunctionStorageRegistry.Initialize(ITrConfigRegistry registry)` 接收 `ITrConfigRegistry` 参数
3. `RegistryCoordinator.Initialize(ITrConfigRegistry registry)` → `SingletonCoordinator<ITrConfigRegistry>.Set(registry)`
4. `FunctionStorageRegistry.Registry` getter: `(IFunctionRegistry)Share.Registry.RegistryCoordinator.Registry`

**关键问题**：`SingletonCoordinator<ITrConfigRegistry>` 的泛型参数是 `ITrConfigRegistry`（接口）。当 `Instance` 在 `Set()` 之前被访问时，`Activator.CreateInstance<ITrConfigRegistry>()` 会抛出 `MissingMethodException`（接口不能实例化）。但日志中没有异常，说明 `Set()` 先被调用了。

**但日志显示 `Count=0`**，说明 `Instance` 返回的实例是空的。这意味着 `Set()` 注入的 `_registry` 实例在 `RegisterAll()` 之前被 `Set()` 了，但 `Instance` 返回的不是同一个实例。

**最可能的根因**：`SingletonCoordinator<ITrConfigRegistry>` 的 `Instance` getter 中，`_isSet` 的 `volatile` 读取和 `lock` 之间存在竞态条件。虽然 `volatile` 保证了可见性，但 `Instance` 的第一次检查 `if (_isSet)` 在 `lock` 之外，如果 `Set()` 还没执行完（还在 `lock` 块内），`_isSet` 可能还是 `false`，`Instance` 会进入 `lock` 块并尝试 `Activator.CreateInstance<ITrConfigRegistry>()`。

### 7.3 修复方案：消除 `FunctionStorageLifecycle` 的 `_registry` 字段

**核心思路**：消除 `FunctionStorageLifecycle` 的 `_registry` 字段，让它直接通过 `RegistryCoordinator.Registry` 获取注册表实例。这样所有组件都通过 `RegistryCoordinator` 获取同一个注册表实例，不存在实例不一致问题。

#### 修改文件清单

| 文件 | 修改内容 |
|------|---------|
| `CsharpPrj/Operation/FunctionStorage/Framework/FunctionStorageRegistry.cs` | 移除 `_registry` 字段，构造函数不再接收 `registry` 参数，`Registry` 属性委托给 `RegistryCoordinator.Registry` |
| `FileDriven/FileDriven.Execution/Lifecycle/FrameworkInitializer.cs` | `new FunctionStorageLifecycle()` 不再传参，`resolvedFunctionStorageLifecycle.Registry` 改为 `RegistryCoordinator.Registry` |

#### 具体修改

**1. `FunctionStorageLifecycle` 类修改：**

```csharp
// 修改前
public class FunctionStorageLifecycle : Modules.Registry.IRegistryLifecycle
{
    private readonly Modules.Registry.FunctionRegistry _registry;
    private readonly ExecutionFramework.Engine.FunctionExecutor _executor;
    private bool _initialized;

    public Modules.Registry.FunctionRegistry Registry => _registry;
    public ExecutionFramework.Engine.FunctionExecutor Executor => _executor;

    public FunctionStorageLifecycle(
        Modules.Registry.FunctionRegistry? registry = null,
        ExecutionFramework.Engine.FunctionExecutor? executor = null)
    {
        if (executor != null && registry == null)
            throw new ArgumentException(...);

        _registry = registry ?? new Modules.Registry.FunctionRegistry();
        _executor = executor ?? new ExecutionFramework.Engine.FunctionExecutor(
            _registry,
            new ExecutionFramework.Abstractions.NullParameterProcessor(),
            new ExecutionFramework.Engine.FallbackTypeConverter());
    }

    public void Initialize()
    {
        if (_initialized) return;
        FunctionStorageRegistry.Initialize(_registry);
        Registrations.MathFunctionRegistrar.RegisterAll(_registry);
        AppServiceProvider.Register<IFunctionRegistry>(_registry);
        WorkFlowMethodUsage.DefaultBasicRegistryProvider = () => _registry;
        _initialized = true;
    }
}

// 修改后
public class FunctionStorageLifecycle : Modules.Registry.IRegistryLifecycle
{
    private bool _initialized;

    /// <summary>获取底层注册表实例（委托给 RegistryCoordinator）</summary>
    public Modules.Registry.FunctionRegistry Registry
        => (Modules.Registry.FunctionRegistry)Share.Registry.RegistryCoordinator.Registry;

    /// <summary>获取底层执行器实例（基于共享注册表创建）</summary>
    public ExecutionFramework.Engine.FunctionExecutor Executor { get; }

    /// <summary>创建 FunctionStorageLifecycle 实例（无参构造函数）</summary>
    public FunctionStorageLifecycle()
    {
        Executor = new ExecutionFramework.Engine.FunctionExecutor(
            Share.Registry.RegistryCoordinator.Registry,
            new ExecutionFramework.Abstractions.NullParameterProcessor(),
            new ExecutionFramework.Engine.FallbackTypeConverter());
    }

    public void Initialize()
    {
        if (_initialized) return;
        var registry = Share.Registry.RegistryCoordinator.Registry;
        Registrations.MathFunctionRegistrar.RegisterAll(registry);
        AppServiceProvider.Register<IFunctionRegistry>(registry);
        WorkFlowMethodUsage.DefaultBasicRegistryProvider = () => registry;
        _initialized = true;
    }
}
```

**2. `FrameworkInitializer` 修改：**

```csharp
// 修改前
var resolvedFunctionStorageLifecycle = new FunctionStorageLifecycle();
resolvedFunctionStorageLifecycle.Initialize();
var registry = resolvedFunctionStorageLifecycle.Registry
    ?? throw new InvalidOperationException(...);
var resolvedFileDrivenLifecycle = new FileDrivenLifecycle(registry);

// 修改后
var resolvedFunctionStorageLifecycle = new FunctionStorageLifecycle();
resolvedFunctionStorageLifecycle.Initialize();
var registry = Share.Registry.RegistryCoordinator.Registry
    ?? throw new InvalidOperationException(...);
var resolvedFileDrivenLifecycle = new FileDrivenLifecycle(registry);
```

#### 风险

- **低风险**：`RegistryCoordinator.Registry` 已经是共享注册表实例，所有组件都通过它获取
- **向后兼容**：`FunctionStorageLifecycle.Registry` 属性类型不变（`Modules.Registry.FunctionRegistry`），但内部实现改为从 `RegistryCoordinator.Registry` 获取
- **类型安全**：`RegistryCoordinator.Registry` 返回 `ITrConfigRegistry`，需要强制转换为 `IFunctionRegistry`（`FunctionRegistry` 实现了 `IFunctionRegistry`）

## 八、架构演进

### 8.1 注册表实例管理演进

```
v1（2026-06-14）: FunctionStorageLifecycle 持有自己的 _registry 实例
    → 问题：多个组件持有不同实例，函数注册后其他组件找不到

v2（2026-07-08 17:30）: 引入 RegistryCoordinator，通过 Set() 同步实例
    → 问题：SingletonCoordinator<ITrConfigRegistry> 的泛型参数是接口，
           延迟初始化时 Activator.CreateInstance<ITrConfigRegistry>() 会抛出异常

v3（2026-07-08 18:00）: 消除 FunctionStorageLifecycle 的 _registry 字段
    → 所有组件直接通过 RegistryCoordinator.Registry 获取共享实例
    → 不存在实例不一致问题
```

### 8.2 当前架构

```
FrameworkInitializer.Initialize()
    → new FunctionStorageLifecycle()          // 无参构造函数
        → Registry 属性委托给 RegistryCoordinator.Registry
    → FunctionStorageLifecycle.Initialize()
        → MathFunctionRegistrar.RegisterAll(RegistryCoordinator.Registry)
    → new FileDrivenLifecycle(RegistryCoordinator.Registry)
        → MathLibrary.RegisterAll(RegistryCoordinator.Registry)
    → WorkFlowMethodUsage.BasicRegistry
        → RegistryCoordinator.Registry         // 同一个实例
    → WorkFlowMethodUsage.Executor
        → _functionExecutor(RegistryCoordinator.Registry)  // 同一个实例
```

所有组件通过 `RegistryCoordinator.Registry` 获取同一个注册表实例，不存在实例不一致问题。
