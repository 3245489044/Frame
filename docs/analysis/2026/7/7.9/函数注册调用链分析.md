# 函数注册调用链分析

> 分析时间：2026-07-09
> 问题现象：运行时 `FunctionRegistry` 中注册函数数量为 0，导致事件触发时 `Function 'SetValue' not found in any registry`

---

## 1. 问题概述

### 1.1 运行时日志

```
[DEBUG] [WorkFlowMethod] [workflowmethod:WorkflowMethodExecution_Registry_notfound_diag] {
  "function": "SetValue",
  "containsKey": false,
  "registryHash": "021128C3",
  "registryType": "Modules.Registry.FunctionRegistry",
  "totalRegistered": 0    ← 注册表为空！
}
```

### 1.2 直接原因

`FunctionLibraryLifecycle.Initialize()` 中的反射调用全部静默失败，导致没有任何函数被注册到 `FunctionRegistry`。

## 4. 设计问题

### 4.1 依赖方向错误

`FunctionLibraryLifecycle` 位于 `Registry` 项目（底层），却试图通过反射调用上层模块（`FunctionStorage`、`FileDriven.Business`、`Agent`）的注册方法。

```
❌ 当前设计（反向依赖）：
   Registry (底层) ──反射调用──→ FunctionStorage (上层)
   Registry (底层) ──反射调用──→ FileDriven.Business (上层)
   Registry (底层) ──反射调用──→ Agent (上层)
```

### 4.2 反射调用不可靠

- `Type.GetType()` 需要正确的程序集限定名，容易出错
- 异常被 `catch {}` 静默吞掉，无任何错误日志
- 编译时无法检查类型是否存在

---

## 5. 修复方案（IoC 控制反转）

### 5.1 方案概述

`FunctionLibraryLifecycle` 不直接调用任何具体类的 `RegisterAll()`，而是通过委托列表让上层模块注入注册逻辑。

### 5.2 FunctionLibraryLifecycle 修改

```csharp
// File: CsharpPrj/Modules/Registry/11_FunctionLibraryLifecycle.cs
public class FunctionLibraryLifecycle : IRegistry, IRegistryLifecycle
{
    private bool _initialized;

    /// <summary>
    /// 注册动作委托列表
    /// <para>上层模块通过此列表注入自己的注册逻辑，实现 IoC 控制反转。</para>
    /// <para>示例：lifecycle.RegistrationActions.Add(r => FunctionStorage.MathLibrary.RegisterAll(r));</para>
    /// </summary>
    public List<Action<IFunctionRegistry>> RegistrationActions { get; } = new();

    public bool IsInitialized => _initialized;

    public void Initialize()
    {
        if (_initialized) return;
        var registry = UnifiedRegistryCenter.Instance.Functions;

        foreach (var action in RegistrationActions)
            action(registry);

        _initialized = true;
    }

    public void Clear() => _initialized = false;
    public void Shutdown() => _initialized = false;
}
```

### 5.3 FrameworkInitializer 修改

```csharp
// File: FileDriven/FileDriven.Execution/Lifecycle/FrameworkInitializer.cs
// 步骤 4：注册 FunctionLibraryLifecycle（统一注册所有 Library 函数）
var lifecycle = new FunctionLibraryLifecycle();

// 通过 IoC 注入注册逻辑（上层模块提供具体实现）
lifecycle.RegistrationActions.Add(r => FunctionStorage.MathLibrary.RegisterAll(r));
lifecycle.RegistrationActions.Add(r => FunctionStorage.Libraries.BuiltInUnitsLibrary.RegisterAll(r));
lifecycle.RegistrationActions.Add(r => FileDriven.Business.Registrations.MathBrowserFunctions.RegisterAll(r));
lifecycle.RegistrationActions.Add(r => FunctionStorage.UIToolbox.RegisterAll(r));
lifecycle.RegistrationActions.Add(r => FunctionStorage.WorkflowLibrary.RegisterAll(r));
lifecycle.RegistrationActions.Add(r => FunctionStorage.Registrations.MathFunctionRegistrar.RegisterAll(r));
// Agent 函数通过各自的 Register() 方法注册
lifecycle.RegistrationActions.Add(r => Agent.Core.AgentLoopFunction.Register());
lifecycle.RegistrationActions.Add(r => Agent.Planner.SKPlannerFunction.Register());
lifecycle.RegistrationActions.Add(r => Agent.McpTools.McpToolFunction.Register());
lifecycle.RegistrationActions.Add(r => Agent.Guardrails.GuardFunction.Register());

unifiedRegistry.RegisterRegistry("FunctionLibrary", lifecycle);
```

### 5.4 修复后的依赖方向

```
✅ 修复后设计（IoC 控制反转）：
   Registry (底层) ──定义委托接口──→ (无依赖)
   FileDriven.Execution (上层) ──注入注册逻辑──→ Registry
   FileDriven.Execution (上层) ──直接调用──→ FunctionStorage
   FileDriven.Execution (上层) ──直接调用──→ FileDriven.Business
   FileDriven.Execution (上层) ──直接调用──→ Agent
```

1. **修改 `FunctionLibraryLifecycle.cs`**：移除所有反射方法，改为 `RegistrationActions` 委托列表
2. **修改 `FrameworkInitializer.cs`**：在创建 `FunctionLibraryLifecycle` 后注入注册动作
3. **构建验证**：确保编译通过
4. **运行验证**：确认 `totalRegistered > 0`
