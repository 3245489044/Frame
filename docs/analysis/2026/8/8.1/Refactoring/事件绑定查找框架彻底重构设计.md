# 事件绑定查找框架彻底重构设计（消除不稳定字段逻辑）

> **目标**：彻底消除 `BindingVerifier` 对「硬编码反射字段名候选集」的依赖（已踩坑 3 次：`EventClick` → `s_ClickEvent` → `s_clickEvent`），建立「挂载即事实、触发即验证、断言才反射」的三层查找框架。
> **关联**：`[CR: docs/Refactoring/事件绑定问题排查记录.md]` | `[CR: docs/analysis/2026/7/7.31/事件绑定三聚拢点重构设计.md]`
> **层级**：L2-L3（策略+规范）
> **测试命令**：`echo 10 | EnableMent\交互启动.bat`

---

## 一、背景与痛点

### 1.1 现状（2026-07-31 晚，根因修复后）

事件绑定已恢复 `boundCount=6, assert event-bound 12/12 PASS`，但修复方式为「事后补丁」——在 `BindingVerifier.HasSubscription` 中硬编码 3 个候选字段名轮流尝试。这种方案逻辑脆弱，任何 WinForms 运行时升级改动字段名都会再次失效。

### 1.2 脆弱点清单（代码级确认）

| # | 脆弱点 | 位置 | 后果 |
|---|--------|------|------|
| **V1** | 硬编码字段名候选集 `{EventClick, s_ClickEvent, s_clickEvent}` | `BindingVerifier.cs` `HasSubscription` | 新版本字段名变更即失效 |
| **V2** | 回退路径 `HasSubscriptionViaEventInfo` 同样硬编码候选集 | `BindingVerifier.cs` L90+ | 回退路径同脆弱 |
| **V3** | 验证与挂载不对称：挂载用 `EventInfo.AddEventHandler`（公共 API），验证却猜静态字段名 | `WinFormsEventBus.cs` vs `BindingVerifier.cs` | 两端信息源不同，是「boundCount=0 而委托已挂」的根源 |
| **V4** | `FieldInfo.GetValue(control)` + `events[key]` 的字段/属性依赖 | `BindingVerifier.cs` L76-84 | `Events` 实为 public 属性，但代码按私有反射获取（冗余脆弱） |
| **V5** | 「探测列表」写死 3 个候选，新变体不覆盖 | probe 实测字段为 `s_clickEvent`（全小写） | 靠猜，非模式驱动 |

### 1.3 关键事实（重构依据）

1. **挂载端零猜测**：`WinFormsEventBus.EventInfoResolutionStep` 用 `GetType().GetEvent()` + `EventInfo.AddEventHandler()`，全程公共 API。
2. **`Control.Events` 是 public 属性**：`public EventHandlerList Events`，无需私有反射。
3. **事件键字段是 static readonly object**：`s_clickEvent` 为静态字段，`GetValue(null)` 即可；且对**所有控件共享**，只需按 `(Type, eventName)` 探测一次。
4. **CLR 无公共 API 直接读事件订阅者**：delegate 存在私有静态键字段中，`EventHandlerList` 是唯一公共入口（但获取键需字段名或字段探测）。

## 二、核心设计：三层验证

> 设计对齐 `Coupling-ObservationCollapse [AX]`（观测即真实）——「真实」由绑定挂载事件本身证明，而非事后猜反射字段。

```
┌─────────────────────────────────────────────────────────────┐
│ 第 1 层 · 挂载即事实（记录型）→ 主统计路径                    │
│   DeclarationBindingStep.BindSingleEvent==true               │
│     → ctx.AddBoundControl()（已实现）                        │
│     → boundCount = result.BoundCount（管线记录，不经反射）    │
├─────────────────────────────────────────────────────────────┤
│ 第 2 层 · 触发即验证（行为型）→ click 前置路径                │
│   ClickSystem.PerformDirectClick(btn)                        │
│     → 移除 HasSubscription 前置                              │
│     → 直接 PerformClick() + 副作用断言验证                   │
├─────────────────────────────────────────────────────────────┤
│ 第 3 层 · 显式断言才反射（诊断型）→ assert event-bound        │
│   IEventSubscriptionInspector.HasSubscribers(control,event)  │
│     → 模式驱动 probe + (Type, eventName) 缓存                │
│     → 仅诊断用途，失败不阻断主流程                           │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 第 1 层：挂载即事实（主统计）

- **已实现**：`DeclarationBindingStep` 在 `BindSingleEvent` 成功后立即 `ctx.AddBoundControl`（聚拢点②）。
- **改造**：`EventBindingSystem.VerifyAndBuildOutput` 的 `verifiedBoundCount` **改用管线 `result.BoundCount`**（记录型），不再以 `CountBound(verifiedBindings)` 反射核算作为主统计。
- **收益**：统计恒等于真实委托（挂载成功即计数），彻底消除反射误报导致的 `boundCount=0` 矛盾。

### 2.2 第 2 层：触发即验证（click 路径）

- **现状**：`ClickSystem.PerformDirectClick` 前置 `HasSubscription`，反射失败 → 拒绝点击。
- **改造**：控件存在即 `PerformClick()`；执行结果由 `ExecutionResultComponent` 与副作用断言验证。
- **收益**：消除「反射误报导致无法点击」的恶性循环；点击行为由实际副作用证明，而非反射预判。

### 2.3 第 3 层：显式断言才反射（诊断）

- **仅 `assert event-bound`** 这类显式验证命令使用反射。
- **接口抽象**：`IEventSubscriptionInspector`（可替换、可 mock）。

## 三、交付物详细设计

### 3.1 新接口 — `IEventSubscriptionInspector`

```csharp
namespace Share.EventBindingOrchestrator.Abstractions;

/// <summary>
/// 事件订阅检查器 — 检查控件事件是否已有订阅者（诊断用途）
/// <para>设计：模式驱动字段探测 + (Type, eventName) 缓存，不硬编码字段名。</para>
/// </summary>
public interface IEventSubscriptionInspector
{
    /// <summary>
    /// 检查控件指定事件是否有订阅者
    /// </summary>
    /// <param name="control">控件实例</param>
    /// <param name="eventName">事件名（如 click / Click）</param>
    /// <returns>true=有订阅者；false=无订阅者或事件不存在；null=无法验证（字段探测失败）</returns>
    bool? HasSubscribers(Control control, string eventName);
}
```

> 返回 `bool?`：`null` 表示「无法验证」（新旧版本字段探测均失败），调用方按诊断上下文处理（warning + 保守 true），不阻断。

### 3.2 探测实现 — `WinFormsEventSubscriptionInspector`

```csharp
namespace Share.EventBindingOrchestrator.Adapters;

public sealed class WinFormsEventSubscriptionInspector : IEventSubscriptionInspector
{
    private readonly ConcurrentDictionary<(Type, string), FieldInfo?> _fieldCache = new();

    public bool? HasSubscribers(Control control, string eventName)
    {
        if (control == null || string.IsNullOrWhiteSpace(eventName))
            return false;

        var pascal = Normalize(eventName);
        var key = (control.GetType(), pascal);
        var field = _fieldCache.GetOrAdd(key, _ => ProbeEventField(pascal));

        if (field == null)
            return null; // 无法验证（探测失败，交由调用方保守处理）

        // Control.Events 是 public 属性（EventHandlerList）
        var events = control.Events;
        var keyObj = field.GetValue(null); // 静态字段：GetValue(null)
        return events[keyObj] is Delegate d && d.GetInvocationList().Length > 0;
    }

    /// <summary>
    /// ★ 模式驱动探测：不猜死列表，而是按「object 类型 + Event 后缀 + 事件名匹配」动态筛选
    /// </summary>
    private static FieldInfo? ProbeEventField(string pascalEvent)
    {
        return typeof(Control)
            .GetFields(BindingFlags.NonPublic | BindingFlags.Static)
            .FirstOrDefault(f =>
                f.FieldType == typeof(object) &&
                f.IsStatic &&
                f.Name.EndsWith("Event", StringComparison.OrdinalIgnoreCase) &&
                f.Name.Contains(pascalEvent, StringComparison.OrdinalIgnoreCase));
    }

    private static string Normalize(string eventName)
        => eventName.Length == 0
            ? eventName
            : char.ToUpperInvariant(eventName[0]) + eventName.Substring(1);
}
```

**关键简化**：
1. `Control.Events` 是 **public** 属性 → 移除私有反射（V4 消除）。
2. 静态字段 `GetValue(null)` → 无需实例字段取值。
3. 模式驱动 `EndsWith("Event") + Contains(pascalEvent)` → 一次覆盖 `EventClick`/`s_ClickEvent`/`s_clickEvent`/`eventClick` 等所有变体（V1/V2/V5 消除）。
4. `(Type, eventName)` 缓存 → `Control` 静态字段对所有控件共享，只需探测一次（性能无忧）。

### 3.3 `BindingVerifier` 简化

- `HasSubscription` 委托给 `IEventSubscriptionInspector`（DI 注入 / 静态默认实现）。
- 删除硬编码候选集两处 + `HasSubscriptionViaEventInfo`。
- 保留 `FindControl`（控件空间查找，与绑定链共用 `Controls.Find`）。
- `CountBound` 保留但仅用于诊断快照（`EventBindingSystem` 快照中 `IsBound` 标志），主统计走 `result.BoundCount`。

### 3.4 主统计改造 — `EventBindingSystem.VerifyAndBuildOutput`

```csharp
// 改动前：verifiedBoundCount = CountBound(verifiedBindings)  ← 反射核算
// 改动后：verifiedBoundCount = result.BoundCount              ← 管线记录（挂载即事实）
// 快照部分保留 HasSubscription（诊断），但不再影响主统计
```

### 3.5 click 前置改造 — `ClickSetGetSystems.PerformDirectClick`

```csharp

// 改动后：PerformClick() 直接触发；结果由 ExecutionResultComponent + 副作用断言验证
```

### 3.6 DI 注入 — `EventBindingInitializer`

```csharp

    new WinFormsEventSubscriptionInspector());
```

### 3.7 `Using` 清理

- `BindingVerifier.cs`：移除 `System.ComponentModel`（`EventHandlerList` 经 `Control.Events` 返回即可用，无需 using 仍可；确认是否保留）。

## 六、原则对齐

| 原则 | 对齐点 |
|------|--------|
| `Coupling-ObservationCollapse [AX]` | 「真实」= 挂载成功事件，记录型主统计优先；反射仅诊断 |
| `SyncProtocolTriple [AX]` | 触发验证（第2层）由副作用确认，非反射预判 |
| `ScopeAnchor [AX]` | 验证逻辑收敛到 `IEventSubscriptionInspector` 唯一入口 |
| `RepeatedCallStable [AX]` | `(Type, eventName)` 缓存保证重复断言零额外开销 |

## 七、风险与取舍

| 取舍 | 说明 |
|------|------|
| 为什么不纯记录（完全不反射） | `assert event-bound` 是显式验证命令，期望「真实验证」；模式驱动 + 缓存已消除脆弱性 |
| 探测失败返回 `null` | 「无法验证」语义化，调用方保守处理（warning + true），不阻断点击/统计 |
| 子类自定义事件 | 缓存按 `control.GetType()`，子类声明的新事件走自身类型探测；`Control` 基类事件共享基类缓存 |
| 性能 | 静态字段探测仅一次（按 (Type, eventName) 缓存），hash 查找 O(1) |
| WinForms 版本升级 | 字段名变化不再破坏——模式驱动而非字面量匹配 |
