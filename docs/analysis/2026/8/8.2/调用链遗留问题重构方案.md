## 二、批 E5：执行接口统一（IEventExecutionService 收口）

### 目标
消除 `IEventExecutionService`（返回 `ExecutionResult`）与 `TConfig.IFunctionExecutor`（返回 `FunctionExecutionResult`）双接口并存的冗余——两者等价可达同一执行引擎（`WorkflowMethodExecutionService` 同时实现二者）。

### 现状
- 命令链（`CommandInputPort`/`ExecuteCommandStage`）走 `IEventExecutionService`
- ECS 链（`FunctionSystem`/`StepExecutor`/`PipelineExecutor`）走 `IFunctionExecutor`
- `WorkflowMethodExecutionService` / `FunctionExecutor`（StateHoldDriven）/ `Modules.ExecutionFramework.FunctionExecutor` 三处实现 `IFunctionExecutor`

### 文件改动清单
| 文件 | 动作 |
|------|------|
| `CsharpPrj/Plate/TConfig/Abstractions/IEventExecutionService.cs` | 保留为统一执行接口 |
| `CsharpPrj/Plate/TConfig/Abstractions/IFunctionExecutor.cs` | 评估废弃（或降为内部适配） |
| `CsharpPrj/Operation/WorkFlowMethod/WorkflowMethodExecutionService.cs` | 保留 `IEventExecutionService` 实现，移除/降级 `IFunctionExecutor` 显式实现 |
| `CsharpPrj/Modules/ExecutionFramework/Engine/Core/FunctionExecutor.cs` | 改为适配 `IEventExecutionService`（或删除，统一到 WorkflowMethod 实现） |
| `CsharpPrj/Operation/StateHoldDriven/FunctionStorage/Framework/Core.cs` | 同上 |
| 消费方：`FunctionSystem`/`StepExecutor`/`PipelineExecutor`/`RgeGraphScheduler` | 改用 `IEventExecutionService` |

### 验证
- `dotnet build FileDriven.sln / MainProj.sln` 0 错误
- 命令链 + ECS 链函数执行行为回归

> ⚠️ **风险**：`IFunctionExecutor` 涉及 ExecutionFramework（`FunctionSystem`/`StepExecutor`）与 StateHoldDriven 两处实现，改动面大，建议**单独立项**、先建适配后删冗余（两阶段）。

## 三、批 E8：控件查找统一收敛

### 目标
消除 3 套重叠的控件查找实现，收敛为统一查找器（沿用 B2 作用域路径下钻能力）。

### 现状（重叠实现）
| 位置 | 实现 |
|------|------|
| `EventBindingPipelineFactory.FindControlByReflection` | `Controls.Find(name, true)` 递归穿透 + 反射 DFS 回退 |
| `EventBinder.FindControlByName` | 父控件 `Controls` DFS 递归 |
| `BindingVerifier.FindControl` | 验证链查找 |
| `EventBindingPipelineFactory.FindControlByPath`（B2 新增） | 容器路径逐层下钻 |

### 文件改动清单
| 文件 | 动作 |
|------|------|
| `EventBindingOrchestrator/Invoke/ControlTreeWalker.cs` | 增补统一查找入口 `FindControl(object container, string name, string? scopePath)` |
| `EventBinder.cs`（BackEndDriven/IoC）| `FindControlByName` → 委托统一查找器 |
| `EventBindingPipelineFactory.cs` | `FindControlByReflection`/`FindControlByPath` → 委托统一查找器 |
| `BindingVerifier` | `FindControl` → 委托统一查找器 |

### 验证
- 多层嵌套同名控件精确命中（复用 B2 测试场景）
- 按钮点击/验证/写回三路径行为一致

## 四、批 E9：命令链统一收口（消除直调）

### 目标
`CommandInputPort.ExecuteSingleWorkflowAsync` 绕过门面直调 `IEventExecutionService`，导致同一函数经命令链（CommandInputPort / ExecuteCommandStage）时超时/审计策略与主链不一致。

### 文件改动清单
| 文件 | 动作 |
|------|------|
| `CsharpPrj/Operation/BackEndDriven/CommandExecution/CommandInputPort.cs` | `ExecuteSingleWorkflowAsync` 改经 `IEventPlatform.InvokeFunctionAsync`（Source=ExecCommand）|
| `CsharpPrj/Share/CommandFramework/Invoke/ExecuteCommandStage.cs` | 复核 `_executionService` 直调路径，统一经 `IEventPlatform`（确认 ReferenceStrategy 后）|

### 验证
- exec 命令与按钮点击共享同一执行入口（审计/超时一致）
- 命令管线行为回归

> ⚠️ **例外**：`CommandInputPort` 在 BackEndDriven，`IEventPlatform` 在 Share 层（已确认引用方向可行——BackEndDriven 已引用 EventBindingOrchestrator）。

## 五、批 E6：ExecutionResult 类型体系收敛（P2，独立批次）

### 目标
消除 8+ 处同名 `ExecutionResult` 类，统一到单一执行结果模型。

### 现状（碎片化定义）
| 位置 | 说明 |
|------|------|
| `BackEndDriven/Models/ExecutionResult.cs` | 门面层 |
| `Share/FrameworkAbstractions/Utilities/ExecutionResult.cs` | 通用 |
| `Modules/Threading/ExecutionStatus.cs` | 线程层 |
| `Share/UniversalReference/Core/Models/ExecutionResult.cs` | 通用引用 |
| `Share/CommandFramework/Execution/CommandPipeline/Models/CommandResults.cs` | 命令管线 |
| `StateHoldDriven/WorkflowExecution/WorkflowExecutionEngine.cs` | 工作流 |
| `Plate/TConfig/Models/ExecutionModels.cs` | TConfig 核心 |
| `BasicMethod/Map/Container/Abstractions/Messages.cs` | 容器 |

### 建议
- **不在本次执行**：全仓靠 `using 别名` 消歧，迁移风险极高
- 建议独立立项：以 `TConfig/Models/ExecutionModels.cs` 为唯一权威（或 `Share/FrameworkAbstractions`），各层 `using 别名` → `using 全局 using` 收敛
- 逐步替换：从顶层消费方（`FunctionCallFacade`/`IEventPlatform`）反向收敛
