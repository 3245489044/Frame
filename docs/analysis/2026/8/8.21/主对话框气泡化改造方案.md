# 主对话框气泡化改造方案

> 场景：Agent 运行时控制台（`AgentRuntimeUI.json`）右侧「④ 主对话框」页，当前对话历史以纯文本展示，改造为气泡式对话界面。
>
> 日期：2026-08-21

## 1. 现状分析

### 1.1 展示载体

「④ 主对话框」页的对话历史绑定在 `conversationHistoryTextBox`，一个**只读纯文本框**（`style: readonly-bg + readOnly`），布局约占页内 0.62 宽度、0.56 高度：

- 类型：`textbox`（多行 + 双向滚动 + Consolas 9pt）
- 内容来源：`AgentUi_ConversationSend` / `AgentUi_ConversationHistory` 的输出回写
- 位置：`FileDriven/DrivenConfig/JsonConfig/AgentRuntimeUI.json` `pageConversation` 页

### 1.2 数据形态

会话历史由 `AgentUiLibraryConversation.ConversationHistoryAsync` 产出，逐条拼为文本行：

```text
[{Round}][{Role}{:Stage}] {Text}
```

- 例：`[1][user] 帮我查询输出`、`[1][assistant:act] 处理完成`
- 角色 `Role`：`user` / `assistant` / 各层 `sub-agent`
- 阶段 `Stage`：分层工作流步骤（collect / analyze / act 等）

### 1.3 为什么纯 textbox 做不了气泡

- 纯文本框**无左右对齐、无底色衬底、无圆角、无彩色标识**，信息只能靠文本前缀区分；
- 无法体现「user 靠右 / agent 靠左」的组织意图，可读性差；
- 要气泡必须换用**能渲染 HTML 的表面**。

### 1.4 为什么 HTML 应独立为模块（与 Markdown 平级）

现有 `markdownviewer` 控件走 Markdig 渲染且开启 `DisableHtml()`（`MarkdownHtmlRenderer.cs` 的 `Pipeline`），会**转义所有原始 HTML**（防 XSS：用户/任务载荷中的 `<script>` 不得进 DOM）。

- Markdown 在本项目是**一等模块**：`CsharpPrj/Plate/MarkdownViewer/`（控件 + 渲染器 + 独立 csproj）+ `markdownviewer` 控件类型 + 专属值契约。
- HTML 富文本是**另一种内容格式**：不应寄生在 markdownviewer 里塞 `@html` 魔法前缀，而应**同样单独建一个平级模块 `HtmlViewer`**，职责、控件、契约、安全边界各自独立。
- 这与现有架构一致：`contents = 传输自描述的格式协议；显示端各自接管自己的格式`。

## 2. 目标

把「④ 主对话框」从「纯文本行」升级为「气泡式对话」，并以**独立 `HtmlViewer` 模块**承载 HTML 富文本渲染：

| 消息角色 | 对齐 | 气泡样式 | 附加信息 |
|----------|------|----------|----------|
| user | 右对齐 | 主题色（蓝）气泡 | 轮次 / 角色角标 |
| assistant / sub-agent | 左对齐 | 中性色（灰）气泡 | 轮次 / 角色 / 阶段角标 |

- 统一运行结果（`resultTextBox`）**保持纯文本不变**，不纳入气泡化范围。
- HTML 富文本统一走 `htmlviewer`（可信通道）；markdown 仍走 `markdownviewer`（Markdig sanitize）。两路独立、互不污染。

## 3. 独立 HtmlViewer 模块（核心）

### 3.1 模块结构（对等 MarkdownViewer）

```
CsharpPrj/Plate/HtmlViewer/
├── HtmlViewer.cs            // 控件：WebView2，SetHtmlAsync / ApplyFontSizeAsync
├── HtmlDocumentRenderer.cs  // 纯函数：body HTML + 主题 CSS → 完整 HTML 文档壳
└── HtmlViewer.csproj        // 独立工程（引用 Microsoft.Web.WebView2）
```

| Markdown 独立模块 | HTML 独立模块（新） |
|---|---|
| `MarkdownViewer.cs` | `HtmlViewer.cs` |
| `MarkdownHtmlRenderer.cs`（Markdig→HTML） | `HtmlDocumentRenderer.cs`（body→完整页壳） |
| `MarkdownViewer.csproj` | `HtmlViewer.csproj` |
| `markdownviewer` 控件类型 | `htmlviewer` 控件类型 |
| `RegisterMarkdownViewerContract` | `RegisterHtmlViewerContract` |
| `@fontsize:` 字号指令 | `@fontsize:` 同样支持 |

### 3.2 职责划分

- **HtmlViewer 控件**：只负责「展示」。持有 HTML 字符串 → `EnsureCoreWebView2Async`（一次性初始化）→ `NavigateToString`。镜像 `MarkdownViewer` 的生命周期与可反复 `SetHtmlAsync` / `ApplyFontSizeAsync`，**不做任何解析/转义**。
- **HtmlDocumentRenderer（纯函数）**：负责「组装」。把 body HTML 片段包进完整页面（内嵌主题 CSS 壳、CJK 排版），等价 `MarkdownHtmlRenderer.ToMarkdownHtml` 的壳。供宿主与测试复用。
- **生产端渲染器**（气泡等）负责「encode」：用户/模型文本先 `HtmlEncode` 再拼入 body。

### 3.3 安全边界（反转定位，必须明确）

- **markdownviewer**：`DisableHtml` 在**消费端** sanitize——第三方 markdown 输入里的标签一律转义。
- **htmlviewer**：是**可信富文本通道的唯一入口**，直接 `NavigateToString`，**自身不再二次转义**。XSS 防线移到**生产端渲染器**——只有受信渲染器（`ConversationHtmlRenderer` 等）产出 HTML，且内含文本一律 `HtmlEncode`。
- 因此**不需要 `@html\n` 魔法前缀**：htmlviewer 的 Text 契约语义本身即「HTML 渲染」。
- 边界判定：能把 HTML 送进 htmlviewer 的，只有注册过的渲染器/函数；用户与模型原始输入永远先经 renderer encode，再进 body。

## 4. 改造方案

### 4.1 新增 `Plate/HtmlViewer` 模块

按 3.1 建目录与工程，实现 `HtmlViewer` 控件 + `HtmlDocumentRenderer`；在 `FrontEndDriven.csproj` 增加对 `HtmlViewer.csproj` 的 ProjectReference（与 MarkdownViewer 并列，参考现有 `FrontEndDriven.csproj` 第 79 行）。

### 4.2 注册控件类型与值契约

- `ControlTypeRegistry.cs`：注册 `htmlviewer` → `new HtmlViewer()`（契约允许 `html`/`fontSize` 可选属性，对齐 `markdownviewer` 的 `markdown`）。
- `BuiltInValueContracts.cs`：新增 `RegisterHtmlViewerContract`——Text 语义 writer → `SetHtmlAsync(html)`（HtmlViewer 直接渲染，不走 Markdig）；`@fontsize:` 指令与 `Range` 字号语义同 markdownviewer。

### 4.3 新增气泡渲染器 `ConversationHtmlRenderer`

- 定位：纯函数，对标 `TaskPoolMarkdownRenderer`，与渲染/值契约解耦。
- 输入 `ConversationMessage[]`，输出 **body HTML 片段**（含气泡 CSS + 嵌套在 `HtmlDocumentRenderer` 壳内使用）。
- 遍历消息按角色布局：`user` → 右侧蓝气泡；`assistant`/`sub-agent` → 左侧灰气泡；附 `{Round} {Role}{:Stage}` 角标；浅/深主题变量；空历史返回空态文案。
- 所有消息文本 `System.Net.WebUtility.HtmlEncode` 后再入 DOM。
- 放置：`Projects/Agent/src/Agent.Launcher/Modules/ConversationHtmlRenderer.cs`，或 `FrontEndDriven/Rendering/`（若需多宿主通用）。

### 4.4 会话库返回气泡 HTML

`AgentUiLibraryConversation` 改为「取历史 → 气泡渲染 → 返回 body HTML 片段」（**无任何前缀头**，交由 htmlviewer 契约直接渲染）：

- `ConversationHistoryAsync`：渲染完整历史；
- `ConversationSendAsync`：**发送后回显完整历史**，不再只返回单行摘要，否则气泡页看不到推进结果（`svc.SendAsync` 推进逻辑保持，仅输出改为渲染后的气泡）；
- 会话未装配/空态兜底文案保持纯文本即可（htmlviewer 对纯字符串直接渲染为普通文本节点）。

### 4.5 JSON 换绑定目标

`AgentRuntimeUI.json` `pageConversation` 页：

- 把 `conversationHistoryTextBox` 替换为 **`htmlviewer`**，新控件名 `conversationHistoryViewer`；
- `sendMessageButton` / `loadHistoryButton` 的 `output` 改指 `conversationHistoryViewer`；
- `conversationStateTextBox`（运行态单行）与 `resultTextBox`（统一结果）不动；
- 布局沿用原区域（0.02, 0.22, 0.62, 0.56），气泡在 WebView2 内自适应。

## 5. 验收标准

1. 载入 `AgentRuntimeUI.json` → 「④ 主对话框」页无白屏/异常，会话选择/新建/刷新可用；
2. 选择会话 → 点「载入历史」→ 历史以气泡呈现：user 右蓝、agent 左灰，含轮次/角色/阶段角标；
3. 输入消息 → 点「发送」→ 新答复以气泡追加到最下方；
4. 用户/模型文本含 `<`、`>`、`&`、`"` 等字符时不带出 HTML 标签/脚本（生产端 encode 生效）；
5. 空会话显示空状态文案，不抛异常；
6. 既有 markdown 通道不受影响：数据库页/模板说明页 markdown 渲染、JSON 高亮照常（`DisableHtml` 及 htmlviewer 两路各自独立）。

## 7. 边界与取舍

- **独立成模块**：HTML 富文本与 Markdown 平级，职责/控件/契约/工程各自独立，不共用一条魔法暗线；未来图表/日志/看板等富文本复用 htmlviewer。
- **两路安全边界清晰**：markdownviewer = 消费端 Markdig sanitize；htmlviewer = 可信通道，防线在生产端渲染器 encode。
- **不变更渲染器界的输入形态**：渲染器一律输出 body 片段，由 `HtmlDocumentRenderer` 统一包壳；值契约只用语义分派，不嗅探内容格式。
- 「统一运行结果」区域维持纯文本，聚焦主对话框气泡化，避免一次改动范围过大。
