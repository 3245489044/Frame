# 会话发送调用链：框架层去重与收敛重构方案

> 日期：2026-08-22 ｜ 范围：`AgentUi_ConversationSend → ConversationSessionService → ConversationPipeline → WorkflowRunner` 会话发送主链路
> 状态：**审计已完成**，本方案给出框架层收敛设计（非测试脚本级修补）
> 关联：与《工作流调用链重构与 UniversalReference 联动方案》D1–D5 互补；本文档专做**重复 / 冗余 / 错误逻辑**审计与收敛，不重复 D 系列主线。

---

## 一、背景与目标

对 `agent_real_llm_test.json` 的「发送」链路做调用链审计，发现沿途存在**同职责多实现、重复对象构造、同值多键播种、取消/异常语义并存**等问题。这些问题不影响 `collect-analyze-act.json` 三条简单步骤的正确，但随着会话模板复杂化会放大（E2/E3 类语义漂移、Y2 类构造开销、R1 类双写风险）。

**总目标**：在保持既有行为契约的前提下，把链路上重复、冗余、错误的逻辑收敛为**单一实现、单一事实源、单一契约**。

**手段**：面向框架层（`Conversation*` 服务 + `WorkflowRunner` + `RoundStepInvoker`）做小步收敛，不新增机械代码，不触碰测试脚本命令映射。

## 四、重构设计

> 排序按「依赖 + 风险」：先契约（E 类）、再持久化/收敛（R 类）、最后开销（Y 类）。每项含：现状 → 目标 → 改动 → 验证标准（含自动化断言）。

### 工作 A：取消语义收敛（E1）

- **现状**：`RunSignalAsync` 捕获所有异常含 OCE，`Finalize...` 用兜底令牌尾写，随后 `throw runError`；取消路径的正确性依赖两个分支是否一致。
- **目标**：取消与异常单一路径、语义清晰。
- **改动**：
  1. `ConversationPipeline.RunSignalAsync` catch 拆为 `catch (OperationCanceledException)` 与 `catch (Exception)`。
  2. OCE 分支只做「标 Cancelled + 尾写」，**不 rethrow**（由上层沿调用链取消传播）；非 OCE 才标 Faulted + rethrow。
  3. 尾写令牌统一用 `CancellationToken.None`，并在 `FinalizeConversationStateAsync` 注释里写明「状态完备优先于取消及时性」的取舍。
- **验证标准**：
  - 单测 `ConversationPipelineTests`：注入抛 OCE 的 `runWorkflow`，断言 `item.Status==Cancelled`、`GetBackendAudit` 已写、且 OCE **不**向上传播。
  - 注入抛普通异常的 runner，断言 `Status==Faulted` 且异常上抛。

### 工作 B：成功准则单一契约（E2）

- **现状**：runner 与 pipeline 各自判成败。
- **目标**：判定收敛到单一 truth——`WorkflowRoundResult.Error` 为唯一权威。
- **改动**：
  1. pipeline 侧 `RunSignalAsync` 的逻辑（已有）保持不变；runner 侧 `ok` 字段改为**仅供模板决策引用、不参与会话层判断**（消除双判）。
  2. 给 `WorkflowRoundResult` 增加只读属性 `bool IsSuccessful => Error == null`，两处判定收敛到它。
- **验证标准**：
  - `WorkflowRunner` 测试：RunToEnd 模板无错误 → ok；有步骤错误 → ok=false。
  - `ConversationPipelineTests`：会话成功与否与 `result.Ok` 解耦（改 ok 不影响会话结果），始终以 `result.Error` 为准。

### 工作 C：act 步参数契约补齐（E3）

- **现状**：`act` 步只有 `[system,l1,l2,session_id]`，无 `question`。
- **目标**：每个下游消费其真实所需源键，不依赖「l1 恰好是原文」的隐式约定。
- **改动**（模板级，框架联动）：
  1. `collect-analyze-act.json` act 步 `ParameterKeys` 显式加 `question`。
  2. `SeedWorkflow` 保持 `question=text`；确认 `cline_execute` 默认参数白名单（`RoundSpecLoader.cs#L36`）含 `question` 或在模板 ParameterKeys 表达。
- **验证标准**：`agent_real_llm_test.json` 全链回归；`RoundStateMapperTests` / `RoundSpecLoaderTests` 断言 act 步入参含 question。

### 工作 D：节点输出双写治理收敛（R1）

- **现状**：横切持久化 + 终态信封补写，用守卫防重复。
- **目标**：收敛为**单一持久化通道**，守卫作为不变量校验而非日常路径。
- **改动**：
  1. 以 `PersistStepAsync`（onAfterStep 横切）为权威写点；终态信封仅补写「无步骤对应的节点端口」（`guard_output` 的 `safe_output/output` 这类非步骤 ResultKeys）。
  2. 将 `IsPortPersisted` 判断下沉为 `NodeOutputStore` 的幂等写（`WriteOutputAsync` 内 upsert by `(workflowId,nodeKey,port)`）+ 断言（`Debug.Assert` 防同端口双写告警）。
- **验证标准**：`ReferenceGroundingWriteThroughTests` 与持久化测试全部通过；压测断言 `exec_result` 节点仅一条记录。

### 工作 E：错误分类单通道（R3）

- **现状**：`onStepError` 挂钩分类一次 + `result.HasErrors` 再兜底。
- **目标**：单通道分类，兜底仅覆盖「挂钩未命中」。
- **改动**：
  1. 确认 `onStepError` 恒定先于 `RunRoundAsync` 的 `result.HasErrors` 分支（静态管线一定按序回调）后，移除后者对 `ctx.Error` 的再赋值，仅保留「挂钩未命中时」的兜底守卫（带注释标注其为不可达偏差）。
  2. 若静态管线保证不了回调顺序，则在挂钩中直接写 `result` bearer，去掉双写。
- **验证标准**：`Agent.Axioms.Tests` / `ConversationPipelineTests` 中制造步骤异常，断言 `ErrorClass/ErrorStep` 一次赋值、无覆盖。

### 工作 F：状态外置单收割（R4）

- **现状**：`RoundStateMapper.Harvest` + `DataContainerBinder.BindHarvestPhase` 双路径收本轮输出。
- **目标**：收敛为单一收割器，另一路径降为只读审计。
- **改动**：
  1. 以 `DataContainerBinder`（容器映射）为权威收割通道；`RoundStateMapper.Harvest` 改为在容器收割后仅做只读一致性校验（`Debug.Assert`）。
  2. `seedDiag/harvestDiag` 保留为诊断，不再承担写职责。
- **验证标准**：`RoundStateMapperTests` 全绿；行为等价（BuildHarvest 输出与旧 Harvest 快照一致）。

### 工作 G：`NodeExecutionService` 单例注入（Y2）

- **现状**：每步/每持久化 `new NodeExecutionService`。
- **目标**：构造一次、全程复用。
- **改动**：
  1. `RoundStepInvoker` 成员一次性构造 `NodeExecutionService`（`_nodeOutputs` 等已是成员，注入到公共服务）。
  2. 移除 `ExecuteStepAsync`/`PersistStepAsync` 内的重复 `new`。
- **验证标准**：部署后 `AgentLog.RoundStepInvoker_ExecuteStepAsync_completed` 依旧每次打印；`NodeExecutionService` 构造次数 = 每轮 1 次（可加计数诊断）。

### 工作 H：`SendAsync` 顺带返回历史（Y1）

- **现状**：`ConversationSendAsync` 发送后再 `GetHistoryAsync` 二次读。
- **目标**：令一次调用同时返回渲染所需数据，省二次 store 读。
- **改动**（接口契约，需全量核对调用方）：
  1. `ConversationReply` 增加 `IReadOnlyList<ConversationMessage> Messages`（由 `RunSignalAsync` 构造时从 `log` 快照填充）。
  2. `ConversationSendAsync` 直接 `RenderBody(reply.Messages)`，不再 `GetHistoryAsync`。
  3. 确认 `ConversationHistoryAsync`（UI「载入历史」）仍走 `GetHistoryAsync`，不动。
- **验证标准**：单测断言 `Send` 返回的 `Messages` 与 `GetHistoryAsync` 结果一致；脚本第 27 步 `get conversationHistoryTextBox` 输出不变。

### 工作 I：会话锁字典有界化（Y4）

- **现状**：`_locks` 无界增长。
- **目标**：有界 + 可回收。
- **改动**：
  1. 将 `ConcurrentDictionary<string, SemaphoreSlim>` 换为受 `LRUCache<string, SemaphoreSlim>`（容量上限，如 256）或按最近使用淘汰的 `ConcurrentLru` 包装。
  2. 锁承诺「同会话串行」语义不变——淘汰仅影响新进会话的第一把锁竞争，不影响正确性。
- **验证标准**：注入 1000 个不同会话名，断言字典 `Count ≤ 上限`；同一会话并发仍串行（现有并发测试通过）。

### 工作 J：种子上下文去冗余（Y3）

- **现状**：同值多键播种。
- **目标**：按消费方真实所需只播种一次，保留关键兼容别名。
- **改动**：
  1. 保留 `question`（answer 消费）与 `l1=text`（cline_execute 消费「本轮问题」）为主源。
  2. `user_input` 迁移为 `question` 的兼容别名（`RoundStateMapper` 读取侧统一到 `question`，逐步下线 `user_input`）。
  3. `conversation/prompt` 与 `l2` 收敛为以 `l2`（历史窗口）为准，其余由全局 KeyMapping 映射。
- **验证标准**：`RoundSpecLoaderTests` / 模板导入测试断言每个种子键有且仅有一个权威来源；全链 LLM 输入与重构前一致。

## 五、分阶段实施计划

> 每阶段独立可部署、可回归；后继阶段不依赖先前阶段的非必要中间态。

| 阶段 | 工作项 | 理由 | 回归信号 |
|---|---|---|---|
| P0 | A（取消语义） | 错误语义面最高风险 | agent_conversation_* 全脚本 + 取消注入单测 |
| P1 | B（成功契约）· C（act 参数）· E（错误单通道） | 契约收敛，影响面集中 | ConversationPipeline/RoundSpec 测试组 |
| P2 | D（双写治理）· F（单收割） | 持久化收敛，依赖 P0/P1 单通道 | ReferenceGroundingWriteThrough + 持久化测试 |
| P3 | G（单例注入）· H（Send 带历史）· I（锁有界）· J（种子去重） | 纯开销/整洁，风险最低 | 既有 Agent 全量测试 + LLM 脚本回归 |

**依赖约束**：H 需先于任何「Send 返回值消费方」改动；C 需同步更新模板与默认参数白名单；否则模板热载会出现缺参。

## 六、回归风险与回退策略

- **风险1（B）**：若某上层读取 `result.Ok`，收敛后语义需显式迁移；先在代码库 grep `\.Ok` 确认消费点再改。
- **风险2（H）**：`ConversationReply` 增加字段是契约变更；先加字段 + 旧路径共存一个版本，再切 `ConversationSendAsync` 不再重读。
- **风险3（Ins/I）**：竞态仅在超并发时暴露；用「保留 + 淘汰+重建」策略保证锁承诺不变。
- **回退**：每项独立提交、独立 revert；P 阶段可单独回退不牵连他项。改动全程保留旧 Array 快照/No-op 守卫。
