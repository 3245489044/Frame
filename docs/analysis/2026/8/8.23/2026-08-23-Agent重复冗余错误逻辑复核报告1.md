## 三、错误逻辑（Erroneous）

### E1.【中-高】`LlmStateDirector` 写入 `RunContext.SchedulerContext` 后从不清理（AsyncLocal 陈旧状态泄漏，本轮新发现）

- **位置**：
  - 写入：`src\Agent.Axioms\Scheduling\LlmStateDirector.cs` `GenerateWithToolsAsync`（L94）`if (RunContext.Current is { } rc) rc.SchedulerContext = context;`
  - 承载：`src\Agent.Runtime\State\Loops\RunContext.cs` `SchedulerContext { get; set; }`（L62，普通可写属性）
  - 消费：`src\Agent.Axioms\SemanticKernel\Functions\SchedulerAssistantTools.cs`（L23/L33 经 `AgentRunCancellation.GetSchedulerContext()` 读取）
- **现象**：**[已验证]** `RunContext.Enter` 返回的 `ScopeRestore.Dispose` **只恢复 `_current.Value` 实例引用**（`RunContext.cs:40-43`），**不清理已设置实例内的 `SchedulerContext` 属性**。同一 run 内 `RunContext.Current` 指向同一 `RunContext` 实例，而 `SchedulerContext` 是该实例上的可写属性：
  1. **陈旧残留**：某轮走 tools 路径（`_enableToolCalling=true`）写入后，后续轮若 `_enableToolCalling=false`（或该轮生成失败提前 return），`SchedulerContext` 保留**上一轮**的调度快照；辅助工具读到过期 `AvailableStrategyIds`/`Telemetry`。
  2. **跨 run 泄漏**：若 run 结束未重建 `RunContext` 实例（或嵌套 Enter 恢复前值引用同一实例），`SchedulerContext` 可泄漏到外层/并行作用域。
- **根因**：作用域恢复只做"引用还原"，未对"可写属性"做清理/还原；`SchedulerContext` 属当轮导演私有上下文，却挂在跨轮共享的 `RunContext` 上且无生命周期管理。
- **建议**（任选其一）：
  - 在 `GenerateWithToolsAsync` 的 `finally` 中 `rc.SchedulerContext = null`（最直接）；
  - 或在 `RunContext.Enter` 的 `ScopeRestore` 中保存并还原 `SchedulerContext` 原值（对嵌套最稳健）；
  - 或把调度导演上下文移出 `RunContext`，改为 `LlmStateDirector` 实例内 `AsyncLocal<SchedulerDirectorContext?>` 私有字段（隔离导演私域，不污染共享 run 上下文）。

### E2.【低】`QuerySnapshotAsync` 的 `ContinueWith(t.Result)` 异常/取消语义缺失（08-19 报告 ⑦ 残留一处）

- **位置**：`src\Agent.StorageBridge\Storage\StorageBridgeCommands.cs` `QuerySnapshotAsync`（L185-187）：
  ```csharp
  => db.Snapshots.LoadAsync(...).ContinueWith(t => (object)new { ... t.Result }, ct);
  ```
- **现象**：**[残留]** 08-19 报告（错误 7）指出该类多处 `ContinueWith(t.Result)` 无异常/取消分支；本轮复核确认 `StoreCheckpointAsync` 等**已改 `await`**（注释 `A6.4`），但 `QuerySnapshotAsync` **仍残留** `ContinueWith(t.Result)` —— 上游 DB 失败会抛 `AggregateException` 且吞掉取消语义。
- **建议**：改为 `await` + 直接构造返回值，与同文件其余方法一致。

### E3.【低】`McpClientManager.Dispose` 同步阻塞等待残留（08-19 报告 ① 部分修复）

- **位置**：`src\Agent.Modules\MCP\McpClientManager.cs` `Dispose()`（L421-438）：
  ```csharp
  Task.Run(() => DisconnectAsync().GetAwaiter().GetResult()).GetAwaiter().GetResult();
  ```
- **现象**：**[残留]** 08-19 报告（错误 1）的"UI 线程死锁"风险已通过 `Task.Run` 脱离 `SynchronizationContext` 规避（注释 `A1`）；但仍是**同步阻塞等待整个 `DisconnectAsync`**，而 `DisconnectAsync` 最坏可阻塞约 60s（读循环已停、shutdown 响应无人读取时），会**阻塞线程池线程**。属"死锁已解、阻塞未除"。
- **建议**：若调用方可异步化，改 `DisposeAsync`/`await DisconnectAsync`；否则在 `DisconnectAsync` 内为 shutdown 单独设短超时。
