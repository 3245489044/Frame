## 1. 背景与定位

`HierarchyMethod` 现有定位（见功能分析文档）是**零 LLM、通用、层次（Nodes → Tasks → History）的编排骨架**。当前 `Projects/Agent/src` 中"节点 → 上下文 → Cline 执行器"这条链路，本质上是**通用编排框架 + LLM 专属提示词协议 + Cline 专属传输**三者混在一个应用层里。

前版方案把它拆成"执行引擎 + 端口"。第二版把**上下文组装**提升为更通用的框架，按 HierarchyMethod 既有三层结构重组，使被抽取物成为**跨 Nodes / Tasks / History 三层的通用编排框架**，而不是孤立的执行循环：

```
上下文组装 = 节点的编排(Node) + task 的复用(Tasks) + history 的构建(History)
```

**抽取目标**：把链路中"与 LLM / 具体执行器无关"的编排能力下沉为跨三层的通用框架；把"L0/L1/L2 提示词协议、Cline daemon 传输、边界框架"留在 Agent 作为可注入适配器。对齐现有"框架本体零 LLM"原则。

### 2.1 链路现状（Agent 侧）

```

① RoundSpecLoader(Agent.Core/Nodes)
   └─ agent-loop.json ──► RoundSpec / RoundStep(已在 HierarchyMethod.Nodes.Workflows)
      ^ 一份 worklow = 一个"可复用 task 模板"

② WorkflowRunner(Agent.Core/Nodes) ──► StaticAsyncPipeline<RoundPipelineContext>（按序执行节点）

⑥ provide_prompt(PromptFrameworkFunction)   ← 上下文投影（LLM 专属）
   └─ user_input/goal/plan_summary/exec_result ──► L0/L1/L2 ──► system/l1/l2
     （L1 按 taskKey 缓存 = 任务级复用）

   └─ system/l1/l2 + session/cwd/provider ──► AgentExecutorRequest
⑧ EndpointResolver ──► IExecutionEndpoint(ClineDaemon/Local)

各轮产物 ──► NodeExecutionRecord + decision + exec_result ──► 节点输出端口/引用边
        ──► 归并到任务(ur_tasks) 与历史(ur_histories) 引用关系   ← history 构建
```

## 3. 抽取边界与目标抽象（三层通用框架）

下沉到 HierarchyMethod 的新增抽象（命名空间 `Operation.HierarchyMethod`），**按三层组织**：

### 3.1 Nodes 层 —— 节点编排（NodeGraphOrchestrator）

收敛执行循环为统一编排器，只依赖函数调用端口，零 LLM：

```csharp
namespace Operation.HierarchyMethod.Nodes.Execution;

/// <summary>节点图编排器：按工作流(节点集)顺序列表，解析入参→调函数→持久化输出，自建节点关系。</summary>
public sealed class NodeGraphOrchestrator
{
    public NodeGraphOrchestrator(
        INodeFunctionInvoker    functionInvoker,  // 函数调用端口（解耦 WorkFlowMethod）
        IDataSpaceFactory?      dataSpaceFactory, // 数据空间工厂（默认内存）
        INodeExecutorHooks?     hooks,            // onAfterStep / onStepError 横切
        INodeOutputStore?       outputs,          // 节点输出端口（可空增强）
        INodeStore?             nodes,            // 图关系库（可空）
        IReferenceGrounding?    grounding);       // 自动建边（task→node / node→node）

    Task<NodeRoundResult> RunRoundAsync(
        NodeWorkflowSpec spec,   // = RoundSpec（Nodes 层工作流模板）
        NodeRoundContext ctx,    // 会话/轮作用域（Tasks 层注入）
        CancellationToken ct = default);
}

/// <summary>函数调用端口 —— 解耦"引擎调用注册函数"与"具体注册表（WorkFlowMethod）"。</summary>
public interface INodeFunctionInvoker
{
    Task<IReadOnlyDictionary<string, object?>> InvokeAsync(
        string funcName,
        IReadOnlyDictionary<string, object?> parameters,   // 参数一律经 FunctionContext 语义
        CancellationToken ct);
}
```

> 编排 → TaskGraphService / 引用边维护 → NodeToNode / task→node（复用现有关系服务，引擎只编排不复制写边）。

### 3.2 Tasks 层 —— 任务复用（task 模板实例化 + 会话/轮复用）

把"一份工作流被不同 task/会话反复实例化"显式化为端口：

```csharp
namespace Operation.HierarchyMethod.Tasks;

/// <summary>任务作用域提供器：给定 worklow 模板 + taskKey/session，解析本轮种子状态供编排。</summary>
public interface ITaskScopeProvider
{
    Task<TaskScope> ResolveTaskScopeAsync(
        NodeWorkflowSpec spec, string taskKey, string? sessionId, CancellationToken ct);
}
/// <summary>一轮实例化的任务作用域：种子数据空间 + 已归并历史键集 + 轮状态头。</summary>
public sealed record TaskScope(
    string TaskKey, string? SessionId, int Round,
    IReadOnlyDictionary<string, object?> Seeds,   // RoundStateMapper.Seed 的通用形态
    string? HistoryId);                            // 归并到哪个历史容器
```

要点：
- `RoundStateMapper.Seed/Harvest` 通用化为 `ITaskScopeProvider`（种子提取）与收割回调，Agent 用 StateCenter 适配。
- **L1 任务级缓存（keyed by taskKey）**是"任务复用"的 LLM 侧体现，保留在 Agent 投影器适配器，框架只定义缓存端口/键命名约定。

### 3.3 History 层 —— 历史构建与回喂（HistoryProjector）

把"每轮产物沉淀为历史、历史再投影为下一轮上下文"通用化：

```csharp
namespace Operation.HierarchyMethod.History;

/// <summary>把一轮编排结果追加到历史容器，并把累积历史投影为下次执行的上下文。</summary>
public interface IHistoryProjector
{
    /// <summary>每个节点/任务执行后调用，沉淀历史记录 + 引用边（history_owns_task / session_owns）。</summary>
    Task PersistRoundAsync(NodeRoundResult round, TaskScope scope, CancellationToken ct);

    /// <summary>把某 task 累积历史投影为下一轮执行上下文（事务无关的只读重建）。</summary>
    Task<NodeRoundInput> BuildContextAsync(
        string taskKey, string? sessionId, CancellationToken ct);
}
```

要点：
- `NodeExecutionRecord + decision + exec_result + rule_match` 本轮沉淀为 `HistoryRecord`，通过 `HistoryRelationManager` 建 `history_owns_task / session_owns` 边。
- **"上下文组装"的终点** = `BuildContextAsync`：从历史重建 `NodeRoundInput`，交给投影器（Agent 的 `provide_prompt`）填 L0/L1/L2。
- `IExecutionContextProjector`（前版）并入历史回喂 + 提示词投影，成为三层的粘合点。

### 3.4 中立契约（跨三层共享）

```csharp
namespace Operation.HierarchyMethod.Nodes.Execution;
public sealed record NodeExecutionRequest(
    IReadOnlyDictionary<string, string?> Messages,  // system / user1 / user2 …（不含协议知识）
    string? SessionId = null, string? WorkingDirectory = null,
    IReadOnlyDictionary<string, object?>? Extras = null);

public sealed record NodeExecutionResult(
    string Text, string? Decision, bool Ok, Exception? Error = null,
    IReadOnlyDictionary<string, object?>? Extras = null);   // ClineResult 为富化子类

public sealed record NodeExecutionRequest(
    IReadOnlyDictionary<string, string?> Messages, string? SessionId = null,
    string? WorkingDirectory = null, string? DataDirectory = null,
    IReadOnlyDictionary<string, object?>? Extras = null);
```

## 6. 兼容性与约束落地

| 约束（来源：项目记忆） | 落地方案 |
|----------------------|----------|
| 执行必须经 NodeExecutor + WorkflowContext | 编排器保留 `WorkflowContext` 结构（中立化），函数调用统一经 `INodeFunctionInvoker`，内部仍走 `WorkFlowMethod.Usage` |
| 函数参数一律经 FunctionContext | `INodeFunctionInvoker.InvokeAsync` 只传 `parameters`（FunctionContext 语义），Agent 适配器负责适配 |
| 模块注册用反射 `TryRegister*`，模块不可用不崩 | 三层端口一律可空注入 + `UnavailableDiagnostics` 守卫，未装配走增强路径 no-op |
| 新工具经 MCP Bridge | 执行端点适配器保持走现有 Cline daemon / MCP 传输 |
| 新特性应增强现有循环而非新建模块 | 本抽取是"把现有循环上移为跨三层通用框架"，复用既有 `StaticAsyncPipeline`、`TaskGraphService`、`HistoryRelationManager`，不新增重复执行路径 |
| 诊断存内存、不导出 | 三层编排沿用现有 AgentLog 归集，不落地导出 |

## 7. 风险与验证

| 风险 | 缓解 |
|------|------|
| 编排器改动 `WorkflowRunner` 主循环引入回归 | 六阶段拆分，每阶段独立编译 + 跑一轮验证；复用 `StaticAsyncPipeline` 语义不变 |
| `WfContext`/`WorkFlowMethod` 强耦合难一次性剥离 | `INodeFunctionInvoker` 端口先在 Agent 内做包装层再下沉，调用方不动 |
| 中立结果丢 Cline 富化字段 | 中立基类 + `ClineResult` 子类 `Extras` 保留富化信息 |
| Task/History 归并关系错误 | 复用既有 `TaskGraphService`/`HistoryRelationManager` 写边原语，编排只编排不复制写边 |
| L0/L1/L2 仍绑 Agent.Operation | 明确边界：投影器/执行端点适配器必须留在 Agent，框架只定义端口与历史回喂 |

**验收标准**：
1. `Operation.HierarchyMethod` 编译不含 `Cline` / `L0/L1/L2` / `WorkFlowMethod` 提示词类型依赖。
2. Nodes 编排 / Tasks 复用 / History 构建三个抽象可独立被别的工作流消费（非 Agent 专属）。
3. Agent 侧 `provide_prompt` / `cline_execute` / `EndpointResolver` 退化为端口适配器。
4. 三种执行路径（agent-loop / collect-analyze-act / Task 即对话）一轮行为与抽取前一致；跨轮历史回读上下文可重建。
5. `node.*` 输出端口 / 终态信封补写 / rule_match 决策判定无回归。

## 实施记录（2026-08-25 三阶段落地）

### 阶段一 · 中立契约
- 新增框架契约（`Operation.HierarchyMethod.Nodes.Execution`）：`NodeExecutionRequest` / `NodeExecutionResult` / `NodeRoundResult` / `NodeRoundInput` / `EndpointProgress` / `IExecutionEndpoint`。
- `IExecutionEndpoint` / `EndpointProgress` 自 Agent.Modules 下沉框架；Agent 端点（ClineDaemon/Local/Answer）改为实现框架中立接口。
- **设计差异**：方案要求 `ClineResult` 直接继承 `NodeExecutionResult`，但 `AgentExecutorResult.Error`(string?) 与方案 `NodeExecutionResult.Error`(Exception?) **同名属性类型冲突**。改为 **`NodeExecutionContract` 映射助手 + `Extras` 承载富化**（FailureStage/EmptyReason/TokenUsage/StopReason 往返，rule_match 结构化归因不丢）。
- `NodeExecutionResult.Error` 最终采用 `string?`（比 Exception 更中立且与 AgentExecutorResult 对齐）。

### 阶段二 · 函数调用端口
- 新增 `INodeFunctionInvoker` + Agent 适配器 `WorkFlowMethodFunctionInvoker`（包 `WorkFlowMethodUsage.CallFunctionAsync`，构造 WorkflowContext，参数经 FunctionContext 语义）。
- `NodeExecutionService.ExecuteAsync` 消费端口，摆脱 `WfContext` 直调。
- **设计差异**：方案端口返回 `IReadOnlyDictionary<string,object?>`，但节点端口定向提取（`ExtractProps` 的 ClineResult 按 ResultKeys 全写）需节点上下文，沉入中立端口会泄漏 Agent 类型或改变行为。改为返回**原始返回值 `object?`**，提取留在节点层。

### 阶段三 · NodeGraphOrchestrator（无适配器方案）
- 新增框架编排器 `NodeGraphOrchestrator`（`RunRoundAsync` 主循环）+ 策略端口 `IWorkflowDecisionPolicy` / `IFinalAnswerPolicy` / `IRoundStatePort` / `INodeExecutor` + `NodeRoundContext` + `NodeExecutionKeys`。
- **无适配器**：不建包装 Adapter，现有类直接实现框架端口：
  - `RoundStepInvoker` 直接实现 `INodeExecutor` + `INodeExecutorHooks`（执行返回 record + 横切持久化 + 错误归因）。
  - `WorkflowRunner` 直接实现 `IWorkflowDecisionPolicy` + `IFinalAnswerPolicy` + `IRoundStatePort`，删除 `BuildPipeline`，主循环委托 `NodeGraphOrchestrator`。
- **关键迁移**：
  - `RoundPipelineContext` → 框架 `NodeRoundContext`（`StateAdapter` 从 ctx 移到 `RoundStepInvoker.StateAdapter` 实例字段，因 NodeRoundContext 是中立类型）；`RoundPipelineContext.cs` 主代码停用、文件保留（测试 `StateContextAdapterTests` 仍引用）。
  - guard_input echo / return spec 移入 `RoundStepInvoker.ExecuteStepAsync`；guard_output + `RoundStateMapper.Harvest` + 终态信封移入 `WorkflowRunner`（`IRoundStatePort.HarvestAsync`）。
  - `INodeExecutorHooks` 签名带 `ctx`（持久化需从 ctx 检索步骤产物）；`INodeExecutor.ExecuteStepAsync` 带 `globalMapping`（来自 spec）。
- **验证**：`HierarchyMethod` / `Agent.Launcher` / `Agent.Core.Tests` / `Agent.Axioms.Tests` 全编译通过；`RoundStepInvokerTests` 4/4 通过。

### 阶段四 · TaskScopeProvider + 历史沉淀（Tasks/History）
