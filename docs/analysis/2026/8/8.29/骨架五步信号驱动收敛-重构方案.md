# 骨架五步 → 信号驱动主循环收敛重构方案

> **版本**：v0.1（重构设计稿）　**日期**：2026-08-29
> **延续**：承接《信号驱动SK会话主循环整合方案》（同目录 8.29）——该方案已将会话路径整合进 `SignalDrivenFoldEngine` 单一推进机制；
> 本方案进一步把遗留的**骨架五步**（`guard_input → provide_prompt → cline_execute → rule_match → guard_output`）中
> 的三个步骤收敛进 skill 体系与信号处理，并删除执行器薄包装，实现真正**单一路径、单一 skill 注入口径、单一信号裁决**。
> **方向（决策）**：
> 1. `guard_input` + `provide_prompt` → **合并进 skill 逻辑**，增强现有 skill 加载（skill 成为提示词统一入口）；
> 2. `rule_match` → **合并进信号处理**，其决策本质是一条信号（`FoldSignalKind`）；
> 3. `cline_execute` → **薄包装，删除**（真正执行在 `IAgentExecutor`，workflow function 只是壳）。

## 一、背景与目标

### 1.1 现状问题（静态分析结论）

主循环存在**两条并列推进机制**与**三个游离步骤**，违反 `SingleImplementation` / `RedundancyElimination`：

| 推进机制 | 载体 | 状态 |
|----------|------|------|
| 骨架五步管线 | `WorkflowRunner` 内层 `guard_input→provide_prompt→cline_execute→rule_match→guard_output` | 遗留主循环 |
| 信号驱动折叠 | `SignalDrivenFoldEngine` + `ChainSignalResolver` + `SkConversationFoldOperator` | 已整合的会话路径 |

骨架五步中的三个步骤与信号驱动模型职责重叠：

- **`provide_prompt`（L0/L1/L2 装配 + SkillBlock 注入）** 与 `SkConversationFoldOperator.ExpandAsync` 的「选 skill → Build → 拼 system」**重复实现**，且选择器口径不一致（主循环 `Select` 不含 Rare，折叠 `SelectWithRare` 含 Rare）。
- **`guard_input`（输入安全过滤）** 与信号驱动的 `ExternalInput` 载荷输入应统一做安全过滤，但散落在 workflow function。
- **`rule_match`（continue/stop/error 决策）** 与信号驱动的 `ChainSignalResolver` 链推进 / `FoldSignalKind`（`StepCompleted`/`Terminal`）**语义重叠**——决策词本质可视为一条信号。
- **`cline_execute`（取 system/l1/l2 → ResolveExecutor → ExecuteAsync）** 是**薄壳**，真实逻辑在 `IAgentExecutor`（`ClineAgentExecutor`）/ 折叠算子 `SkConversationFoldOperator` 已含执行分发；workflow function 包装冗余。

### 1.2 目标

```
一条主循环 = 信号驱动折叠（SignalDrivenFoldEngine）
一个 skill 入口 = SkillInjector（合并 输入安全过滤 + L0/L1/L2 装配 + SkillBlock 注入）
一个信号裁决 = 决策信号化（rule_match 语义 → FoldSignalKind / ChainSignalResolver）
一个执行面 = ISignalDrivenOperator（删除 cline_execute workflow function 薄壳）
```

## 三、重构设计

### 3.1 方向 A：`guard_input` + `provide_prompt` → skill 逻辑（SkillInjector 统一入口）

**目标**：把「输入安全过滤 + 分层提示词装配 + SkillBlock 注入」合并为单一 `SkillInjector`，`skill` 成为 system 提示词的唯一统一入口，增强 skill 加载（skill 可声明承载 L1/L2 语义）。

**新增** `Agent.Modules/Skill/SkillInjector.cs`：

```csharp
// 单一装配入口：输入守卫 → 选 skill → 装配分层 system（L0 + SkillBlock）→ 返回
public static class SkillInjector
{
    public sealed record InjectResult(
        string System,              // L0 + SkillBlock（原 provide_prompt assemble）
        IReadOnlyList<string> SelectedSkills,
        string? BlockedReason,      // 输入守卫命中 → 非空
        string? L1, string? L2);    // 承载任务/步骤级语义（skill front-matter 可扩展）

    public static async Task<InjectResult> InjectAsync(
        string userInput, string goal, string taskKey,
        string? constraints = null, string? hint = null,
        IReadOnlyList<SkillDefinition>? hot = null,
        IReadOnlyList<SkillDefinition>? rare = null,
        CancellationToken ct = default);
}
```

**职责合并**：
1. **输入守卫（原 guard_input）**：`InputSafetyGuard.Check(input)` → 命中返回 `BlockedReason`（复用 `GuardFunction.CheckInputSafety` 逻辑，抽到 `Agent.Guardrails` 纯函数 `InputSafetyGuard`，供 SkillInjector 调用，`GuardFunction` 仅保留 `guard_output`）。
2. **选 skill（统一口径）**：统一走 `SkillSelector.SelectWithRare` 语义（热集 + 懒集，显式点名才注入 Rare；自动匹配恒排 `OnDemand`），消除 `Select`/`SelectWithRare` 两路径口径分歧。
3. **装配（原 provide_prompt）**：`SkillPromptAssembler.Build(selected)` → `System = L0 + SkillBlock`；L1/L2 由 skill `front-matter` 扩展承载（`kind: task`/`step`），或回退既有 `PromptCatalog.BuildL1/L2`。

**消费点替换**：
- `PromptFrameworkFunction` 的 `skills` 阶段 → 委托 `SkillInjector`（或整段收敛，见方向 C 的执行面收敛）。
- `SkConversationFoldOperator.ExpandAsync` 的选 skill + Build → 委托 `SkillInjector.InjectAsync`。

**注意**：`InputSafetyGuard` 从 `Agent.Guardrails` 抽取纯函数后，`SkillInjector`（Agent.Modules）依赖 `Agent.Guardrails` 需确认项目依赖无环（`Agent.Modules` 可引用 `Agent.Guardrails`）；若成环则把 `InputSafetyGuard` 下沉到 `Agent.Axioms` 公共守卫库。


### 3.2 方向 B：`rule_match` → 信号处理（决策信号化）

**目标**：`rule_match` 的 `continue/stop/error` 决策本质是信号，并入 `FoldSignalKind` / `ChainSignalResolver`。

**现状语义对齐**：
- `continue` ↔ `StepCompleted`（链推进）→ `ChainSignalResolver` 表驱动映射下一步；
- `stop` ↔ `Terminal`（链终点）→ 框架 `SignalCutoffPolicy` 收敛成功 `run_to_end`；
- `error` → 映射 `ICutoffPolicy` 截断（预算终止 / 失败收敛），归 `ErrorClass` 分类。

**改动**：
1. 扩展 `FoldSignal` 可选携带决策载荷：`FoldSignal<TVertex>` 新增 `Decision` 字段（`FoldDecision` 枚举：`Continue/Stop/Error`，对应 `DecisionWordClassifier` 词表），使信号可表达规则语义。
2. 新增 `RuleSignalResolver : ISignalResolver`：当信号携带决策时——`Stop→null(链终点)`、`Error→null+error 标志`、`Continue→查 ChainSignalResolver 转移表`；无决策载荷时回退纯表驱动（既有 `ChainSignalResolver`）。
3. **删除 `RuleMatchFunction` 的 workflow function 注册**；其规则评估内核 `RuleEngine`/`RuleSetLoader` 保留，作为「决策 → 信号」的规则求值器（`RuleDecisionEvaluator.Evaluate(execResult, stepCount) → FoldDecision`），被算子或解析器调用。
4. `DecisionWordClassifier`（决策词→`LoopDecision`）与 `FoldDecision` 收敛为单一映射（`DecisionWordClassifier.Map` 是唯一权威，`FoldDecision` 为其信号域投影）。

### 3.3 方向 C：`cline_execute` 薄包装删除

**目标**：`ClineExecutorFunction` 仅是「读 system/l1/l2 → `ResolveExecutor` → `ExecuteAsync`」的壳，真正执行在 `IAgentExecutor`；折叠算子 `SkConversationFoldOperator.DispatchAsync` 已含执行分发（进程内直调/MCP/SK 聊天）。

**改动**：
1. **删除** `Agent.Modules/Cline/ClineExecutorFunction.cs` 及其 `Register()`（`WorkflowFunctionRegistrar` 注册）。
2. 执行面统一由 `ISignalDrivenOperator`（`SkConversationFoldOperator`）承担：skill 声明 `executor: cline` → `ClineFoldExecutor`（复用 `ClineAgentExecutor`，进程内直调）→ 未命中回退 MCP → 皆缺 SK 聊天兜底（`DispatchAsync` 现状已含）。
3. `IAgentExecutor` 注册表（`AgentRuntimeManager.ResolveExecutor`）保留——由算子/编排解析执行器，删除 workflow function 中转。
4. 同步清理依赖 `cline_execute` 的模板/端口（`agent-loop.json` 骨架、`WorkflowRunner` 内层步骤表）。
