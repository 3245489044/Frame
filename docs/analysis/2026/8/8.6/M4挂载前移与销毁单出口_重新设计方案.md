# M4 挂载前移与销毁单出口 — 重新设计方案

> 依据：《FrontEndDriven_ECS基准渲染重构方案.md》§M4（生命周期与挂载收编）执行后的遗留再设计。
> 现状基线：M1/M2/M3/M5/M6 已落地（HEAD 63aff8c4 + 1a26796e），脚本 5（47/47）、脚本 7（12/12）、脚本 10（35/35）全绿。

## 一、问题速览

| # | 遗留 | 性质 | 现状 |
|---|------|------|------|
| 1 | **root 创建依赖 Apply（架构冲突）** | 挂载时相 | `RenderStageRunner.cs:133` 记载：挂载前移尝试因 root 控件由 Apply 创建而回滚；root 未注册时 `AttachRootToHost` 入待挂队列、宿主计数为 0 → 布局基准在挂载前按未就绪宿主定死 |
| 2 | **销毁无单出口** | 生命周期 | `EcsGate.DestroyScopeAsync` 三分支（`_compositionLifecycle` / `_scopeDestroyer` / `DestroyScopeEntities` 兜底）；`ConfigurationLifecycleManager` 双职责（启动编排 BootstrapAsync + 销毁 DestroyScopeAsync） |
| 3 | **ContainerRegistry 状态与 ECS 挂载状态双轨** | 状态收敛 | `ContainerRegistry` 仍持有挂载状态写入口（`MarkMounted`/`MarkUnmounted`），与 ECS 挂载状态语义并存 |

## 二、现状分析

### 2.1 渲染时相（挂载前移阻塞点）

```
Collect(CsgEntryPoint 全量快照) → Apply(WinFormApplier 全量 SetBounds/Add，创建 root 实体控件+Register)
  → Mount(RenderMountStage: AttachRootToHost + TryAttachPending) → Bind(EventBindingSystem)
```

- **root 物理控件唯一创建点 = WinFormApplier（Apply 阶段）**（`RenderPipelineStages.cs:277` 注释明确）。
- `HostMountService` 已有「待挂队列 + TryAttachPending 自愈补挂」，但补挂时相仍在 Apply 之后。
- `HostBasisSystem`（宿主基准决议）在渲染前执行 → 宿主未挂载 root 时基准来自父链/窗口，非真实客户区。

### 2.2 销毁路径（多套并存）

```
EcsGate.DestroyScopeAsync
  ├─ StateCenter 收敛路径：_compositionLifecycle.ScopeDestroyed(scope)   （R3/R5 已接入，唯一目标路径）
  ├─ 旧路径：_scopeDestroyer.DestroyScopeAsync(scope)                    （ConfigurationLifecycleManager）
  └─ 兜底：_composition.DestroyScopeEntities(scope)

ConfigurationLifecycleManager（IScopeDestroyer）
  ├─ BootstrapAsync：启动编排（按 BootPhase 逐 scope LoadToScopeAsync）
  └─ DestroyScopeAsync：PlatformEvent.Destroying → OnBeforeDestroy 钩子 → DestroyScopeEntities → OnAfterDestroy → Destroyed
```

- `StateCenter` 已聚合三个生命周期 Provider（`IScopeLifecycle`/`ICompositionLifecycle`/`IContainerLifecycle`，`StateCenterFactory` 装配），但 EcsGate 仍保留旧分支（兼容未收敛前）。

### 2.3 挂载状态

- 写入口分散：`HostMountService.SetMounted` → `ContainerRegistry.MarkMounted`；`RenderStageRunner` 销毁时经 `IContainerLifecycle.MarkMounted(false)`；`ContainerRegistry.MountState` 枚举。
- 设计目标（原方案 §136）：`ContainerRegistry` 降级只读宿主寻址表，挂载状态移入 ECS。

## 三、目标设计

### 3.1 挂载前移（root 先挂 → 基准就绪 → 投影子树）

**核心思路**：把 root 物理控件创建从 Apply（WinFormApplier 内）**前移到挂载阶段**——在 Collect 之后、Apply 之前创建 root **空壳控件**并挂入宿主，使：

1. 宿主在投影子树前**已收到 root**（真实客户区就绪）；
2. `HostBasisSystem` 基准决议可在**挂载后**执行（基准来源 = 真实宿主客户区）；
3. Apply 只负责填充子树（root 已挂载则幂等跳过创建）。

```
新时相：Collect → PreMount（创建 root 空壳 + 挂入宿主）→ HostBasis（基准决议，宿主已就绪）
  → Apply（填充子树；root 幂等）→ Bind
```

**改动点**：
| 位置 | 改动 |
|------|------|
| `WinFormApplier` | root 控件创建逻辑抽离；Apply 对 root 实体检测「已挂载」则跳过创建（幂等） |
| 新 `PreMountStage`（或 `RenderMountStage` 前移） | 在 Apply 前经 `HostMountService.CreateAndAttachRoot(scope)` 创建 root 空壳并挂宿主 |
| `HostMountService` | 新增 root 空壳创建语义（`Dock=Fill` 占位），取代「仅解析已存在 root」 |
| `HostBasisSystem` | 基准决议移到挂载后触发（订阅挂载完成事件或 PreMountStage 后调用） |
| 待挂队列 | 保留为兜底（root 创建失败/宿主未解析时入队），但正常路径不再依赖「Apply 后补挂」 |

**幂等与安全**：
- 重复渲染（同 scope）：root 已挂载 → PreMount 短路；宿主子控件数不叠加。
- root 0x0 兜底：空壳以 `Dock=Fill` 占位，尺寸由宿主决定；子树投影后 layout 重算覆盖。

### 3.2 销毁单出口（迁移 StateCenter）

**目标**：销毁序列唯一化，全部经 `StateCenter`（`ICompositionLifecycle.ScopeDestroyed` + `IScopeLifecycle` 状态机）。

| 位置 | 改动 |
|------|------|
| `ConfigurationLifecycleManager` | 移除 `DestroyScopeAsync` 与 `IScopeDestroyer` 实现，**收敛为启动编排**（`BootstrapAsync` 保留）；销毁经 StateCenter |
| `EcsGate.DestroyScopeAsync` | 三分支收敛为**单一路径** `_compositionLifecycle.ScopeDestroyed(scope)`（删除 `_scopeDestroyer` 分支与 `DestroyScopeEntities` 兜底；`IScopeDestroyer` 接口废弃） |
| `ScopeLifecycleAdapter`（StateCenter 已装配） | 承载完整销毁序列：`PlatformEvent.Destroying` → `OnBeforeDestroy` 钩子 → `composition.ScopeDestroyed`（ECS 销毁）→ `HostMountService` 物理卸载 → 投影索引清理 → 状态复位 → `OnAfterDestroy` → `PlatformEvent.Destroyed` |
| `RenderStageRunner.DestroyScopeEntities` | 保持 ECS 销毁职责；挂载状态写统一经 `IContainerLifecycle`（现状已如此，见 2.3） |

**销毁序列唯一权威**：`StateCenter.Scopes`（`IScopeLifecycle`）——挂载/销毁/重载状态机（原方案 §82 新增 `ScopeLifecycleSystem` 的方向由 StateCenter 生命周期 Provider 承载）。

### 3.3 ContainerRegistry 降级 + 挂载状态入 ECS

| 项 | 设计 |
|----|------|
| `ContainerRegistry` | 降级为**只读宿主寻址表**（`ResolveByScopeOrHostKey`/`ResolveScopeByHostKey` 保留）；`MarkMounted`/`MarkUnmounted`/`MountState` 写入口移除，挂载事实读 ECS |
| ECS 挂载状态 | 新增 `MountStateComponent`（scope/hostKey/mounted/at）；`MountStateMachine`（或 `HostMountService` 内部）为**唯一写入口**（挂载/卸载/作用域失效联动） |
| 消费方迁移 | `ContainerAssertionService`/`ValidateMountSystem` 读 ECS 挂载状态（`MountStateComponent`），替代 `ContainerRegistry.GetMountState` |
| `ContainerLifecycleAdapter` | 改为读 ECS 投影（转发 MountStateComponent），不再直接写 Registry |

## 四、实施步骤（独立任务，按序推进）

### M4a 挂载前移（先做，依赖最小）
1. `WinFormApplier`：抽离 root 创建 → 幂等短路（root 已挂载跳过）。
2. 新 `PreMountStage` 或 `RenderMountStage` 前移：Apply 前 `CreateAndAttachRoot(scope)`。
3. `HostBasisSystem` 基准决议移到挂载后。
4. 回归：脚本 5/7/10 + `dock_layout_demo`（宿主自愈）。

### M4b 销毁单出口
1. `ScopeLifecycleAdapter` 补全销毁序列（钩子/事件/物理卸载/状态复位）。
2. `ConfigurationLifecycleManager` 移除销毁职责（仅留 BootstrapAsync）。
3. `EcsGate.DestroyScopeAsync` 收敛单一路径；`IScopeDestroyer` 废弃（R2 流程）。
4. 回归：脚本 10（侧边栏切换 WorkflowInputUI 替换 MathFunctions 的销毁正确性）、无实体泄漏（`GetEntityCount` 回稳）。

### M4c Registry 降级 + 挂载状态入 ECS
1. 新增 `MountStateComponent` + `MountStateMachine`（唯一写入口）。
2. `ContainerRegistry` 只读化（移除写入口）。
3. 消费方迁移（`ContainerAssertionService`/`validate-mount` 读 ECS）。
4. 回归：脚本 7（`validate-mount` 12/12）+ 单测（MountState 状态机）。

## 五、风险与回滚

| 风险 | 级别 | 缓解 / 回滚 |
|------|------|-------------|
| root 空壳创建时序错乱 → 宿主子控件计数异常（重复 Add） | 高 | 幂等短路 + 已挂载检测；回滚：恢复 Apply 内创建 + 待挂队列补挂（现状） |
| 基准决议移动后布局基准变化 → 比例布局偏移 | 高 | 挂载后基准 = 真实客户区（预期更准）；对比 dock demo/脚本 7 位置断言；回滚：基准决议保持渲染前 |
| 销毁单出口迁移丢生命周期钩子语义（OnBeforeDestroy/OnAfterDestroy） | 中 | 序列显式保留钩子调用（ScopeLifecycleAdapter 内）；回滚：恢复 EcsGate 三分支 |
| Registry 只读化破坏消费方（ContainerAssertionService 等） | 中 | 先迁移消费方再移除写入口；回滚：恢复 MarkMounted |

## 附录：与既有 M4 方案的差异

- 原方案 §134「挂载前移：root 先挂进宿主 → 宿主尺寸就绪 → 再投影子树」：本次给出**可实施路径**——root 空壳创建前移（解决「root 依赖 Apply」回滚根因），而非仅移动基准决议。
- 原方案 §135「scope 销毁单出口（替代 EcsGate.DestroyScopeAsync/ContainerProjector/DestroyScopeEntities 多套）」：本次明确**收口到 StateCenter 生命周期 Provider**（EcsGate 三分支已部分收敛，本次完成收敛）。
- 原方案 §136「ContainerRegistry 降级只读 + 挂载状态移入 ECS」：本次给出 `MountStateComponent` 具体载体与消费方迁移顺序。
