# 布局基准宿主对齐：容器内控件被裁剪不可见修复方案

> **日期：** 2026-08-06
> **范围：** FrontEndDriven 渲染管线（RenderStageRunner.ExecuteRenderStage → AlignLayoutBasisToHost）
> **关联故障：** `math_functions_test.json` 运行成功（47/47 PASS）但侧边栏 Subtract 等四个运算按钮不可见
> **关联历史：** `侧边栏未加载假阳性分析_validate与控件挂载断链.md`（挂载断链）、`FrontEndDriven_布局重叠缺陷四层重构方案.md`（布局基准）

---

## 1. 现象

脚本 `Math\math_functions_test.json` 全命令 PASS、`Success=true`，但界面侧边栏（sideContainer）中
Add/Subtract/Multiply/Divide 四个运算按钮整行不可见（文本框/分组框可见）。

**关键认识**：命令链与渲染链完全解耦——

- 命令链（`ClickSetGetSystems.cs`）：`ControlFinder.FindByName` 按 **Name** 在真实 WinForms 控件树中递归查找
  （不检查 Visible/尺寸/命中测试），点击走 `btn.PerformClick()` 程序化触发 → 按钮"存在即可点"；
- 渲染链：布局（`LayoutSystem`）→ 快照（`CsgEntryPoint.CollectSnapshot`）→ 应用（`WinFormApplier`/`PropertyApplier.SetBounds`）。

两条链仅以"控件对象在控件树中"为交集，故「不显示」与「运行成功」可并存。

## 2. 根因

`ConfigDrivenControlFactory.CreateRootEntity` 把 root 实体的布局基准 `ContainerSizeComponent`
设为配置 form 宽高（`MathFunctions.unified.json` = **500×480**），全部子控件按该基准比例排布；
而物理宿主 `sideContainer` 是 MainLayout 主分割 Panel2（约 342px 宽，更早运行窗口 1200 宽时约 296px），
root 面板挂载后经 Dock=Fill 兜底填满宿主 → **按 500px 基准排布的按钮行超出宿主可见区被裁剪**：

| 按钮 | 500px 基准下的 x 区间 | 342px 宿主内 |
|------|----------------------|--------------|
| addButton | 47–137 | ✓ |
| subtractButton | 151–241 | ✓ |
| multiplyButton | 254–344 | ✗ 越界 |
| divideButton | 358–448 | ✗ 不可见 |

四个按钮共享同一父容器 functionGroupBox、同一行，故缺陷表现为"整行消失"。

## 3. 修复

`RenderStageRunner.ExecuteRenderStage(scope)` 在渲染收集前新增 `AlignLayoutBasisToHost(scope)`：

1. 经 `HostMountService.ResolveHost(scope)` 解析宿主；
2. 目标尺寸 = 宿主客户区；宿主自身 **0×0**（未挂根前 dock=None，挂载自愈后 Dock=Fill 填满父面板）→
   **回退父面板客户区**（实证：sideContainer hostClient=0x0，父 mainSplitter_Panel2=342x817 有效）；
3. 将 root 实体 `ContainerSizeComponent` 更新为目标尺寸并 `LayoutSystem.RecalculateAll()` 重算，
   使子控件按宿主实际尺寸重排；
4. 幂等短路：基准已一致则跳过；字面 Form 宿主保持配置基准。


342×817 基准下按钮 x 区间：32–94 / 103–165 / 174–236 / 245–307 —— 全部落在 342px 容器内。

## 5. 附带效果

- MainLayout（宿主为非 Form 根容器，实际窗口 1384×861）与 Content（contentContainer 620×815）同步对齐，
  消除同类"设计尺寸 > 宿主客户区"的裁剪（如 ConfigSelector 无 form 段默认 1200×800 基准装进 620px 容器）；
- 新日志 `RenderStageRunner_AlignLayoutBasisToHost`（Info，每次作用域首次对齐）/ `_skip`（Debug，跳过原因）。

## 6. 遗留

- 窗口缩放/分割条拖动后 sideContainer 尺寸变化时，scope 无关的重渲染（`ExecuteRenderStage()` 无参）不做基准重对齐；
  如需可在后续扩展为按 scope 检测宿主尺寸变化触发重对齐。
- 按钮在 342px 宽度下约 62px 宽，长文本（"减法 (Subtract)"）会被裁剪，属配置排版议题，可后续改为两行排布。
