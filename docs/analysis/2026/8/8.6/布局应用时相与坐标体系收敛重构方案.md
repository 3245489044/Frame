# 布局应用时相与坐标体系收敛重构方案（Layout Coherence）

> **版本：** v1.0
> **日期：** 2026-08-06
> **状态：** 方案设计完成，待实施
> **范围：** 布局应用时相（何时应用）、坐标换算出口（单一权威）、物理应用类型感知、阶段数据依赖契约、构建部署单轨
> **关联故障：** `layout_validation_test.json` 三次运行（06:01 / 06:24 / 06:39）持续暴露的：
> - 可见性契约 `inHost=false` 假阴性（7 条告警在布局应用前触发）
> - 重叠检测坐标伪影（terminalPanel 屏幕坐标被重复累加：1832 → 2469）
> - TextBox 高度被 `AutoSize` 回缩（outputTextBox 412x21，后经补丁修复）
> - `FileDriven\BuildOutput` 新旧 DLL 并存（部署不可判定）

---

## 〇、结论摘要

本次关联故障的**三个残留问题不是孤立 bug，而是同一组设计缺陷在不同消费方的投影**：

1. **布局应用时相无单一权威** —— 可见性检查在"布局已应用"之前运行，且无信号可查 → `inHost=false` 假阴性；
2. **坐标体系三基准并存、无统一换算出口** —— ECS form 相对 / 物理 parent 相对累加 / 屏幕绝对三套语义各自手写 → 重叠检测坐标伪影；
3. **物理应用无控件类型感知** —— `SetBounds` 对 TextBox 的 `AutoSize` 回缩无感知，`物理≠ECS` 被当作常态审计而非缺陷信号 → ECS_MISMATCH 常态化。

重构方向：收敛为**单一权威**（对应 `[CR: axioms:Strategy.SingleImplementation@consume]` 与 `[CR: axioms:AX.StateSnapshot@consume]`），而非逐点打补丁。

## 二、设计缺陷清单

### D1 · 布局应用时相无单一权威（何时应用不可判定）

- **证据**：渲染阶段（`RenderVisibilityCheckStage`）先于物理布局应用运行；`MainForm OnLoad` 的 `appliedNodeCount=18` 与管线 `AppliedCount` 是两套计数；Apply 日志 Debug 级。
- **机理**：
  ```
  渲染管线渲染阶段:  Collect → Apply(SetBounds) → Mount → Visibility → Bind
  MainForm OnLoad:    BootstrapAsync → … → appliedNodeCount=18   ← 第二套"应用"路径
  ```
  `RenderContext.ApplyResult` 已由 `RenderApplyStage` 回填（S2 引入），但 `RenderVisibilityCheckStage.CanExecute` 只用 `context.PartRender`，**未 gate 在"布局已应用"信号上**。
- **违反公理**：`[CR: axioms:AX.StateSnapshot@consume]` —— 可见性检查读取的物理状态在不同时相不确定（`readsFrom(s)→deterministic(op,s)` 不成立）。

### D2 · 坐标体系三基准并存、无统一换算出口（SingleImplementation 违反）

- **证据**：同一批控件三套坐标值 —— 重叠检测 `(2469,452)`（屏幕基准，handle 敏感、嵌套重复累加）、可见性检查 `(626,737)`（form 相对累加）、位置报告 `(626,43)`（ECS form 相对）。
- **机理**：三个消费方各自手写换算，互相无编译/运行期一致性约束：
  | 消费方 | 基准 | 换算方式 | 缺陷 |
  |--------|------|---------|------|
  | `RenderVisibilityCheckStage` | form 相对 | 父链 `.Location` 累加（GetFormRelativeBounds） | 依赖"布局已应用" |
  | `ControlTreeWalker`（重叠检测） | 屏幕绝对 | `RectangleToScreen` 覆盖 | handle 状态敏感，嵌套重复累加 |
  | `LayoutInspectSystem`（位置报告） | ECS form 相对 | 直读 `ComputedLayoutComponent` + 物理对照 | 仅对照，不换算 |
- **违反公理**：`[CR: axioms:Strategy.SingleImplementation@consume]` —— 坐标换算应单点化，现状三处重复且语义漂移。
### D3 · 物理应用无控件类型感知（物理≠ECS 被常态化）

- **证据**：TextBox `AutoSize=true` 将 `SetBounds(高 694)` 回缩为 21px；ComboBox 高度受 `DropDownStyle` 约束；`SyncActualContainerSizes` 对 ECS_MISMATCH **只审计不回写**（注释明言"记录架构缺陷"）。
- **机理**：`PropertyApplier.ApplyProperties` → `adapter.SetBounds(…)` 对控件类型无适配；行为适配被补丁散在 `CreateControl`（`ApplyControlBehavior`），而非布局应用内核；`物理≠ECS` 成为常态审计项而非应用失败的缺陷信号。
- **违反公理**：`[CR: axioms:AX.StateSnapshot@consume]` 的确定性子句（同一布局意图 → 同一物理结果）与 `ExternalConsistency` 语义。

### D4 · 管线阶段数据依赖无显式契约

- **证据**：`StagePipeline` 阶段间依赖只靠 `CanExecute` 的隐式标志（`PartRender` / `Snapshot != null`），无"阶段 N 已完成"的可查询信号；下游阶段可无视上游产出直接运行。
- **机理**：`RenderContext` 已有 `ApplyResult` 字段，但**未形成阶段门禁约定** —— `RenderVisibilityCheckStage` 可读未确定状态。

### D5 · 构建部署双轨（运行加载旧 DLL 不可判定）

- **证据**：`FileDriven\BuildOutput` 下新旧两份 `FrontEndDriven.dll` / `Share.LayoutAnalysis.dll` 并存；8.1 文档已记录过"DLL 时间戳"类问题。
- **机理**：**构建输出无唯一部署目录契约**；本轮修复生效（加载新 DLL）纯属运气。

## 三、重构方案（单一权威收敛）

> 原则：与既有公理体系对齐——布局真源 = ECS（M1 单向化），布局应用 = 单一权威阶段，坐标换算 = 单一出口，物理应用 = 类型感知内核，部署 = 单轨。

### S1 · 布局应用状态单一权威（治 D1/D4）

- `RenderContext` 新增阶段信号：`bool LayoutApplied`（`RenderApplyStage` 成功 SetBounds 后置位）。
- `RenderVisibilityCheckStage`：
  - `CanExecute` 增加 `context.LayoutApplied` gate —— 布局未应用 → 跳过并记 `Debug`（明确"检查延后"，而非误报）；
  - 检查中**补打违规控件实际 `Left/Top` + host 尺寸**（诊断日志），使"未应用 vs 真违规"可判定。
- 统一渲染入口：布局应用**唯一**发生在渲染管线 `RenderApplyStage`；`MainForm OnLoad` 只触发渲染、不重复应用（对齐 `[CR: axioms:Strategy.SingleImplementation@consume]`）。
- `WinFormsOutputPort_ApplySnapshot_start` / `WinFormApplier_ApplyResult_summary` 升 **Info**（时相可判定）。

**落点**：`RenderPipelineStages.cs`、`Ports.cs`、`fde_log_messages.json`

### S2 · 坐标换算单一出口（治 D2）

- 新增 `LayoutCoordinateResolver`（唯一权威）：
  - `ToFormRelative(control)` —— 父链 `.Location` 累加（不含窗体，与可见性检查现口径一致）；
  - `ToScreen(control)` —— 统一经 `PointToScreen` 且**显式声明 handle 回退策略**（未创建 → form 相对 + form 屏幕位置，杜绝混合基准）；
  - `FromEcs(ComputedLayoutComponent)` —— ECS form 相对直读。
- 三个消费方（`RenderVisibilityCheckStage` / `ControlTreeWalker` / `LayoutInspectSystem`）全部改经该出口；**删除各自手写累加**。
- 重叠检测改用 `ToFormRelative` 口径（与可见性检查同基准），消除 handle 依赖与嵌套重复累加。

**落点**：新增 `CsharpPrj/Share/LayoutAnalysis/UIInspector/LayoutCoordinateResolver.cs`（或 `FrontEndDriven/Shared`），改 `ControlTreeWalker.cs`、`RenderPipelineStages.cs`、`LayoutInspectSystem.cs`


### S3 · 布局应用类型感知内核（治 D3）

- `PropertyApplier.ApplyProperties` 的 `SetBounds` 分支增加控件类型适配：
  - `TextBoxBase` → 应用前 `AutoSize = false`（布局高度由 ECS 驱动）；
  - `ComboBox` → 按 `DropDownStyle` 处理高度（`DropDownList` 由字体约束，审计豁免声明）；
  - 其余类型保持 `SetBounds` 直设。
- **移除** `WinFormsOutputPort.ApplyControlBehavior`（行为适配下沉到布局应用内核，消除"创建处补丁"）；`ControlBehaviorComponent` 保留（multiline/readOnly/scrollBars 仍由创建期应用，但 `AutoSize` 统一由内核保证）。
- `SyncActualContainerSizes` 从"首次 Apply 审计"改为**每次 Apply 后审计**，ECS_MISMATCH 升 **Warning** 并计入 `ApplyResult` 缺陷数（从"常态记录"升为"缺陷信号"）。

**落点**：`PropertyApplier.cs`、`Ports.cs`、`WinFormApplier.cs`、`fde_log_messages.json`

### S4 · 部署单轨（治 D5）

- 清理 `FileDriven\BuildOutput` 下旧版 DLL（8/5 时间戳），固定运行脚本引用 `CsharpPrj\BuildOutput`（MainProj 输出）为唯一部署根。
- 构建后校验：运行脚本入口断言"目标 DLL 时间戳 = 最近构建时间"，不符即告警。

**落点**：运行脚本（`运行测试GUI模式.ps1`）、构建配置
