# 容器状态解耦 — 基于通用状态管理框架的应用层重构设计

> **定位**：应用层（FrontEndDriven + FileDriven）重构文档
> **目标**：基于《通用状态管理框架_基于InternalStorage扩展设计.md》的状态基座，重构 sideContainer 动态容器加载调用链，使容器加载与 click 函数调用同构，彻底解除「逻辑作用域 ↔ 物理宿主控件」的耦合。
> **日期**：2026-08-02
> **依赖**：`Modules.InternalStorage.State`（文档一设计的状态领域层）

---

## 一、重构前后调用链对比

### 1.1 现状（耦合）

```
LoadSidePanel (UIToolbox)
  → LoadConfigToScope("Side","sideContainer")        ← 硬编码 scope↔控件名
    → ILoadConfigPort.LoadConfigAsync(path,"Side","sideContainer")
      → ConfigurationLifecycleManager.LoadAsync(config,"Side","sideContainer")
        → ResolveHost → ControlPool.GetControl("sideContainer")   ← 跨层状态查询
        → EcsGate.LoadConfigAndRenderAsync(...)
```

### 1.2 目标（解耦，与 click 同构）

```
LoadSidePanel 按钮 click
  → 函数命令：ContainerCommandExecutor.ExecuteLoad("Side", configPath)   ← 只认逻辑作用域
    → ContainerStateStore.Set("Side", state{Loading})                    ← 写状态（无 UI 依赖）
      → [StateChanged 事件]
        → ContainerProjector.OnContainerStateChangedAsync("Side", state) ← 应用层投影
          → HostBindingStore.ResolveHostKey("Side") → "sideContainer"    ← 逻辑绑定查宿主键
          → ControlPool.GetControl("sideContainer")                      ← 仅此处触碰物理控件
          → EcsGate.LoadConfigAndRenderAsync(config,"Side",hostControl)
```

**核心变化**：
1. 调用方只操作**逻辑作用域**（"Side"）与**状态**，不再直接操作物理控件。
2. 状态 → 控件的映射由 `HostBindingStore`（声明式）承担，而非硬编码。
3. 渲染由 `ContainerProjector` **响应状态事件**自动触发，调用方无感知。

## 二、新增应用层组件

### 2.1 ContainerCommandExecutor（命令执行器，与 click 同构）

无状态命令门面，注册为函数库（与 `UIToolbox` 的 click 函数一致），只依赖状态门面，不触碰控件。

```csharp
namespace FrontEndDriven.State.Commands;

/// <summary>容器加载命令 —— 与 click 函数同构的无状态命令，只写状态不碰控件</summary>
public sealed class ContainerCommandExecutor
{
    private readonly ContainerStateStore _stateStore;   // Modules.InternalStorage.State

    public ContainerCommandExecutor(ContainerStateStore stateStore);

    /// <summary>加载配置到指定逻辑作用域（无 UI 依赖的原子命令）</summary>
    public async Task<bool> LoadToScopeAsync(string scope, string configPath)
    {
        // ① 幂等检查（经 ConfigVersion）
        var current = _stateStore.Get(scope);
        if (current is { ConfigPath: not null } &&
            string.Equals(current.ConfigPath, configPath, StringComparison.OrdinalIgnoreCase))
        {
            return true; // 已加载同一配置
        }

        // ② 写 Loading 状态（触发投影准备）
        _stateStore.Set(scope, new ContainerState(scope, configPath, Status: ContainerStatus.Loading,
            UpdatedAtUtc: DateTime.UtcNow));

        try
        {
            // ③ 委托底层加载（复用现有管线）——经 ILoadConfigPort 保留对原有渲染的支持
            //    注意：此处只给 scope + configPath，不给控件名！
            return await LoadCoreAsync(scope, configPath);
        }
        catch (Exception ex)
        {
            _stateStore.Set(scope, new ContainerState(scope, configPath,
                Status: ContainerStatus.Failed, LastError: ex.Message, UpdatedAtUtc: DateTime.UtcNow));
            return false;
        }
    }
}
```

**设计要点**：
- 签名是 `(scope, configPath)`，**不含** `targetControlName` —— 这正是与 click 同构的关键。
- 状态写入先于渲染，投影器据此可做 Loading 态展示（可选）。

### 2.2 ContainerProjector（投影器，状态→渲染）

实现 `IStateChangedHandler`（文档一定义的契约），是"状态 → 控件渲染"的唯一桥梁。

```csharp
namespace FrontEndDriven.State.Projection;

/// <summary>容器投影器 —— 订阅容器状态变更，自动渲染到宿主控件</summary>
public sealed class ContainerProjector : IStateChangedHandler
{
    private readonly ContainerStateStore _stateStore;
    private readonly HostBindingStore _bindingStore;
    private readonly ControlPool _controlPool;         // 仅用于 hostKey→Control 解析
    private readonly EcsGate _gate;
    private readonly IUIDispatcher _uiDispatcher;      // 切 UI 线程渲染

    public ContainerProjector(
        ContainerStateStore stateStore,
        HostBindingStore bindingStore,
        ControlPool controlPool,
        EcsGate gate,
        IUIDispatcher uiDispatcher);

    // 订阅入口（由 StateSubscriptionHub.Attach(this) 调用）
    public async Task OnContainerStateChangedAsync(string scope, ContainerState state)
    {
        if (state.Status == ContainerStatus.Loading)
            return; // Loading 态可忽略（或用于显示提示）

        // ① 解析宿主键（逻辑层）
        var hostKey = _bindingStore.ResolveHostKey(scope);
        if (string.IsNullOrEmpty(hostKey))
            return; // 未绑定宿主，静默等待（避免挂错宿主）

        // ② 解析物理控件（仅在渲染前触碰 UI）
        var host = _controlPool.GetControl(hostKey);
        if (host == null)
            return; // 宿主尚未渲染注册，等下次状态事件

        // ③ 渲染（复用现有 EcsGate 管线，切 UI 线程）
        await _uiDispatcher.InvokeAsync(
            () => _gate.LoadConfigAndRenderAsync(state.Config!, scope, host));
    }

    public Task OnHostBindingChangedAsync(string scope, string hostKey) => Task.CompletedTask;
}
```

**设计要点**：
- **只有投影器触碰物理控件**，命令执行器与状态门面保持纯净。
- 宿主未注册/未绑定时**静默跳过**，不挂错宿主（根治现状时序脆弱性）。
- 复用 `EcsGate`/`ConfigurationLifecycleManager` 底层管线，不重写渲染。

### 2.3 BootHostBindingRegistrar（声明式宿主绑定注册器）

从 `MainLayout.json` 的 `container.sourceType="state"` + `stateScope` 声明自动建立绑定，**取代硬编码**。

```csharp
namespace FrontEndDriven.State.Projection;

/// <summary>宿主绑定注册器 —— 从配置声明的 state 容器建立 scope↔hostKey 绑定</summary>
public static class BootHostBindingRegistrar
{
    /// <summary>从 UIConfiguration 扫描 state 容器声明并注册绑定</summary>
    public static void RegisterFromConfig(UIConfiguration config, HostBindingStore bindingStore)
    {
        foreach (var container in ScanStateContainers(config))
        {
            // container.StateScope = "Side", container.Name = "sideContainer"
            bindingStore.Bind(container.StateScope, container.Name, "json-declared");
        }
    }
}
```

> 需在 `UIConfiguration` 的容器模型增加 `StateScope` 字段（见第三节 JSON 声明升级）。

## 三、JSON 声明升级

### 3.1 MainLayout.json：sideContainer 声明语义升级

```json
// ★ 原：隐含"需要手动取控件宿主"
{
  "type": "container",
  "name": "sideContainer",
  "dock": "Fill",
  "container": { "sourceType": "dynamic", "autoLoad": false }
}

// ★ 改：声明式状态容器（sourceType: state + stateScope），绑定由配置驱动
{
  "type": "container",
  "name": "sideContainer",
  "dock": "Fill",
  "container": {
    "sourceType": "state",
    "stateScope": "Side",
    "autoLoad": false
  }
}
```

### 3.2 模型与注册链

```
UIConfiguration(模型) 新增: ContainerConfig.StateScope / ContainerConfig.SourceType=="state"
  → JsonConfigService.LoadConfigAsync(MainLayoutPath)    // 反序列化含新字段
  → BootHostBindingRegistrar.RegisterFromConfig(bootConfig, bindingStore)
      // 自动执行: bindingStore.Bind("Side", "sideContainer", "json-declared")
```

## 四、UIToolbox 改造（命令注册）

### 4.1 LoadSidePanel / BrowseConfigFile 归一为状态命令

```csharp
// 原（依赖 ILoadConfigPort + 控件名）:
private static bool LoadSidePanelShared()
    => LoadConfigToScope("Side", UIControlNames.SideContainer);

// 改（只操作逻辑作用域，与 click 同构）:
registrar.Register("LoadSidePanel",
    (Func<string, bool>)(configPath =>
        CommandExecutor.LoadToScopeAsync("Side", resolvePath(configPath)).GetAwaiter().GetResult()),
    new[] { new ParameterDescriptor { Name = "configPath", Type = typeof(string) } },
    "加载 JSON 配置到 Side 作用域（状态命令）");
```

> 仍保留"打开文件对话框"场景：`LoadSidePanelShared` 改为 `dialog 选择路径 → CommandExecutor.LoadToScopeAsync("Side", path)`，不再传控件名。

### 4.2 移除硬编码映射

- 删除 `LoadConfigToScope(scope, targetControl)` 中与控件名耦合的签名。
- `UIControlNames.SideContainer` 仅保留给 `BootHostBindingRegistrar` 的声明映射使用（单一来源）。

## 六、状态流转时序

```
① 启动引导                     ② 用户点击 Load Side
MainForm.OnLoad                    │
  └ BootstrapAsync(MainLayout)     ▼
      └ 渲染 sideContainer      LoadSidePanel (函数命令)
      └ (BootHostBindingRegistrar) │
          Bind("Side","sideContainer")   ▼
                               ContainerCommandExecutor.LoadToScopeAsync("Side", path)
                                     │
                                     ▼
                               ContainerStateStore.Set("Side", {Loading})
                                     │  StateChanged↓
                                     ▼
                               ContainerProjector.OnContainerStateChangedAsync
                                     │  HostBindingStore.ResolveHostKey("Side") → "sideContainer"
                                     │  ControlPool.GetControl("sideContainer")
                                     ▼
                               EcsGate.LoadConfigAndRenderAsync(config,"Side",host)
                                     │
                                     ▼
                               ContainerStateStore.Set("Side", {Loaded, NodeCount})
```

## 七、收益总结

| 维度 | 现状 | 重构后 |
|------|------|--------|
| 心智模型 | 容器加载是"操作控件" | 容器加载 = "更新状态"，与 click 同构 |
| 函数签名 | `(scope, 控件名)` | `(scope, configPath)` 无 UI 泄露 |
| scope↔宿主 | UIToolbox 硬编码 | 配置声明 + HostBindingStore |
| 宿主查找 | 跨层 ControlPool 查询 | 投影器集中解析，未注册时静默等待 |
| 状态位置 | ContainerView._core | ContainerStateStore（InternalStorage） |
| 可测性 | UI 线程强依赖 | 命令/状态层可单测 |

## 八、分阶段落地计划

| 阶段 | 内容 | 验证 |
|------|------|------|
| 1 | 文档一状态层落地（ContainerState/StateStore/HostBindingStore） | 单测通过，无 UI 依赖 |
| 2 | `ContainerCommandExecutor` + `ContainerProjector`（新组件） | 新链路可用 |

**兼容策略**：阶段 1-2 新增组件行为独立，不影响现有调用链；阶段 3-5 逐步切换，每阶段可回归。`ILoadConfigPort`/`EcsGate`/`ConfigurationLifecycleManager` 保留为底层编排，不强拆。

## 九、风险与对策

| 风险 | 对策 |
|------|------|
| `DataChanged` 在写入线程触发 | 投影器内部经 `IUIDispatcher` 切 UI 线程（复用现有） |
| 宿主未注册时事件早于渲染 | 投影器静默跳过 + 宿主注册后再写一次状态触发重投影 |
| 幂等（重复点击同配置） | `ContainerStateStore.Get` 比对 `ConfigVersion` 短路 |
| 状态层与 ECS 作用域清理冲突 | `DestroyScopeEntities` 由 EcsGate 保留负责，状态层只记录状态 |
| 多容器并发加载 | `ContainerStateStore` 线程安全（ConcurrentDictionary 底座） |
