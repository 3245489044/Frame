# 主循环对话统一接入历史容器（ur_histories）重构方案

> **版本**：1.0　**日期**：2026-08-30
> **性质**：重构方案（分析 + 实施纲领）
> **决策依据**：主循环（agent-loop）子 Cline 对话现以 `cline_messages` 节点（ur_nodes）存储，与子智能体（会话 send）的 `ur_histories` 历史容器不一致；目标统一为 `ur_histories`，`taskKey = historyId`（用户已确认方案 A 迁移）。

---

## 1. 背景与现状

主循环与子智能体的对话存储分裂为两套容器：

| 维度 | 主循环 agent-loop | 会话 send（子智能体） |
|------|-------------------|------------------------|
| 驱动 | 任务驱动（ur_tasks） | 对话驱动（taskKey = 会话名 = historyId） |
| 子对话存储 | `cline_messages` 节点（ur_nodes） | `ur_histories`（`ConversationLog`） |
| 消息模型 | `ClineMessage`（type/say/ask/text/reasoning/tool） | `ConversationMessage`（Role/Stage/SubAgent/Text/Round） |
| 历史容器 | 无（非对话流） | `IHistoryStore`（SessionId 维度 upsert） |
| 决策 | `rule_match` 产决策词、节点记录 | `run_to_end` 收敛 |

### 1.1 主循环对话归档链路（代码事实）

```
AgentFrameworkAssembler.cs L345
  AppServiceProvider.Register<IClineMessageArchive>(new NodeStoreClineMessageArchive(nodeStore))   // 基于 ur_nodes
  AppServiceProvider.Register<ClineArchiveSettings>(...)
ClineAgentExecutor.ExecuteAsync

  调用后 TryArchiveRoundAsync(r, dataDir)

```

### 1.2 子智能体会话 send 历史写入（对照）

```
ConversationPipeline.PersistHistoryAsync
  → IHistoryStore.UpsertAsync(taskKey, ConversationLog)   // ur_histories 幂等 upsert
  → 节点产出写 ur_nodes + cross_db_link 挂 task（Tool 气泡从 ur_nodes 合成）
```

---

## 2. 不合理点

1. **双真源 / 双模型**：主循环对话存 `cline_messages` 节点，子智能体对话存 `ur_histories`，读侧 / 回放 / UI 无法统一。
2. **无会话对话流**：主循环缺失 `user / assistant / tool` 的对话视图，无法与子智能体在同一 `ur_histories`（同 historyId）聚合展示。
3. **resume 脱节**：主循环 resume 依赖 `cline_messages` 节点回灌，与 `ur_histories` 历史容器脱节，无法复用统一历史。
4. **消息模型不统一**：`ClineMessage`（Cline CLI 特有）与 `ConversationMessage`（会话通用）两套结构，缺映射器。

---

## 3. 目标

- 主循环子 Cline 对话映射为 `ConversationMessage` 写入 `ur_histories`，`taskKey = historyId`，**与子智能体完全一致**、同 history 聚合。
- **单真源**：`ur_histories` 为统一对话容器；`cline_messages` 节点退役（resume 改从 `ur_histories` 回灌）。
- 主循环对话与 send 会话在相同 `taskKey` 下共存（History=Task 上层容器归拢多 task 多 node）。

---

## 4. 设计决策（已确认）

| 决策 | 取值 |
|------|------|
| 存储容器 | `ur_histories`（`ConversationLog` / `IHistoryStore`） |
| historyId | `taskKey` = 会话名（与子智能体 send 完全一致） |
| 迁移策略 | **方案 A 迁移**：单真源，`cline_messages` 退役 |
| resume 回灌 | 改从 `ur_histories` 最近对话回灌 |

---

## 5. 消息映射（`ClineMessage` → `ConversationMessage`）

| `ClineMessage` | `ConversationMessage` |
|----------------|------------------------|
| `type=user`（外部输入） | `Role=User`，`Stage=null`，`SubAgent=null` |
| `type=assistant` / `say`（assistant 文本/状态） | `Role=Assistant`，`Stage=cline_execute`，`SubAgent=cline` |
| `type=use_tool` / `tool_result` / `reasoning` / `ask` | `Role=Tool`（可折叠气泡），`Stage=cline_execute`，`SubAgent=cline` |
| 失败 / 空结果 | `Role=Error` |

- `Round` = 主循环轮次；`AtUtc` = 消息时间戳（`ClineMessage.Ts`）。
- 目标文件：`Agent.Modules/Cline/ClineMessageMapper.cs`（纯函数，可零 AI 单测）。

> **关键保留**：`ur_histories` 的 `ConversationMessage` 是会话级模型；Cline resume 需原始 `messages.json` 形态。迁移时需在消息上保留原文（如经 payload/meta 字段携带 `ClineMessage` 原文，或独立保留），否则 resume 无法重建 Cline 消息。

---

## 6. 分层改动

| 文件 | 改动 |
|------|------|
| **新增** `Agent.Modules/Cline/ClineMessageMapper.cs` | `ClineMessage` 序列 → `ConversationMessage` 序列（纯函数映射，见 §5） |
| **新增** `Agent.Modules/Cline/HistoryClineMessageArchive.cs` | 实现 `IClineMessageArchive`，基于 `IHistoryStore`（ur_histories）：`ArchiveAsync`→按 taskKey 追加映射消息；`LoadAsync/LoadLatestAsync`→从 ur_histories 读；`NextRoundAsync/ListRoundsAsync`→由消息 `Round` 推导 |
| **改** `Agent.Launcher/Composition/AgentFrameworkAssembler.cs` L345 | 装配改为 `Register<IClineMessageArchive>(new HistoryClineMessageArchive(historyStore, taskKeyMapper))`；移除 `NodeStoreClineMessageArchive` 注册 |
| **改** `Agent.Modules/Cline/ClineDaemonEndpoint.cs` | `TryRestoreMessagesFileAsync` 回灌来源改为 `HistoryClineMessageArchive`（从 ur_histories 重建 messages.json）；`TryArchiveRoundAsync` 委托不变（仍 `_archive.ArchiveAsync`，实现已切换） |
| **改** 主循环读侧 | 主循环对话从 `ur_histories` 读（与子智能体统一，经 `IHistoryStore.GetAsync(taskKey)`） |

### 6.1 装配接线要点

- `HistoryClineMessageArchive` 需同时拿到：`IHistoryStore`（ur_histories）+ `taskKey` 解析（主循环 task 的 taskKey）。
- 主循环 task 的 Cline `sessionId` 与 `taskKey` 的映射：`historyId = taskKey`；`sessionId` 保留在 archive 内（resume 需 Cline session 连续性），或在消息 `SubAgent`/meta 字段记录。

---

## 7. 迁移 / 兼容

| 阶段 | 动作 |
|------|------|
| 过渡期（读侧兼容） | 主循环读对话时：优先 `ur_histories`，缺失回退 `cline_messages` 节点（存量可读，不丢历史） |
| 存量迁移 | 一次性脚本：遍历 `cline_messages` 节点 → `ClineMessageMapper` 映射 → 写 `ur_histories`（taskKey 由 sessionId 反查 / 按约定） |
| 收尾 | `cline_messages` 节点置 `dep` 或按 `ReferenceGuardedDeprecation` 流程退役（确认无引用后清理） |

---

## 8. 验证

1. `Agent.sln` 编译 **0 错误**。
2. 主循环跑一轮：`ur_histories` 出现 taskKey 对话流（`user` + `cline` 各层 `assistant`/`tool` 消息），与子智能体 send 同 history 聚合。
3. **resume**：新轮能从 `ur_histories` 回灌重建 messages.json，上下文连续（Cline session 不丢）。
4. 会话 send 与主循环在相同 taskKey 下共存不冲突（History=Task 归拢正确）。
5. 存量 `cline_messages` 数据可读（读侧兼容/迁移后无丢失）。

---

## 9. 风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| **resume 链路** | Cline resume 需原始 `messages.json` 形态；`ConversationMessage` 为会话级模型，重建可能丢 Cline 特有字段（tool 调用/思考） | §5「关键保留」：消息携带 Cline 原文 payload；resume 回灌从原文重建 |
| **taskKey 与 Cline sessionId** | `historyId=taskKey`，但 Cline 内部 resume 需 `sessionId` | archive 内保留 sessionId 映射，resume 用 sessionId、展示用 taskKey |
| **消息映射语义** | Cline 工具消息 / 思考 → `Tool` 角色，需可折叠展示且不丢原文 | 映射器保留原文；UI 折叠 Tool 气泡 |
| **双真源残留** | 过渡期 `cline_messages` 与 `ur_histories` 并存 | 读侧兼容统一出口，尽快迁移收尾 |
| **主循环 task 无 taskKey 场景** | 部分直连调用无 taskKey | 回退默认 `default`（对齐 send 空 taskKey 语义） |
