# Agent 存储项目重构方案（集中化持久化 + IoC 反转 + 配置动态化）

> **日期**：2026-08-09
> **定位**：重构文档（方案 + 落地清单）
> **目标**：把散落在 UniversalReference / SqliteRelate / ConfigurationHelper 中的零散持久化配置，**收敛到一个集中的 Agent 存储项目（`Agent.Persistence`）**，实现数据库原生持久化、持久化逻辑 IoC 反转、后端由配置动态切换。
> **前置依据**：`Agent/docs/workflow-langgraph-precise-comparison.md`、`Agent/docs/langgraph-integration-analysis.md`、`CsharpPrj/Share/UniversalReference/` 源码与 `docs/Introduction/Universal/06_数据库使用逻辑.md`。

---

## 一、背景与现状问题：持久化配置是零散的

当前持久化相关能力分散在多处，且多为**全局静态 + 硬编码 + 编译期开关**，既不集中、也不可配置切换：

| # | 现状散点 | 文件 | 问题 |
|---|----------|------|------|
| 1 | 全局静态 SQLite 路径 | `UniversalReference/Storage/SqliteRelate.cs`（`DataUniversal.DataBasePath` 静态） | 先赋值再用，任何 SQLite 代码读同一全局可变字段，非注入 |
| 2 | 硬编码工厂开关 | `UniversalReference/Core/Interfaces/UniversalReferenceManagerFactory.cs`（读静态 `_dataDirectory` 选 Persistent/Default） | 后端选择写在编译期逻辑里，不随配置变 |
| 3 | 全局静态配置 | `UniversalReference/Core/ConfigurationHelper.cs`（只读 ProjectRoot/appsettings.json 的静态 `IConfiguration`） | 不可注入、不可按模块隔离 |
| 4 | 具体类散落构造 | `UniversalReference/Storage/GraphDatabaseStorage.cs`（内部 `new UniversalReferenceManagerFactory.Create()`）、`LocalStorage.cs`（默认路径硬编码 `DataManage\DataBase`） | 消费方直接依赖具体实现 |
| 5 | 文件级 JSON 持久化 | `UniversalReference/Core/Managers/PersistentUniversalReferenceManager.cs`（`resources.json`/`references.json` 全量落盘） | 非数据库原生；全量序列化、高并发有丢失更新风险 |
| 6 | Agent 状态无持久化 | `Agent.Core/Loops/AgentRunner.cs`、`WorkFlowMethod/LoopFramework/Axioms/AxiomContext.cs`（状态全在内存可变对象） | 无跨会话、无崩溃恢复 |

> **核心问题**：持久化的"依赖方向"错了——业务代码依赖具体后端和全局静态配置，而不是依赖抽象端口；后端选择被写死，无法通过配置动态切换。

---

## 二、重构目标：集中构建一个 Agent 存储项目

**不要零散配置，而是集中到一个项目**：

> 新建独立项目 **`Agent/src/Agent.Persistence`**（Agent 存储项目），作为 Agent 体系**唯一的持久化与存储组合根**：
> - 集中吸收上述 6 类散点（连接、后端选择、配置绑定、图引用、checkpoint/快照）；
> - 基于 `UniversalReference` 提供**数据库原生**持久化（Schema + 事务）；
> - 持久化逻辑 **IoC 反转**：业务只依赖抽象端口；
> - 后端选择 **配置动态化**：改一个配置节即可切换 Sqlite/LiteDB/Graph/Local。

**关键取舍**：此前曾考虑把持久化引擎放在 `CsharpPrj/Share/`（业务无关、供 FileDriven 复用）。本方案按你的要求改为**集中在 Agent 内**，与其它 Agent 项目（`Agent.Core`/`Agent.Contract`/`Agent.Axioms`）命名与放置一致；`UniversalReference` 保持为被依赖的底层基础设施，不反向改造 Agent。

## 三、目标架构

```
业务逻辑（Agent.Core / AgentRunner / Agent.Launcher）
   │  只依赖抽象端口（不依赖具体后端）            ← IoC：依赖反转
   ▼
Agent.Persistence / Abstractions（端口）
   IPersistenceStore · ICheckpointStore · IResourceReferenceStore
   IDbConnectionFactory · IDbCommandExecutor · IDbSchemaInitializer
   ▲
Agent.Persistence / Resolvers
   PersistenceProviderFactory.Resolve(PersistenceOptions)   ← 配置驱动动态解析
   │  按 Provider 选实现
   ▼
Agent.Persistence / Sqlite | LiteDB | Graph | Local（适配器，均基于 UniversalReference）
   ▲
配置持久化： appsettings.json "Persistence" 节 → PersistenceOptions（单一配置源）
```

依赖方向（单向、无环）：

```
Agent.Persistence → UniversalReference（CsharpPrj/Share）+ WorkFlowMethod.LoopFramework.Axioms（AxiomContext 快照）
Agent.Core ──────→ Agent.Persistence
Agent.Launcher ───→ Agent.Persistence（组合根装配 AddAgentPersistence）
```

## 五、统一配置模型（集中配置，替代零散配置）

### 5.1 配置模型 `PersistenceOptions`

```csharp
public sealed class PersistenceOptions
{
    public PersistenceProvider Provider { get; set; } = PersistenceProvider.Sqlite;
    public string DatabasePath { get; set; } = "";           // 收敛原 SqliteRelate.DataBasePath / LocalStorage 默认路径
    public string ConnectionString { get; set; } = "";       // 收敛原 SqliteRelate 连接串
    public string TablePrefix { get; set; } = "ur_";          // 表前缀隔离
    public bool AutoCreateSchema { get; set; } = true;
    public int? MaxProgress { get; set; }                     // 可选的跨模块收敛项（对齐 AgentConfig）
    public PersistenceBackupOptions Backup { get; set; } = new();
}
```

### 5.2 单一配置节（`appsettings.json`，宿主根）

```json
{
  "Persistence": {
    "Provider": "Sqlite",
    "DatabasePath": "Agent/data/agent.db",
    "ConnectionString": "Data Source=Agent/data/agent.db;Version=3;",
    "TablePrefix": "ur_",
    "AutoCreateSchema": true,
    "Backup": { "Enabled": true }
  }
}
```

### 5.3 零散配置 → 集中的迁移映射

| 原散点 | 迁移目标 |
|--------|----------|
| `SqliteRelate.DataUniversal.DataBasePath = path` | `PersistenceOptions.DatabasePath` / `.ConnectionString` |
| `SqliteRelate` 静态 `ExecuteSQL` 等 | `Agent.Persistence.Sqlite.SqliteSession`（实例，注入连接串） |
| `UniversalReferenceManagerFactory.Create()` / `SetDataDirectory` | `PersistenceProviderFactory.Resolve(options.Provider)` |
| `ConfigurationHelper.GetConfiguration("...")` | `IOptions<PersistenceOptions>` 绑定 `Persistence` 节 |
| `LocalStorage` 默认路径 `DataManage\DataBase` | `PersistenceOptions.DatabasePath` |
| `GraphDatabaseStorage` 内部 `new UniversalReferenceManagerFactory.Create()` | `Agent.Persistence.Graph.GraphPersistenceStore`（构造注入 `IUniversalReferenceManager`） |
| `PersistentUniversalReferenceManager`（JSON 全量） | `SqlitePersistenceStore`（Schema + 事务，DB 原生） |
| `AxiomContext` 内存状态 | `Agent.Persistence.Core`（`SnapshotSerializer` + `ur_snapshots`/`ur_checkpoints`） |

## 六、IoC 反转与配置动态解析（核心）

### 6.1 端口（Abstractions，业务只依赖这些）

```csharp
public interface IPersistenceStore
{
    Task InitializeAsync();
    ICheckpointStore Checkpoints { get; }            // 快照/checkpoint（LangGraph 兼容端口）
    IResourceReferenceStore Resources { get; }       // 资源+引用（映射 IUniversalReferenceManager）
    Task<ITransaction> BeginTransactionAsync();      // 数据库原生事务
}
```

### 6.2 组合根（配置驱动动态解析，替代硬编码开关）

```csharp
public static class PersistenceProviderFactory
{
    private static readonly IReadOnlyDictionary<PersistenceProvider, Func<IServiceProvider, IPersistenceStore>> _registry =
        new Dictionary<PersistenceProvider, Func<IServiceProvider, IPersistenceStore>>
        {
            [PersistenceProvider.Sqlite] = sp => new SqlitePersistenceStore(sp.GetRequiredService<IDbConnectionFactory>(), ...),
            [PersistenceProvider.LiteDB] = sp => new LiteDBPersistenceStore(...),
            [PersistenceProvider.Graph]  = sp => new GraphPersistenceStore(sp.GetRequiredService<IUniversalReferenceManager>(), ...),
            [PersistenceProvider.Local]  = sp => new LocalPersistenceStore(...),
        };

    public static IPersistenceStore Resolve(IServiceProvider sp, PersistenceProvider provider)
        => _registry.TryGetValue(provider, out var f) ? f(sp)
           : throw new NotSupportedException($"未注册的持久化后端: {provider}");
}
```

### 6.3 DI 装配（`Extensions/`，宿主即 Agent.Launcher 调用）

```csharp
public static IServiceCollection AddAgentPersistence(this IServiceCollection services, IConfiguration config)
{
    services.Configure<PersistenceOptions>(config.GetSection("Persistence"));
    services.AddSingleton<IDbConnectionFactory>(sp =>
        new SqliteConnectionFactory(sp.GetRequiredService<IOptions<PersistenceOptions>>().Value));
    services.AddSingleton<PersistenceProviderFactory>();
    services.AddSingleton<IPersistenceStore>(sp =>
        PersistenceProviderFactory.Resolve(sp, sp.GetRequiredService<IOptions<PersistenceOptions>>().Value.Provider));
    return services;
}
```

> 消费方（`AgentRunner` 等）只注入 `IPersistenceStore`；**切换后端 = 改 `Persistence.Provider` 配置，零代码改动**——这是 IoC 反转的验收标准。

## 七、数据库原生后端（基于 UniversalReference）

`SqliteSession` 把 `SqliteRelate` 的静态 API 收敛为实例（连接串由构造注入，消除全局静态 `DataBasePath`）：

```csharp
public sealed class SqliteSession : IDbCommandExecutor
{
    private readonly string _cs;
    public SqliteSession(string connectionString) => _cs = connectionString;
    public int ExecuteNonQuery(string sql, IDictionary<string, object>? p = null)
        => SqliteRelate.DataUniversal.ExecuteSQL(_cs, sql, p, cmd => cmd.ExecuteNonQuery()); // 底层静态升级为接受连接串
}
```

`SqliteSchema` 用 `SqliteRelate.DataCreate.CreateTable` 建表（数据库原生 Schema）：

| 表 | 用途 |
|----|------|
| `ur_resources` | 资源（Id/ResourceType/Name/Symbol/MetadataJson） |
| `ur_references` | 引用关系（SourceId/TargetId/RefType/Strength） |
| `ur_checkpoints` | LangGraph 兼容 checkpoint（ThreadId/CheckpointNs/CheckpointId/ParentId/ChannelJson/VersionsJson/Step） |
| `ur_writes` | 挂起写 / reducer 合并 |
| `ur_snapshots` | Agent 状态快照（AxiomContext 序列化） |

## 八、实施步骤（分期）

| 阶段 | 内容 | 验收 |
|------|------|------|
| **P0 项目骨架** | 建 `Agent.Persistence` 项目 + `Abstractions` + `PersistenceOptions` + `SqliteConnectionFactory`/`SqliteSession` + `SqlitePersistenceStore` + `SqliteSchema` | 单测：建表、资源 CRUD、事务提交/回滚 |
| **P1 配置动态化** | `PersistenceProviderFactory` + `AddAgentPersistence(IServiceCollection, IConfiguration)`；注册 Sqlite/LiteDB/Graph/Local 四后端 | 改 `Provider` 配置即换后端；单测覆盖 |
| **P2 反转接入** | `Agent.Core` 依赖 `IPersistenceStore`；替换 `SqliteRelate.DataBasePath`/`UniversalReferenceManagerFactory` 调用点；废弃全局 `SetDataDirectory` | Agent 主循环跑通，进程重启续跑 |
| **P3 checkpoint/快照** | `ur_checkpoints/ur_writes/ur_snapshots` 落地；`AxiomContext` ↔ 快照；reducer 合并；LangGraph `BaseCheckpointSaver` 桥 | 崩溃恢复、跨会话恢复通过 |
| **P4 增强** | Graph 后端血缘、多 daemon 并行事务 + 乐观锁、备份策略、Local→Sqlite 一次性迁移工具 | 压力/并发/迁移演练 |

## 九、风险与权衡

| 风险 | 缓解 |
|------|------|
| `SqliteRelate` 全静态 + 全局 `DataBasePath` | 用 `SqliteSession`/`SqliteConnectionFactory` 实例壳收敛；静态保留为底层驱动，旧 FrameManage 调用方不受破坏 |
| 多 worker 并发写 checkpoint | `ur_writes` + 版本字段乐观并发 + 事务；按 `thread_id` 串行化 |
| 配置驱动后校验缺失 | `PersistenceOptionsValidator`（Provider 合法、连接串非空、路径可写）在组合根 fail-fast |
| 从 JSON 全量落盘迁移到 DB 有数据迁移成本 | 一次性迁移工具：Local → Sqlite（`resources.json` 灌入 `ur_resources`） |
| Agent 内集中 vs Share 复用 | 按本方案集中在 Agent；若后续 FileDriven 也需持久化，再把 Abstractions 抽到 Share（本项目已隔离端口，便于上移） |

## 十、验收标准（Done Definition）

1. 存在单一项目 `Agent.Persistence`，集中了连接、后端选择、配置绑定、checkpoint/快照、图引用五类持久化逻辑。
2. `SqliteRelate.DataBasePath` / `UniversalReferenceManagerFactory.SetDataDirectory` / 散落 `new GraphDatabaseStorage()` 不再被 Agent 代码直接调用。
3. 业务（`AgentRunner` 等）只依赖 `IPersistenceStore` / `ICheckpointStore` 端口。
4. 修改 `appsettings.json` 的 `Persistence.Provider` 即可在 Sqlite/LiteDB/Graph/Local 之间切换，无代码改动。
5. 崩溃恢复：进程重启后从最后 checkpoint 续跑；跨会话：同 `thread_id` 恢复 `session_id` 续跑。
6. 全部通过 DB 原生事务；`ur_*` 表结构自动创建且可迁移。
