# 提示词管理整理优化方案：格式生成收敛为系统提示词

> 日期：2026-08-09 | 范围：`Agent/Config/prompts` + `Agent/src/Agent.Axioms/Prompts` | 关联：HFSM 租约链 / 公理框架
> 状态：方案（待评审）

---

## 一、背景与问题

当前提示词资产集中在 `Agent/Config/prompts/`，但**生命周期、加载机制、消费方三者混杂**，导致“提示词管理混乱”：

| 文件 | 层级 | 加载机制 | 消费方 |
|------|------|----------|--------|
| `system.prompt.dsl.md` | L0 | 纯拼接（`PromptCatalog.L0FileNames`） | 主 Cline 执行智能体 |
| `loop-axioms.system.md` | L0 | 纯拼接 | 主 Cline |
| `logic-axioms.system.md` | L0 | 纯拼接 | 主 Cline |
| `l1l2-generator.system.md` | L1/L2 生成协议 | DSL 解析（`PromptDslParser`→`PromptProtocol`） | L1/L2 生成器 LLM 调用 |
| `boundaries.system.md` | L2 边界公理 | 不解析（`[BindAxiom]`→`Plate.Axioms.L2`） | 代码绑定 |

核心矛盾：**“格式生成”（JSON 输出规则、Schema 声明、返回规约信封）被拆散到多个文件与多个层级**，没有单一归属。本方案把**格式契约统一上收为 L0 系统提示词的一个固定格式段**，并让它**既被模型读、又被代码解析**，消除“两处真相”与散落。

---

## 二、目标

1. **格式生成 = 系统提示词**：所有“输出 JSON、对齐 Schema、返回规约信封”的格式指令收敛为 L0 的一个 `format` 段，进程级常驻、模型每次可见。
2. **Schema 单一真相**：Schema / 必填域 / 枚举只在 `format` 段声明一次；C# DTO 由解析结果派生或校验，杜绝“模型文案 vs C# 常量”漂移。
3. **DSL 解析统一**：`format` 段既被模型读、又被解析器解析为 `PromptFormatSpec`（C# 数据），与“纯模型声明”的规则文件、“纯权威声明”的边界文件职责分离。
4. **生成器不再自带格式文案**：L1/L2 生成器的“只输出 JSON、对齐 Schema”改为引用/拼接 L0 格式段。
5. **回退链收敛**：消除多源镜像默认，单一回退路径。

---

## 三、现状资产与生命周期盘点

- **L0 三件套**（`PromptCatalog.L0FileNames`，启动拼接一次）：身份/操作/安全/输出格式（`system.prompt.dsl.md`）、循环熔断契约（`loop-axioms.system.md`）、逻辑算子与全量公理（`logic-axioms.system.md`）。
- **L1/L2 协议**（`l1l2-generator.system.md`，`PromptDslParser` 解析 → `PromptProtocol`）：L1/L2 模板 + 生成器 system/user 模板 + replan 条件；`PromptBuilder` 组装生成器提示，`PromptText.Fill` 填槽。
- **边界协议**（`boundaries.system.md`）：`SpatialBoundary`/`BoundaryPressureModel`/`BoundaryTriggerArbiter`/`BoundaryIntentClassification`。
- **C# 镜像 DTO**：`GeneratedTaskPrompt`/`GeneratedStepPrompt`（L1/L2）、`AgentReturnSpec`/`ChildAgentReturn`（返回规约）、`PromptValidator`（JSON 校验）。
- **回退链**：磁盘 → 嵌入资源 → 空协议；`PromptDefaults` 默认；`RuleSet.EmbeddedJson`/`EmbeddedProtocol` 各一份。

## 四、根因分析

| # | 根因 | 证据 |
|---|------|------|
| R1 | 格式生成指令无单一归属 | 主 Cline 格式在 `system.prompt.dsl.md` §四；L1/L2 生成器格式在 `l1l2-generator` 的 `L1GeneratorSystem`/`L2GeneratorSystem`；边界自评在 `boundaries` + `l1l2` §2.1 |
| R2 | Schema 两处真相（模型文案 vs C# 常量） | `ReturnEnvelopeSchema`(L0) vs `AgentReturnSpec`；`L1/L2StepPromptSchema`(l1l2) vs `GeneratedTaskPrompt`/`GeneratedStepPrompt` |
| R3 | 同一种 DSL 部分解析、部分摆设 | `[Gate] ReturnEnvelopeGate`(L0) 不被解析；`[Gate] L2ReplanConditions`(l1l2) 被解析为 `ReplanCondition` |
| R4 | L0 职责混杂 | L0 混入 `Ps1First`/`ReadStrategy`/`Strategy` 反模式等执行规则，而输出格式规则反而下沉到生成器 |
| R5 | 填槽 vs 生成两条路径混在 `PromptProtocol` | 规则模板填槽（零 LLM）与生成器 LLM JSON 生成共用 `Generator.SystemTemplate/UserTemplate` |
| R6 | 回退链复杂、默认多源 | 磁盘 → 嵌入 → 空协议；`PromptDefaults`/`EmbeddedProtocol`/`EmbeddedJson` 多份镜像 |
| R7 | 命名与目录未按职责分 | “system”歧义（L0 系统提示词 / 生成器 SystemTemplate / `system.prompt.dsl.md`）；`Config/prompts` 平铺无分区 |

## 五、目标架构：格式契约单一真相

```
L0（进程级常驻，模型每次可见）
 ├─ format.system.md   ← 新增：全部格式声明（JSON 输出规则 + Schema + 返回规约信封）
 │      ↓ 被 PromptDslParser（统一 parser）解析
 │      ↓ 生成 PromptFormatSpec（C# 数据）→ 驱动/校验 GeneratedTaskPrompt / GeneratedStepPrompt / AgentReturnSpec
 ├─ system.prompt.dsl.md   ← 身份/操作/安全（纯模型声明，不解析）
 ├─ loop-axioms.system.md  ← 循环熔断契约（纯模型声明）
 └─ logic-axioms.system.md ← 逻辑算子/公理（纯模型声明）
L1/L2 生成器（l1l2-generator.system.md）
 └─ Generator.SystemTemplate 不再内置格式文案，改为引用 L0 format 段
边界（boundaries.system.md）← 纯权威声明（不变）
```

**关键不变量**：`format` 段是**唯一**同时被“模型读 + 代码解析”的提示词；规则文件保持“纯模型声明”，边界文件保持“纯权威声明”，三者职责分离、不混不串。

## 六、方案设计

### 6.1 新增 `format.system.md`（L0 格式段，并入 `PromptCatalog.L0FileNames`）

内容（从各处**收拢**而来，语义不变、位置统一）：
- `OutputShape` / `OutputGate` / `OutputWellFormed` / `FormatFidelity`（现有，从 `system.prompt.dsl.md` §四迁入）
- `ReturnEnvelopeSchema` / `ReturnSpecEnvelope` / `ReturnEnvelopeGate`（现有返回规约）
- `L1TaskPromptSchema` / `L2StepPromptSchema` / `BoundaryAction` 枚举（从 `l1l2-generator.system.md` 迁入/共享）
- 新增 `[Schema]` 前缀（或复用 `[Type]`）承载结构化 Schema 声明，使解析器能按统一语法消费

### 6.2 统一解析：`format.system.md` → `PromptFormatSpec`

- 扩展 `PromptDslParser`（或新增 `FormatSpecParser`）解析 `format.system.md`：
  - Schema 名、字段（含类型/必填/枚举）、输出指令文本 → `PromptFormatSpec`（C# DTO）。
  - 产出：`FormatSchemas`（`schema_name → { fields, required, enum }`）+ `FormatInstructions`（模型文案段）。
- `PromptCatalog` 增加 `FormatSpec` 属性（磁盘 → 嵌入 → 空，与现有回退链一致）。

### 6.3 C# DTO 由 `PromptFormatSpec` 派生/校验（消除 R2）

- `GeneratedTaskPrompt` / `GeneratedStepPrompt` / `AgentReturnSpec` / `ChildAgentReturn`：
  - 字段集合由 `PromptFormatSpec` 的对应 Schema 声明派生；
  - `PromptValidator` 的必填域、枚举取值从 `PromptFormatSpec` 读取，不再硬编码；
  - 引入**一致性校验**（启动时比对 C# DTO 字段 ⊇/⊆ Schema 字段，漂移即 fail-fast/告警）。

### 6.4 生成器不再自带格式文案（R1/R5）

- `l1l2-generator.system.md` 的 `L1GeneratorSystem`/`L2GeneratorSystem` 中“只输出 JSON、对齐 Schema X”改为**引用 L0 `format` 段**（`PromptBuilder.BuildTask/StepGenerationPrompt` 把 `format` 段拼入 SystemTemplate），不重复内置 JSON 指令。
- 保留生成器专属的“任务语义”文案，仅移除格式/JSON 重复描述。

### 6.5 目录与命名规约（R4/R7）

```
Agent/Config/prompts/
 ├─ format.system.md        # L0 格式段（可解析，单一真相）
 ├─ system.prompt.dsl.md    # L0 身份/操作/安全（纯模型声明）
 ├─ loop-axioms.system.md   # L0 循环熔断契约
 ├─ logic-axioms.system.md  # L0 逻辑/公理
 ├─ l1l2-generator.system.md# L1/L2 生成协议（仅任务语义，格式引用 format）
 └─ boundaries.system.md    # L2 边界权威声明
```
- 命名：`*.system.md` 统一指“系统提示词/契约”；新增前缀 `format`/`axioms`/`generator` 明确职责。
- 注释头统一标注“可解析 / 纯模型声明 / 纯权威声明”。

### 6.6 回退链收敛（R6）

- 统一为一条链：`Config/prompts/` 磁盘 → 同源嵌入资源 → 空默认。
- 移除重复默认源（`EmbeddedProtocol`/`EmbeddedJson` 归一），`PromptDefaults` 仅保留极小兜底。

## 九、验证标准

1. **格式单一真相**：`OutputShape`/`ReturnEnvelopeSchema`/`L1/L2StepPromptSchema` 在 `format.system.md` 中只出现一次，`system.prompt.dsl.md`/`l1l2-generator` 不再重复定义。
2. **C# 与 Schema 一致**：`PromptValidator` 必填域/枚举来自 `PromptFormatSpec`；启动校验 C# DTO ⊇/⊆ Schema，漂移即 fail-fast/告警。
3. **生成器继承格式**：L1/L2 生成器 system 提示含 L0 format 段，不再自带 JSON 格式文案。
4. **回退唯一**：磁盘 → 嵌入 → 空默认单链，无多源默认。
5. **行为不回归**：构建 0 警告 0 错误；`Agent.ClineUsage.Tests` 全绿（含返回规约解析、RoundStateMapper）；主路径决策/熔断语义不变。

## 十、关键决策与取舍

- **format 段并入 L0 组合**（而非独立加载）：保证模型每次常驻可见，代价是 L0 变长 → 用“置两端高注意区”+ 精简措辞缓解（对齐 `FormatInstructionLocality`）。
- **格式段“可解析”**（而非纯文案）：换取 C# 派生/校验、消除两处真相，代价是解析器要支持 `[Schema]` 语法（复用现有 DSL，扩展量小）。
- **生成器引用 format 而非复制**：单一真相，代价是生成器 prompt 依赖 L0 段存在（由 P0 保证）。
- **向后兼容**：format 段收拢语义不变，旧输出（无信封）仍走文本启发回退，不破坏子智能体旧行为。
