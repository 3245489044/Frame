# Agent 模块化架构设计：声明式工作流为骨架、公理框架为桥梁

> 日期：2026-08-09 | 范围：`Agent/src` 全部模块 | 关联：clinerules（axioms/formula/logic）

---

## 1. 背景与目标

历史 Agent 代码存在两类可观察问题：

1. **双引擎并存的“冲突感”**：`AgentOrchestrator.RunAsync` 直跑 `agent-loop.json`（声明式工作流），`AxiomAgentLauncher` 则自建 execute lambda（公理框架），两条“运行”线各自维护终止/计数/超时，且 `AgentLauncher` 管线装配了 AgentOrchestrator 却在其公理路径中完全不使用。
2. **横切关注点分散**：终止值（`MaxIterations`/`MaxSteps`/各 `Timeout`）、错误/重试、提示词装配、工作流产物判定、注册幂等模板在多个文件重复实现。

**目标态**：以**声明式工作流为骨架**（定义“每一轮做什么”），以**公理框架为桥梁**（提供“循环控制语义：何时停/怎么熔断/错误怎么分级/跨轮状态怎么收敛”），实现模块化（显式端口 + 单向依赖、无环）与聚拢（每个横切关注点唯一归属）。

设计原则（对齐 clinerules `Strategy` 元级指导）：
- **SingleImplementation**：同一能力只保留一个 canonical 实现。
- **RedundancyElimination**：无调用方即死代码，确认后删除。
- **LogicCorrectness**：语义与意图一致，识别分叉并修复（如 E1 竞态）。

## 4. 编排核心（Agent.Core）

### 4.1 `AgentRunner`（组合根）
依赖注入装配骨架/决策/配置端口，驱动公理引擎，是**唯一运行入口**：

### 4.2 `WorkflowRunner`（骨架适配器 + 数据驱动）
- 按声明式 `RoundSpec` 顺序调用已注册工作流函数执行"一轮"；跨轮状态（history/step_count/上一步结果/提示）经 `AxiomContext.Data` 持久化。
- **骨架完全数据化**：`RoundSpec` 默认从 `Config/workflows/agent-loop.json` 加载（`BuildRoundSpec` 沿 `on_success` 提取主路径线性链，跳过 `start` 桩，决策节点 `rule_match` 无 `on_success` 天然终止 → **剥离 `continue → provide_prompt` 自闭环**）；未找到/解析失败回退内置 `DefaultRoundSpec`。
- 主路径：`guard_input → provide_prompt → cline_execute → rule_match`；`decision=="stop"` 时追加 `guard_output`（输出安全过滤）。

### 4.3 `LoopDecisionMapper`（决策映射唯一归属）
| 工作流结果 | 公理语义 | 引擎结果 |
|---|---|---|
| `decision=continue`（未完成） | `EvalOutcome.Partial` | `LoopDecision.Continue` |
| `decision=stop`（完成） | `EvalOutcome.Pass` | `LoopDecision.Success`(TS) |
| `decision=error` / 执行失败 | `EvalOutcome.Fail`/`ParseError` + `ErrorClass` | budget 升级；终止仍由 `TerminationDecider` 裁决 |
| 无显式决策 | 按产出文本判 `Pass`/`Partial` | — |

终止/熔断/错误分级全部委托领域内核（`TerminationDecider`/`BudgetEscalator`/`ErrorClassifier`），不再各自手写计数。

### 4.4 `AgentLoopConfig`（配置收敛）

## 5. 骨架数据源：agent-loop.json

`Agent/Config/workflows/agent-loop.json` 是 `RoundSpec` 的唯一数据源，保持"声明式工作流为骨架"：
- 节点含 `Symbol/NodeId/FuncName/ParameterKeys/ResultKeys/NextNodeConfig.Configs`。
- `BuildRoundSpec` 从 `start` 沿 `on_success` 提取主路径，`rule_match` 的 `continue/stop/error` 兜底分支仍保留在 JSON 中供人读，但跨轮循环语义由公理引擎（token）承载。
- 修改一轮步骤只需改 JSON，无需改代码（可编辑、可观测）。
