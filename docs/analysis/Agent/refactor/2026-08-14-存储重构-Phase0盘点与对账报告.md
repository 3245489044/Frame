## 四、关键发现（对重构方向的影响）

1. **资源/引用真源当前在 LiteDB 图**（`graph-log.db`，`GraphIndexedResourceReferenceStore`），**不在 SQLite**——SQLite 的 `ur_resources`/`ur_references` 表**已建好但空**。
2. **收拢落点已现成**：SQLite schema 已预建 `ur_resources`/`ur_references`，Phase 6 迁移 = 把 LiteDB 数据填充进这两张表，再把图降级为从 SQLite 重投影，无需新建表。
3. `Persistence.Provider = "Sqlite"` 已确认；SQLite 具备原生事务（`SqliteTransaction` + `SqliteAmbientTransaction`），单库原子写能力现成。
4. 双库结构 = 「SQLite 骨干（状态/事实/配置）+ LiteDB 图（资源/引用）」，**两条持久化线无统一真源、无跨库事务**——与本报告重构方向一致：以 SQLite 为唯一真源，图降为只读投影。
5. 实现存在多套 `IResourceReferenceStore` 并存（SingleImplementation 收敛点）；`GraphIndexedResourceReferenceStore` 内部有「改内存图→落库+尽力而为回滚」非原子写与 `__dangling` 悬空哨兵（一致性/引用完整性风险点）。

---

## 五、结论与 Phase 1 建议

- 重构方向成立且落点现成：**SQLite 为唯一真源，LiteDB 图降级为从 ur_resources/ur_references 重投影的只读缓存**。
- **Phase 1 首个落地动作**：新增/复用 SQLite 真源实现 `IResourceReferenceStore`（填充已建 ur_resources/ur_references，含幂等 UPSERT + 事务 + 引用完整性校验），并把 `ResourceStoreFactory` 装配从 `GraphIndexedResourceReferenceStore` 切到该 SQLite 实现；`GraphIndexedResourceReferenceStore` 保留为只读投影（`RebuildProjectionAsync` 从 SQLite 载入 CoreGraph）。

### 7.2 Phase 5 — 任务=快照镜像列收拢 ✅
**根因**：`TaskPool.cs`（Share 通用状态机）用 `UpdateStatusAsync` 管理 Status 列，而 `UpdatePayloadAsync` 只写 PayloadJson → `AgentTaskItem.Status`(PayloadJson) 与 ur_tasks.Status 列可能漂移。

| 变更 | 说明 |
|------|------|
| **新增 `Share.TaskStatusPool/TaskPool/IStatusAwareTaskPoolItem.cs`** | 可选契约 `TaskExecutionStatus Status { get; set; }`；实现者（快照驱动）以载荷内 Status 为权威，写通道同步 Status 镜像列 |
| **`AgentTaskItem` 实现 `IStatusAwareTaskPoolItem`** | 已有 `Status` 属性，声明实现 |
| **`SqliteTaskPoolStore<TItem>`** | `EnqueueAsync`：Status 列 = 载荷内 Status（快照驱动）；`UpdatePayloadAsync`：事务内同步 `PayloadJson` + `Status` 列；`UpdateStatusAsync`：迁移后同步回写 `PayloadJson.Status`（消除双写漂移） |
| **`InMemoryTaskPoolPersistence<TItem>`** | `EnqueueAsync`/`UpdatePayloadAsync` 同步条目 Status（对齐） |

**语义**：非 `IStatusAwareTaskPoolItem`（通用条目）维持"状态机驱动 Status 列"不变；Agent 的 `AgentTaskItem`（任务=快照）以载荷内 Status 为唯一真源，Status 列由其派生，单一写通道在事务内维护 → 消除「Status 列 / PayloadJson.Status」双真源漂移。

**验证**：`StateManagement.Tests`（SqliteTaskPoolStore + TaskPoolWithSqlite 集成）**40/40 通过**；`Agent.Launcher` 编译 0 错误。
