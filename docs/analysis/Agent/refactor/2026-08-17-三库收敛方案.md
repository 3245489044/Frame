# Agent 存储三库收敛（nodes / tasks / resources）

> **日期**：2026-08-17（**2026-08-18 更新**：节点库由「LiteDB 单集合」回迁「SQLite ur_nodes 极简键值+JSON」，见下方 ③/更新说明）。
> **目标**：把 Agent 数据层从「7 张 `ur_*` 碎片表」收敛为三个逻辑存储，物理落点 SQL=2 表、LiteDB=1 集合（图）。
> **原则**：架构层收敛（统一契约 + 单一真相 + 物理落点归一），不打补丁。

## 一、目标模型

| 逻辑存储 | 职责 | 物理引擎 | 落点 |
|----------|------|----------|------|
| ① 基础节点库 `nodes` | 一切逻辑/记录：input/output/event/checkpoint(记录点)/**config**/**keymapping**/resource | **SQLite**（2026-08-18 由 LiteDB 回迁） | **表 `ur_nodes`**（纯「键名 NodeKey + 一个 JSON」；全元数据随 Json，NodeType/ThreadId 过滤由 JSON 表达式索引 `json_extract` 支撑） |
| ② 状态集合 `tasks` | 任务定义 + 运行时状态 + 调用的模型 | SQLite | 表 `ur_tasks` |
| ③ 关系库 `resources` | 连接 tasks ↔ nodes 的有向边（引用关系） | **LiteDB 图库** | **`graph-log.db`**（`ur_references` + CoreGraph，`ur_resources` 已下线） |

旧表收敛去向：`ur_keymappings`→nodes(keymapping) · `ur_config`→nodes(config) · `ur_checkpoints`→nodes(checkpoint) ·
`ur_inputs/ur_outputs/ur_events`→nodes(NodeType) · `ur_references`→resources(LiteDB 图) · `ur_snapshots`→tasks(任务=状态根)。

> **更新说明（2026-08-18）**：原方案把①基础节点库落在 LiteDB 单集合 `ur_nodes`；经评审后**回迁 SQLite**——`SqliteNodeStore`（`Sqlite/SqliteNodeStore.cs`）以纯「键名 + 一个 JSON」承载，节点全部元数据（NodeType/ThreadId/Key/Status/PayloadJson/RelationsJson/CreatedAt/UpdatedAt）随 Json 持久化（真单源），表仅 `Id/NodeKey/Json` 三列，NodeType/ThreadId 过滤由 JSON 表达式索引（`json_extract`）支撑（旧版散列/生成列表由 `MigrateLegacySchema` 自动折入 Json 并清列）；与 `ur_tasks` 同库同连接、纳入同一 SQLite 环境事务（单库原子）。`LiteDBNodeStore`/`LiteDBZoneStore` 移除，三区承载更名为 `NodeZoneStore`（后端无关）。SQL `ur_resources` 不建（引用关系唯一真源 = LiteDB 图库 `graph-log.db`）。旧 `agent.nodes.db` 已移入 `Agent/_deprecated/`。

## 二、已落地（本阶段，三工程编译 0 警告 0 错误）
