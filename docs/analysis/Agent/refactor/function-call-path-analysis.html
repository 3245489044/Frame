一、项目总体架构

Agent 项目采用 HFSM（分层有限状态机）+ 公理引擎驱动的架构范式，通过声明式骨架循环执行智能体任务。项目分为 9 个子项目，按职责分为四层：

层子项目职责
入口层Agent.Launcher启动入口，组合根装配，两条启动路径
核心层Agent.Core Agent.Axioms编排器、循环引擎、工作流骨架、边界框架、提示词分层、规则引擎、LLM 客户端
适配层Agent.ClineUsage Agent.McpTools Agent.GuardrailsCline 子代理执行池、MCP 工具桥接、输入输出安全守卫
契约层Agent.Contract Agent.Calculate接口定义/数据契约/边界模型，纯计算函数（压力/估算/哈希）
Agent.State 目录存在但为空，无任何实现代码。

二、两条启动路径

路径 A: AgentLauncher.StartAsync — 管线式（5 阶段）

适合宿主嵌入场景，通过 StagePipeline 编排 5 个有序阶段，每阶段有 CanExecute 门控：

AgentLauncher.StartAsync(userInput, options, ct) |[1] new AgentLaunchContext(userInput, options, ct) |[2] PipelineUsage.CreateStagePipeline("Agent 启动管线") |[3] pipeline.Register(LoggingStage, InitializeStage, InjectCancellationStage, RunStage, DisposeStage) |[4] await pipeline.ExecuteAsync(ctx, ct) | -> [阶段0] LoggingStage.ExecuteAsync -> AgentLog.Initialize(path) | -> [阶段1] InitializeStage.ExecuteAsync -> AgentCoreRuntime.Apply -> ApplyBoundaryFramework -> AgentModuleRegistrar.SetupAgentAsync | -> [阶段2] InjectCancellationStage -> orchestrator.SetCancellationCheck | -> [阶段3] RunStage.ExecuteAsync -> orchestrator.RunAsync(userInput, ct) | -> [阶段4] DisposeStage -> orchestrator.Dispose() |[5] return AgentLaunchResult.Ok() / Fail(error)

路径 B: AxiomAgentLauncher.RunAsync — 直连式

适合脚本/测试场景，跳过管线直接调用编排器：

AxiomAgentLauncher.RunAsync(userInput, maxProgress, ct, configure) |[1] new AgentConfig { MaxProgress = maxProgress } |[2] configure?.Invoke(config) |[3] AgentCoreRuntime.Apply(config.ConfigDirectory, config.StrictConfig) |[4] config.ApplyBoundaryFramework() |[5] await AgentModuleRegistrar.SetupAgentAsync(config.BuildLoopConfig(), o = AgentOptionalModules.Register(o, config)) |[6] using var orchestrator = ... |[7] return await orchestrator.RunAsync(userInput, ct) |[8] using 释放 -> orchestrator.Dispose()

两条路径的差异

维度AgentLauncherAxiomAgentLauncher
编排方式StagePipeline 五阶段管线直接调用（无管线）
日志初始化LoggingStage 阶段0缺失（不经过 LoggingStage）
返回类型AgentLaunchResult (bool+string)AxiomLoopResult (完整循环结果)
异常处理catch 后返回 Failcatch 后 throw（异常向上传播）
using 管理finally 手动 Disposeusing var 语法糖

两条路径共享同一组合根序列：AgentCoreRuntime.Apply -> ApplyBoundaryFramework -> AgentModuleRegistrar.SetupAgentAsync

三、组合根装配

AgentOptionalModules.Register — 可选模块装配

按 AgentConfig 开关显式装配三个模块，依赖方向单向（Launcher -> 适配模块）：

AgentOptionalModules.Register(orchestrator, config) |[1] if (config.RegisterCline): [默认 true] | ClineModule.Register() -> ClineExecutorFunction.Register() | orchestrator.RegisterAgentExecutor(new ClineAgentExecutor()) | |[2] if (config.RegisterGuardrails): [默认 true] | GuardFunction.Register() -> guard_input / guard_output | (try-catch 吞异常，仅记日志) | |[3] if (config.RegisterMcpTools): [默认 true] | new McpClientManager() -> ConnectAsync() (同步等待) | orchestrator.RegisterDisposable(manager) | McpToolFunction.Initialize(manager) + Register() | (try-catch 吞异常，仅记日志)
Guardrails 和 McpTools 注册失败被 try-catch 吞掉（仅记日志），不阻断启动；Cline 注册失败则会向上抛出异常。

Route — 决策路由（确定性，零 LLM）

信号预算级别动作说明
Done任意Terminate任务完成，终止循环
Error>= 2SwitchAgent熔断升级，切换子代理
Error< 2Retry受限重试
Retry任意Continue推进下一跳

五、工作流管道（StaticAsyncPipeline）— 五个步骤

每轮执行时，WorkflowRunner 构建并执行一个线性管道，包含 4 个必行步骤 + 1 个条件步骤：

六、边界评估调用链 — 双通道仲裁

边界评估采用 双通道并行采集 + 仲裁合并 模式，模拟脊神经（反应式/确定性）和皮层（主动式/LLM自评）的双系统：

DefaultBoundaryFramework.PostRoundAsync(ctx, signal, ct) |(1) ContextEstimator.Estimate(signal, promptChars) | -> signal.HasRealTokens ? 真实token : chars/4.0 估算 | |(2) UpdateCrossRound(signal, priorLength) | -> progress ? _noProgressSteps=0 : _noProgressSteps++ | -> _lengthWindow.Enqueue/Dequeue | |(3) InfoGainSmoothing.Ewma(_lengthWindow, alpha) // EWMA 平滑速率 | |(4) [反应式通道] _reactive.Evaluate(effSignal, config, estimate, ...) | -> LogicalBoundaryEvaluator.Evaluate | -> BoundaryPressureCalculator.Compute // 三维压力 | -> contextPressure = Clamp(chars / (limit * watermark), 0, 1) | -> infoGainPressure = 1 - (rate - minRate) / (1 - minRate) | -> complexityPressure = Clamp(round/maxRounds) + stepsRatio | -> score = WeightedAverage([ctx, info, comp], [w_ctx, w_info, w_comp]) | -> hysteresisHeld = wasTriggered && score >= releaseThreshold | -> triggered = stopBreach || (!hysteresisHeld && (anyDim || score >= threshold)) | -> ClassifyKind(signal, config, assessment) | -> ProtocolStop / TokenExhaust / ErrorClass / ContextPressure / InfoGain / Complexity | |(5) [主动式通道] _proactive.Evaluate(effSignal, config, estimate, ...) | -> 门控1: !cfg.Enabled || intent==null -> Healthy | -> 门控2: !ActionWhitelist.Contains(intent.Action) -> Healthy | -> 门控3: intent.Confidence < MinConfidence -> Healthy | -> 门控4: advisory降级 (contextPressure低时Compact降级为advisory) | -> Triggered: true, Action: intent.Action | |(6) BoundaryTriggerArbiter.Merge(reactive, proactive, config) | -> !config.Reactive.Enabled -> proactive or Healthy | -> reactive.Triggered -> reactive (脊神经短路优先) | -> proactive.Triggered -> proactive | -> else -> Healthy | |(7) [触发后处理] | -> BoundaryReconstructor.Apply(current, logical) | -> current.Apply(assessment, effectiveRoot) | -> BuildHint(action) // compact/resubmit/rescope/escalate | -> ctx.Data[ReconstructHint] = rebuilt.Hint | -> if Escalate: ctx.Token.Max = Math.Max(max, Math.Min(6, max+1)) // 有界升级

十、关键设计模式总结

模式实现位置说明
HFSM 租约链LeaseDeriver + AgentRunner.Route()自上而下派生只读有界租约，自下而上回收信号并确定性路由
公理引擎驱动AxiomLoopEngine + RoundLifecycle五步轮次（Execute/Collect/Evaluate/Decide/Adjust）+ 终止裁决
双通道边界评估DefaultBoundaryFrameworkReactive（脊神经/确定性）+ Proactive（皮层/LLM自评）并行采集 → Arbiter 仲裁
零 LLM 规则引擎复用RuleEngine同时服务 rule_match 循环控制和 provide_prompt 的 needsReplan 判定
幂等注册守卫FunctionRegistrar.RegisterOnceInterlocked 原子计数，防多路径重复注册
IoC 控制反转IPromptComposer + AppServiceProviderAgent.Core 定义接口，PromptRequestComposer 实现，反向解析
结构化归因优先ClineResultClassifier + AgentReturnSignalMapper优先消费强类型 ClineResult/ChildAgentReturn，文本兜底分类
显式装配替代反射AgentOptionalModules.Register按 config 开关显式装配 Cline/McpTools/Guardrails，依赖单向
迟滞边界控制BoundaryPressureCalculator + hysteresisReleaseThreshold触发后保持迟滞区间，避免边界状态频繁振荡
有界升级PostRoundAsync (Escalate)升级进度预算封顶 Math.Min(6, max+1)，防止无限升级
