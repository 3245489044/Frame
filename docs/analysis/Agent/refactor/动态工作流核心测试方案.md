# 动态工作流核心测试方案

## 概述

本文档定义 Agent 项目动态工作流功能的精简核心测试方案。测试覆盖三个核心维度：**DynamicWorkflowMerger 解析与构建**、**AgentLoopFunction 循环控制**、**WorkFlowMethod 集成**。

## 测试文件

### `tests/Agent.Tests/DynamicWorkflowCoreTests.cs`

集中测试动态工作流最核心的能力，所有测试数据内联在代码中，无需额外测试数据文件。

---

## 测试用例

### 一、DynamicWorkflowMerger 解析与构建（5 个测试）

#### 1.1 ParseFragment_标准workflow_fragment格式_应成功解析

**目的：** 验证 `DynamicWorkflowMerger.ParseFragment` 能正确解析标准 `workflow_fragment` 嵌套格式。

**输入：**
```json
{
  "workflow_fragment": {
    "nodes": [
      {
        "Symbol": "process",
        "NodeId": "step_1",
        "FuncName": "mcp_call_tool",
        "ParameterValues": {
          "server": "filesystem",
          "tool": "read_file",
          "arguments": { "path": "/workspace/main.py" }
        },
        "ResultKeys": ["file_content"]
      }
    ],
    "key_mapping": {
      "file_content": "analysis_input"
    }
  }
}
```

**预期结果：**
- 返回非 null 的 `WorkflowFragment` 实例
- `Nodes.Count` 为 1
- `Nodes[0].NodeId` 为 `"step_1"`
- `Nodes[0].FuncName` 为 `"mcp_call_tool"`
- `KeyMapping` 包含 `"file_content" → "analysis_input"`

---

#### 1.2 ParseFragment_直接nodes数组格式_应成功解析

**目的：** 验证兼容格式（直接 `nodes` 数组）的解析能力。

**输入：**
```json
{
  "nodes": [
    {
      "Symbol": "process",
      "NodeId": "step_1",
      "FuncName": "sk_chat",
      "ParameterValues": { "input": "分析代码" },
      "ResultKeys": ["analysis"]
    }
  ]
}
```

**预期结果：**
- 返回非 null 的 `WorkflowFragment` 实例
- `Nodes.Count` 为 1
- `Nodes[0].FuncName` 为 `"sk_chat"`

---

#### 1.3 ParseFragment_无效JSON_应返回null

**目的：** 验证异常输入的处理。

**输入：**
```json
{ "invalid": "data" }
```

**预期结果：**
- 返回 null

---

#### 1.4 BuildWorkflowJson_单节点_应生成有效JSON

**目的：** 验证 `DynamicWorkflowMerger.BuildWorkflowJson` 能正确构建单节点工作流 JSON。

**输入：**
```csharp
var fragment = new WorkflowFragment
{
    Nodes = new List<FragmentNode>
    {
        new FragmentNode
        {
            Symbol = "process",
            NodeId = "step_1",
            FuncName = "mcp_call_tool",
            ParameterValues = new Dictionary<string, object>
            {
                ["server"] = "filesystem",
                ["tool"] = "read_file",
                ["arguments"] = new Dictionary<string, object> { ["path"] = "test.txt" }
            },
            ResultKeys = new List<string> { "content" }
        }
    }
};
```

**预期结果：**
- 返回非空字符串
- 可被 `JsonDocument.Parse` 解析
- 包含 `"NodeId": "step_1"` 和 `"FuncName": "mcp_call_tool"`

---

#### 1.5 BuildWorkflowJson_多节点链式_应生成有效JSON

**目的：** 验证多节点链式工作流的构建。

**输入：**
```csharp
var fragment = new WorkflowFragment
{
    Nodes = new List<FragmentNode>
    {
        new FragmentNode { Symbol = "process", NodeId = "read", FuncName = "mcp_call_tool",
            ParameterValues = new Dictionary<string, object>
            {
                ["server"] = "filesystem", ["tool"] = "read_file",
                ["arguments"] = new Dictionary<string, object> { ["path"] = "test.txt" }
            },
            ResultKeys = new List<string> { "content" } },
        new FragmentNode { Symbol = "process", NodeId = "analyze", FuncName = "sk_chat",
            ParameterValues = new Dictionary<string, object> { ["input"] = "分析内容" },
            ResultKeys = new List<string> { "analysis" } }
    },
    KeyMapping = new Dictionary<string, string> { ["content"] = "analysis_input" }
};
```

**预期结果：**
- 返回非空字符串
- 包含 2 个节点定义
- 包含 `KeyMapping` 信息

### 二、AgentLoopFunction 循环控制（3 个测试）

#### 2.1 IsTaskComplete_含完成标记_应判定完成

**目的：** 验证 `AgentLoopFunction.IsTaskComplete` 能正确识别完成标记。

**输入：**
```json
{ "workflow_fragment": { "status": "complete" } }
```

**预期结果：**
- 返回 `true`

**补充用例：**
- 输入 `{ "status": "complete" }` → 返回 `true`
- 输入 `{ "workflow_fragment": { "status": "in_progress" } }` → 返回 `false`
- 输入 `"普通文本回复"` → 返回 `false`
- 输入 `""` → 返回 `true`（空字符串视为完成）

---

#### 2.2 IsJsonWorkflowFragment_含节点数组_应识别为片段

**目的：** 验证 `AgentLoopFunction.IsJsonWorkflowFragment` 能正确识别工作流片段。

**输入：**
```json
{
  "workflow_fragment": {
    "nodes": [{ "NodeId": "step_1", "FuncName": "mcp_call_tool" }]
  }
}
```

**预期结果：**
- 返回 `true`

**补充用例：**
- 输入 `{ "nodes": [{ "NodeId": "step_1" }] }` → 返回 `true`
- 输入 `{ "workflow_fragment": { "nodes": [] } }` → 返回 `false`（空数组）
- 输入 `"普通文本"` → 返回 `false`
- 输入 `""` → 返回 `false`

---

#### 2.3 ShouldCompressContext_超过阈值_应触发压缩

**目的：** 验证上下文压缩触发条件。

**输入：**
```csharp
// 构造超过 10 条的历史记录
var history = new List<Dictionary<string, object>>();
for (int i = 0; i < 12; i++)
{
    history.Add(new Dictionary<string, object>
    {
        ["role"] = "assistant",
        ["content"] = $"第 {i + 1} 轮回复"
    });
}
```

**预期结果：**
- `ShouldCompressContext(history)` 返回 `true`
- `CompressHistory(history)` 返回的列表长度不超过 6（1 条摘要 + 5 条最近记录）
- 压缩后的第一条记录 `role` 为 `"system"`，包含 `[上下文摘要]` 标记

---

### 三、WorkFlowMethod 集成（2 个测试）

#### 3.1 RegisterAndCallFunction_注册并调用_应成功

**目的：** 验证 WorkFlowMethod 的函数注册和调用链路。

**步骤：**
1. 调用 `WorkFlowMethodUsage.Initialize()`
2. 注册一个测试函数：`WorkFlowMethodUsage.RegisterAsyncFunction("test_func", async (ctx) => { return new { status = "ok", input = ctx.Parameters["input"] }; })`
3. 调用该函数：`var result = await WorkFlowMethodUsage.CallBridgedFunctionAsync("test_func", context)`

**预期结果：**
- 调用返回非 null 结果
- 结果中包含 `status` 为 `"ok"`
- 结果中包含传入的 `input` 值

**清理：**
- 调用 `WorkFlowMethodUsage.Reset()` 重置状态

---

#### 3.2 BuildWorkflow_节点列表_应生成有效JSON

**目的：** 验证 `WorkFlowMethodUsage.BuildWorkflow` 能正确构建工作流 JSON。

**输入：**
```csharp
var nodes = new List<object>();
WorkFlowMethodUsage.AddNode(nodes, "start", "start", "agent_loop",
    new object[] { "user_input" }, new object[] { "result" }, "入口节点");
WorkFlowMethodUsage.AddNode(nodes, "end", "end", "complete",
    null, new object[] { "final_result" }, "完成节点");
```

**预期结果：**
- 返回非空字符串
- 可被 `JsonDocument.Parse` 解析
- 包含 2 个节点
- 第一个节点 `Symbol` 为 `"start"`，`FuncName` 为 `"agent_loop"`
