## 摘要

构建 **规划智能体 + 循环框架（调度侧）**：规划智能体给 Cline 执行智能体**分发任务**并让 Cline 自动运行，用**循环框架**保证终止性、预算性与安全性。本框架负责**提示词的分级和分发**（L0/L1/L2）与**任务的规划**（规划即文档），执行操作落到底层的 Ps1 执行框架。

**当前阶段重点**：① 提示词的分级和分发；② 任务的规划；③ 循环骨架。

## 三、规划智能体 + 循环框架

### 3.1 提示词分级与分发（`provide_prompt`）

- **L0 系统提示词** `Config/prompts/system.prompt.md`：进程级常量（身份/安全/输出格式 + 「操作一律走 Ps1 + 拓展协议」规范）。固定、命中前缀缓存（0.1× 输入）。
- **L1 任务提示词**：任务级（goal/constraints/plan 摘要），首步 SK 生成一次，任务内缓存复用。
- **L2 步骤提示词**：步骤级（上步 exec_result + next_prompt_hint），模板填槽默认零 LLM；`rule_needs_replan` 命中时 SK 兜底。
- **分发器**：统一出口，决定「哪个子任务 → 哪套 L1/L2 → 给 Cline 执行」，即任务分发 + 提示词分发的统一出口。

### 3.2 任务规划（规划即文档，《省着用/循环用》落地）

规划器（SK/DeepSeek）输出结构化 JSON Plan：

```json
{
  "plan_id": "p_...",
  "goal": "...",
  "subtasks": [
    { "id": "s1", "action": "file.ops.batch_replace", "target": "src/*.cs", "params": { } }
  ],
  "dependency": ["s1→s2"]
}
```

分发器逐子任务：经 Ps1 执行框架解析能力 → 组装 L2 提示词 → 交 Cline 执行（契约文件/指针化留作 v2）。

### 3.3 循环框架（`rule_match` + 多层守卫，《循环调用谱系》落地）

`agent-loop.json` 升级 v4 主路径：

```
start → guard_input → provide_prompt → cline_execute → rule_match
  rule_match: continue → provide_prompt（带 hint）循环
              stop    → guard_output → end
              error   → sk_plan（兜底）→ dynamic_workflow_executor
```

- **判停权谱系**：rule_match（规则判定，主）＋ max_steps（步数）＋ 预算（token/美元）＋ 人工（CheckCancellation）＋ 模型 end_turn（兜底）。
- **规则集** `Config/rules/loop-rules.json` 首匹配：`exit_error / done_marker / need_more / max_steps / default→stop`（吸收态，可证明终止）。
- **降级链**：规则损坏 → 内置默认规则；SK 失败 → 纯模板；Cline 不可用 → `sk_plan`/MCP 兜底；`max_steps` → 强制 stop。

## 七、关键决策与取舍

- **调度在 C#、执行在 Ps1**：「Ps1 优先」约束执行操作，调度逻辑复用既有 C# Agent，避免重写。
- **承接既有设计文档**：P0-P2 与其一致，不重复设计。
- **拓展协议是闭环关键**：不实现则新任务仍会退化到 Cline 内置工具（见执行框架文档）。
- **规划即文档**：本阶段即输出 JSON Plan，为 v2 契约文件/指针化留接口。

---

## 八、验证与验收标准

1. **循环控制零 LLM**：`rule_match` 全程不调 LLM（continue/stop 全由规则集判定）。
2. **L0 缓存命中**：系统提示词进程级固定，内容一致可复现。
3. **模板优先**：继续步默认零 LLM，仅 `rule_needs_replan` 命中时调 SK。
4. **无无限循环**：`max_steps` 守卫 + 规则 `default → stop` 双保险。
5. **规划即文档**：规划器输出结构化 JSON Plan，分发器按子任务装配 L2 提示词。
