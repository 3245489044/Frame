
## 一、总体：一次重构的目标

最近一次提交 `de6bd25be Agent任务池和执行快照合并` 完成的关键重构是 **把「任务」与「快照」合并为同一实体**。重构前（见仓库内既有文档 `Agent/任务池调度循环执行链.md` v1.0）以 `SchedulerState` 为唯一持久根、`AxiomContext` 每轮派生存根、走 `RestoreSchedulerStateAsync` 恢复路径；重构后 **`AgentTaskItem` 同时实现 `ITaskPoolItem + ILoopState + IAgentLoopState`**，成为唯一权威状态根 —— **「修改任务 = 修改快照」**，单条 `PayloadJson` 即唯一权威状态基座（重启恢复 / 状态查询 / 投影均由此字符串派生）。

## 二、快照体系（Snapshot）

快照入口分**两条**：

1. **任务快照（主路径，单一状态基座）**
   - `Agent.Core/TaskPool/AgentTaskItem.cs`：载荷（TaskKey/Priority/MaxRetries/UserInput/ThreadId/InputKey/SchedulingMode/SchedulerRulesKey）+ 运行时契约（`ILoopState`：Budget/Token/Flag/Round/LastEval/LastResultText + `DataSpace`）+ 生命周期（`Status`）+ Agent 扩展（Scope/ContinuousFailures/CurrentStrategyId/AvailableStrategyIds/`AgentStatus`/RecentTransitions）。
   - 投影内聚于状态类自身：`ToRuntimeSnapshot(stage)`；`SchedulerStateProjector.Project` 仅剩**委托薄壳**（消除"双快照并存"缺陷 3.1）。
   - 落库：`AgentRunner.PersistRuntimeAsync` → `ITaskPoolPersistence<AgentTaskItem>.UpdatePayloadAsync(TaskKey, state)`，写回 `PayloadJson`（每轮 `next()` 边界）。

2. **租约快照（每轮派生）**
   - `SnapshotSerializer`（Agent.Persistence）仍把 `AxiomContext` ↔ `Snapshot` DTO 落 `ur_snapshots`，供旧持久化路径用；`AxiomContext` 本轮不再是持久根，仅作**每轮派生执行租约**（共享 Data/Budget/Token/Flag 引用 + 播种标量 Round/LastEval/Scope）。

## 三、重构完的调用链

### 1) 装配（组合根，Agent.Launcher）
```
AgentHost.RunAsync / AxiomAgentLauncher.RunAsync / AgentLauncher.StartAsync
  → AgentFramework.StartAsync(config, ct)
      → AgentFrameworkAssembler.AssembleAsync  (Modules.Pipeline StagePipeline)
          FrameworkLogging → Validate → Llm → Runtime(建 AgentOrchestrator+模块)
          → Boundary → Orchestrator(注册模块/执行器) → Persistence(IPersistenceStore)
          → DataStore(DataStoreHosting.RegisterAsync → DataStoreEngine)
          → ResourceGraph → Reactive(EnableReactiveTrigger 时 RegisterReactive)
          → TaskPool(EnableTaskPool 时 RegisterTaskPool)
      → SetCancellationCheck + AgentUiHost.AttachTaskPool
```

### 2) 任务池接线（DataStoreHosting.RegisterTaskPool）
```
Sqlite ur_tasks / 内存 → TaskPoolStoreFactory.Create → ITaskPoolPersistence<AgentTaskItem>
执行器集合 = [ LlmTaskExecutor(orchestrator), RuleTaskExecutor(orchestrator.ConfigStore) ]   // Hybrid + Config(零 LLM) 共存
→ new AgentTaskPoolAdapter(store, executors, options)
→ WireRoundPauseCheck(orchestrator)  // orchestrator.SetRoundPauseCheck(PauseGateAsync) → AgentRunner.LlmGate
→ WirePauseGate()                    // 给 IPauseAwareTaskExecutor 注入 _pool.WaitIfPausedAsync（零 LLM 循环边界暂停）
→ Start(ct)                          // 消费循环启动
```
（另有 `TaskPoolHosting.TryBootstrapRulePoolAsync`：纯零 LLM 池，仅 `RuleTaskExecutor` + 复用 `AgentUiHost.Database`。）

### 3) 任务执行（TaskPool → AgentOrchestrator）
```
TaskPool<AgentTaskItem,AxiomLoopResult>.Start 消费 → handler(item, executionId, ct)
  → AgentTaskPoolAdapter.Resolve(item)         // 按 SchedulingMode：Hybrid→Llm / Config→Rule
  → executor.ExecuteAsync(item, taskKey, ct)
      [LLM]  LlmTaskExecutor: _orchestrator.SetTaskPoolPersistence(p) → _orchestrator.RunAsync(item, ct)
      [Rule] RuleTaskExecutor: AxiomContext 派生 + SnapshotDrivenLoopEngine<AxiomContext,AxiomRound> + RoundLifecycle 五步
  → WriteOutputAsync(ur_outputs)  /  异常路径 WriteFailureOutputAsync（失败保留错误行可重放）
```

### 4) AgentOrchestrator.RunAsync(item)
```
→ RefreshLoopConfigAsync（ur_config 热读）→ EmitRun(RunStarted)
→ Runner = AgentRunnerFactory.Create(AgentRunnerAssemblyInput)（懒建、InvalidateRunner 使失效重建）
   Runner.CancellationCheck/LlmGate/TaskPoolPersistence = 实例持有注入
→ runner.RunAsync(item, timeout, ct)
```

### 5) AgentRunner.RunHybridInternalAsync —— 快照驱动主循环（唯一路径）
```
state = item                      // 单根：任务 = 快照
Publish(Project(state,"started"))
decisionPoint = new DecisionPoint(_mapper)
director = item.SchedulingMode==Config ? ConfigStateDirector : LlmStateDirector
scheduler = new HybridSchedulerStateMachine(director, new TransitionGuard(), state)
Functor scope "agent-run"：Set(token,budget)/SetTaskKey/SetTaskItem/SetSchedulingMode/SetCancellationCheck/SetLlmGate
SnapshotDrivenLoopEngine<AgentTaskItem,RoundOutcome>.RunAsync(
    execute: ExecuteHybridRoundAsync(decisionPoint, s, ct)
    next:    NextHybridRoundAsync(scheduler, s, outcome, ct)
    budgetTerminate: 读 lastDecision(闭包) 终值 → TerminationDecider.ShouldTerminate 兜底)
```

**execute（单轮）** `ExecuteHybridRoundAsync`：
```
lease = CreateLeaseContext(state)   // 共享引用租约
_roundPipeline.ExecuteAsync(rctx)   // StaticAsyncPipeline 五阶段：
   pre_round(空间边界) → lease_derive(LeaseDeriver) → run_round
   → post_round(逻辑边界) → wrap(AxiomActionResult)
run_round: PlanRound(activeStrategy)→RoundPlan(Executor) → ctx.Data[RoundKeys.Executor]
   → WorkflowRunner.RunRoundAsync（骨架五步 guard_input→provide_prompt→cline_execute→rule_match→guard_output）
RoundLifecycle.RunAsync(lease, execute=桩返回 rctx.Result, evaluate=decisionPoint.EvaluateRound, ct)
   // 共享五步单一载体：Collect/Evaluate/Decide/Adjust（进度/熔断/halt/轮次/TS/TO/TM 单一裁决）
→ RoundOutcome(result, lease, round.Eval, round.Decision)
```

**next（状态转移）** `NextHybridRoundAsync`：
```
lastDecision = outcome.Decision                    // 写闭包
HarvestDeterministicCore(state, lease)             // ① 单根收割（标量核心回写根）
scheduler.AdvanceAsync()                           // ② 混合调度（LLM 提议 + TransitionGuard 守卫，原子施加）
  决策 Applied && SwitchStrategy → state.Data[ActiveStrategy]  // ③ 回写策略
_runtimeState.Publish(Project(state,"running"))    // ④ 运行态发布
PersistRuntimeAsync(state)                         // ⑤ PayloadJson 落库（单一状态基座）
```

**循环后**：Publish("completed") → PersistRuntimeAsync → `LoopDecisionConvergence.ConvergeFinal` → `AxiomLoopResult`。

### 6) 暂停门（合作式挂起）
```
cline_execute 在真实 LLM 调用前 → AgentLoopFunction.CheckLlmGateAsync
  → AgentRunCancellation.GetLlmGate()（run 作用域注入）→ AgentRunner.LlmGate = adapter.PauseGateAsync
      → 读 GetTaskKey()（Functor AsyncLocal）→ ClearTaskKey → _pool.WaitIfPausedAsync(key) → SetTaskKey 回填
零 LLM（RuleTaskExecutor）：ExecuteStepAsync 内经 IPauseAwareTaskExecutor._pauseGate（= WaitIfPausedAsync）
```
键经 `AgentRunCancellation`（Functor/AsyncLocal）贯通；暂停阻塞期间 `ClearTaskKey` 防自死锁/防 key 残留。

## 四、既有文档 vs 当前代码（差异点）

仓库内 `Agent/任务池调度循环执行链.md`（v1.0, 2026-08-12）部分描述已**过期**：

| 项 | 文档 v1.0（旧） | 当前代码（重构后） |
|----|-----------------|-------------------|
| 唯一持久根 | `SchedulerState` + `RestoreSchedulerStateAsync` | `AgentTaskItem`（任务=快照），无恢复调用，直接以 item 为 TState |
| 执行器 | 单一 LLM 导演路径 | 执行器解耦集合：`LlmTaskExecutor`(Hybrid) + `RuleTaskExecutor`(Config 零 LLM) |
| 暂停 | 仅 LLM 调用点 | LLM 调用点 + 零 LLM `WirePauseGate` 循环边界 |
| 快照投影 | 独立 `SchedulerStateProjector` | 投影内聚 `IAgentLoopState.ToRuntimeSnapshot`，Projector 为委托薄壳 |
| 终止裁决 | 私有 ComputeDeterministicCore 组合 | 共享 `RoundLifecycle.Decide` 单一裁决 + 闭包 lastDecision + `TerminationDecider` 兜底 |
| 持久化 | AxiomContext 快照（ur_snapshots） | 主路径写 `PayloadJson`；SnapshotSerializer 退居旧持久化 |

## 五、结论

重构后调用链是**单向无环、单根权威**的：
`ur_tasks(写即激活) → TaskPool 消费 → AgentTaskPoolAdapter.Resolve(按 SchedulingMode) → [LlmTaskExecutor→AgentOrchestrator.RunAsync | RuleTaskExecutor→SnapshotDrivenLoopEngine] → AgentRunner.RunHybridInternalAsync(SnapshotDrivenLoopEngine + RoundLifecycle 五步单一载体 + HybridSchedulerStateMachine 混合调度) → PayloadJson 落库 + ur_outputs 回写`。核心特征是「任务 = 快照」的单一状态基座，五步/终止/熔断收敛到共享 `RoundLifecycle`，执行器可插拔（Cline 只是执行器状态之一）。
