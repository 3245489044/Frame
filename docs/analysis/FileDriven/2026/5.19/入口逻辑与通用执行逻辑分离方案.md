# FileDriven 入口逻辑与通用执行逻辑分离方案

## 1. 背景与目标

### 1.1 当前问题

FileDriven 和 WorkFlowMethod 两个项目中，**入口逻辑**（用户交互、脚本加载、UI 事件）与**执行逻辑**（工作流引擎、脚本引擎、函数执行）高度耦合，导致：

- **循环依赖风险**：WorkFlowMethod 内部无法安全使用 FileDriven 的 Script 引擎
- **复用困难**：执行逻辑被入口层绑定，无法独立使用
- **测试复杂**：测试执行逻辑需要启动完整的入口环境

### 1.2 目标

将执行逻辑抽象为**通用执行框架**，入口逻辑作为**独立的外层消费者**，实现：

- 入口层 → 执行框架：**单向依赖**
- 执行框架：**零入口依赖**
- WorkFlowMethod 内部可安全使用执行框架的 ScriptEngine

## 3. 组件职责与接口定义

### 3.1 ScriptEngine（通用脚本引擎）

**职责**：解析脚本语法、管理执行流程、提供执行上下文

**位置**：通用执行框架层，不依赖任何入口组件

```csharp
/// <summary>
/// 通用脚本引擎 - 解析并执行脚本文件/字符串
/// 不依赖任何入口层组件，可被 FileDriven 和 WorkFlowMethod 共同使用
/// </summary>
public interface IScriptEngine
{
    /// <summary>执行脚本文件</summary>
    Task<ScriptExecutionResult> ExecuteFileAsync(string filePath);

    /// <summary>执行脚本内容</summary>
    Task<ScriptExecutionResult> ExecuteAsync(string scriptContent);

    /// <summary>注册自定义命令处理器</summary>
    void RegisterCommand(string name, Func<ScriptCommand, Task<ScriptResult>> handler);

    /// <summary>获取脚本执行上下文</summary>
    IScriptContext Context { get; }
}

/// <summary>脚本执行上下文</summary>
public interface IScriptContext
{
    /// <summary>变量存储</summary>
    Dictionary<string, object> Variables { get; }

    /// <summary>已加载的 UI 配置</summary>
    Dictionary<string, object> LoadedConfigs { get; }

    /// <summary>函数注册表引用</summary>
    IFunctionRegistry FunctionRegistry { get; }
}

/// <summary>脚本命令</summary>
public class ScriptCommand
{
    public string Name { get; set; }          // load/set/click/get/sleep
    public string[] Args { get; set; }        // 命令参数
    public string RawText { get; set; }       // 原始命令文本
}

/// <summary>脚本执行结果</summary>
public class ScriptExecutionResult
{
    public bool IsSuccess { get; set; }
    public List<ScriptResult> StepResults { get; set; } = new();
    public string? ErrorMessage { get; set; }
}

/// <summary>单步脚本结果</summary>
public class ScriptResult
{
    public string Command { get; set; }
    public bool IsSuccess { get; set; }
    public object? Value { get; set; }
    public string? ErrorMessage { get; set; }
}
```

**内置命令**（ScriptEngine 自带，不依赖入口）：

| 命令 | 语法 | 说明 |
|------|------|------|
| `sleep` | `sleep <ms>` | 等待指定毫秒数 |
| `echo` | `echo <message>` | 输出消息 |
| `setvar` | `setvar <name> <value>` | 设置上下文变量 |
| `getvar` | `getvar <name>` | 获取上下文变量 |
| `call` | `call <funcName> <args...>` | 调用注册函数 |
| `exit` | `exit` | 退出脚本执行 |

**扩展命令**（由入口层通过 RegisterCommand 注册）：

| 命令 | 语法 | 说明 | 注册方 |
|------|------|------|--------|
| `load` | `load <configPath>` | 加载 UI 配置 | FileDriven 入口 |
| `set` | `set <control> <value>` | 设置控件值 | FileDriven 入口 |
| `click` | `click <control>` | 点击控件 | FileDriven 入口 |
| `get` | `get <control>` | 获取控件值 | FileDriven 入口 |
| `close` | `close <formName>` | 关闭窗体 | FileDriven 入口 |

### 3.2 WorkflowEngine（通用工作流引擎）

**职责**：加载工作流定义、执行工作流步骤

**位置**：通用执行框架层

```csharp
/// <summary>
/// 通用工作流引擎 - 加载并执行工作流定义
/// 支持线性执行和图结构执行两种模式
/// </summary>
public interface IWorkflowEngine
{
    /// <summary>从文件加载工作流定义</summary>
    IWorkflowDefinition? LoadWorkflow(string filePath);

    /// <summary>按名称获取工作流定义</summary>
    IWorkflowDefinition? GetWorkflow(string workflowName);

    /// <summary>执行工作流</summary>
    Task<string> ExecuteWorkflowAsync(string workflowName, string input);

    /// <summary>执行工作流定义</summary>
    Task<string> ExecuteWorkflowAsync(IWorkflowDefinition definition, string input);

    /// <summary>注册工作流定义</summary>
    void RegisterWorkflow(IWorkflowDefinition definition);

    /// <summary>获取所有工作流名称</summary>
    IEnumerable<string> GetAllWorkflowNames();

    /// <summary>设置工作流配置文件路径</summary>
    void SetConfigBasePath(string basePath);
}

/// <summary>工作流定义</summary>
public interface IWorkflowDefinition
{
    string WorkflowName { get; }
    string DisplayName { get; }
    string Description { get; }
    string Version { get; }
    IReadOnlyList<IWorkflowStep> Steps { get; }
    IReadOnlyDictionary<string, string> OutputMapping { get; }
}

/// <summary>工作流步骤</summary>
public interface IWorkflowStep
{
    string StepName { get; }
    string FuncName { get; }
    IReadOnlyList<string> InputKeys { get; }
    string OutputKey { get; }
    IReadOnlyList<string> Parameters { get; }
}
```

**执行模式**：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **线性执行** | 按 steps 索引顺序执行，变量替换 `${key}` | 简单工作流、向后兼容 |
| **图结构执行** | 委托 WorkFlowMethod 的 PipelineExecutor | 复杂图工作流、循环/分支 |

### 3.3 CommandEngine（通用命令引擎）

**职责**：注册/执行命令、适配器模式挂载后端

**位置**：通用执行框架层

```csharp
/// <summary>
/// 通用命令引擎 - 命令注册、解析、执行
/// 不依赖任何入口组件，通过适配器模式扩展
/// </summary>
public interface ICommandEngine
{
    /// <summary>执行命令</summary>
    Task<ICommandExecutionResult> ExecuteAsync(string command);

    /// <summary>注册命令处理器</summary>
    void RegisterHandler(string commandName, Func<string[], Task<ICommandExecutionResult>> handler);

    /// <summary>获取已注册命令列表</summary>
    IEnumerable<string> GetRegisteredCommands();
}

/// <summary>命令执行结果</summary>
public interface ICommandExecutionResult
{
    bool Success { get; }
    string Command { get; }
    object? Value { get; }
    string? Error { get; }
    TimeSpan Elapsed { get; }
}
```

### 3.4 FunctionRegistry（通用函数注册表）

**职责**：统一管理所有可执行函数

**位置**：通用执行框架层

```csharp
/// <summary>
/// 通用函数注册表 - 统一管理 FileDriven 和 WorkFlowMethod 的函数
/// </summary>
public interface IFunctionRegistry
{
    /// <summary>注册函数（委托方式）</summary>
    void Register(string name, Delegate function, string? description = null);

    /// <summary>注册异步函数</summary>
    void RegisterAsync(string name, Func<WorkflowContext, Task<object>> func);

    /// <summary>注册工作流函数</summary>
    void RegisterFunction(string name, Func<WorkflowContext, object> func);

    /// <summary>执行函数</summary>
    Task<IFunctionExecutionResult> ExecuteAsync(string functionName, object? parameters = null);

    /// <summary>获取已注册函数名称</summary>
    IEnumerable<string> GetRegisteredNames();

    /// <summary>检查函数是否存在</summary>
    bool Contains(string name);
}
```

## 4. 入口层改造

### 4.1 FileDriven 入口层

改造后的 FileDriven 入口层只负责：

1. **接收用户输入**（脚本文件、UI 事件、CLI 命令）
2. **通过 EntryBridge 委托到通用执行框架**
3. **处理执行结果**（显示到 UI、输出到控制台）

```csharp
// FileDriven 入口层 - CliModeRouter 改造后
public class CliModeRouter
{
    private readonly IEntryBridge _bridge;  // 依赖入口桥接，而非直接依赖执行框架

    public async Task ExecuteScriptAsync(string scriptPath)
    {
        // 委托到桥接层，桥接层再委托到 ScriptEngine
        var result = await _bridge.ExecuteScriptAsync(scriptPath);
        foreach (var step in result.StepResults)
        {
            Console.WriteLine($"[{step.Command}] {step.Value}");
        }
    }
}

// FileDriven 入口层 - GuiCommandAdapter 改造后
public class GuiCommandAdapter
{
    private readonly IEntryBridge _bridge;

    // load 命令：委托桥接层加载 UI 配置
    public async Task<OperationResult<object>> DoLoadAsync(string target)
    {
        await _bridge.LoadUiConfigAsync(target);
        return OperationResult<object>.SuccessResult(target, $"Loaded: {target}");
    }

    // click 命令：委托桥接层执行
    public async Task<OperationResult<object>> DoClickAsync(string target)
    {
        await _bridge.ExecuteUiCommandAsync("click", target);
        return OperationResult<object>.SuccessResult(null, $"Clicked {target}");
    }
}
```

### 4.2 WorkFlowMethod 入口层

改造后的 WorkFlowMethod 入口层：

```csharp
// WorkFlowMethod 入口层 - WorkflowUseage 改造后
public static class WorkflowUseage
```

## 5. 入口桥接层 (Entry Bridge)

桥接层是入口层和通用执行框架之间的**唯一通道**：

```csharp
/// <summary>
/// 入口桥接层 - 入口层与通用执行框架之间的唯一通道
/// 职责：接收入口请求，委托到通用执行框架
/// </summary>
public interface IEntryBridge
{
    // ---- 脚本执行 ----
    Task<ScriptExecutionResult> ExecuteScriptAsync(string filePath);
    Task<ScriptExecutionResult> ExecuteScriptContentAsync(string content);

    // ---- 工作流执行 ----
    Task<string> ExecuteWorkflowAsync(string workflowName, string input);
    Task<string> ExecuteWorkflowDefinitionAsync(IWorkflowDefinition definition, string input);

    // ---- 命令执行 ----
    Task<ICommandExecutionResult> ExecuteCommandAsync(string command);

    // ---- UI 操作 ----
    Task LoadUiConfigAsync(string configPath);
    Task ExecuteUiCommandAsync(string command, string target);

    // ---- 函数执行 ----
    Task<IFunctionExecutionResult> ExecuteFunctionAsync(string name, object? parameters = null);
}

/// <summary>
/// 默认桥接实现 - 直接委托到通用执行框架
/// </summary>
public class DefaultEntryBridge : IEntryBridge
{
    private readonly IScriptEngine _scriptEngine;
    private readonly IWorkflowEngine _workflowEngine;
    private readonly ICommandEngine _commandEngine;
    private readonly IFunctionRegistry _functionRegistry;

    public DefaultEntryBridge(
        IScriptEngine? scriptEngine = null,
        IWorkflowEngine? workflowEngine = null,
        ICommandEngine? commandEngine = null,
        IFunctionRegistry? functionRegistry = null)
    {
        _scriptEngine = scriptEngine ?? new ScriptEngine();
        _workflowEngine = workflowEngine ?? new WorkflowEngine();
        _commandEngine = commandEngine ?? new CommandEngine();
        _functionRegistry = functionRegistry ?? new UniversalFunctionRegistry();
    }

    public async Task<ScriptExecutionResult> ExecuteScriptAsync(string filePath)
    {
        return await _scriptEngine.ExecuteFileAsync(filePath);
    }

    public async Task<ScriptExecutionResult> ExecuteScriptContentAsync(string content)
    {
        return await _scriptEngine.ExecuteAsync(content);
    }

    public async Task<string> ExecuteWorkflowAsync(string workflowName, string input)
    {
        return await _workflowEngine.ExecuteWorkflowAsync(workflowName, input);
    }

    // ... 其他方法实现
}
```

## 6. 循环依赖防护

### 6.1 架构级防护

```
入口层 (FileDriven/WorkFlowMethod)
    │ 只依赖 IEntryBridge
    ▼
入口桥接层 (EntryBridge)
    │ 只依赖通用执行框架的接口
    ▼
通用执行框架 (ScriptEngine/WorkflowEngine/FunctionRegistry)
    │ 零入口依赖
    ▼
不依赖任何上层组件
```

### 6.2 代码级防护

在桥接层添加调用栈检测：

```csharp
public class CircularDependencyGuard
{
    private readonly AsyncLocal<HashSet<string>> _callStack = new();

    public IDisposable Enter(string callerId)
    {
        _callStack.Value ??= new HashSet<string>();

        if (_callStack.Value.Contains(callerId))
        {
            throw new InvalidOperationException(
                $"检测到循环调用: {callerId}。调用栈: {string.Join(" → ", _callStack.Value)}");
        }

        _callStack.Value.Add(callerId);
        return new CallGuardScope(() => _callStack.Value.Remove(callerId));
    }

    private class CallGuardScope : IDisposable
    {
        private readonly Action _onDispose;
        public CallGuardScope(Action onDispose) => _onDispose = onDispose;
        public void Dispose() => _onDispose();
    }
}
```

### 6.3 编译期防护

通过项目引用关系确保单向依赖：

```
WorkFlowPrj.sln
├── WorkFlowEngine.Abstractions      # 接口定义（零依赖）
├── WorkFlowEngine                   # 通用执行框架（依赖 Abstractions）
├── FileDriven (入口层)              # 依赖 WorkFlowEngine.Abstractions + WorkFlowEngine
└── WorkFlowMethod (入口层)          # 依赖 WorkFlowEngine.Abstractions + WorkFlowEngine
```

**禁止**：WorkFlowEngine 项目引用 FileDriven 或 WorkFlowMethod 项目。

## 9. 调用示例

### 9.1 FileDriven 入口调用

```csharp
// 当前方式（耦合）
var engine = new CommandEngine();
var result = engine.ExecuteFileAsync("test_script.txt");

// 改造后方式（分离）
var bridge = new DefaultEntryBridge();
bridge.RegisterScriptCommand("load", async (cmd) => {
    // 入口层注册的 load 命令
    await _mainForm.LoadSideContainerAsync(cmd.Args[0]);
    return new ScriptResult { IsSuccess = true };
});

var result = await bridge.ExecuteScriptAsync("test_script.txt");
```

### 9.2 WorkFlowMethod 内部使用 ScriptEngine

```csharp
// WorkFlowMethod 内部 - 安全使用脚本引擎
public class WorkflowProcessor
{
    private readonly IEntryBridge _bridge;

    public async Task ExecuteNodeAsync(NodeConfig node)
    {
        if (node.ExecutionMode == "script")
        {
            // 直接调用通用执行框架的 ScriptEngine
            // 不经过 FileDriven 入口层，不会循环
            var result = await _bridge.ExecuteScriptContentAsync(node.ScriptContent);

            // 将脚本执行结果合并到工作流上下文
            foreach (var (key, value) in result.Context.Variables)
            {
                _workflowContext.Set(key, value);
            }
        }
        else
        {
            // 正常函数执行
            await ExecuteFunctionAsync(node);
        }
    }
}
```

### 9.3 循环检测示例

```csharp
// 桥接层自动检测循环
var guard = new CircularDependencyGuard();

// 正常调用
using (guard.Enter("WorkflowProcessor"))
{
    await _bridge.ExecuteScriptAsync("script.txt");
    // ✅ 正常执行
}

// 循环调用（ScriptEngine 内部又调回 WorkflowProcessor）
using (guard.Enter("WorkflowProcessor"))
{
    await _bridge.ExecuteScriptAsync("circular_script.txt");
    // ❌ 抛出 CircularDependencyException
}
```

## 10. 总结

| 维度 | 改造前 | 改造后 |
|------|--------|--------|
| **架构** | 入口与执行耦合 | 三层分离：入口 → 桥接 → 执行框架 |
| **循环风险** | 高（互相引用） | 无（单向依赖） |
| **复用性** | 低（绑定入口） | 高（通用框架独立） |
| **可测试性** | 低（需启动完整环境） | 高（可单独测试执行框架） |
| **扩展性** | 低（修改执行逻辑影响入口） | 高（执行框架独立演进） |
| **WorkFlowMethod 使用 FileDriven** | 不可行（循环） | 可行（通过通用框架） |

**核心原则**：
1. 执行框架**不引用**任何入口层项目
2. 入口层**只引用**执行框架的接口和桥接层
3. 桥接层是**唯一通道**，负责请求转发和循环检测
4. WorkFlowMethod 内部使用 ScriptEngine 时，调用的是通用执行框架，**不经过 FileDriven 入口层**
