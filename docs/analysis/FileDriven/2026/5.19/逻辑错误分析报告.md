## ✅ 已修复的严重逻辑错误

### ✅ 1. WorkflowEngine.cs — 工作流执行逻辑完全失效
**文件**: `FileDrivenFramework.Core/WorkflowEngine.cs`
**修复**: 
- 移除无参构造函数和 `IFunctionExecutor` 参数构造函数，强制要求传入 `PipelineAdapter`
- 移除 `ExecuteWorkflowLegacyAsync` 独立工作流执行逻辑（变量替换、函数调用、结果传递）
- 移除 `ResolveParameters` 方法和 `VarPrefix`/`VarSuffix` 常量
- 当 `_pipelineAdapter == null` 时抛出 `InvalidOperationException`，明确提示需要 UI 配置管线
- **设计原则**: 工作流不应有独立的执行逻辑，所有工作流必须通过 UI 加载的配置（PipelineAdapter）执行
**状态**: ✅ 已修复

### ✅ 2. FunctionRegistry.cs — void 返回类型表达式树编译可能异常
**文件**: `FileDrivenFramework.Core/FunctionRegistry.cs`
**修复**: 使用 `Expression.Call` 替代 `Expression.Invoke`，避免 void 返回类型抛出 `ArgumentException`。同时为 void/Task/ValueTask 等不同返回类型分别处理。
**状态**: ✅ 已修复

### ✅ 3. FunctionRegistry.cs — Task<T> 结果获取存在竞态条件
**文件**: `FileDrivenFramework.Core/FunctionRegistry.cs`
**修复**: 使用 `dynamic` 关键字获取 `Task<T>.Result`，避免反射竞态条件；对非泛型 Task 返回 null；新增 ValueTask 支持。
**状态**: ✅ 已修复

### ✅ 4. CommandEngine.cs — Obsolete 方法保留在接口中
**文件**: `FileDrivenFramework.Core/CommandEngine.cs`
**修复**: 移除 `[Obsolete]` 属性，改为文档注释说明建议使用 `CommandFileExecutor` 替代。
**状态**: ✅ 已修复
