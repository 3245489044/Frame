# FileDriven 通用逻辑框架提取分析报告

## 一、当前架构全景

```
FileDrivenFramework.Abstractions/          ← 14个接口，零依赖（基础框架，不动）
FileDrivenFramework.Core/                  ← 通用实现（基础框架，不动）
├── CommandEngine / CommandExecutionResult / CommandFileExecutor
├── WorkflowEngine (保留 Pipeline 容器功能)
├── SharedWorkflowDefinition
├── FunctionRegistry / FunctionExecutor / FunctionExecutionResult
├── DescriptorBuilder
└── JsonProcessingService

FileDriven.CLI/                            ← CLI 驱动层
FileDriven.UI/                             ← WinForms UI 驱动层
FileDriven.Launcher/                       ← 启动入口

FunctionStorage/                           ← 运行时核心（所有运行时逻辑在此）
├── WorkflowExecutionLayer.cs              ← 工作流执行引擎
├── WorkflowSkeletons.cs                   ← SkeletonFlow 管线（已从 Core 迁移至此）
├── WorkflowLibrary.cs                     ← 工作流注册
├── ModelLibrary.cs / MathLibrary.cs       ← 业务函数
└── UIConnector.cs                         ← UI 事件绑定
```

## 二、已完成迁移

**迁移内容：** 整个 `WorkflowSkeletons.cs` 从 `FileDrivenFramework.Core` 迁移到 `FunctionStorage`

| 类型 | 说明 |
|------|------|
| `WorkflowContext` | 工作流执行上下文 |
| `WorkflowDefinition` / `WorkflowStep` | 工作流 JSON 模型 |
| `LoadWorkflowSkeleton` | 工作流加载骨架 |
| `ExecuteStepSkeleton` | 步骤执行骨架（变量替换 + 调用 FunctionExecutionFramework） |
| `BuildWorkflowOutputSkeleton` | 输出映射构建骨架 |
| `WorkflowPipelineFactory` | SkeletonFlow 管线工厂 |
| `LoadInputTemplateSkeleton` | 默认输入加载骨架 |
| `LoadWorkflowDetailsSkeleton` | 工作流详情加载骨架 |

**变更：**
- 原文件：`FileDriven/FileDrivenFramework.Core/WorkflowSkeletons.cs` → **已删除**
- 新文件：`FunctionStorage/WorkflowSkeletons.cs` → **已创建**
- 命名空间：`FileDrivenFramework.Core` → `FunctionStorage`
- 移除了对 `FileDrivenFramework.Core` 的依赖（原 `using FunctionStorage` 不再需要）

### ✅ WorkflowEngine 执行逻辑分析

**结论：无需额外迁移。**

`FileDrivenFramework.Core.WorkflowEngine` 的 `ExecuteWorkflowAsync` 在无 Pipeline 时是**空壳**（直接返回 input，没有步骤执行逻辑）。真正的执行逻辑已经在 `FunctionStorage.WorkflowExecutionLayer` 中。

WorkflowEngine 保留在 Core 层作为：
- **Pipeline 容器**：持有 `IPipeline<string, string>` 实例
- **通用框架代码**：实现 `IWorkflowEngine` 接口

## 三、架构原则

```
基础框架（FileDrivenFramework.*）← 不动
  ├── Abstractions：纯接口定义
  └── Core：通用实现（FunctionRegistry、CommandEngine 等）

运行时逻辑（FunctionStorage）← 所有工作流执行业务在此
  ├── WorkflowExecutionLayer：JSON 工作流执行引擎
  ├── WorkflowSkeletons：SkeletonFlow 管线
  ├── WorkflowLibrary：工作流注册
  └── 其他业务函数库

驱动层（FileDriven）← 纯 UI/CLI
  ├── UI：WinForms 界面
  ├── CLI：命令行模式
  └── Launcher：启动入口
```
