# FileDriven 日志系统使用指南

## 概述

FileDriven 框架使用基于 **Placeholder 模板** 的日志系统。日志消息定义集中存储在 `filedriven_log_messages.json` 中，C# 代码通过 `FileDrivenLogPlaceholderHandler.Log()` 或 `LogPlaceholderHandlerBase.Log()` 引用这些定义。

**核心原则：** 日志消息模板定义在 JSON 中，代码中只引用消息 ID。日志的格式化、级别、分类都由 JSON 控制。

---

## 一、日志消息定义文件

**路径：** `FileDriven/filedriven_log_messages.json`

### 消息结构

```json
{
  "version": "1.0",
  "description": "FileDriven 日志消息定义",
  "messages": {
    "消息ID": {
      "level": "Info|Warning|Error|Debug",
      "category": "分类名称",
      "template": "日志模板文本 {参数名}"
    }
  }
}
```

### 字段说明

| 字段 | 说明 |
|------|------|
| `消息ID` | 唯一标识，命名规范：`ClassName_MethodName_description` |
| `level` | 日志级别：`Info` / `Warning` / `Error` / `Debug` |
| `category` | 分类标签，用于过滤：`Launcher_Bootstrap` / `Launcher_Lifecycle` / `FileDriven_Command` / `FileDriven_General` / `FileDriven_Inspector` |
| `template` | 日志模板，`{参数名}` 占位符会被实际值替换 |

### 命名规范

消息 ID 使用 `ClassName_MethodName_description` 格式：
- `ScriptConverter_Pipeline_Failed` — ScriptConverter 类的管线失败
- `GuiModeRunner_Run_Summary` — GuiModeRunner 的执行摘要
- `CommandLoopSkeleton_ExecuteCore_ok` — 命令循环执行成功

## 二、在 C# 代码中使用日志

### 方式一：使用 FileDrivenLogPlaceholderHandler.Log（推荐）

适用于引用了 `FileDriven.Logging` 项目的模块（如 `FileDriven.Launcher`、`FileDriven.UI`、`FileDriven.Pipeline`）。

```csharp
using Common.PlaceholderFramework.Integrated.Handlers;

// 无参数
FileDrivenLogPlaceholderHandler.Log("消息ID");

// 带参数
FileDrivenLogPlaceholderHandler.Log("消息ID", new { 参数名 = 值 });
```

**示例：**
```csharp
// 简单消息
FileDrivenLogPlaceholderHandler.Log("GuiModeRunner_Run_start");

// 带参数
FileDrivenLogPlaceholderHandler.Log("GuiModeRunner_Run_executing_command_file",
    new { commandFile = actualCommandFile });

// 多个参数
FileDrivenLogPlaceholderHandler.Log("GuiModeRunner_Run_Summary",
    new { totalCommands = 10, successCount = 8, failCount = 2 });
```

### 方式二：使用 LogPlaceholderHandlerBase.Log（避免循环引用）

适用于不能引用 `FileDriven.Logging` 的项目（如 `FileDriven.Utilities`，因为 `FileDriven.Logging` 已引用它）。

```csharp
using Common.PlaceholderFramework.Integrated.Handlers;

LogPlaceholderHandlerBase.Log("消息ID", "FileDriven", "filedriven:", new { 参数名 = 值 });
```

**示例：**
```csharp
LogPlaceholderHandlerBase.Log("ScriptConverter_Pipeline_Failed",
    "FileDriven", "filedriven:", new { errorReport });
```

> **注意：** 方式二需要显式传入 `"FileDriven"` 模块名和 `"filedriven:"` 前缀。方式一已封装这些参数。

## 三、添加新日志的步骤

### 步骤 1：在 JSON 中定义消息

打开 `filedriven_log_messages.json`，在 `messages` 对象末尾添加：

```json
"MyClass_MyMethod_my_event": {
  "level": "Info",
  "category": "FileDriven_General",
  "template": "我的事件发生: {myParam}"
}
```

### 步骤 2：在 C# 代码中引用

```csharp
FileDrivenLogPlaceholderHandler.Log("MyClass_MyMethod_my_event",
    new { myParam = someValue });
```

### 步骤 3：添加 using 引用（如尚未添加）

```csharp
using Common.PlaceholderFramework.Integrated.Handlers;
```

## 四、日志分类说明

| 分类 | 用途 | 示例 |
|------|------|------|
| `Launcher_Bootstrap` | 框架启动初始化 | 工作目录设置、路径别名注册、健康检查 |
| `Launcher_Lifecycle` | 框架运行生命周期 | GUI 模式启动、脚本执行、框架关闭 |
| `FileDriven_Command` | 命令执行相关 | 命令成功/失败、控件操作 |
| `FileDriven_General` | 通用日志 | 脚本转换、配置加载、模板处理 |
| `FileDriven_Inspector` | UI 检查器 | 控件树遍历、布局分析、重叠检测 |

---

## 五、日志级别说明

| 级别 | 含义 | 使用场景 |
|------|------|----------|
| `Info` | 正常信息 | 启动完成、命令成功、执行摘要 |
| `Warning` | 警告 | 文件未找到、降级成功、非关键失败 |
| `Error` | 错误 | 转换失败、加载失败、异常 |
| `Debug` | 调试信息 | 详细处理过程（当前 JSON 中未使用，可添加） |

## 六、常见问题

### Q: 日志没有输出？
A: 检查 `filedriven_log_messages.json` 是否已通过 `FileDrivenLogPlaceholderHandler.Initialize()` 初始化。初始化通常在 `FrameworkInitializer` 中完成。

### Q: 消息 ID 未找到的警告？
A: 日志系统会输出 `Log message 'xxx' not found for keyPrefix 'filedriven:'`。检查 JSON 中是否定义了该消息 ID。

### Q: 参数占位符未替换？
A: 确保 JSON 模板中的 `{参数名}` 与 C# 代码中 `new { 参数名 = 值 }` 的参数名**完全一致**（大小写敏感）。

### Q: 循环引用问题？
A: 如果项目 A 引用了项目 B，而项目 B 又引用了项目 A，则不能使用 `FileDrivenLogPlaceholderHandler.Log`（它在项目 B 中）。应使用 `LogPlaceholderHandlerBase.Log` 并显式传入模块名和前缀。
