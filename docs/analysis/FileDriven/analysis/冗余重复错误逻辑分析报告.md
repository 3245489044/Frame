# FileDriven 冗余/重复/错误逻辑综合分析报告

> 分析日期：2026-06-08
> 分析范围：FileDriven 全部子项目（Launcher, Logging, Pipeline, Utilities, JsonRefer, UI）

---

## 一、错误逻辑（Bugs）

### B1（P1）: FileDrivenPipelineContext 与 LogPipelineContext 字段重复
- **问题**：两个 Context 类各自独立声明了 9 个相同字段（BatchId, BatchName, Source, Description, WorkflowId, ProjectRoot, IsPipeMode, PipeName, EnabledCategories）
- **修复**：引入 `BatchContextData` 共享类，两个 Context 通过组合模式持有同一实例，消除字段重复
- **涉及文件**：`FileDrivenPipelineContext.cs`, `LogPipeline.cs`

### B2（P2）: Console 模式摘要输出格式不统一
- **问题**：`FileDrivenLogManager.Shutdown()` 中 Console 模式直接调用 `BatchManager.Instance.GetSummary()`，输出格式与 `LogSummarySkeleton` 不一致
- **修复**：Console 模式也使用与 `LogSummarySkeleton` 一致的格式输出（`===== 批次日志摘要 =====`）
- **涉及文件**：`FileDrivenLogManager.cs`

### B3（P3）: echo 命令内联逻辑未提取为独立方法
- **问题**：echo 命令逻辑直接写在 switch 分支中，与其他命令（load/close/sleep 等）风格不一致
- **修复**：提取为 `HandleEcho()` 独立方法
- **涉及文件**：`NonEventCommandHandler.cs`

### B4（P2）: EmergencyDump 重复检查
- **问题**：`EmergencyDump()` 和 `EmergencyDumpToSqlite()` 各自独立执行 `LogRepository.GetAll().ToList()` 和空检查
- **修复**：提取 `TryGetLogs()` 共享方法
- **涉及文件**：`EmergencyDumpHelper.cs`

### B5（P0）: Usage.LoadConfig() 每次创建新 PipelineEntry
- **问题**：`Usage.LoadConfig()` 每次调用都 `new PipelineEntry()`，导致配置加载后无法在后续调用中使用
- **修复**：使用静态 `_sharedEntry` 字段 + 双重检查锁，确保复用同一实例
- **涉及文件**：`Usage.cs`

### B6（P0）: Bootstrapper.Demo() 和 SetupGlobalExceptionHandling() 访问级别问题
- **问题**：`Bootstrapper.Demo()` 和 `SetupGlobalExceptionHandling()` 是 `private`，`Usage.Demo()` 和 `Usage.SetupGlobalExceptionHandling()` 无法委托调用
- **修复**：改为 `internal`
- **涉及文件**：`FileDrivenBootstrapper.cs`

## 二、重复逻辑（Duplications）

### D1（P1）: FileDrivenPipelineContext 与 LogPipelineContext 字段重复
- 同 B1，已通过 `BatchContextData` 组合模式修复

### D2（P2）: Demo() 方法重复
- **问题**：`Usage.Demo()` 和 `Bootstrapper.Demo()` 各自独立实现相同的演示流程
- **修复**：`Usage.Demo()` 委托给 `Bootstrapper.Demo()`
- **涉及文件**：`Usage.cs`, `FileDrivenBootstrapper.cs`

### D3（P2）: SetupGlobalExceptionHandling() 重复
- **问题**：`Usage.SetupGlobalExceptionHandling()` 和 `Bootstrapper.SetupGlobalExceptionHandling()` 各自独立实现相同的异常捕获逻辑
- **修复**：`Usage.SetupGlobalExceptionHandling()` 委托给 `Bootstrapper.SetupGlobalExceptionHandling()`
- **涉及文件**：`Usage.cs`, `FileDrivenBootstrapper.cs`

### D4（P2）: LogPipeline 构建方法重复
- **问题**：`BuildDefaultPipeline()`, `BuildMinimalPipeline()`, `CreateWithLogCollect()`, `CreateWithLogCollectAndExceptionHandling()` 各自独立创建骨架实例
- **修复**：提取 `CreateBaseSkeletons()` 共享方法
- **涉及文件**：`LogPipeline.cs`

### D5（P2）: EmergencyDump 重复检查
- 同 B4，已通过 `TryGetLogs()` 提取修复

## 三、冗余逻辑（Redundancies）

### R1（P1）: LoggingManager 与 FileDrivenLogManager 双层外观
- **问题**：`LoggingManager` 和 `FileDrivenLogManager` 都是日志系统的外观类，职责重叠
- **修复**：`LoggingManager` 合并到 `FileDrivenLogManager`，`LoggingManager` 标记为 `Obsolete` 并委托给 `FileDrivenLogManager`
- **涉及文件**：`LoggingManager.cs`, `FileDrivenLogManager.cs`

### R2（P3）: Usage.cs 废弃方法未标记 Obsolete
- **问题**：`InitializeFramework()` 和 `ShutdownFramework()` 已迁移到 Bootstrapper，但未标记 `[Obsolete]`
- **修复**：添加 `[Obsolete]` 特性
- **涉及文件**：`Usage.cs`

### R3（P3）: CliModeRunner.cs 退化文件
- **问题**：`CliModeRunner.cs` 内容已完全迁移到 `FileDrivenBootstrapper`，成为空壳文件
- **修复**：删除文件
- **涉及文件**：`FileDriven.Utilities/CLI/CliModeRunner.cs`（已删除）

### R4（P3）: LogInjectionSkeletons.Wrap() 退化方法
- **问题**：`Wrap()` 仅委托给 `new LoggingSkeletonWrapper(inner)`，无额外逻辑
- **修复**：移除 `Wrap()` 方法
- **涉及文件**：`Skeletons.cs`

### R5（P3）: PipelineEntry 静态委托方法
- **问题**：`CreateFileDrivenPipeline()` 和 `BuildCommandPipeline()` 仅委托给 `PipelineFactory`
- **评估**：保留作为便捷入口（有实际调用者：实例方法 `CreatePipeline()` 和 `IEventPipelineExecutor.Execute()`）
