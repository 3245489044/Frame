# 渲染管线收敛重构：状态驱动单一路径设计

> **日期**：2026-08-02
> **触发问题**：`LoadConfigToTarget`（加载 MathFunctions 到 `sideContainer`）渲染"成功"（收集 29 实体、应用 29），但 `sideContainer` 校验无子控件 → `VerifyContainerMounted` 返回 false → `LoadConfigToTarget` 报"目标容器 'sideContainer' 未挂载任何配置子控件（渲染未生效）"。
> **根因**：容器加载存在 **两条并行渲染管线**（状态驱动 / 传统直接调用），由 `HostBindingStore.IsBound(scope)` 运行时分流。两管线在宿主解析、渲染结果感知上语义不一致，各自用补丁弥合，最终导致"渲染结果"与"验证结果"分叉且无法同步感知。
> **战略升级**：从 bug 修复 → 架构级「渲染管线收敛：状态驱动单一路径，消除补丁」。

---

## 一、背景与动机

### 1.1 问题现象

```
exec LoadConfigToTarget → LoadConfigPortAdapter.LoadConfigAsync(path, "Side", "sideContainer")
  └─ HostBindingStore.IsBound("Side") == ?   ← 运行时分流点
      ├─ true  → 状态管线：ContainerCommandExecutor → 写状态 → 投影器异步渲染 → RenderWaiter 等回写
      └─ false → 传统管线：ConfigurationLifecycleManager.LoadAsync → ResolveHost → 直接渲染
  → 无论哪条路径，sideContainer 校验 Controls.Count == 0
  → "目标容器 'sideContainer' 未挂载任何配置子控件（渲染未生效）"
```

日志证据：

```
[22:39:44.025] RenderPipelineComposition: 执行完整管线 — scope=Side, hasRootContainer=true
[22:39:44.030] WinFormsOutputPort: 应用控件快照 — controlCount=30
[22:39:44.047] [ERROR] [UIToolbox] 目标容器 'sideContainer' 未挂载任何配置子控件（渲染未生效）
[22:39:44.553] validate titleLabel / statusLabel 成功   ← 渲染实际发生在其它宿主（主窗体）
```

### 1.2 战略结论

「加载配置到容器」本应是 **单原子动作**，但当前被拆成两套并行实现、跨 4 个模块、多层间接：

| 关注点 | 状态管线 | 传统管线 |
|--------|---------|---------|
| 宿主解析 | HostBindingStore → ControlPool | ResolveHost（hostResolvers → ControlPool → 主窗体递归兜底） |
| 渲染触发 | 状态写 + 事件订阅 + 异步响应 | 直接方法调用 |
| 结果感知 | RenderWaiter 事件等待 + 超时兜底 | 方法返回值 |
| 失败反馈 | 投影器静默跳过 | 回退主窗体（渲染错位无报错） |

**两套实现 + 五处补丁** = `LoadSide` 排查艰难的根源。问题可能藏在任意一层，只能在各层可能性里猜测。

## 二、现状诊断

### 2.1 当前双管线结构

```
                    ┌─ IsBound(Side)=true ──→ 状态管线（异步事件驱动）
LoadConfigPortAdapter┤
                    └─ IsBound(Side)=false ─→ 传统管线（同步直接调用）
```

**状态管线（异步）**：

```
LoadConfigPortAdapter
  → ContainerCommandExecutor.LoadToScopeAsync
    → ContainerStateStore.Set(scope, Loading)      ← 中间态
    → new RenderWaiter(...)                        ← 事件等待器
    → ContainerStateStore.Set(scope, Loaded)       ← 触发 StateSubscriptionHub
    → ContainerProjector.OnContainerStateChangedAsync（订阅响应）
      → HostBindingStore.ResolveHostKey(scope)
      → ControlPool.GetControl(hostKey)            ← 可能 null → 静默跳过
      → EcsGate.LoadConfigAndRenderAsync
    → RenderWaiter 等回写（Loaded/Failed）          ← 超时按"已提交"成功
```

**传统管线（同步）**：

```
LoadConfigPortAdapter
  → ConfigurationLifecycleManager.LoadAsync
    → ResolveHost(hostControlName)
      → _hostResolvers → ControlPool → 主窗体递归查找 → 主窗体兜底
    → EcsGate.LoadConfigAndRenderAsync(config, scope, host)
```

### 2.2 补丁清单（本次重构要消除的）

| 编号 | 补丁 | 位置 | 掩盖的问题 |
|------|------|------|-----------|
| **P1** | `IsBound(scope)` 运行时分流 | `LoadConfigPortAdapter.LoadConfigAsync` | 两套实现并存，同一动作两种语义 |
| **P2** | `RenderWaiter` 超时按"已提交"成功 | `ContainerCommandExecutor` | 状态驱动无法同步感知渲染结果 → 假成功 |
| **P3** | `ResolveHost` 递归查找 + 主窗体兜底 | `ConfigurationLifecycleManager` | 宿主解析不可靠 → 渲染错位到主窗体无报错 |
| **P4** | 投影器静默跳过渲染 | `ContainerProjector.RenderCoreAsync` | 宿主未注册时无反馈 → 调用方不知情 |
| **P5** | `VerifyContainerMounted` | `UIToolbox.LoadConfigToTarget` | 以上不确定性导致"无异常即成功"的虚假 PASS |

### 2.3 可复用资产（不重复建设）

```
✅ 已有：ContainerStateStore（薄封装 IStorageCell，类型安全状态读写）
✅ 已有：HostBindingStore（scope ↔ hostKey 逻辑绑定）
✅ 已有：ControlPool（hostKey → 物理控件唯一解析源）
✅ 已有：ContainerProjector（唯一触碰物理控件的渲染组件）
✅ 已有：EcsGate.LoadConfigAndRenderAsync（渲染唯一入口）
✅ 已有：ConfigurationLifecycleManager（BootstrapAsync 启动引导 + IScopeDestroyer 销毁编排）
```

## 三、重构目标与设计

### 3.1 目标

**让「状态驱动」成为容器加载的唯一语义，删除传统管线分支与五处补丁。**

理由：
1. `ContainerProjector` 已是唯一触碰物理控件的组件——状态订阅 + 渲染是清晰的单向流
2. 传统直接调用与其重复，是分叉的源头
3. 同步结果契约消除全部"渲染是否成功"的不确定性

### 3.2 重构后的单一流水线

```
LoadConfigPortAdapter.LoadConfigAsync
  → ContainerCommandExecutor.LoadToScopeAsync（唯一入口）
    → ContainerProjector.RenderAsync（同步方法，直接返回真实结果）
      → HostBindingStore 解析宿主键 → ControlPool 解析物理控件（失败即显式异常）
      → EcsGate.LoadConfigAndRenderAsync
      → 返回真实 bool 结果
```

**核心变更**：投影器从"订阅状态异步响应"改为"被命令执行器直接调用"；`RenderWaiter` 事件等待机制删除，渲染结果由方法返回值承载。

## 四、重构步骤

### 步骤 1：`LoadConfigPortAdapter` — 删除分流，只走状态管线

**现状**（`FileDriven/FileDriven.Execution/Ports/LoadConfigPortAdapter.cs`）：

```csharp
public async Task LoadConfigAsync(string configPath, string scopeName, string? targetControlName)
{
    var bindingStore = AppServiceProvider.Resolve<HostBindingStore>();
    if (bindingStore?.IsBound(scopeName) == true)
    {
        var executor = AppServiceProvider.Resolve<ContainerCommandExecutor>();
        ...
        var ok = await executor.LoadToScopeAsync(scopeName, configPath);
        if (!ok) throw new InvalidOperationException($"状态管线渲染失败: {configPath}");
        return;
    }

    // 传统路径
    var config = await JsonConfigService.LoadConfigSmartAsync(configPath);
    ...lifecycleManager.LoadAsync(config, scopeName, targetControlName, ...);
}
```

**重构后**：

```csharp
public async Task LoadConfigAsync(string configPath, string scopeName, string? targetControlName)
{
    var executor = AppServiceProvider.Resolve<ContainerCommandExecutor>()
        ?? throw new InvalidOperationException("ContainerCommandExecutor 未注册到 AppServiceProvider");

    var ok = await executor.LoadToScopeAsync(scopeName, configPath);
    if (!ok)
        throw new InvalidOperationException($"状态管线渲染失败: {configPath}");
}
```

| 删除 | 说明 |
|------|------|
| `IsBound` 判断 | 无分流 |
| HostBindingStore 依赖 | 宿主解析下沉到投影器 |
| `ConfigurationLifecycleManager` 传统路径 | 单一路径 |
| `JsonConfigService.LoadConfigSmartAsync` 预加载 | 投影器已负责配置加载 |

### 步骤 2：`ContainerCommandExecutor` — 删除事件等待，直接调用投影器

**现状**（`CsharpPrj/Operation/FrontEndDriven/State/Commands/ContainerCommandExecutor.cs`）：

```csharp
public async Task<bool> LoadToScopeAsync(string scope, string configPath)
{
    // ① 幂等短路
    // ② 写 Loading 状态
    // ③ new RenderWaiter(...) 订阅渲染回写
    // ④ 写 Loaded 状态（触发 StateSubscriptionHub → 投影器异步渲染）
    // ⑤ await waiter.WaitAsync(RenderTimeout)  // 超时返回 true = "已提交"
}
```

**重构后**：

```csharp
public sealed class ContainerCommandExecutor
{
    private readonly ContainerStateStore _stateStore;
    private readonly ContainerProjector _projector;   // 注入投影器，而非依赖异步桥

    public ContainerCommandExecutor(ContainerStateStore stateStore, ContainerProjector projector)
    {
        _stateStore = stateStore;
        _projector = projector;
    }

    public async Task<bool> LoadToScopeAsync(string scope, string configPath)
    {
        if (string.IsNullOrWhiteSpace(scope)) throw new ArgumentException("作用域不能为空", nameof(scope));
        if (string.IsNullOrWhiteSpace(configPath)) throw new ArgumentException("配置路径不能为空", nameof(configPath));

        // 同步渲染：交给投影器直接执行，返回真实结果
        var state = new ContainerState(
            scope,
            ConfigPath: configPath,
            Status: ContainerStatus.Loaded,
            UpdatedAtUtc: DateTime.UtcNow);

        return await _projector.RenderAsync(scope, state).ConfigureAwait(false);
    }
}
```

| 删除 | 说明 |
|------|------|
| `RenderWaiter` 内部类 | 结果由方法返回值承载，无需事件等待 |
| `RenderTimeout`（30s 超时兜底） | 补丁 P2 消除 |
| `Loading` 中间态写 | 无异步过渡，无需中间态 |
| 幂等短路 | 如需保留，改为 `ContainerStateStore.Get(scope)` 简单判断（可选） |

### 步骤 3：`ContainerProjector` — 暴露同步渲染方法，删静默跳过

**现状**（`CsharpPrj/Operation/FrontEndDriven/State/Projection/ContainerProjector.cs`）：

```csharp
public async Task OnContainerStateChangedAsync(string scope, ContainerState state)
{
    // 仅处理 Loaded
    // 防重入：_rendering 集合
    await RenderCoreAsync(scope, state);
}

private async Task RenderCoreAsync(string scope, ContainerState state)
{
    var hostKey = _bindingStore.ResolveHostKey(scope);
    if (string.IsNullOrEmpty(hostKey)) return;            // 静默跳过
    var host = _controlPool.GetControl(hostKey);
    if (host == null) return;                              // 静默跳过（补丁 P4）
    ...
    var ok = await _gate.LoadConfigAndRenderAsync(config, scope, host);
    _stateStore.Set(scope, updated);                       // 回写状态（供 RenderWaiter）
}
```

**重构后**：

```csharp
public async Task<bool> RenderAsync(string scope, ContainerState state)
{
    // ① 解析宿主键：失败即显式异常（不再静默）
    var hostKey = _bindingStore.ResolveHostKey(scope);
    if (string.IsNullOrEmpty(hostKey))
        throw new InvalidOperationException($"scope '{scope}' 未绑定宿主，无法渲染");

    // ② 解析物理控件：失败即显式异常（补丁 P4 消除）
    var host = _controlPool.GetControl(hostKey);
    if (host == null)
        throw new InvalidOperationException($"宿主 '{hostKey}' 未注册到 ControlPool，无法渲染");

    // ③ 生命周期事件 + 钩子（保留）
    var phaseId = state.ConfigPath ?? scope;
    await _platform.PublishAsync(PlatformEvent.Loading(phaseId, scope, state.ConfigPath ?? string.Empty));
    await LifecycleHookExecutor.ExecuteHooksAsync(_platform, config.Lifecycle?.OnBeforeLoad, scope);

    // ④ 渲染（切 UI 线程）→ 直接返回真实结果
    var ok = await _uiDispatcher.InvokeAsync(() => _gate.LoadConfigAndRenderAsync(config, scope, host));

    // ⑤ onAfterLoad 钩子 + ConfigLoaded 事件
    ...
    return ok;
}
```

| 删除 | 说明 |
|------|------|
| `OnContainerStateChangedAsync` | 投影器不再作为状态订阅者 |
| `_rendering` 防重入集合 | 同步调用无重入问题 |
| 静默跳过分支 | 显式异常（补丁 P4 消除） |
| `_stateStore.Set` 回写 | 不再需要回写驱动事件等待 |

### 步骤 4：`StateSubscriptionHub` + `ContainerStateStore` — 按使用方收敛

- **`StateSubscriptionHub`**：唯一消费方是投影器（异步桥）。收敛后投影器被直接调用 → **可删除**。装配处（`StateServiceCollection.RegisterAll`）同步移除。
- **`ContainerStateStore`**：若仍需运行时状态查询（诊断/审计），保留为纯状态读写；不再承担"触发渲染"职责。如无查询方，一并精简。

### 步骤 5：`ConfigurationLifecycleManager` — 只留引导职责

**现状**：`BootstrapAsync`（启动引导）+ `LoadAsync`（动态加载，含复杂 ResolveHost）+ `DestroyScopeAsync`（销毁编排）。

**重构后**：

| 保留 | 删除 |
|------|------|
| `BootstrapAsync`（boot 声明按序加载） | `LoadAsync` 动态加载分支（状态管线接管） |
| `DestroyScopeAsync`（IScopeDestroyer 销毁编排） | `ResolveHost` 递归兜底（补丁 P3，回归 `ControlPool.GetControl` 直查，失败即报错） |
| `RegisterHostResolver`（root 宿主注册） | `_hostResolvers` 的整体回退逻辑（若仍需要 root 直绑可保留最小映射） |

> 注意：若启动引导阶段（`BootstrapAsync`）仍需同步加载，可保留一个薄包装 `LoadToScopeAsync` 的委托，统一语义。

### 步骤 6：`UIToolbox.VerifyContainerMounted` — 删除/降级

**现状**（补丁 P5）：`LoadConfigToTarget` 渲染完成后强校验容器挂载子控件。

**重构后**：
- 同步结果契约已保证"渲染完成才返回 true"，`VerifyContainerMounted` 的"二次确认"不再必要
- **删除**该校验与 `VerifyContainerMounted` 方法；或**降级**为 WARN 审计（不阻断结果）

## 五、重构前后对比

### 5.1 调用链

**重构前**（双管线）：
```
LoadConfigPortAdapter ── IsBound ──┬─ ContainerCommandExecutor → 状态 → 事件订阅 → 投影器 → RenderWaiter 等待
                                   └─ ConfigurationLifecycleManager → ResolveHost（多层兜底） → 直接渲染
                                   └─ VerifyContainerMounted 二次校验（P5）
```

**重构后**（单一路径）：
```
LoadConfigPortAdapter → ContainerCommandExecutor → ContainerProjector.RenderAsync → EcsGate → 真实 bool
```

### 5.2 补丁消除对照

| 补丁 | 消除方式 |
|------|---------|
| P1 运行时分流 | 删除 `IsBound` 分支，仅存状态管线 |
| P2 RenderWaiter 超时 | 同步方法返回值，删除事件等待 |
| P3 ResolveHost 兜底 | 回归 ControlPool 直查，失败显式异常 |
| P4 投影器静默跳过 | 显式异常 |
| P5 VerifyContainerMounted | 删除或降级 WARN |

## 六、应一并收编的遗留加载路径

除双管线（状态驱动/传统路径）外，框架还存在 **多条历史遗留的配置加载路径**，各自独立实现「路径解析 → 反序列化 → 渲染/注册」，与状态驱动管线重复。本次重构应一并收编，统一收敛到 `ContainerCommandExecutor → ContainerProjector.RenderAsync`。

### 6.1 遗留路径清单

| 编号 | 路径 | 位置 | 现状 | 收编动作 |
|------|------|------|------|---------|
| **L1** | `ConfigLoader.LoadSideContainerAsync` | `FileDriven.JsonRefer/JsonProcessing/ConfigLoader.cs` | 独立侧边容器加载：30s 锁超时 + 路径解析 + 反射调用容器 `LoadConfigAsync` | 删除或委托 `ILoadConfigPort`（锁/路径解析由状态管线统一） |
| **L2** | `FileDrivenApplicationService.LoadUIConfigAsync` / `LoadUIConfigAsyncWithRender` | `FileDriven.Execution/Services/` | 历史中间层：清旧 Entity → 加载 → 创建 → 收集 → 应用 | 已绕过（LoadConfigPortAdapter 不再经此），标注废弃删除 |
| **L3** | `ReflectiveConfigLoader` | `FileDriven.Utilities/UI/ReflectiveConfigLoader.cs` | 反射调用 `FileDrivenApplicationService.LoadUIConfigAsync` | 已冗余（ILoadConfigPort 消除反射），删除 |
| **L4** | `PipelineEntry.LoadConfig` / `_loadedConfigs` | `FileDriven.Pipeline/PipelineEntry.cs` | 共享状态管理器维护已加载配置字典 | 保留字典但与状态驱动解耦；加载动作委托状态管线 |
| **L5** | `ConfigLoader.LoadConfigAsync(object container, ...)` 两个重载 | `FileDriven.JsonRefer/JsonProcessing/ConfigLoader.cs` | 反射调用容器 `LoadConfigAsync` 方法 | 收敛到状态管线（容器本地加载语义由投影器承载） |
| **L6** | `ConfigurationLifecycleManager.BootstrapAsync`/`LoadPhaseAsync` | `CsharpPrj/Operation/FrontEndDriven/Lifecycle/` | 启动 boot 声明按序加载 | **保留**（启动引导非动态加载），但宿主解析统一走 `HostBindingStore→ControlPool`，删除独立 `_hostResolvers` 兜底 |

### 6.2 收编原则

1. **单一入口**：所有「把配置加载进容器」的动作，最终都调用 `ContainerCommandExecutor.LoadToScopeAsync(scope, configPath)`。
2. **宿主解析唯一源**：`HostBindingStore`（scope↔hostKey）+ `ControlPool`（hostKey↔控件），删除各路径自带的递归/反射/兜底查找。
3. **结果契约统一**：一律返回真实 `bool`，杜绝"无异常即成功"的假 PASS。
4. **死代码处置**：已绕过但未删除的路径（L2/L3）直接标注 `[Obsolete]` 后删除，避免误导后续维护者。

### 6.3 收编后状态

```
（统一前）
LoadConfigPortAdapter ──┬─ LoadSideContainerAsync（L1，独立锁+路径解析+反射）
                       ├─ FileDrivenApplicationService（L2，历史中间层）
                       ├─ ReflectiveConfigLoader（L3，反射）
                       ├─ PipelineEntry.LoadConfig（L4，独立字典）
                       ├─ ConfigLoader.LoadConfigAsync（L5，反射容器方法）
                       └─ ConfigurationLifecycleManager（L6，启动引导）

（统一后）
LoadConfigPortAdapter ──→ ContainerCommandExecutor.LoadToScopeAsync ──→ ContainerProjector.RenderAsync
启动引导（L6）         ──→ 同上（复用状态管线，宿主解析统一）
```

1. **构建**：`dotnet build FileDriven/FileDriven.sln` 通过
2. **功能回归**：`echo 10 | EnableMent\交互启动.bat` 运行 `mainlayout_function_test.json`
