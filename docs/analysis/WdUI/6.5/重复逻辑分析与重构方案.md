## 一、🔴 严重问题（逻辑错误 / Bug）

### 1. `WdUIEvents.Unsubscribe` 异步重载无法取消订阅 ✅ 已修复

**位置：** `UI/WdUI.Events.cs`

**问题描述：**
`Unsubscribe(string eventName, Func<object?, Task> handler)` 方法在取消订阅时创建了一个**新的匿名包装委托**，而不是使用之前订阅时创建的包装委托。由于 `Func<object?, Task>` 和 `Action<object?>` 是不同的委托类型，`DefaultEventBus.Unsubscribe(string, Action<object?>)` 内部使用 `handlers.Remove(handler)` 按引用比较，新创建的包装委托与订阅时创建的包装委托不是同一个对象，因此**取消订阅永远不会成功**。

**修复方案：** 维护一个 `ConcurrentDictionary<Func<object?, Task>, Action<object?>>` 映射表，在订阅时保存包装委托的引用，在取消订阅时查找并使用相同的包装委托实例。

---

### 2. `WdUIEvents.Subscribe` 异步重载的 `async void` 风险 ✅ 已修复

**位置：** `UI/WdUI.Events.cs`

**问题描述：**
`Subscribe(string eventName, Func<object?, Task> handler)` 内部包装为 `async void` 委托传递给 `FrameworkEventBus.Subscribe`。`async void` 方法的异常无法被调用者捕获，会直接导致进程崩溃。

**修复方案：** 在 `async void` 包装内部添加 try-catch，捕获异常并通过 `Debug.WriteLine` 记录。

---

### 3. `ConfigContainer.LoadConfig` 同步包装可能导致死锁 ✅ 已修复

**位置：** `UI/WdUI.Container.cs`

**问题描述：**
`LoadConfig(object config)` 方法使用 `Task.Run(async () => await RenderConfigAsync(uiConfig)).GetAwaiter().GetResult()` 在后台线程执行异步操作。在 UI 线程上同步等待可能导致死锁。

**修复方案：** 标记为 `[Obsolete]` 并推荐使用异步版本。

---

### 4. `RenderPipeline.Instance` 与 `WdUIComposer.LayoutContext` 循环依赖 ✅ 已修复

**位置：** `WdUI.RenderPipeline.cs`

**问题描述：**
`RenderPipeline.Instance` 的初始化回调中访问 `WdUIComposer.LayoutContext`，而 `WdUIComposer.LayoutContext` 的初始化回调中又可能访问 `RenderPipeline.Instance`，形成循环依赖。

**修复方案：** 当前已通过 `LayoutContext` 构造函数直接创建 `LayoutMediator` 实例来打破循环依赖。

---

### 5. `ApplyLayoutSkeleton` 中 `FindPanel` 与 `FindChild` 行为不一致 ✅ 已修复

**位置：** `Layout/Skeletons/ApplyLayoutSkeleton.cs`

**问题描述：**
`FindPanel` 方法只查找**直接子控件**中的 Panel，而 `FindChild` 方法使用 `ControlFinder.FindRecursive` 进行**递归查找**。这种不一致可能导致某些 Panel 被跳过。

**修复方案：** 统一使用 `ControlFinder.FindRecursive` 进行查找，确保 Panel 和子控件使用相同的查找策略。

---

### 6. `CreateLayoutPanelSkeleton.RegisterSubContainers` 空操作 ✅ 已修复

**位置：** `Layout/Skeletons/CreateLayoutPanelSkeleton.cs`

**问题描述：**
`RegisterSubContainers` 方法遍历所有子控件，检查是否为 `ConfigContainer`，但最终**不执行任何注册操作**。

**修复方案：** 移除 `RegisterSubContainers` 方法及其调用。

### 18. `LayoutContext.SubscribeResize` 使用 `WeakReference` 但事件订阅仍阻止 GC ✅ 已解决（SkeletonFlow 重构）

**问题描述：**

**评估：** 在 SkeletonFlow 重构中，`SubscribeResize` 已整合到 `RenderPipeline` 的会话管理中，通过 `DisposeSession` 显式清理，不再依赖 `WeakReference` 的自动取消机制。

## 五、🔍 新增发现的问题

### 19. `WdUIEvents.Unsubscribe` 异步重载的包装委托引用不一致

**严重程度：** 🔴 P0

**详细分析：**
`WdUIEvents` 提供了两个 `Subscribe` 重载和两个 `Unsubscribe` 重载。每次调用 `Subscribe` 或 `Unsubscribe` 时，都会创建一个新的匿名 `async` lambda 表达式。C# 编译器为每个 lambda 表达式创建不同的闭包实例，因此 `Subscribe` 创建的包装委托和 `Unsubscribe` 创建的包装委托是**不同的对象**。

`DefaultEventBus.Unsubscribe(string, Action<object?>)` 内部使用 `handlers.Remove(handler)` 按**引用相等**比较委托，因此 `Unsubscribe` 永远无法找到并移除 `Subscribe` 添加的包装委托。

**修复方案：**
维护一个 `ConcurrentDictionary<Func<object?, Task>, Action<object?>>` 映射表：

```csharp
private static readonly ConcurrentDictionary<Func<object?, Task>, Action<object?>> _asyncHandlerMap = new();

public static void Subscribe(string eventName, Func<object?, Task> handler)
{
    Action<object?> wrapper = async data =>
    {
        try { await handler(data); }
        catch (Exception ex) { Debug.WriteLine(...); }
    };
    _asyncHandlerMap[handler] = wrapper;
    FrameworkEventBus.Subscribe(eventName, wrapper);
}

public static void Unsubscribe(string eventName, Func<object?, Task> handler)
{
    if (_asyncHandlerMap.TryRemove(handler, out var wrapper))
    {
        FrameworkEventBus.Unsubscribe(eventName, wrapper);
    }
}
```

### 20. `ConfigContainer.RenderConfigAsync` 中 `ConfigureAwait(true)` 的线程安全问题

**严重程度：** 🟡 P2

**详细分析：**
`LoadConfigAsync(UIConfiguration)` 方法使用 `ConfigureAwait(true)` 确保 await 后回到原始同步上下文。但 `RenderConfigAsync` 内部在 `SuspendLayout/ResumeLayout` 块中调用了 UI 操作。如果调用者不在 UI 线程上，`ConfigureAwait(true)` 会尝试回到原始同步上下文，但原始同步上下文可能不是 UI 线程上下文，导致 UI 操作在非 UI 线程上执行。

**修复建议：** 在 `RenderConfigAsync` 内部使用 `BeginInvoke` 确保 UI 操作在 UI 线程上执行，或明确文档要求调用者必须在 UI 线程上调用此方法。

### 21. `AsyncFormBase` 的 `FormClosingToken` 在 `Dispose` 后返回 `CancellationToken.None`

**严重程度：** 🟡 P2

**详细分析：**
`AsyncFormBase` 的 `FormClosingToken` 属性在 `_disposed` 为 true 时返回 `CancellationToken.None`。`CancellationToken.None` 是一个**永远无法被取消**的令牌。如果子类在 `Dispose` 后获取此令牌并传递给异步操作，这些异步操作将无法被取消，可能导致资源泄漏或操作在窗体关闭后继续执行。

**修复建议：** 在 `Dispose` 中设置一个已取消的 `CancellationToken`，或抛出 `ObjectDisposedException`。
